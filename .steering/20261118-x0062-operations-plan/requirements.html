X-0062 ⑤ 運用案（GAS定期実行化の検討含む） — 要求定義

作成: 2026-11-18 | ステータス: 初版

1. 目的

AIニューステーマ提案ワークフロー（docs/news-theme-workflow.md）を、月次で確実に実行できる運用体制に落とし込む。具体的には以下を決定する：

  • 各Phaseの実行主体（人間／自動／GAS／cron）
  • 定期実行のスケジュールとトリガー
  • GASを利用する場合のアーキテクチャ設計
  • 成果物の保存・管理・通知方法
  • 障害や遅延が発生した場合のエスカレーション

2. ユーザーストーリー

  • 運用担当者として、毎月最初の営業日にAIニューステーマ提案のパイプラインが自動実行され、最新のトレンドKWが収集されていることを望む。
  • 編集担当者として、ChatGPT評価結果を元に記事化判断ができる状態になっていることを望む。そのために、収集済みKWが提案ファイルとして整形されていることを望む。
  • 経営者として、運用の各ステップが可視化され、遅延や停滞が起こったら通知が来ることを望む。
  • 監督AIとして、定期実行の成否がログとして残り、障害時には別の自動経路（他AI）へのフォールバックが効くことを望む。

3. 受け入れ条件

  1. 月次パイプライン（Phase 1→3）がcronまたはGASトリガーで自動起動する
  2. Phase 1のGoogle Trends収集結果が提案ファイルとして出力される
  3. Phase 2のChatGPT入力用フォーマットが自動生成される
  4. Phase 3の提案ファイルが所定の場所に保存され、GitHubに自動commitされる
  5. 運用の各Phaseの状態（未着手／進行中／完了／遅延）がトラッキングされる
  6. GASを使用する場合、Google Sheets上で提案一覧を管理できる
  7. 障害発生時に通知が送られる

4. 制約事項

  • Phase 2（ChatGPT評価）は人間の操作が必要 — 自動化不可
  • Phase 4（記事化判断）は人間の判断が必要 — 自動化不可
  • GASのトリガーは6時間間隔以上の間隔が推奨（無料枠制限）
  • 外部API（Google Trends）の呼び出し頻度は月1回で十分
  • 秘匿値（APIキー等）はGASスクリプトプロパティで管理し、コード内に書かない

5. スコープ外

  • 提案されたテーマの記事本文作成 — 別プロセス
  • SEO効果測定の自動ダッシュボード — X-0057参照
  • 他社サイトの競合分析 — 別提案
