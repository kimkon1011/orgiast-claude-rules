# TOKENS.md — エージェントの入力トークンを抑える

エージェントセッション（Claude Code 監督セッション）の固定入力トークンを実測し、無駄を特定して削減する。読者は全 PC・全アカウントの Claude Code 監督セッション。

## 実測（2026-11-17 / 席 018）

毎セッション自動ロードされるファイルのサイズ:

| ファイル | バイト数 | 概算トークン |
|---|---|---|
| ~/.claude/CLAUDE.md | 145,479 | 約 36,000 |
| ~/.claude/next-session.md | 17,849 | 約 4,500 |
| ~/.claude/shared-memory/MEMORY.md | 6,512 | 約 1,600 |
| ~/.claude/projects/<proj>/memory/MEMORY.md | 5,313 | 約 1,300 |
| ~/.claude/orgiast-mission.md | 5,873 | 約 1,500 |

**毎セッションの固定費は約 45,000 トークン**。うち CLAUDE.md だけで約 80%（約 36,000）を占める。

## 6つのトークンリーク

### リーク1: 同一ファイル内の二重記述

- **症状**: CLAUDE.md（1,650 行）の前半 1〜1,533 行に ONBOARDING 全文（詳細な散文）、後半 1,535〜1,650 行に同じ章番号の 🔴 要約層が入っている。同じ §1.1 のルールが 2 回書かれている。
- **実測**: 1,650 行中、後半の要約層は約 115 行。全文層と要約層の重複は約 1,400 行（約 30,000 トークン相当）。ただし単純削除はできず、全文層は歴史的理由で存在している。
- **なぜ起きたか**: 🔴 要約行を追加した際に、古い全文を削除しなかった。同じファイルの末尾に追記しただけ。
- **直し方**: 要約層を正本とし、全文層の各ブロックを参照先ドキュメントへのリンクに置き換える（要承認）。または全文層を別ファイル（例: `docs/ONBOARDING_ARCHIVE.md`）に出して CLAUDE.md からはリンクのみにする。

### リーク2: superseded なのに残っている矛盾ブロック

- **症状**: 🔴 要約層（現行ルール）と矛盾する古い全文が同じ CLAUDE.md 内に残っている。古い方が長く具体的な記述のため、注意がそちらに引っ張られる。
- **実測**: 確認された 4 件の矛盾:

| # | 古い全文（まだ注入されている） | 新しい 🔴 要約（現行ルール） | 行 |
|---|---|---|---|
| 1 | §1.5「Workspace URL は必ず `/a/orgiast.jp/` を挟む」（約 207 行） | 「`/a/orgiast.jp/` は使わない。authuser=開く人のメール を付ける」 | 758〜964 vs 1578 |
| 2 | §2.4「GitHub 操作は Web UI を最優先。単発 Secret 追加は Web UI で十分」 | 「PR は作った席が自分で着地させる。pr-land.mjs で着地」「gh コマンド実行はやる側」 | 1269 vs 1537 |
| 3 | §1.13「単純編集・grep・置換は Sonnet / Haiku。迷ったら Auto」 | 「既定モデルは Opus。迷ったら Opus」 | 1146 vs 1591 |
| 4 | §1.14「permission mode の既定は auto」 | 「permission mode の既定は bypassPermissions」 | 1181 vs 1598 |

- **なぜ起きたか**: 🔴 行で方針を変えたのに、古い全文を削除・修正しなかった。
- **直し方**: 矛盾ブロック（古い全文）を削除する。ただし CLAUDE.md の削除は承認が必要。あるいは古い全文の冒頭に「⚠ superseded — 🔴 行を参照」の注釈を入れるだけでも、注入側のトークンは変わらないが混乱は減る。

### リーク3: path-scoped にできる章の常駐

- **症状**: GAS 固有のルール（§1.4、約 390 行）が全セッションで読み込まれている。GAS を触らないセッションでも毎回払っている。
- **実測**: §1.4 は 365〜757 行の約 390 行。`rules/gas.md` に path-scoped な同じ内容が既にある。§1.3 自身が「`.gs` / `appsscript.json` に rules/gas.md を適用」と書いており、重複を認識している。
- **なぜ起きたか**: CLAUDE.md が「全セッション共通のルールファイル」という設計で、path-scoped 分離を最初から前提にしていなかった。
- **直し方**: §1.4 の全文を CLAUDE.md から削除し、`rules/gas.md` の参照（1行）に置き換える。削除は承認が必要。

### リーク4: 一度しか使わない手順の常駐

- **症状**: §3「セットアップ手順」（1,452〜1,533 行、約 80 行）は新規メンバーの初回取り込み専用。既に取り込み済みの席では毎回不要。
- **実測**: 約 2,000 トークン相当。全セッションで毎回注入されている。
- **なぜ起きたか**: 一度きりの手順を CLAUDE.md に含めてしまい、分離しなかった。
- **直し方**: §3 の全文を CLAUDE.md から削除し、`docs/SETUP.md` などの別ファイルへのリンクに置き換える。

### リーク5: 「過去事例」ナラティブの肥大

- **症状**: 各ルールの末尾に「過去事例（YYYY-MM-DD）」として長い被害譚が段落で書かれている。教訓は 1 行で足りる。
- **実測**: 例: §1.1.1 の過去事例は「aujust-sales-automation で migration 0011 を…」と約 20 行。同 §1.1.4 も約 20 行。全章で同様。合計で 200 行以上と推定。
- **なぜ起きたか**: 「なぜこのルールができたか」を同じ場所に書く設計。一箇所で完結する反面、毎回全量が注入される。
- **直し方**: 過去事例は「教訓 1 行 + `[[memory-name]]` リンク」に畳み、詳細は個別 memory ファイルに追い出す。

### リーク6: ツール結果後の CLAUDE.md 全文再注入

- **症状**: CLAUDE.md は SessionStart の system-reminder と、最初のツール呼び出し後の "Contents of ..." ブロックの両方で全文が出る。同一内容が 1 ターンに 2 回注入される。
- **実測**: 本セッションで確認。同じ 36,000 トークンが 2 回出現する。つまり固定費のうち約 36,000 トークンが重複している。
- **なぜ起きたか**: SessionStart での注入と、ツール結果後のファイル内容表示が直列している。ハーネスの仕様。
- **直し方**: Claude Code ハーネス側の設定変更が必要。監督セッション側では制御できないため、CLAUDE.md のサイズ自体を減らすことで重複の絶対量を減らす。

## 6つのレバー

### レバー1: 矛盾ブロックを要約層に寄せて全文層から削る

- **やること**: リーク2の 4 件の矛盾ブロック（古い全文）を CLAUDE.md から削除する。あるいは「⚠ superseded」注釈を入れるだけでも混乱は減る。削除には kim の承認が必要。
- **期待削減**: 約 400 行（約 9,000 トークン相当）の注入削減に加え、矛盾による解釈コスト（人間と AI 双方）がゼロになる。
- **検証方法**: 削除後の CLAUDE.md で新規セッションを開始し、両層の矛盾が消えたことを確認。注入トークン数を実測。

### レバー2: 章を path-scoped rules/*.md へ移す

- **やること**: §1.4（GAS ルール）の 390 行を CLAUDE.md から削除し、`rules/gas.md` を参照する 1 行に置き換える。削除には承認が必要。
- **期待削減**: GAS を触らないセッションで約 390 行（約 9,000 トークン）の削減。GAS セッションでは変わらない（path-scoped で別途読まれる）。
- **検証方法**: `.gs` ファイルが無いプロジェクトで新規セッションを開始し、CLAUDE.md の注入トークンが減ったことを確認。

### レバー3: 「過去事例」は教訓 1 行 + リンクに畳む

- **やること**: CLAUDE.md 内の全「過去事例（YYYY-MM-DD）」ブロックを「教訓: 1 行。詳細は `memory/xxx`」に置き換える。全文を個別 memory ファイルに移動する。
- **期待削減**: 約 200 行（約 5,000 トークン）の削減。
- **検証方法**: 新規セッションで注入行数が減ったことを確認。

### レバー4: 一度きりの手順（§3）を別ファイルへ出す

- **やること**: §3 セットアップ手順（約 80 行）を CLAUDE.md から削除し、`docs/SETUP.md` に移動。CLAUDE.md にはリンクだけ残す。削除には承認が必要。
- **期待削減**: 約 80 行（約 2,000 トークン）の削減。
- **検証方法**: 新規セッションで注入行数が減ったことを確認。

### レバー5: 要約層（🔴 行）を正本にし、全文層は参照先ドキュメントへ

- **やること**: CLAUDE.md の全文層（約 1,400 行）を`docs/ONBOARDING_ARCHIVE.md` のような別ファイルに移動。CLAUDE.md には 🔴 要約層のみ残す。削除には承認が必要。
- **期待削減**: 約 30,000 トークンの削減（固定費の約 66%）。
- **検証方法**: 新規セッションで注入トークン数を実測し、従来の 45,000 トークンに対する削減率を確認。

### レバー6: 出力側 — サブエージェントに圧縮指示

- **やること**: 重い探索を Agent（Explore / general-purpose）に委譲する際、「結果 200 字以内、コード本体を含めない」と明示する。
- **期待削減**: 出力トークン。出力は入力より単価が高い（§2.8）ため、入力削減に加えて費用面でも効果がある。定量見積もりは状況依存。
- **検証方法**: 委譲結果が 200 字以内に収まっているか確認。出力トークン量を usage ログで確認。

## やってはいけない

- 要約層と全文層の両方を同時に編集して片方だけ直す — 矛盾が増える。
- 矛盾を見つけたまま放置して新しい 🔴 行だけ足す — 積み増しでトークンだけ増える。
- 削除に承認が必要な箇所を「ついでに消す」 — CLAUDE.md の削除は許可が必要。
- 削減だけで CLAUDE.md の可読性を下げる — 「機械が読めれば良い」は人のメンテナンスを困難にする。
- 全てのレバーを一度に適用しようとする — 1 つずつ検証して効果を測る。
