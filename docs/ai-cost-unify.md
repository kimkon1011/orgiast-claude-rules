# AI費用の月次統合・freee登録候補の確認

既存の `CLOUD_LEDGER_SHEET_ID` のブックに `AI費用サマリ` と `freee登録待ち` を追加する。新しいブックは作らない。freeeへの登録は経理が行い、このツールはfreee APIを呼ばない。

## 月次の手順

1. 購買部管理アプリの既存 `scripts/ai-cost-reconcile.ts` で、対象期間の全支払い元（会社カード・kim個人カードを含む）の明細を読み取り、出力JSONを保存する。出力の `period`、`vendors`、`payers`、`unmatched` を確認する。このリポジトリでは取得処理を重複実装しない。
2. 各サービスの管理画面で対象アカウントの請求書・領収書を取得し、全案件分が取得対象に含まれることを確認する。ローカルログは画面での利用や別PCの利用を網羅しない。ログに無いことは未利用の証拠にはならない。
3. ローカル実測を出力する。採用した換算レートはJSONの `jpyPerUsd` に残る。既定は150円/USDであり、請求書の確定円額とは区別する。

   ```sh
   node tools/ai-usage-local.mjs --months 13 --jpy-per-usd 150 > ai-usage-local.json
   ```

   `ORGIAST_HOME` でログのホームを指定できる。Claudeはそのホームの `.claude/projects`、Codexは既存の `CODEX_SESSIONS_DIRS` 設定を再利用する。複数PCのログを入力にまとめる場合は、同じ実行を重複させず、年月×プロバイダに集約した同一形式のJSONを `--local` で渡す。安いAIは `executor-usage.jsonl` と既存 `COST_PER_MILLION` を使い、Geminiの記録済みUSD（検索費用を含む）は既存Gemini集計で換算する。単価不明・未計測はnull、Claude/Codex等の定額枠もnullとする。
4. 呼び出し元がGAS変更を反映した後、既存 `~/.claude/fleet-sheet.env` の接続先で予行確認する。

   ```sh
   node tools/ai-cost-unify.mjs --freee ./ai-cost-reconcile.json --local ./ai-usage-local.json --months 13 --dry-run
   ```

   dry-runも `ai-cost-describe` を呼び、実ヘッダ・行数を確認する。診断失敗時は中止し、想定値で代用しない。診断ではタブ作成やヘッダ補修を行わない。URL/TOKEN未設定時はstderrに1行出して正常終了する。
5. 内容を確認した呼び出し元が `--dry-run` を外して送信する。`--local` 省略時はその場でローカル集計する。既存の非空セルを再集計値に更新する場合は `--force` を付ける。通常は空セルのみ更新し、更新日時・検出日は常に更新する。サマリと登録待ちは別リクエストなので、後者が失敗した場合は同じ入力で再実行できる。
6. 経理は `freee登録待ち` を請求書・カード明細・freeeの実取引と照合する。摘要案は `AI利用料 <サービス> <年月>`。トークン概算をそのまま確定支払額として登録せず、請求書で金額・支払い元・対象月を確認する。勘定科目・税区分は経理が記入し、手動でfreee登録後に `登録済み` を記入する。

## 判定と保持

- `両方にあり`: freee明細とローカル実測の両方に記録がある。差額は両方の金額が数値のときだけ出す。
- `freeeに無い（要確認）`: ローカル実測だけに記録がある候補。freee入力期間外、未分類明細、支払月のずれ、定額枠なども確認する。未登録と断定しない。
- `実測に無い`: freeeだけに記録がある。定額利用や画面からの利用でも発生し、登録待ちには入れない。
- `判定不能`: 双方の金額が不明で、定額枠とも判断できない。定額枠だと分かる場合は金額nullでも記録の有無に応じた状態を使う。

登録待ちは当月を含む指定月数の範囲で置換し、候補0件になった月の古い機械行も削除する。範囲外の行、登録済み行、科目・税区分など人の記入がある行は削除しない。人の列はforceでも書かない。サマリの備考も機械の許可リストから除外する。

`--force` が無い場合、既存の金額・状態が保持される。標準出力の候補一覧は今回の入力に基づく判定なので、シートの既存値を最新化する運用では `--force` を使う。未送信フィールドはforceでも変更しない。明示的なnullや空の差額は、force時には古い確定値を空に戻す。

この集計の単位は年月×サービスであり、契約・アカウント別の取引明細ではない。複数の契約に対応するANTHROPIC等はvendor名の1行に集約する。支払い元は入力から1つに絞れる場合だけ記載し、複数名義は空欄にする。登録候補の金額nullは無料を意味しない。

## 検証

```sh
node --test tools/ai-cost-logic.test.mjs tools/ai-cost-unify.test.mjs
```

HTTPを注入したテストのみで検証できる。GASのデプロイ、実POST、freeeへの書き込みはこの実装作業では実行しない。
