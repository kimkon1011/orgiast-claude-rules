# AIニュース提案 [P-0006]: PayPay 銀行口座初期設定フローの標準化

## 課題
PayPay 銀行口座の開設・初期設定において、以下の問題が発生している：
- 口座情報（口座番号・支店名・名義）の共有手段が担当者によってバラバラ
- カード・トークン（デビットカード番号・セキュリティコード・暗証番号）の保管方法が統一されていない
- 設定手順が個人の記憶に依存し、引き継ぎ時に情報漏れや設定漏れが発生
- 担当者間の重複作業や設定ミスによる手戻り

## 目的
PayPay 銀行口座の初期設定フローを標準化し、以下の状態を実現する：
1. 口座情報は安全な一元管理場所で共有される
2. カード・トークンの保管・利用ルールが明確
3. 設定手順が文書化され、誰でも同じ手順で設定可能
4. 担当者交代時の情報漏れリスクが最小化される

## 標準化対象フロー

### 1. 口座開設・基本情報の登録

| ステップ | 作業内容 | 担当 | 保管先 |
|----------|----------|------|--------|
| 1-1 | PayPay 銀行アプリインストール（iOS/Android） | 経理 | - |
| 1-2 | 本人確認書類の準備（運転免許証・マイナンバーカード） | 経理 | 案件「経理」フォルダ（閲覧制限） |
| 1-3 | 口座開設申込（アプリ内手続き） | 経理 | - |
| 1-4 | 口座番号・支店名の確認 | 経理 | - |
| 1-5 | 口座基本情報を共有台帳に記録 | 経理 | 共有ドライブ「経理」>「口座情報」シート |

### 2. カード・トークンの発行と保管

| ステップ | 作業内容 | 保管方法 | アクセス権限 |
|----------|----------|----------|-------------|
| 2-1 | PayPay 銀行デビットカード発行申請 | - | - |
| 2-2 | カード到着後、物理カードは金庫保管 | オフィス金庫（施錠管理） | 代表・経理責任者のみ |
| 2-3 | カード番号・有効期限・セキュリティコードを暗号化保存 | 共有ドライブ「経理」>「暗号化情報」（パスワード管理ツール併用） | 経理責任者・代表 |
| 2-4 | オンラインバンキングのログインID/パスワード設定 | パスワード管理ツール（Bitwarden / 1Password） | 経理担当者・代表 |
| 2-5 | 二段階認証（SMS / 認証アプリ）の設定 | 認証アプリ（Google Authenticator / Authy）は経理責任者端末 | 経理責任者のみ |
| 2-6 | 取引暗証番号（4桁）の設定と保管 | パスワード管理ツール（別エントリ） | 経理担当者のみ |

### 3. API・外部連携設定

| ステップ | 作業内容 | 保管先 |
|----------|----------|--------|
| 3-1 | PayPay 銀行 API 利用申込（法人向け） | - |
| 3-2 | API キー・シークレットの発行 | keyserve（`config/ai-key-owners.json` に登録） |
| 3-3 | IP 制限・許可リスト設定 | 管理画面で設定 |
| 3-4 | Webhook URL 設定 | 管理画面 + システム設定ファイル |
| 3-5 | テスト環境での接続確認 | テスト結果を `docs/` に記録 |

### 4. 定期メンテナンス

| 頻度 | 作業内容 | 確認方法 |
|------|----------|----------|
| 毎月 | 残高・取引明細の確認 | オンラインバンキングログイン |
| 3ヶ月ごと | アクセス権限の棚卸し | パスワード管理ツール・共有ドライブの権限確認 |
| 6ヶ月ごと | カード有効期限の確認 | 物理カード・暗号化情報の期限チェック |
| 年1回 | 全設定の見直し・手順書更新 | 本ドキュメントのレビュー |

## 情報管理ルール

### 機密区分と取扱い

| 区分 | 対象情報 | 保存場所 | 共有方法 |
|------|----------|----------|----------|
| 公開可能 | 支店名・銀行名 | 共有ドライブ（制限なし） | メール・チャット |
| 社内限定 | 口座番号・名義 | 共有ドライブ（経理のみ） | 暗号化ファイル添付 |
| 機密 | カード番号・セキュリティコード・暗証番号 | パスワード管理ツールのみ | ツール内共有機能 |
| 最高機密 | API キー・シークレット | keyserve + パスワード管理ツール | 直接手渡し後即消去 |

### 禁止事項
- ❌ 口座情報を Slack / Discord / LINE 等のチャットに平文で投稿
- ❌ カード番号・セキュリティコードをメール本文に記載
- ❌ パスワード・暗証番号を付箋等で物理的に貼り出す
- ❌ API キーをソースコードにハードコード
- ❌ スクリーンショットに口座番号が写った状態で共有
- ❌ 退職者の端末に認証情報を残したままにする

### 担当者交代時の手順
1. パスワード管理ツールのメンバー変更（追加/削除）
2. 物理カードの返却確認（金庫在庫と照合）
3. 認証アプリの再設定（旧担当者端末から解除→新担当者端末へ設定）
4. 二段階認証の電話番号変更（該当する場合）
5. アクセスログの確認（異常有無）
6. 引継ぎ書への記録（HANDOVER.md 準拠）

## 障害・緊急時対応

### カード紛失・盗難
1. PayPay 銀行コールセンターへ即時連絡（050-0000-0000）
2. オンラインバンキングから一時利用停止
3. 経理責任者へ報告
4. 再発行申請
5. 新しいカード到着後、暗号化情報を更新

### 不正アクセス疑い
1. オンラインバンキングから全セッションを強制終了
2. パスワード・暗証番号を即時変更
3. 取引履歴の精査
4. 警察・銀行への届出
5. セキュリティ診断の実施

## 自動化・ツール連携

### 定期チェック自動化（推奨）
```bash
# 口座情報の期限チェック（cron 月次）
node tools/account-expiry-check.mjs --bank paypay

# API キーの有効性確認（cron 週次）
node tools/api-key-verify.mjs --service paypay-bank

# アクセス権限の棚卸しレポート（cron 四半期）
node tools/access-audit-report.mjs --target paypay-bank
```

### Claude Code からの参照方法
```bash
# keyserve から API キーを取得（要権限）
node tools/keyserve.mjs get paypay-bank-api-key

# 口座基本情報を参照（要経理権限）
node tools/account-info.mjs --bank paypay
```
