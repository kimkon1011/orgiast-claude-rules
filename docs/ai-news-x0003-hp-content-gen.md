# X-0003: 独自資料をAI投入してホームページ文章生成（ランブック）

観測日: 2026-11-08。出典: AIニュース digest X-0003「独自資料をAI投入してHP文章生成」。
本稿は「株式会社オージャストで試す手順」＝過去の展示会ブース制作事例・イベント写真・仕様書などの**社内独自資料をAIに与えて**、自社サイト（tetsuko.co.jp）の紹介文や事例ページを生成するための、再現可能なワークフローとツールを文書化したもの。

## 従来の課題

| 問題 | 説明 | 結果 |
|------|------|------|
| AIに「オージャストの実績を書いて」とだけ指示しても、公開情報（汎用的な会社説明）しか生成されない | AIは学習データにない個別案件を知らない | どの企業にも当てはまる無個性な文章になる |
| 事例ページを作るたびに人間が写真を見ながら一から文章を書いている | 毎回の執筆コストが高い | 事例公開の頻度が下がり、サイトが更新されない |
| 社内に散らばった案件データ（CAD図面・写真・仕様書）が活用されない | 資料の所在とフォーマットが統一されていない | せっかくの独自データがAIの入力として使えない |

## ワークフロー全体像

```
[準備] 案件データを構造化JSONに集約
     ↓
[Step 1] ツールで事例紹介文を一括生成（AIに社内データを与えて）
     ↓
[Step 2] 会社紹介（トップページ）の文章を生成
     ↓
[Step 3] 生成されたMarkdown/HTMLをサイトに配置
     ↓
[Step 4] 人間が最終確認・微修正して公開
```

## Step 0: 案件データの構造化（準備）

AIに与える社内資料は、**構造化JSON** の配列として準備する。各案件は以下の必須フィールドを持つ:

```json
[
  {
    "projectId": "C0056",
    "title": "三共精機 Reブース提案",
    "client": "三共精機株式会社",
    "industry": "精密機器製造",
    "event": "ものづくりワールド2026",
    "boothSize": "3m × 6m（小間）",
    "period": "2026-10 提案・2027-02 本番予定",
    "services": ["ブースデザイン", "施工"],
    "description": "三共精機の自社ブランド新製品発表に向けた、リブランディングを意識したブース提案。",
    "highlights": [
      "サーモンピンクを基調としたプレミアム感のあるデザイン",
      "商談スペースと製品展示エリアの動線分離",
      "限られた3m×6m小間でのブランド表現"
    ],
    "results": "見積提示済み・成約率90%",
    "imagePaths": ["docs/assets/images/c0056-photo1.jpg", "docs/assets/images/c0056-render.png"],
    "projectUrl": ""
  }
]
```

最低3件の事例が揃えば、Step 1に進める。フォーマットは `data/booth-projects.json` にサンプルを配置する（付属ツール `tools/booth-case-study-gen.mjs` が読み込む）。

### 写真・画像の準備

各案件の写真は `docs/assets/images/` 配下に `{projectId}-{seq}.jpg` の命名で配置する。推奨:
- ファイルサイズ: 200KB以下（JPEG圧縮、長辺1200px程度）
- アスペクト比: 16:9 または 4:3
- alt属性用の説明文を同時に用意

## Step 1: 事例紹介文を一括生成（ツール使用）

### ツール: `tools/booth-case-study-gen.mjs`

```bash
node tools/booth-case-study-gen.mjs \
  --data data/booth-projects.json \
  --output docs/case-studies/
```

**ツールの動作:**
1. `data/booth-projects.json` から各案件を読み込む
2. 案件ごとに、AI（OpenRouter / Gemini 経由）に以下のプロンプトを送信:
   - **案件サマリ**（80語程度の紹介文）
   - **詳細事例ページ**（Markdown、SEOを考慮した800〜1200語のケーススタディ）
   - **メタディスクリプション**（検索結果向け120字程度）
3. `docs/case-studies/` 配下に `{projectId}-case-study.md` として出力
4. 同時に一覧ページ `docs/case-studies/index.md` を更新

### AIプロンプトの設計（ツール内蔵）

案件データを受け取った際の内部プロンプト:

```
あなたは展示会ブース制作会社のWebライターです。
以下の案件データを基に、自社サイトに掲載するケーススタディ記事を
日本語で作成してください。

【案件データ】
{project JSON}

【出力要件】
1. タイトル: 検索キーワードを含む30〜50字
2. リード文: 「こんな課題→こう解決」の構造で100字
3. 本文: 背景→課題→アプローチ→結果→次の展望の順で800〜1200字
4. メタディスクリプション: 120字以内、数値を含める
5. トーン: B2B専門的だが親しみやすい
```

## Step 2: 会社紹介文の生成

案件データが3件以上揃った時点で、以下のコマンドで会社全体の紹介文を生成する:

```bash
node tools/booth-case-study-gen.mjs \
  --data data/booth-projects.json \
  --company-intro \
  --output docs/intro/
```

出力:
- `docs/intro/company-intro.md` — tetsuko.co.jp トップページや「会社概要」「実績」ページに使える紹介文案

## Step 3: サイトへの配置

生成されたMarkdownを、サイトの該当ページに反映する:

| 生成物 | 配置先 | 備考 |
|--------|--------|------|
| `case-studies/{id}-case-study.md` | tetsuko.co.jp `/case-studies/{id}/` | 事例詳細ページ。JSON-LD マークアップを含む（X-0004 Point 2） |
| `case-studies/index.md` | tetsuko.co.jp `/case-studies/` | 事例一覧ページ。フィルター機能は手動追加 |
| `intro/company-intro.md` | tetsuko.co.jp トップページ・会社概要 | 専門性を伝える導入文として活用（X-0004 Point 1） |

## Step 4: 人間の確認・編集

**AIが生成した文章は必ず人間が確認する。** 確認項目:

- [ ] 事実誤認がないか（架空の数値・固有名詞が入っていないか）
- [ ] 機密情報が含まれていないか（公開不可の顧客情報・金額など）
- [ ] トーンがサイト全体と一貫しているか
- [ ] 画像のalt属性が適切か
- [ ] 引用元の案件が実在するか

## 期待される効果

X-0004（LLMO向けサイトコンテンツの4ポイント）の観点から:

| ポイント | X-0003 の貢献 |
|---------|--------------|
| Point 1: 専門性 | 案件データから抽出された具体的な記述（「3m×6m小間」「精密機器製造」）が、専門性の裏付けになる |
| Point 2: 事例 | 本ワークフローの主成果。構造化された事例が一貫した品質で生成され、公開頻度が上がる |
| Point 3: FAQ | —（X-0003の直接対象外） |
| Point 4: 信頼性 | 数値・固有名詞を含む事例文章が、AI検索での引用されやすさを向上させる |

**目標効果:**
- 事例ページ作成工数: 1件あたり2時間 → 30分（ツール生成＋確認）
- 事例公開頻度: 四半期1件 → 月1件以上
- LLM引用率: 比較クエリでの推薦率20% → 50%（X-0007測定の改善に寄与）

## ツールのインストールと依存

```bash
# ツールはリポジトリ直下で動作
cd /path/to/repo
node tools/booth-case-study-gen.mjs --version
```

依存: Node.js 20+, インターネット接続（OpenRouter API または Gemini API）
認証情報: `.env` または環境変数 `OPENROUTER_API_KEY` / `GEMINI_API_KEY`
LLM呼び出しにはプロジェクト共通のプロバイダルーティング（`tools/provider-routing.mjs`）を使用する。

## 開示

本稿は 2026-11-08 時点の実装計画である。ツール `tools/booth-case-study-gen.mjs` の初回実装は同梱するが、実際の案件データ投入と公開は利用者（株式会社オージャスト社内）が行う。生成された文章は必ず人間の校閲を経てから公開すること。
