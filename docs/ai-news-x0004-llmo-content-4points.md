## 4つのポイント（全体像）

2026年時点の LLMO（LLM Optimization / AI検索最適化）実務において、LLM に正しく引用・評価されるサイトコンテンツには以下の4要素が不可欠である。各ポイントは独立して実施可能で、優先順位は自社の現状スコアに応じて選択する。

| # | ポイント | なぜ重要か | LLM引用への影響 |
|---|----------|-----------|-----------------|
| 1 | **特定分野の専門性** | LLM は「誰が何に詳しいか」を判断して回答に含める。汎用的な表現（「高品質」「豊富な実績」）は引用されない | 指名クエリでの企業説明の正確性・深さに直結 |
| 2 | **具体的な導入事例** | LLM は数値・固有名詞・期間を含む事例を「根拠として引用可能な情報」と認識する | 比較クエリ・課題解決クエリでの推薦確率を決定 |
| 3 | **顧客の疑問に答える情報（FAQ）** | FAQ は LLM が回答文を生成する際の直接的なソースになる。質問＋回答形式が最も抽出されやすい | 全クエリ種別での引用率に影響。最重要ポイント |
| 4 | **Web上の情報の信頼性** | LLM は出典の鮮度・権威・アクセス可能性を（暗黙に）評価する | 回答に含めるか否かの最終的なフィルター |

### 出典と根拠

本稿の4ポイントは以下の外部知見を統合したものである:

- **Google Search Central（2026）**: AI生成検索向け公式ガイド。非コモディティ・peoples-first コンテンツ、明確な見出し構造、高品質画像・動画を推奨。`llms.txt` 等の特殊 AI マークアップは無視すると明言。
- **HubSpot / BCG X / GEOL.ai**: スキーママークアップ・トピックカバレッジ・決定基準の明確化（比較表・5〜7因子の評価軸）の重要性。
- **Onely.com**: Answer-first 構成（回答→詳細）が LLM 抽出率を大きく向上させる。
- **Knowledge Holdings（同業・展示会ブース施工）実績**: コラム記事（ユーザーの質問に答える形式）＋外部対策で AI 引用数 3→19件（6ヵ月）。Google AI 概要 0→8件、Perplexity 1→8件。
- **ローカルマーケティングパートナーズ（2026）**: Answer-first・FAQ充実・比較表と数値データ・独自データの4点をLLMO対策の核と整理。
- **sai X aid コラム・東京大学AI工学博士監修（2026）**: 抽出しやすさ・機械可読性・信頼性（E-E-A-T）の3軸。結論ファースト・構造化データ・FAQ Schema の実装手順。

## Point 1: 特定分野の専門性（Domain Expertise）

### なぜ必要か

LLM が「この企業は何に強いのか」を判断するには、**業種・職種・課題が明確で、かつ汎用的でない記述** が必要。たとえば「展示会ブースの企画・設計・施工を一貫対応」ではなく「中小製造業の展示会初出展向け、3m×3m 小ブースのデザイン〜設営・撤去までを最短2週間で対応」と書かれている方が、LLM は確信を持って引用できる。

### オージャストでの適用

- **現状**: expo-apply アプリ（[PR #1688](https://github.com/kimkon1011/orgiast/pull/1688)）で `llms.txt` / `ai.txt` / `robots.txt` / JSON-LD / メタタグ は整備済み。アプリの技術的枠組みは AI 可読になった。
- **不足**: オージャストの**事業ドメイン説明**（展示会ブース制作会社としての専門性）がサイト上に構造化されていない。`llms.txt` はアプリの説明であり、会社全体の LLMO ではない。
- **施策**: 以下を会社サイト（tetsuko.co.jp）に追加する:
  1. 専門性を1段落で要約した `llms.txt`（会社全体版）をサイトルートに設置
  2. 提供サービス一覧（企画・デザイン・設計・施工・運営・撤去）を JSON-LD `Service` / `Product` でマークアップ
  3. 各サービスページに「このサービスはこんな企業に」の対象セグメントを明示

### 受け入れ条件
- `llms.txt` の観測日・更新履歴を含む
- JSON-LD の `Service` が Google Rich Results Test でパース可能
- 各サービスページに H2「対応可能な企業像」を設置

## Point 2: 具体的な導入事例（Case Studies with Data）

### なぜ必要か

LLM は「〇〇社のブースを制作した」のような定性記述より「A社（製造業・売上30億）の18m² ブースを、企画から撤収まで6週間で対応、来場者アンケート満足度92%」のような**数値・固有名詞・期間を含む事例**を優先して引用する。理由は LLM の学習データが「具体性＝信頼性」と相関しているため。

Knowledge Holdings の事例（AI引用3→19件）でも、具体的なコラム記事が効果の中心だった。

### オージャストでの適用

- **現状**: 事例の体系的な公開は未着手。個別の制作実績は社内に散在。
- **施策**:
  1. 事例ページを新設（`/case-studies/`）。各事例は以下の必須フィールドを含む:
     - 業種 / 企業規模（従業員数または売上）
     - ブース規模（m²） / 予算帯（例: 100〜300万円）
     - 制作期間（例: 企画〜完工 4週間）
     - 成果（来場者数・アンケートスコア・リード獲得数等）
     - 画像3〜5点（alt属性に説明文）
  2. 各事例に `schema.org/Article` と `schema.org/CreativeWork` の JSON-LD を埋め込み
  3. 事例一覧ページにフィルター（業種・規模・予算帯）を設置

### 受け入れ条件
- 最低3件の事例を公開（例: 製造業・医療・IT 各1件）
- 各事例に数値データが2項目以上含まれる
- JSON-LD が Rich Results Test でパース可能

## Point 3: 顧客の疑問に答える情報（FAQ）

### なぜ必要か

**LLMO において最も即効性が高く、実装コストが低い施策が FAQ である。** 理由:

1. FAQ は LLM が回答文を生成する際の直接的なソースになる（Q→A のペアがそのまま回答に使われる）
2. FAQ Schema（`schema.org/FAQPage`）の実装が JSON-LD で容易
3. 2026年の実測では、FAQ ページのあるサイトの LLM 引用率が約2.5倍高いとの報告がある
4. 例「従業員30人の製造業におすすめのDX支援会社は？」のような質問は、FAQ に「小規模製造業向けサービス」の項目があれば直接回答に引用される

### オージャストでの適用

- **現状**: expo-apply アプリにはアプリ自体の FAQ があるが、**オージャストのサービスに関する FAQ は未整備**。
- **施策**: 以下を含む FAQ ページを会社サイトに設置:
  1. **予算・費用系**（最低いくらから？ 見積もりは無料？ 分割支払い可能？）
  2. **納期系**（最短どのくらい？ 繁忙期はいつ？ 追加対応のリードタイムは？）
  3. **サービス範囲系**（設計だけ？ 施工だけ？ 一貫対応とは？ 海外展示会対応？）
  4. **初心者向け**（初めての展示会、何から始める？ どの規模を選ぶ？）
  5. **比較・選定系**（自社で作るより安い？ 他社との違いは？）
  6. **業種別**（製造業・IT・医療・教育など、業種ごとの FAQ）

- 各 Q&A は `schema.org/FAQPage` の JSON-LD で構造化
- 質問は自然な口語体（「展示会に出たいけど何から始めればいい？」）

### 受け入れ条件
- 最低10問の FAQ を公開
- FAQ Schema が Google Rich Results Test でパース可能
- ChatGPT で「オージャスト 費用 いくら」「オージャスト 納期 最短」等の質問で FAQ が引用されることを確認

## Point 4: Web上の情報の信頼性（Trustworthiness & Authority）

### なぜ必要か

LLM は情報の**鮮度・出典の明示・アクセス可能性** を考慮して回答に採用するかを判断する（E-E-A-T の枠組み）。具体的には:

- **鮮度**: ページに「最終更新日」または「観測日」が明示されている
- **出典の明示**: 数値や主張に根拠リンクがある
- **アクセス可能性**: robots.txt で AI クローラーをブロックしていない
- **構造化**: 情報が JSON-LD / マイクロデータで機械可読になっている
- **誤情報対策**: 「これは確定情報ではない」等の但し書きや research.html のような検証ノートを併置

### オージャストでの適用

- **現状**: 以下の施策は expo-apply アプリで実施済み（PR #1688）:
  - ✅ `robots.txt` で AI クローラー（GPTBot, Google-Extended, CCBot, PerplexityBot）を許可
  - ✅ `ai.txt` で AI の利用許可範囲を明示
  - ✅ `index.md` で静的 Markdown 版を提供
  - ✅ `research.html` で検証ノート・エビデンスマップを公開
  - ✅ JSON-LD（WebApplication + FAQPage）の実装
  - ✅ `rel=alternate type=text/markdown` リンク
  - ✅ 最終更新日の明示

- **不足**: これらはアプリ専用。会社サイト（tetsuko.co.jp）では未実施。
- **施策**:
  1. 会社サイトに `robots.txt` / `ai.txt` / `llms.txt` を追加
  2. 各主要ページに `schema.org/Organization` / `LocalBusiness` / `Service` の JSON-LD
  3. 数値を含む記述にはインライン引用または脚注を付与
  4. 全ページにフッターで最終更新日を表示
  5. 別途「お客様の声」や第三者紹介記事を引用した信頼性補強ページを設置

### 受け入れ条件
- `robots.txt` への主要 AI クローラー許可が確認できる
- トップページの JSON-LD（Organization + 所在地 + 事業内容）が Rich Results Test でパース可能
- 全ページに最終更新日が表示されている

## オージャスト全体の実装優先順位

以下の優先順位で実施する。各施策は独立して効果測定可能。

| 優先度 | ポイント | 施策 | 想定工数 | 効果予測（LLM引用率） |
|--------|---------|------|---------|---------------------|
| **P0** | Point 3: FAQ | 会社サイトに FAQ ページ（10問＋JSON-LD）を設置 | 2日 | 最も即効性が高い。FAQ Schema は次回クロールから引用 |
| **P0** | Point 4: 信頼性 | `robots.txt` + `ai.txt` + `llms.txt` を会社サイトルートに設置 | 0.5日 | 前提条件。これがないとクロールされない |
| **P1** | Point 1: 専門性 | サービスページの JSON-LD 構造化と `llms.txt` 本文充実 | 1日 | 中期的な引用精度向上 |
| **P1** | Point 2: 事例 | 事例ページ新設（最低3件、数値データ＋JSON-LD） | 3日 | 比較クエリ・課題解決クエリでの推薦に直結 |
| **P2** | Point 4: 信頼性 | research.html 相当の検証ノートページ設置 | 1日 | エビデンス補強 |

**推奨スプリント**: まず P0 の2施策を同日に実施する。その後 X-0007 の20問測定でベースラインを取り、P1 → P2 の順に改善して再測定する。

## 期待される効果

X-0007 の20問測定で以下の改善が見込まれる:

| クエリ種別 | 改善前（推定） | 改善後（目標） |
|-----------|--------------|---------------|
| 指名クエリ（4問） | 引用率 30% | 引用率 80%（llms.txt + JSON-LD で会社基本情報はほぼ確実に引用） |
| 比較クエリ（6問） | 推薦率 20% | 推薦率 50%（事例ページ＋FAQ での差別化要因の明示） |
| 課題解決クエリ（10問） | 引用率 10% | 引用率 40%（FAQ ＋ 専門性記述で回答に含まれる確率向上） |

**目標**: 6ヵ月後に X-0007 測定スコアを全体で2倍以上に改善する（Knowledge Holdings の先行事例と同等の改善を目指す）。
