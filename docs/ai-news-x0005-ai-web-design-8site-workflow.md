## 各ツールの位置づけ（2026-11-07 Web 検索に基づく）

### Step 1・2: 視覚的方向を見つける（Land-book / Godly）

- **Land-book**（https://land-book.com）: ランディングページ専門のデザインギャラリー。「この業界・用途ならこの方向」という視覚の方向（トーン、レイアウト、配色）を探すのに使う。
- **Godly**（https://godly.website）: 手選び（約半分が AI 生成）の Web / アプリ / ブランディング / モーションデザインをまとめたギャラリー。**2026 年時点で「Recent」（https://recent.design）へリブランドしており、godly.website は同サイトを開く**。リンク恒久化の際は recent.design を参照する。

両者とも自分の作りたいページの「方向」を 2〜3 件スクリーンショットで決めるのが目的であり、「そのままコピー」ではない。

### Step 3: 既製デザインプロンプトを得る（MotionSites）

- **MotionSites**（https://motionsites.ai）: 800 件超の無料「プレミアム Web サイト・プロンプト」集。サイト上で「デザインを選ぶ → Full Prompt をコピー → Claude Code / Cursor / Bolt / Lovable 等の AI ビルダーに貼り付ける」。
- 公式ワークフローの要点（MotionSites 公式・関連記事・公式 Claude Skill から確認）:
  1. **変更を加える前に、まずプロンプトで最初の完成版をそのまま生成する**（何が効いて何が効いていないかを判別するため）。
  2. その後は **1 つの編集ごとに小さなプロンプト**で洗練する（例「モバイルの余白を直す」「見出しサイズだけ大きく」）。
  3. 「プレミアム」「洗練された」等の雰囲気言葉ではなく **具体的な値（hex/px/clamp()、字間、duration、easing）を指定**する方が、非ジェネリックな出力になる。

### Step 4: 最初のバージョンを生成（Studio / AI ビルダー）

digest の「Studio Motionsites で最初のバージョンを生成」は、MotionSites のプロンプトを **AI ビルダー（生成ツール）に貼って最初の完成版を作るステップ**と解釈する。元投稿の「Studio」がどのツールを指すかは未確認のため、オージャストでは **Claude Code / codex-do 等の既存実装環境をそのまま使う**（§1.17・1.18 の既存委譲構成と整合）。

### Step 5: 参照を使ってレイアウトとタイポグラフィを洗練

- 生成後のサイトは「**参照**」を使って詰める: 方向性の合う参照サイト／スクリーンショットを AI ビルダーに渡し「**レイアウトとタイポグラフィは保ったまま、◯◯だけ変える**」と指示する。
- 参照は**方向・構造の参考**であって、ギャラリーのページ全体をコピーするものではない。フォント・画像・素材のライセンスは別途確認する（以下「検証・限界」参照）。

### Step 6: モバイルインタラクションのアイデアを収集（60fps）

- **60fps**（https://60fps.design）: 優れた iOS / Web アプリの UI アニメーション・インタラクションを短い動画で数千本収録したサイト。モバイルのタップ・スワイプ・ローディング等の**動作アイデア**を探すのに使う。
- 実装時は「60fps で動く」を目安に、transform/opacity ベースのアニメーション・GPU に優しいプロパティを使う。

### Step 7: ブランディングとタイポグラフィを探る（Font in Logo）

- **Font in Logo**（https://fontinlogo.com）: 有名ブランドのロゴに使われている**正確なフォント**を特定・表示するサイト。お客様のブランドや自社サイトの「このロゴの書体は何か」を調べ、ブランディング・タイポグラフィの統一に使う。
- 適用例: お客様のロゴ書体が分かれば、提案ページの見出しフォントを同一ファミリーで揃える等のブランド表現を提案材料にできる。

## 株式会社オージャストで試す手順（初回: 展示会出展提案ページを作る）

用途の最初の例として、**「展示会出展を検討しているお客様に送る提案用ランディングページ（1ページで、ブースデザイン案と実績・手順を伝えるページ）」**を作る手順を示す。全ツールが無料・Web 閲覧中心のため、初回は材料収集のみで調達コストゼロ。

1. **方向決め**（約30分）
   - Land-book / Godly（recent.design）で「展示・イベント」「制作会社」「B to B 提案」に近いページを探し、方向性の合うものを 2〜3 件スクリーンショットで保存。
   - 「トーン（高級感 / 信頼 / クリエイティブ）」「配色」「レイアウトの骨格」の3点だけメモする。

2. **プロンプト入手**（約10分）
   - MotionSites で構成が近いプロンプトを選び Full Prompt をコピー。

3. **最初の生成**（本環境で実施）
   - コピーしたプロンプトにオージャストの情報（ブース制作・企画設計施工一貫、大阪、実績等）とトーン指定を追記し、Claude Code / codex-do で**変更を加えない状態でまず 1 版を生成**。
   - 生成物は Google ドライブの案件フォルダに置き、共有 URL で確認（§2.6.2）。

4. **参照で洗練**（1 編集 1 プロンプト）
   - Step 1 のスクリーンショットを参照として渡し、「レイアウト・タイポグラフィは保って、◯◯だけ」の小さな指示を繰り返す。

5. **モバイル動作とブランド**
   - 60fps でモバイルの動作アイデアを 1〜2 個選び、transform/opacity 中心で実装（60fps 目安）。
   - Font in Logo でお客様ブランド（または自社）のロゴ書体を確認し、見出しフォントの揃えを提案に反映。

6. **納品**（§2.6.2 に従う）
   - 修正後のページを公開 URL の実物で検証してから依頼元へ共有。提案本文（件名・本文）は「その1通だけで用が済む」形で送る。

## 検証・限界

- **未実測の明示**: 本稿執筆時点で Land-book / Godly / MotionSites / 60fps / Font in Logo は Web 検索の要約のみで、実ブラウザでの閲覧・実聴は未実施。初回試行時に各 URL を開いて「そのとおり動くか」を確認し、相違があれば本稿に追記する。
- **「Studio」「8つ目」の未確認**: digest の「Studio」が指す具体的ツールと、8 つ目のサイト名は未確認。判明したら本稿を更新する。
- **望ましいのは各ツールが無料閲覧中心であること**（アカウント登録・課金が必要かは各サイトの現行表示で確認）。
- **著作権・ライセンス**: ギャラリー掲載ページの丸ごとコピー・全文転載はしない。フォントはローカルホスト・ライセンス確認（例: Google Fonts の埋め込みライセンス）を実施してから使う。参考にするのは「方向・構造」だけに留める。
- **生成物の検証**: 生成後のページは公開前に実機（PC / スマホ）で 60fps 動作・アクセシビリティ（WCAG 2.1 AA 目安）を確認してからお客様へ共有する。
