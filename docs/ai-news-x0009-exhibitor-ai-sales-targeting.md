# X-0009: 展示会出展リストからのAI営業ターゲット抽出ランブック（承認ポイント付き）

2026-11-07追記: 今回のX-0007-exhibitor-leads-v1との5段対応・実測状態・残件・対象権限は[既存X-0008の再照合表](ai-news-x0008-exhibitor-lead-workflow.md)を参照。本稿の承認先や手順は有効な承認証跡ではなく、取得・送信を自動的に許可しない。


## 冒頭
本文書は、AIニュース提案 X-0009 に記載された手法に基づき、展示会出展企業リストから営業ターゲットを抽出し、個別の営業アプローチ文面を作成するまでの手順を文書化した判断材料です。
本稿に掲載している数値（検索並列数や投稿取得条件等）は元投稿に記載された値であり、オージャスト社内での実測・検証は行っていません。また、本稿は手順と承認フローの整理を目的としており、実際のデータ取得・担当者検索・外部へのメール送信等の実行は本稿の範囲外です。 kim / cr の承認を得た上で別途実施する方針とします。

## 全体フロー

| 段 | ツール | 入力 | 出力 |
| :--- | :--- | :--- | :--- |
| 段1 | Map Your Show エンドポイント / Grok bot 作成 Python スクリプト | 対象展示会の URL または JSON エンドポイント | 出展社基本リスト（社名、ブース番号、出展説明文、WebサイトURL） |
| 段2 | Dropleads | 段1で取得した出展社名・WebサイトURL | ターゲット役職（VP Sales, Head of BD, CRO 等）の担当者連絡先情報 |

## 段1: 出展リスト取得

### 使うツール
Map Your Show の隠れた JSON エンドポイント、Grok bot が作成した Python スクリプト

### 入力
Map Your Show 上で公開されている対象展示会ページの URL およびデータ取得用 JSON エンドポイント

### 出力
出展社基本リスト（出展社名、ブース番号、出展社概要説明文、企業 Web サイト URL）

### オージャストでの適用先
展示会ブース制作の営業において、自社が出展・参加を検討している展示会の出展企業を一括でリスト化し、新規ブース装飾提案の母集団を形成する際に適用する。

### リスクと承認ポイント
- **(a) スクレイプ利用規約・robots.txt**: 取得対象となる Map Your Show および各展示会サイトの利用規約、および `robots.txt` の記述を事前確認し、自動取得が禁止されていないか、サーバに過剰な負荷をかけない仕様であるかを確認する。
- **(e) 外部送信は人の承認後のみ**: 取得スクリプトの実行自体を承認事項とする（Grok bot 作成のスクリプトは中身を人が読んでから実行。投稿記載の仕組みで、未検証）。外部への送信は行わない。
- **(b)(c)**: 段1の取得項目は企業情報（社名・ブース・説明・サイト）が中心で LinkedIn は使わない。個人名が含まれる場合は段2の(c)に従う。
- **(d) 有料 API 費用の事前見積**: スクリプト実行前に1件のテスト取得で要する通信・処理費用の実費を計測し、「1件単価 × 出展社数 ＝ 推定総額」および上限額を明示して kim / cr の事前承認を得る。

## 段2: 担当者抽出

### 使うツール
Dropleads

### 入力
段1で取得した出展社名および企業 Web サイト URL

### 出力
シニアタイトル（VP of sales / head of BD / CRO 等）を持つ担当者情報（最大 3 人 / 社）

### オージャストでの適用先
学会協賛メディアの協賛募集において、協賛予算の意思決定権を持つ事業開発責任者や営業幹部（BD / Sales 責任者）を特定し、キーマンへ直接アプローチするために適用する。

### リスクと承認ポイント
- **投稿記載・未検証の仕様設定**:
  - 対象企業規模: `25-250 employees`（投稿記載・未検証）
  - 処理並列度: `32 lookups in parallel`（投稿記載・未検証）
  - 抽出上限: 最大 3 人 / 社（投稿記載・未検証）
- **(a) スクレイプ利用規約・robots.txt**: Dropleads 側の利用規約（取得データの再利用・営業利用の可否）は未確認。確認前は実行しない。
- **(c) 個人情報・特定電子メール法**: 氏名・役職・連絡先は個人情報。取得前に利用目的を決め、営業メール送付時は同意の有無・オプトアウト導線を確認する。
- **(d) 有料 API 費用の事前見積**: Dropleads での検索着手前に、1件あたりの取得実費（クレジット代金等）を実測し、「1件単価 × 対象社数 ＝ 総額上限」を提示して kim / cr の事前承認を得る。
- **(e) 外部送信は人の承認後のみ**: 本段では外部へ何も送らない。担当者への連絡は段5の承認フローに従う。

## 段3: 除外清掃

### 使うツール
AI 分類ツール（`tools/llm-ask.mjs`）

### 入力
段2で得られた担当者情報付き出展社リスト

### 出力
ディストリビューター、業界協会、報道・メディア機関等を除外した、自社の直接顧客候補のみで構成された清掃済みリスト

### オージャストでの適用先
展示会ブース制作の営業および学会協賛メディアの協賛募集の両方において、ブース施工や協賛枠の直接の買主とならない「代理店・各種団体・メディア」を事前に自動判別して排除し、営業効率を最適化するために適用する。

### リスクと承認ポイント
- **(c) 個人情報・特定電子メール法**: 抽出・清掃されたリストに含まれる個人名・役職・連絡先情報の取り扱いについて、個人情報保護法に基づき利用目的を明確化し、安全に保管する。
- **(d) 有料 API 費用の事前見積**: 安い AI（`tools/llm-ask.mjs`）で分類する場合も、件数が多いときは先に1〜10件で1件あたりの費用を測り、総額上限を示して承認を得る。
- **(e) 外部送信は人の承認後のみ**: 除外判定の結果は人が目視確認してから次段へ進む。判定の誤り（除外漏れ・誤除外）は承認前に補正する。
- **(a)(b)**: 本段は新たなスクレイプ・LinkedIn アクセスを行わない（段1・段2・段4の取得済みデータのみ使用）。

## 段4: LinkedIn 活動確認

### 使うツール
Fetchin

### 入力
段3で清掃されたターゲット担当者の LinkedIn プロフィール情報

### 出力
ターゲット担当者の LinkedIn 上での発信アクティビティデータ

### オージャストでの適用先
学会協賛メディアの協賛募集において、SNS 上で活発に情報発信を行っているキーマンを特定し、直近の関心テーマに合致した協賛企画を提案するための事前情報収集に適用する。

### リスクと承認ポイント
- **投稿記載・未検証の取得条件**:
  - 取得対象期間: `last 60 days` の投稿（投稿記載・未検証）
  - 取得件数上限: `last 5 posts`（投稿記載・未検証）
- **(b) LinkedIn 規約**: Fetchin を介した LinkedIn データの取得および利用が、LinkedIn の利用規約およびデータアクセス制限に違反していないかを事前に検証する。
- **(c) 個人情報・特定電子メール法**: 個人の投稿内容は個人情報になり得る。取得は営業判断に必要な最小限（話題の把握）に留め、保存期間と利用目的を決めてから実行する。
- **(e) 外部送信は人の承認後のみ**: 本段では外部へ何も送らない（LinkedIn への接続・メッセージ送信を含む）。
- **(d) 有料 API 費用の事前見積**: Fetchin の利用前に1件あたりの取得実費を計測し、「1件単価 × 検索件数 ＝ 総額上限」を算定した上で kim / cr の承認を得る。

## 段5: サイト分析とメッセージ作成

### 使うツール
Web スクレイパー、生成 AI（`tools/llm-ask.mjs` / `tools/grok-ask.mjs`）

### 入力
清掃済みターゲット企業の Web サイト全体の構造化データ、および担当者の活動情報

### 出力
AI による企業分析結果（「何を出荷・販売しているか」「誰が顧客か」「なぜ今アプローチすべきか」）および個別のブース訪問提案メッセージ

### オージャストでの適用先
展示会ブース制作の営業において、出展予定企業の Web サイトから相手製品の特長やターゲット層を分析し、「当日のブース集客を最大化する装飾・施工の提案」を軸とした出展ブース訪問の事前約束（アポイント）メッセージ作成に適用する。

### 実例（投稿記載の例。オージャストの成果ではありません）
- **対象**: 約100人規模の廃水処理会社（PACK EXPO および IPPE 出展）の VP of sales
- **内容**: 相手の製品特性と出展展示会（PACK EXPO / IPPE）でのターゲット客層を AI 分析し、出展当日にブースへ訪問して集客改善等の意見交換を行うことを提案する文面。
*(注: 上記実例は元投稿に記載された事例の引用であり、オージャスト社内での実績・成果ではありません)*

### リスクと承認ポイント
- **(a) スクレイプ利用規約・robots.txt**: 対象企業の Web サイト全体をスクレイピングする際、当該サイトの `robots.txt` および利用規約を確認し、アクセス間隔を空けるなどサーバーに過剰な負荷をかけない制御を行う。
- **(c) 個人情報・特定電子メール法**: 営業メールを作成・送信する際は、特定電子メール法に基づき、配信停止（オプトアウト）の受付方法および送信者情報（株式会社オージャスト、担当者名、連絡先）を明記する。
- **(e) 外部送信は人の承認後のみ**: 自動プログラムによるメールの直接送信は行わず、`tools/gmail-draft.mjs` 等で下書きを作成した上で、メール本文全文を画面上に提示し、人が内容を確認して明示的な承認を行った場合のみ送信する。複数の企業へアプローチする場合であっても、一括自動送信は行わず 1 社ずつ個別承認を実施する。

## dry-run 手順（外部アクセスなしで確認できる範囲）

外部ネットワークへのアクセスを行わず、ローカル環境および手元の既存データのみで実施可能な確認手順は以下の通りです。

1. **除外清掃ルールの動作確認**
   - 手元の CSV データ（ダミーの出展社名・概要文数行）を作成し、代理店・協会・メディア等を分類排除するスクリプト（`tools/llm-ask.mjs` 等）の判定ロジックが意図通り機能するかローカルで確認する。
2. **文面穴埋めテンプレートの検証**
   - 抽出データ（社名、役職、分析要約等）を変数として手動設定し、アプローチ文面テンプレートに正しくデータが埋め込まれ、文章として不自然さがないかローカルで出力テストを行う。
3. **概算費用計算式のチェック**
   - 仮の対象件数を入力し、「1件あたりの想定単価 × 対象件数 ＝ 推定総額」および上限設定が正しく計算されるか数式・ロジックを確認する。
4. **署名・オプトアウト表記の出力確認**
   - メール文面生成処理において、特定電子メール法に基づいた「オプトアウト案内」および「送信者情報（オージャスト担当者名・連絡先）」が漏れなく末尾に挿入されるかローカル環境で確認する。
