# X-0009: 繰り返しシステムプロンプトのKVキャッシュ共有でTTFT80%削減

> 2026-11-09 設計・実装。自動セッションによる初回実装。

## 概要

LLMにおいて同じシステムプロンプトが繰り返し使われる場合、ゲートウェイ層でKVキャッシュのプレフィックスを共有することで、初回トークン出力時間（TTFT: Time-To-First-Token）を最大80%削減できる。

## 問題

株式会社オージャストでは展示会ブース提案の生成時に、以下のような共通デザインガイドラインをシステムプロンプト先頭に固定している：

```
あなたは展示会ブースのプロジェクトマネージャー兼デザイナーです。
以下のデザインガイドラインに従って提案を生成してください：
- ブースサイズは標準小間（2.7m×6m）
- 使用可能な構造材はアルミフレーム（パイプ径28mm/48mm）
- パネル高さは2.5mまで（天吊り不可）
- 床材は標準グレーカーペット
- 照明はLEDスポットライト（100W相当）×4基まで
...
```

各案件（出展企業）ごとに提案を生成するたびに、この同じプロンプトが送られ、毎回フルコンテキストで推論が始まる。KVキャッシュが共有されていないため、同一のシステムプロンプト部の計算が無駄に繰り返される。

## 解決策

ゲートウェイで以下の処理を行う：

1. **プレフィックス正規化**: 共通システムプロンプトをリクエスト先頭に固定し、バイト単位で一致させる
2. **KVキャッシュの事前生成**: 最初のリクエストでシステムプロンプトのKVキャッシュを計算
3. **キャッシュ再利用**: 後続のリクエストで事前生成したKVキャッシュをアタッチ
4. **TTFT測定**: 各リクエストのTTFTを記録し、効果を定量化

OpenRouter/Anthropic API は自動的に prompt caching をサポートしており、同じプレフィックスが連続して送られると自動的にキャッシュヒットする。本実装ではこの機能を活用し、ゲートウェイ層でリクエストの順序制御と測定を行う。

## アーキテクチャ

```
[共通デザインガイドライン]
        ↓
[KVキャッシュプレフィックスゲートウェイ]
        ↓
  ┌─────────────────┐
  │ リクエスト分割器  │ ← システムプロンプト先頭nトークンが同一か判定
  └────────┬────────┘
           ↓
  ┌─────────────────┐
  │ キャッシュ制御器  │ ← 初回はキャッシュ生成、2回目以降は再利用
  └────────┬────────┘
           ↓
  ┌─────────────────┐
  │ TTFT測定器       │ ← 各リクエストの初回トークン到達時間を記録
  └────────┬────────┘
           ↓
  ┌─────────────────┐
  │ コスト集計器      │ ← キャッシュ割引（cached tokens）の経済効果
  └────────┬────────┘
           ↓
  [OpenRouter API / Anthropic API]
```

## 実装コンポーネント

### `tools/kv-cache-prefix-gateway.mjs`

LLM API 呼び出しをラップし、KVキャッシュプレフィックス共有を管理するゲートウェイ。

#### 主な機能

- **`extractCommonPrefix(requests[])`**: 複数リクエストから共通のシステムプロンプトプレフィックスを抽出
- **`gatewayRequest(request, cacheState)`**: キャッシュ状態を管理しながらLLM APIを呼び出し
- **`measureTTFT(response)`**: レスポンスから初回トークン到達時間を計測
- **`reportCacheEfficiency(results[])`**: キャッシュ効率のレポート生成

#### 使い方（CLI）

```bash
# デモモード: 共通プレフィックスを使った複数リクエストを順次実行しTTFTをレポート
node tools/kv-cache-prefix-gateway.mjs --demo
```

## 計測指標

| 指標 | 説明 | 目標 |
|------|------|------|
| TTFT (初回) | キャッシュなしの初回リクエストTTFT | 基準値 |
| TTFT (キャッシュ) | キャッシュヒット時のTTFT | 基準値の20%以下 |
| キャッシュヒット率 | キャッシュ再利用が発生したリクエストの割合 | 80%以上 |
| コスト削減率 | キャッシュ割引によるトークンコスト削減 | 50%以上 |
