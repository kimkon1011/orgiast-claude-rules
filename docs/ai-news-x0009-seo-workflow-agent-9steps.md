# X-0009: SEOワークフローをAIエージェント化する9ステップ

観測日: 2026-11-08。出典: AIニュース提案 [X-0009]。

## 概要

SEOのワークフローをAIエージェント化する9ステップの手法を、株式会社オージャストの展示会ブース制作サイト（`orgiast.jp`）の**キーワードリサーチワークフロー**に適用し、人間プロセスの文書化からエージェント化までを試行する。

## 選択したワークフロー: 展示会ブース制作のキーワードリサーチ

オージャストのWebサイトは以下のサービスページで構成される:

| ページ | テーマ | 現状のSEO優先度 |
|---|---|---|
| `/` | トップ（イベント・クリエイティブ制作） | 高 |
| `/event` | イベントプロデュース（事例一覧） | 中 |
| `/event/{id}` | 個別事例（展示会・株主総会・周年行事等） | 高（ロングテール） |
| `/creative` | クリエイティブ制作（映像・Web・グラフィック） | 中 |
| `/clients` | クライアント一覧 | 低 |
| `/services/flow` | 申し込みの流れ | 低 |
| `rebooth.co.jp` | Re:ブース（別ドメイン） | 高（独立サイト） |
| `orgiast-product.jp/sdgs/` | SDGs展示ブース（別ドメイン） | 中 |
| `event-shop.jp` | 社内イベント百貨店（別ドメイン） | 低 |

このキーワードリサーチワークフローを選んだ理由:
- 展示会ブース制作の受注には検索経由の流入が不可欠
- キーワードリサーチは毎週の属人作業でありAI化の効果が大きい
- 別ドメイン含めた横断的なキーワード管理が必要
- Search Console API/Keyword Plannerへの接続がブロックされているため、代替手段を組み込んだワークフロー設計が必要

## Step 2: 既存の人間プロセスを文書化

### 現行の人間プロセス

#### Phase A: 現状把握（所要: 1〜2時間）

```
1. Google Search Console にログイン（要 SA 鍵）
2. 過去3ヶ月のクエリレポート（Queries.csv）をエクスポート
3. 過去3ヶ月のページレポート（Pages.csv）をエクスポート
4. 表示回数・CTR・平均掲載順位の推移をスプレッドシートに記録
5. ポジション5〜20のクエリを抽出（改善余地のある範囲）
6. クリック数が前月比で減少したページ・クエリにフラグ
```

#### Phase B: キーワード発掘（所要: 2〜3時間）

```
7. 展示会業界のトピックリストを更新（展示会カレンダー・ニュースから）
8. Google Keyword Planner で月間検索ボリュームを調査
9. 競合サイト（他ブース制作会社）のコンテンツを巡回
10. 社内の営業・制作チームから顧客検索クエリをヒアリング
11. 別ドメイン（rebooth.co.jp, event-shop.jp）のキーワードも収集
12. 収集したキーワードをカテゴリ別に整理
```

#### Phase C: 評価と優先順位付け（所要: 1〜2時間）

```
13. 各キーワードを検索意図で分類:
    - Informational（知りたい）: 「展示会ブース 選び方」「ブース制作 比較」
    - Commercial（調べたい）: 「展示会ブース制作 費用」「Reブース 価格」
    - Transactional（申し込みたい）: 「ブース制作 依頼 大阪」「展示会出展 代行」
14. キーワード難易度（KD）と検索ボリュームのマトリックスを作成
15. ビジネス価値（単価×成約率）で重み付け
16. 既存ページのトピックカバレッジを評価（足りないトピックを特定）
17. 優先度スコア = 検索ボリューム × ビジネス価値 ÷ 難易度
```

#### Phase D: コンテンツ提案（所要: 1時間）

```
18. 優先キーワードごとに推奨ページ種別を決定:
    - サービスページ（高意図・高ボリューム）
    - 事例ページ（高意図・低ボリューム/業界特化）
    - コラム/ブログ（低意図・高ボリューム）
19. 既存ページのタイトル・H1・メタディスクリプションの最適化提案
20. 内部リンク構造の改善提案
21. 出力をスプレッドシートにまとめ、制作チームと共有
```

### ボトルネック（AIで解消する部分）

| # | ボトルネック | 現状のコスト | AI化解消方法 |
|---|---|---|---|
| B1 | GSCデータ取得にSA鍵が必要 | ブロック中（未対応） | BigQuery一括エクスポート経路に切り替え、または手動CSV取込 |
| B2 | 競合サイト巡回が手動 | 毎回2時間 | 巡回と差分抽出をAIエージェントが自動実行 |
| B3 | キーワード分類（意図・カテゴリ）が属人 | 判断ブレあり | LLM分類で一貫性確保 |
| B4 | 優先度計算がExcel手動 | 更新忘れ多発 | 自動計算＋ダッシュボード化 |
| B5 | コンテンツ提案書作成が手作業 | 毎回1時間 | テンプレート＋AI生成で数分に短縮 |

```markdown
# 展示会ブース制作 キーワードリサーチエージェント

## 目的
株式会社オージャストのWebサイト（orgiast.jp）および関連ドメインを対象に、展示会ブース制作関連のキーワードリサーチを実行し、優先順位付きのキーワードリストとコンテンツ最適化提案を生成する。

## 入力
- 自社サイトのページ一覧（またはクロール結果）
- 競合サイトのページ一覧（複数社）
- GSCクエリデータ（ある場合）
- 直近の展示会カレンダー

## 手順

### Phase 1: 現状把握
1. 自社サイトの全ページをクロールし、URL・タイトル・H1・メタディスクリプションを抽出
2. 各ページに含まれる主要キーワードを抽出
3. GSCデータがあれば、過去3ヶ月のクエリパフォーマンスを読み込む
4. 各ページのトピックカバレッジを評価

### Phase 2: キーワード発掘
5. 競合サイト（指定URLリスト）をクロール
6. 各競合の主要キーワードを抽出
7. 展示会カレンダーから直近の展示会情報を取得
8. ツール（Keyword Planner等）からのデータがあれば取り込む
9. 全キーワードをユニークに統合

### Phase 3: 評価と優先順位付け
10. 各キーワードの検索意図を分類（Informational / Commercial / Transactional）
11. ビジネス価値の推定（想定受注単価 × 成約率）
12. 競合のカバレッジを評価
13. 優先度スコアを計算

### Phase 4: コンテンツ提案生成
14. カバレッジ不足のキーワードを特定
15. 推奨ページ種別を割り当て
16. 既存ページのタイトル・H1最適化提案を生成
17. 内部リンク構造の改善案を提案

## 出力
- `output/keywords-priority.csv`: 優先度順キーワード一覧
- `output/content-gaps.md`: コンテンツギャップ分析
- `output/optimization-suggestions.json`: 最適化提案
```

## Step 6: AIプラットフォームにスキルを追加

### スキル追加先

本スキルは `skills/booth-kw-research/SKILL.md` として配置し、Claude Codeの `Skill` ツールから呼び出せるようにする。

### 配置構成

```
skills/booth-kw-research/
├── SKILL.md          ← エージェント指示（Step 5で定義）
├── process/
│   ├── phase1-crawl.mjs      ← サイトクロール（既存tools/llm-ask.mjs活用）
│   ├── phase2-collect.mjs    ← キーワード収集・統合
│   ├── phase3-score.mjs      ← 優先度スコアリング
│   └── phase4-propose.mjs    ← コンテンツ提案生成
├── data/
│   ├── competitors.json      ← 競合サイト設定
│   └── business-value.json   ← サービスのビジネス価値マップ
└── output/                   ← 出力先
```

### 実装方針

Codexで実装する。各フェーズのスクリプトは以下の原則に従う:

- `phase1-crawl.mjs`: `fetch` + `node-html-parser` で自社・競合サイトをクロール。`robots.txt`を遵守し、`delay_s`を設定
- `phase2-collect.mjs`: クロール結果からキーワードを抽出し、重複排除
- `phase3-score.mjs`: `tools/llm-ask.mjs` を呼び出して検索意図を分類。スコアリングロジックは純JSで計算
- `phase4-propose.mjs`: 上記3フェーズの結果からMarkdown提案書を生成

## Step 8: テストと調整

### テスト計画

| テスト | 方法 | 合格条件 |
|---|---|---|
| 単体テスト (Phase 1) | モックHTMLでクロール実行 | 全aタグのURL・タイトルを正しく抽出 |
| 単体テスト (Phase 2) | 既知キーワードを混ぜたテストデータ | 重複排除＋統合結果が期待値と一致 |
| 単体テスト (Phase 3) | 既知の意図を持つキーワードで分類 | 分類精度90%以上（人間レビューとの一致率） |
| 結合テスト | 全4Phaseを直列実行 | 出力ファイルが全スキーマに適合 |
| オフライン検証 | 実データなしでスキーマ検証 | エラー0、全出力スキーマ準拠 |

### 調整項目

| 調整対象 | 初期値 | 調整基準 |
|---|---|---|
| クロール深度 | 3階層 | 初回テスト後、必要に応じて増減 |
| キーワード統合の類似度閾値 | 80% | 重複多ければ引き上げ |
| LLM分類のtemperature | 0.1 | 分類は低めに設定 |
| 優先度スコアの重み | Volume:0.4, Value:0.35, Difficulty:0.25 | ビジネス優先度で調整 |

### 既知の制約

- GSC API/Keyword Plannerへのアクセスがない場合、検索ボリュームデータは代替手段（公開Googleデータや推定値）に頼る
- クロールは`robots.txt`を遵守するが、サイト側の変更により取得不能になる可能性がある
- LLM分類はバイアスを含む可能性があるため、重要なキーワードは人間のレビューを推奨
