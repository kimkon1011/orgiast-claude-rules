# X-0014: Grok Bot + Claude Code コーディング手順

- **ステータス**: PHASE1 設計完了（2026-11-11）
- **AIニュース提案**: Grok Bot（xAI）をコミュニケーター兼リサーチャーに据え、製品アクセス（サンドボックス・curl）でリサーチ→実装プロンプト化→Claude Code/Devin に委譲→Grok Bot 追加QA のループでコードを量産する
- **オージャスト適用**: 自社ウェブサイト（orgiast.jp）のブースサイト更新を、Grok Bot に要件リサーチさせ Claude Code で実装する

---

## 1. 概要

### 1.1 なぜ Grok Bot をコミュニケーターにするか

| 要素 | 従来（Claude 単独） | Grok Bot + Claude Code 連携 |
|---|---|---|
| リサーチ | Claude の内蔵Web検索（精度不安定） | Grok の x_search + サンドボックス + curl による製品アクセス |
| コスト | 高思考モデルのリサーチ兼務 | Grok はリサーチに特化（安価・高速） |
| スマホ介入 | Claude スマホアプリが未対応 | Grok アプリからいつでも途中介入・方向修正 |
| 検証 | 自己検証（見落としリスク） | Grok Bot が別視点で第三者検証 |
| 並列度 | 1セッション1直列 | リサーチと実装を並列実行可能 |

## 2. Phase 1: Grok Bot によるリサーチ

### 2.1 使用する Grok の機能

| 機能 | 用途 | 呼び出し方 |
|---|---|---|
| **x_search** | X/Twitter からの情報収集・トレンド分析 | Grok チャットに「Xで調べて」と依頼 |
| **Sandbox（Python）** | データ分析・スクレイピングプロト作成 | Grok に「Pythonで解析して」と依頼（Curl/Requests使用可） |
| **ファイル解析** | PDF/画像からの情報抽出 | Grok にファイルをアップロード |
| **Web ブラウズ** | 競合サイト・要件ページの閲覧 | Grok に URL を渡して分析依頼 |
| **画像認識** | スクリーンショットからのUI解析 | スクショを Grok にアップロード |

### 2.2 リサーチプロンプトテンプレート

Grok Bot にリサーチを依頼するときのテンプレート:

```
# リサーチ依頼

## 目的
<プロジェクトの目的を1行で>

## 調査項目
1. <項目1>: 競合の実装例・料金
2. <項目2>: 必要なAPI・技術スタック
3. <項目3>: 参考URL・ベストプラクティス

## 出力形式
以下のJSON構造でまとめてください:
{
  "findings": [
    {
      "item": "<項目名>",
      "summary": "<要約>",
      "sources": ["<URL>", ...],
      "confidence": "high|medium|low"
    }
  ],
  "recommended_approach": "<推奨アプローチ>",
  "risks": ["<リスク1>", ...],
  "estimated_effort": "<工数見積>"
}

## 制約
- 価格情報は出典URL付きで
- 実測値のみ記載（憶測は「推定」と明記）
```

## 3. Phase 2: Claude Code / Devin による実装

### 3.1 ワーカー選択マトリクス

| 条件 | 推奨ワーカー | 理由 |
|---|---|---|
| フロントエンド・UI生成 | Claude Code（hy4） | HTML/CSS/JSの品質が安定 |
| バックエンド・API開発 | Codex（GPT-5） | 定額・リファクタリング得意 |
| データ分析・スクレイピング | Devin | 環境構築〜テストまで完結 |
| WordPress テーマ/プラグイン | Claude Code | WordPress 知識が豊富 |
| パッケージング・CI/CD | Codex | 反復作業に強い |
| モバイルアプリ | Devin / Claude Code | ビルド環境に応じて |

## 4. Phase 3: Grok Bot QA ループ

### 4.1 QA 依頼プロンプト

Grok Bot に QA を依頼するときのテンプレート:

```
# QA 依頼

## 実装の成果物
<PR の URL またはコード全文>

## 検証項目（リサーチ段階で Grok 自身が定義した基準）
- <項目1>
- <項目2>
- <項目3>

## チェックポイント
1. 機能的正しさ: 仕様通り動くか
2. セキュリティ: 既知の脆弱性パターンがないか
3. パフォーマンス: 想定負荷に耐えられるか
4. メンテナンス性: コードは読みやすいか
5. アクセシビリティ: 基準を満たすか

## 出力形式
{
  "passed": [<合格項目>],
  "failed": [{"item": "<不合格項目>", "reason": "<理由>", "severity": "critical|major|minor"}],
  "suggestions": ["<改善提案1>", ...],
  "overall": "pass|conditional_pass|fail"
}
```

### 4.2 QA ループの制御

- **最大ループ回数**: 3回（無限ループ防止）
- **重大バグ**: 1回目で検出された critical は即時修正優先
- **軽微な改善**: 3回目でも残る minor は「次回対応」として記録

### 4.3 スマホでの QA 結果レビュー

Grok アプリで QA 結果を開くと、スマホから以下のアクションが可能：

1. ✅ 合格 → そのままデプロイ承認
2. 🔄 再実装 → 修正指示を追記して Claude Code へ
3. ⚠️ 条件付き合格 → 軽微な残件を記録してデプロイ
4. ❌ 不合格 → 重大バグを指摘して差し戻し

## 7. 利点とリスク

### 7.1 利点

| 観点 | 効果 |
|---|---|
| リサーチ品質 | Grok の x_search で X/Twitter のリアルタイム情報が取得可能 |
| コスト効率 | リサーチを Grok（従量・安価）に任せ、Claude/Codex は実装に集中 |
| スマホ対応 | Grok アプリからいつでも方向修正・追加指示・承認 |
| 第三者検証 | Grok が別の視点でコードを検証（自己検証の見落とし低減） |
| 並列性 | リサーチ中に別の実装が進められる |

### 7.2 リスクと対策

| リスク | 対策 |
|---|---|
| Grok のリサーチ精度にバラつき | 出典URLの明示を必須化、confidence 評価を付ける |
| プロンプト変換時の情報損失 | 変換前後の差分を自動比較するツールを別途作る |
| QA ループの無限回帰 | 最大3回で打ち切り、残件は次回に持ち越し |
| Grok API の利用制限 | xAI アカウントの autoTopUp 設定で対応 |
