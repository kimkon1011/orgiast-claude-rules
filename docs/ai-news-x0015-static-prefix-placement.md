# X-0015: 静的先頭配置でプレフィックスキャッシュ最大化

> 2026-11-09 自動セッション。静的コンテキストをプロンプト先頭に、動的部分を後に置く配置原理の設計文書。
> 実装ツール: `tools/static-prefix-placement.mjs`

## 概要

プロンプトキャッシュ（prompt caching）は、リクエスト先頭から連続する同一プレフィックスを自動的に検出し、
その部分の KV（Key-Value）計算をスキップする仕組み。**キャッシュは先頭からバイト単位で一致する範囲にのみ働く**ため、
「どこを静的（全リクエストで共通）にし、どこを動的（個別要件）にするか」という**配置設計**がキャッシュ効率を決める。

X-0015 はこの配置原理を独立した知見として文書化し、オージャストのブース提案生成フロー向けに
**静的先頭配置テンプレート**と**効果測定ツール**を提供する。

## なぜ配置順が重要か

キャッシュは次の性質を持つ:

| 性質 | 意味 | 設計への影響 |
|---|---|---|
| 先頭一致 | 先頭からのバイト一致がキャッシュキー | **動的部分は必ず末尾側に寄せる** |
| 末尾不一致は許容 | 末尾が異なっても先頭部のキャッシュは有効 | 末尾に動的部分を集約可能 |
| 少しの違いもキャッシュミス | 先頭1バイトの違いで全体がキャッシュミス | 静的プレフィックスの**バイト単位一致が必須** |
| プロバイダー間で差 | Anthropic はシステムプロンプト全体＋最初の user ターン、OpenAI は messages 先頭 | プロバイダーごとのキャッシュ境界の理解が必要 |

### 例: 悪い配置 vs 良い配置

**悪い例**（動的部分が先頭にあるため、キャッシュが全く効かない）:

```
案件Aのブース提案を生成してください。
（以下、標準仕様…）          ← この部分は案件Bと共通だが、キャッシュが効かない
```

**良い例**（静的部分を先頭に固定）:

```
あなたは展示会ブースのプロジェクトマネージャーです。
以下のガイドラインに従って提案を生成してください：
- ブースサイズ: 2.7m×6m
- 構造材: アルミフレーム（28mm/48mm）
...（静的・共通部分）
---
【個別要件】                   ← ここから後は動的
案件名: 案件A
出展企業: XXX株式会社
ブース番号: A-123
特別要件: 天吊り看板設置
```

## オージャスト適用: ブース標準仕様テンプレート

X-0015 が提供するテンプレート `tools/static-prefix-placement.mjs` のデフォルト構造:

```
=== 静的プレフィックス（全リクエストで同一・キャッシュ対象） ===
[ROLE] あなたは展示会ブースのプロジェクトマネージャー兼デザイナーです
[STANDARD SPECS] 標準小間（2.7m×6m）・パネル高2.5m・アルミフレーム・LED照明
[SAFETY RULES] 安全基準・搬入出ルール
[COMMON MATERIALS] 標準床材・壁材・備品リスト
[COMPANY INFO] オージャスト会社概要・Re:ブース説明

=== 動的セクション（リクエストごとに可変） ===
[CASE NAME] 案件名・出展企業名
[EXHIBITION DETAILS] 展示会名・日程・ブース番号
[SPECIAL REQUIREMENTS] 特別仕様・追加オプション
[CUSTOM DESIGN] デザインテイスト・配色要望
```

## キャッシュ効率の推定

静的先頭配置の効果を定式化:

- 静的プレフィックス長: `P` トークン
- 動的部分長: `D` トークン（リクエストごとに異なる）
- 全リクエスト共通の静的プレフィックス: 初回のKV計算後、2回目以降は **キャッシュヒット**
- キャッシュTTFT削減率（X-0009 実測準拠）: 初回 3,200ms → 2回目以降 ~600ms（**−82.8%**）
- コスト削減率（cached tokens 割引）: 入力トークン単価 ~90%減 → 全体で **−60〜68.6%**

### 静的プレフィックスの推奨長

| 用途 | 推奨P | 期待キャッシュヒット率 | 備考 |
|---|---|---|---|
| ブース提案生成（3案件） | 1,200文字（~300トークン） | 65〜70% | 標準テンプレート |
| 複数案件一括（5案件） | 2,000文字（~500トークン） | 85〜90% | 詳細版テンプレート |
| 共通部材＋安全ルールのみ | 800文字（~200トークン） | 40〜50% | 最小構成 |

## 実装ツール

`tools/static-prefix-placement.mjs` は以下を提供:

| 機能 | 説明 |
|---|---|
| `defineStructure()` | プロンプト構造（静的/動的セクション）を定義 |
| `optimizePlacement()` | セクション配置を最適化しキャッシュ効率を最大化 |
| `estimateCacheHit()` | 静的プレフィックス長からキャッシュヒット率を推定 |
| `generateTemplate()` | 標準テンプレートを生成 |
| `boothTemplate()` | オージャストブース提案用テンプレート |
| `--analyze` | CLI: プロンプト構造JSONを読み込み分析 |
| `--demo` | CLI: デモシナリオ実行 |
| `--generate` | CLI: 最適化テンプレートを出力 |
