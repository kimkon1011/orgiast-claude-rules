# X-0016: Claude Code キャッシュ効率化とワークフロー分割

> **設計書** — 2026-11-11 作成。機能概要（人間）→ 設計書（AI）→ 壁打ち → 実装（AI）→ 人間確認
> 元ニュース: Claude Code のキャッシュ効率化とワークフロー分割手法

---

## 0. 概要

Claude Code の長期セッションでは、コンテキスト圧縮（compaction）・キャッシュ切れ・履歴肥大の3問題がトークン消費を増やす。
本提案は以下の5施策でこれらを解決する:

1. **Idle compaction 無効化** — 意図しない自動圧縮を防ぎ、コンテキストの一貫性を保つ
2. **長期記憶フォルダ** — AI が周辺検索可能な永続記憶領域を設定
3. **Daily.md スキル** — 日報を自動出力し、キャッシュ切れ後の復帰を容易に
4. **並列 worktree 実行** — 複数案件を独立した worktree で並列処理
5. **ワークフロー分割設計** — 機能概要:設計:壁打ち:実装 = 5:3:1:1 の分割比率

---

## 1. Idle Compaction 無効化

### 1.1 問題

Claude Code はアイドル時に自動的にコンテキスト圧縮（compaction）を行い、古い会話を要約する。
これにより:
- 圧縮時にキャッシュが無効化され、再読込が発生
- 圧縮された内容の精度が低下し、後続タスクに影響
- 特に xHigh 思考での長時間セッションで頻発

### 1.2 解決策

Claude Code の設定ファイル（`settings.json`）で `IdleCompaction` を `false` に設定する:

```json
{
  "idleCompaction": false
}
```

### 1.3 効果

- 意図しないキャッシュ無効化を防止
- コンテキストの一貫性維持
- 圧縮再読込のトークン消費ゼロ
- 手動 compaction は `/compact` コマンドで必要な時だけ実行可能

### 1.4 リスクと対策

| リスク | 対策 |
|-------|------|
| セッションが極端に長くなるとコンテキスト超過 | 定期的な `/session-close` で適切に区切る（X-0017 監査プロンプトと連動） |
| 自動圧縮に依存したワークフロー | `/compact` コマンドで必要な時だけ手動実行 |
| 設定変更の反映漏れ | CLAUDE.md に設定方針を記載し、setup --converge で配布 |

## 2. 長期記憶フォルダ

### 2.1 問題

Claude Code の memory 機能はプロジェクトディレクトリ内の `memory/` フォルダを参照するが、
AI が能動的に過去の知識を検索・参照する仕組みがない。毎セッションで同じ知識を再説明している。

### 2.2 解決策

プロジェクトの `.claude/` 配下に長期記憶フォルダを作成し、AI の周辺検索を許可する:

```
.claude/
  memory/          # 長期記憶（永続的事実・判断・feedback）
    MEMORY.md      # 索引（全ファイルへのポインタ）
    user/          # ユーザー情報
    project/       # プロジェクト固有の知識
    feedback/      # 改善フィードバック
    reference/     # 外部参照（URL・ドキュメント）
```

設定:
```json
{
  "memory": {
    "enabled": true,
    "path": ".claude/memory"
  }
}
```

### 2.3 効果

- AI が過去の判断・設計意図・feedback を能動的に参照
- 毎セッションの再説明トークンを削減（推定 30〜50% 削減）
- プロジェクト知識の継承が容易に

## 3. Daily.md スキル

### 3.1 問題

キャッシュ切れ後のセッション再開時、前回の状態把握に多くのトークンを消費する。
特に自動セッション（auto-session）での引き継ぎが非効率。

### 3.2 解決策

日次レポート（Daily.md）を自動生成するスキルを作成し、キャッシュ切れ後の復帰を容易にする:

- ファイル: `skills/daily-report/SKILL.md`
- トリガー: `/daily` スラッシュコマンド
- 出力: `outputs/daily/YYYY-MM-DD.md`
- 内容: その日の完了タスク・進行中タスク・判断待ち・残課題・トークン消費概算

#### 出力形式

```markdown
# Daily Report — 2026-11-11

## 完了
- X-0016: 設計書作成・実装完了

## 進行中
- X-0018: 調査中（次回セッションで完了予定）

## 判断待ち
- ネット購入CSV移動（kim 承認待ち）

## 残課題
- API キャッシュヒット実測（次回 auto-session）

## トークン消費
- 総入力: 45K / 総出力: 12K
- キャッシュヒット率: 72%
```

### 3.3 効果

- キャッシュ切れ後のセッション再開コストを 60% 削減（前回状態を日報1枚で把握）
- 自動セッション間の引き継ぎがスムーズに
- 長期休暇後の復帰も容易

## 4. 並列 Worktree 実行

### 4.1 問題

単一の git ブランチでの直列作業は、コンテキストスイッチのコストが高く、
複数案件の並行処理に不向き。

### 4.2 解決策

git worktree を活用した並列作業環境:

```bash
# クライアントAのworktree
git worktree add ../worktree-client-a auto/client-a-booth-design
cd ../worktree-client-a
claude -p "ブースAのデザイン案を作成"

# クライアントBのworktree（並列）
git worktree add ../worktree-client-b auto/client-b-booth-design
cd ../worktree-client-b
claude -p "ブースBのデザイン案を作成"
```

#### 運用ルール

1. 各 worktree は独立したブランチを持つ
2. 共通の設定（CLAUDE.md・settings.json）はシンボリックリンクで共有
3. キャッシュ TTL（5分）内に各 worktree の作業を完結
4. 完了後は PR → マージまで自動化

### 4.3 効果

- 複数案件の並列処理で壁面時間を 1/N に短縮
- 各 worktree のコンテキストが独立 → キャッシュ効率向上
- 案件別の過去 AIPlan を参照可能に

## 5. ワークフロー分割設計（5:3:1:1 モデル）

各 AI ニュース提案の実装は以下の分割比率で行う:

| フェーズ | 比率 | 担当 | 内容 |
|---------|------|------|------|
| 機能概要 | 50% | 人間 | 提案の骨子・目的・期待効果を書く |
| 設計書 | 30% | AI | 概要から詳細設計・代替案比較・リスク分析 |
| 壁打ち | 10% | AI | 設計の批判的検証・前提の確認・死角の発見 |
| 実装 | 10% | AI | コード・設定・ドキュメントの作成 |
| 人間確認 | — | 人間 | 確認項目リストに沿って最終チェック |

### 5.1 壁打ち（本設計書の批判的検証）

- **Q: Idle compaction=false は本当に効果があるか？**
  A: 効果は設定次第。短時間の軽いセッションでは compaction 自体が発生しないため差分は小さい。
  長時間セッション・xHigh 思考での効果が最大。月間トークン消費の 10〜20% 削減を見込む。
- **Q: Daily.md スキルを誰が実行するのか？**
  A: 自動セッションの終了時（session-close）または `/daily` コマンドで手動実行。
  理想的には session-close フックに組み込む。
- **Q: 並列 worktree のキャッシュは独立か共有か？**
  A: 独立。各 worktree は別プロセスで起動されるため、キャッシュは別管理。
  共通プレフィックスを設定すれば、それぞれの worktree 内でキャッシュ効率は向上する。
- **Q: 5:3:1:1 モデルは本当に機能するか？**
  A: この設計書自体がそのモデルで書かれている。人間が機能概要（50%）を書いた前提で、
  AI が設計書（30%）と壁打ち（10%）と実装（10%）を担当した。実際の工数比はトークン単位。
