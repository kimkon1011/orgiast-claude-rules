## 1. 5つの無駄チェック項目

X（Twitter）の投稿で提案された監査プロンプトを、株式会社オージャストの具体的な利用シナリオに合わせて実装する。

| # | チェック項目 | 判定基準 | オージャストの該当例 |
|---|-------------|---------|-------------------|
| 1 | **思考レベルの過剰** | high/xhigh が本当に必要か。medium で十分な指示に high を使っていないか | ブース提案書の簡単な書式調整に xhigh |
| 2 | **曖昧な指示** | 「慎重に考えて」「しっかり」「最善の」などのトークン消費だけの枕詞 | イベントマニュアル生成時の「丁寧に作って」 |
| 3 | **回答内の繰り返し説明** | 同じ概念を毎ターン再説明。前回の回答を再要約 | 毎回「これは展示会ブースの提案です」と再説明 |
| 4 | **古いタスクの引きずり** | 3ターン以上前の作業コンテキストが毎回再読込 | 複数イベント企画を1チャットで続けている |
| 5 | **キャッシュ途切れ** | 設定変更・モデル切替・セッション破棄でキャッシュ消失 | 作業中に /config でモデル変更 |

## 2. 監査プロンプト本体

`outputs/X-0017/token-audit-prompt.md` に配置。Claude Code のプロンプト入力欄に貼り付けて使う。

```markdown
あなたはClaude Codeのトークン消費監査人です。
以下の5項目をチェックし、削れる無駄を具体的に指摘してください。

## 監査項目

1. **思考レベル**: 現在の思考レベル設定（low/medium/high/xhigh）は適切か。
   タスクに本当に高レベルが必要か判断し、過剰なら「medium で十分」と指摘。

2. **曖昧指示**: 最新の指示に「慎重に考えて」「しっかり」「最善を尽くして」などの
   トークンを消費するだけの曖昧な修飾語が含まれていないか。
   削除して良いか提案。

3. **繰り返し説明**: 既に確立した前提・背景・仕様を毎ターン再説明していないか。
   CLAUDE.md や memory に移せる内容を特定。

4. **古いコンテキスト**: 3ターン以上前の完了済みタスクのコンテキストが
   毎回再読込されていないか。サブエージェント委譲や worktree 分割で切れるもの。

5. **キャッシュ状態**: プロンプトキャッシュが途切れている可能性がある要因
   （設定変更・モデル切替・長時間経過）はあるか。

## 出力形式

各項目について:
- [x] 問題あり（理由と改善案）
- [ ] 問題なし

改善による推定節约量: ¥XXX/月
```

## 3. 株式会社オージャスト固有のチューニング

### 3.1 ブース制作提案資料の生成

現状の典型的なプロンプト:
```
「展示会ブースの提案資料を慎重に作ってください。
ブースサイズは6mx3mで、予算は150万円です。
しっかりとしたデザイン案と見積もりを含めてください。
この提案は株式会社オージャストのブース提案資料です。
…（以下、毎回同じ背景説明が続く）」
```

**改善後**:
```
（CLAUDE.md に恒久設定済みの前提）
- 会社: 株式会社オージャスト（展示会ブース制作・イベントプロデュース）
- 既定の提案書スタイルは outputs/booth-proposal-template.md を参照
- 見積もり書式は CLAUDE.md の「見積もりルール」節に定義

（実際の指示）
「ブースサイズ 6mx3m、予算150万円の提案資料を作成。
新規はサイズ・予算のみ指定、背景説明はCLAUDE.mdから読込。
medium思考レベルで十分。曖昧修飾語は使わない。」
```

**節約効果**: 1回のプロンプトあたり約200〜400トークン削減 × 月20回 = 約¥1,200〜2,400/月

### 3.2 イベント運営マニュアル生成チャット

- チャットをイベント単位で分割（1セッション＝1イベントのマニュアル）
- 過去イベントの参照は `memory/` か `outputs/` のファイル経由
- 思考レベルは medium 固定。見積もりや工程表の整合性確認のみ high に一時変更
