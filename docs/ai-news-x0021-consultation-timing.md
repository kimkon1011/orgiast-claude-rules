# X-0021: Sonnet+Fable役割分担でコスト約1/5 — 相談タイミングの明文化

> AIニュース提案 2026-11-18
> 対象: CLAUDE.md の相談タイミングルール、Sonnet+Fable の役割分担

## 概要

日常のコーディング・文章作成は **Sonnet 5.5**（effort high）、要所の判断だけ **Fable 5.1** を `/advisor fable` で呼び出す構成で、全 Opus 比 **約1/5のコスト** に抑制できる。この構成を機能させるには、**いつ相談するか**を CLAUDE.md に明文化し、Claude が自律判断できるようにする必要がある。

本提案では3つの具体的な相談タイミングを CLAUDE.md に追加する。

## 1. 3つの相談タイミング

### 1.1 計画の行き詰まり時（15分以上進まない場合）

設計・実装計画を立てていて15分以上進展がない場合、`/advisor fable` で Fable に相談する。

**なぜ**: 行き詰まりを放置すると時間とトークンを浪費する。Fable の俯瞰的視点で抜け道・別解が見つかる確率が高い。

**使用例**:
```
/advisor fable ブースレイアウトで通路幅を1.2mにするか1.5mにするか決まらない。
展示物のサイズは…（状況説明）
```

### 1.2 同じエラーが2回連続した時

テスト失敗・コンパイルエラー・API応答エラーが2回連続した場合、`/advisor fable` で根本原因の切り分けを相談する。

**なぜ**: 同じエラーを3回目に試す前に根本原因分析を行うことで、試行回数とコストを削減できる。Fable の推論力で原因特定の精度が上がる。

**使用例**:
```
/advisor fable 同じテストが2回連続で失敗している。
エラーメッセージ: … 試したこと: …
```

### 1.3 作業完了前の最終確認

PR作成・外部送信・デプロイの直前に、`/advisor fable` で最終確認を依頼する。

**なぜ**: 完了前に Fable のチェックを受けることで、見落とし・整合性の問題を事前に検出し、手戻りを防ぐ。

**使用例**:
```
/advisor fable このPRの変更内容を最終確認してください。
注意点: この変更は本番DBに影響します。
```

```markdown
### 1.13.2 相談タイミング（Sonnet + Fable advisor）
**🔴 Sonnet 5.5 を日常作業（コード作成・テスト実行・文章作成）に使い、要所判断だけ `/advisor fable` で Fable 5.1 に相談する。相談は以下の3タイミングに限定:**

2. **同じエラー2回連続** — 根本原因の切り分けが必要な時
3. **作業完了前** — PR作成・送信・デプロイ直前の最終確認
**コスト: 全 Opus 比 約1/5（全 Sonnet の場合）。Fable 相談は全体の3%未満に抑制。**
```
