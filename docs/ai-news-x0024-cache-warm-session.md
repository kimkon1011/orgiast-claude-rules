# X-0024: キャッシュ漏れ防止でセッションコスト削減（実測版）

> 2026-11-12。提案文の「起動時にモデルを固定・休憩時にコンパクト・/usage でヒット率確認」を、
> ローカルのセッション JSONL から機械的に測る道具 `tools/cache-warm-audit.mjs` を作り、
> このPC（HP / Windows）の実セッション 73 本で検証した結果。

## 1. 結論（3行）

1. 実測ヒット率は **97.3%**（cache_read 29.85億 / 総入力 30.67億トークン）。キャッシュは既に強く効いており、**削減余地は「漏れ」に集中**している。
2. 漏れの実体は「モデル切替」だった。73セッション中、実モデルの切替は **1回だけ**、そこでヒット率が **99.7% → 0.0%** に落ちた（キャッシュ全再構築）。
3. コンパクトは 8 回あり、うち 8 回で「直後3ターンの書き込み増＋ヒット率低下」を検出。**コンパクト自体は漏れではなく、直後の再ウォームが漏れ**。

### 漏れの実例（唯一の実モデル切替）

```
session f47bba4e…（2374ターン・haiku-4-5 → haiku-5-5・2249ターン目）
before 99.7% → after 0.0%（ヒット率）
```
切替1回で、それまでの会話コンテキスト全部がキャッシュから外れ、次のターンで丸ごと書き直しになる。
この1セッションの想定費用は $177。切替直後の再構築だけで数ドル規模。

## 3. 施策（提案文の3点を、実測に合わせて具体化）

### 3-1. モデルを固定する（効果が実証された唯一の項目）
- **セッション途中でモデルを変えない。** 変える必要があるなら、切替後に「同じ長いプレフィックス」を再送して再ウォームするコストを織り込む。
- 実装: `tools/cache-warm-audit.mjs` の `MODEL_SWITCH` / `SWITCH_CACHE_LOSS` を日次で回し、0件を保つ。
- 注意: `<synthetic>`（コンパクト要約などの合成行）をモデル切替と誤検出しないよう、ツール側で除外済み。**この誤検出を直さないと「コンパクトのたびに切替」と誤判定する**（初版で実際に31件の偽イベントが出た）。

### 3-2. コンパクトは「休憩時」に。直後の再ウォームを前提にする
- コンパクト後は必ずキャッシュが冷える（実測 8/8 で再構築を検出）。**ターンの途中で細かくコンパクトするより、区切りの良いところで1回**の方が安い。
- コンパクト直後は、長い共通プレフィックス（システムプロンプト＋仕様書）を**先に1回通してから**本題に入る。これで2ターン目以降がヒットに戻る。
- 実装: `COMPACT_RECACHE` の件数を週次で見る。減らないならコンパクトの頻度か位置が悪い。

### 3-3. /usage のヒット率は「セッション単位」で見る
- 直近の `/usage` だけでなく、`node tools/cache-warm-audit.mjs --since <月初> --top 10` で**セッション横断**に見る。/usage は現在セッションのみ、こちらは全セッションの漏れ点を出す。
- 併用: `tools/usage-stats.mjs`（モデル別・日別の集計）、`tools/cache-audit.mjs`（コード側で `cache_control` が付いていない大prefixの静的検出）。

## 4. ブース企画の長文仕様プロンプトへの適用

展示会ブース企画は「長い仕様書＋画像指示」を何度も使い回すため、キャッシュ効率の影響が最も大きい業務。

1. **1セッション＝1案件・1モデル**で回す。デザイン案を10個出すときも、モデルは途中で変えない。
2. 仕様書（共通プレフィックス）を**先頭に固定**し、案の差分（色・レイアウト・コピー）だけを後ろに置く。順序を入れ替えない。
3. 案の生成が一区切りしたら、**そこでコンパクト**。次の案群は同じ仕様書プレフィックスを先頭から再送してウォームに戻す。
4. 案件終了時に `node tools/cache-warm-audit.mjs --dir ~/.claude/projects --since <開始日> --top 5` で、その案件のセッションに `SWITCH_CACHE_LOSS` / `COLD_START_LOOP` が出ていないか確認する。

期待値: 仕様書プレフィックスが毎ターン再利用されれば、入力の 95% 以上が cache_read 単価（入力の 1/10）で済む。実測でも定常状態は 97〜99% に乗っている。

## 5. ツール仕様

```
node tools/cache-warm-audit.mjs [--dir <path>] [--since YYYY-MM-DD] [--top N] [--min-turns N] [--json] [--help]
```

- 既定の `--dir` は `~/.claude/projects`。配下の `*.jsonl` を再帰探索。
- セッションごとに: ターン数 / モデル / モデル切替回数と前後ヒット率 / 入力・cache_read・cache_creation・出力 / ヒット率 / 想定費用 / キャッシュ無し比の削減額 / フラグ。
- フラグ: `MODEL_SWITCH` `SWITCH_CACHE_LOSS`（切替後3ターンで30ポイント以上低下）`COLD_START_LOOP` `LOW_HIT` `COMPACT` `COMPACT_RECACHE`。
- 単価は env で上書き可（`CLAUDE_INPUT_USD_PER_M` ほか4つ、既定は Sonnet 系目安）。
- 読み取り専用。ネットワーク・書き込みなし。壊れた行は `badLines` に数えて続行。

テスト: `node --test tools/cache-warm-audit.test.mjs`（16件）。
