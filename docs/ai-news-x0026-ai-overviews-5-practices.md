# AI Overviews 向け5つの実践 — X-0026

> **目的**: Google AI Overviews からの引用獲得を最大化するため、タイトル・メタ説明・一次情報・意図分類・測定の5軸で実践パターンを定義し、株式会社オージャストの展示会ブース制作サイト（orgiast.jp）に適用する。
>
> **前提**: AI Overviews はユーザーの質問に対し複数ソースを要約して回答を生成する。引用されるには、回答の根拠となる情報が検索画面から直接読み取れる構造であることが必須。

---

## 1. タイトルの型（Title Patterns for AI Overviews）

AI Overviews はタイトルタグを引用元の識別子として重視する。以下の6型を使い分ける。

### Type A: 質問回答型（Question → Answer）

```
[質問]？[答え] | [サイト名]
```

| 要素 | ルール |
|------|--------|
| 質問部 | 「とは」「なぜ」「どうやって」「いくら」で終える |
| 答え部 | 8〜15字で端的に回答 |
| 全体 | 55〜60字以内 |

**orgiast.jp 向け例**:
- `展示会ブースの費用は？1坪30〜80万円が相場 | オージャスト`
- `大阪で展示会ブース制作を頼むには？5つの選び方 | オージャスト`

### Type B: 数字入りハウツー型（Numbered How-To）

```
[数字][動詞][目的]：[補足] | [サイト名]
```

| 要素 | ルール |
|------|--------|
| 数字 | 3〜7（奇数が記憶に残りやすい） |
| 動詞 | 「選ぶ」「作る」「決める」など行為動詞 |
| 補足 | 12〜20字で成果や特徴を追加 |

**orgiast.jp 向け例**:
- `展示会ブースを7ステップで作る：初めての出展者向け完全ガイド | オージャスト`
- `予算別に選ぶ！展示会ブース制作会社5社の比較ポイント | オージャスト`

### Type C: 「完全ガイド」型（Comprehensive Guide）

```
[対象読者]のための[トピック]完全ガイド[年] | [サイト名]
```

**orgiast.jp 向け例**:
- `中小企業のための展示会出展完全ガイド2027 | オージャスト`
- `Re:ブース導入ガイド：サステナブル展示の始め方 | オージャスト`

### Type D: 「比較」型（Comparison）

```
[A] vs [B]：[軸]で比較 | [サイト名]
```

**orgiast.jp 向け例**:
- `新製ブース vs Re:ブース：コストと環境性能を徹底比較 | オージャスト`
- `東京 vs 大阪：展示会ブース制作の地域別特徴 | オージャスト`

### Type E: 「事例」型（Case Study / Example）

```
[企業種]の[テーマ]事例：[数字]の成果 | [サイト名]
```

**orgiast.jp 向け例**:
- `中小企業の展示会成功事例：リード獲得180%増 | オージャスト`
- `万博パビリオン級ブース制作の舞台裏 | オージャスト`

### Type F: 「メリット」型（Benefit-First）

```
[メリット]なら[サービス]｜[補足] | [サイト名]
```

**orgiast.jp 向け例**:
- `CO2 77%削減ならRe:ブース｜環境展示を実現 | オージャスト`
- `初出展でも安心：フルサポートの展示会ブース制作 | オージャスト`

### 適用ルール

- コアページ（/booth, /event, /rebooth, /works, /company）は Type C または Type A
- ブログ記事は Type B または Type E
- ランディングページは Type F
- 比較コンテンツは Type D
- タイトル末尾のサイト名は「 | オージャスト」に統一（パイプ前後に半角スペース）

## 2. メタ説明文を「予告編」に変える方法（Meta Description as AI Trailer）

AI Overviews はメタ説明文を引用表示することが多い。従来のSEOメタ説明とは異なる「予告編」設計が必要。

### 2.1 構造ルール

```
【フック（15〜25字）】+ 【回答/根拠（40〜60字）】+ 【続きの誘導（30〜40字）】
```

| パート | 役割 | 字数 | 禁止事項 |
|--------|------|------|----------|
| フック | ユーザーの疑問を拾う。「〜なら」「〜には」「〜は」 | 15〜25 | 「このページでは」「当社では」などの書き出し |
| 回答/根拠 | 具体的な数字・事実・手段を1文で | 40〜60 | 抽象表現（「充実」「豊富」）のみ |
| 続きの誘導 | 詳細を知る理由を暗示 | 30〜40 | 「詳細はこちら」だけ |

### 2.2 orgiast.jp 向け例

| ページ | 現状のメタ説明（例） | AI Overviews 向け |
|--------|---------------------|-------------------|
| /booth | 「大阪の展示会ブース制作ならオージャスト」 | 「展示会ブース制作の費用相場は1坪30〜80万円。予算別の最適な工法と7拠点対応の実績を解説します。」 |
| /event | 「イベント企画制作のことなら」 | 「企業イベントの集客を最大化するには？企画立案から運営までの完全サポート手順をご紹介。」 |
| /rebooth | 「環境に配慮した展示会ブース」 | 「CO2排出量77%削減のRe:ブース。従来ブースと比較したコスト・期間・デザイン性を徹底比較。」 |
| /works | 「展示会ブース制作実績」 | 「万博パビリオン制作から中小企業ブースまで。業種別50件以上の制作実績を写真付きで紹介。」 |
| /company | 「株式会社オージャスト」 | 「全国7拠点・万博パビリオン制作実績。展示会ブース制作で年間200件以上のプロジェクトを手掛ける。」 |

### 2.3 AI Overviews 向けメタ説明の品質チェック

- [ ] 最初の120字以内にキー情報（数字・固有名詞・回答）があるか
- [ ] 「クリックして詳細を確認してください」型の無意味な誘導ではないか
- [ ] ページの主たる回答を1文で要約しているか
- [ ] AI Overviews が引用しても不自然でない日本語になっているか
- [ ] 同じサイト内で重複するメタ説明がないか

## 3. 一次情報を検索画面に伝える見せ方（Primary Source Presentation）

AI Overviews は信頼できる一次情報を優先する。ページ内に「誰が・いつ・どのデータに基づいて」を明示する。

### 3.1 ページ内可視要素

| 要素 | 配置 | 記載内容 | AI Overviews への効果 |
|------|------|----------|----------------------|
| 更新日 | 記事タイトル直下 | 2026年11月12日 | 鮮度シグナルとして引用されやすくなる |
| データ引用元 | 本文中（リンク付き） | 「経済産業省 調査結果（2026）」 | 外部権威を引用元として認識 |
| 著者/監修者 | 記事末尾またはサイドバー | 「監修：展示会プロデューサー ○○」 | 専門性のシグナル |
| 数値ハイライト | 記事冒頭の箇条書き | 「✓ 年間200件以上対応 ✓ 全国7拠点」 | 回答の具体的根拠として引用 |
| 構造化データ | JSON-LD（非表示） | Product / FAQ / Article スキーマ | 機械可読な事実として認識 |

### 3.2 JSON-LD 優先順位（X-0028 と連携）

X-0028 で整備した拡張スキーマに加え、AI Overviews 向けに以下を優先:

1. **FAQPage** — 「よくある質問」形式で Q&A を提供（AI Overviews の直接引用対象）
2. **Article** — 公開日・更新日・著者を明示
3. **Product** — 価格・特徴・評価（Re:ブース等のサービスに適用）
4. **HowTo** — 手順のあるコンテンツ（「展示会出展の手順」等）

### 3.3 ブログ記事のテンプレート（AI Overviews 向け）

```
---
タイトル: [Type A or B のタイトル]
メタ説明: [予告編形式]
公開日: YYYY-MM-DD
最終更新日: YYYY-MM-DD
著者: [名前]
カテゴリ: [展示会ノウハウ / Re:ブース / イベント制作]
---

## 📊 この記事でわかること（箇条書き・数字入り）

- [主要な回答1]
- [主要な回答2]
- [主要な回答3]

## [質問形式のH2見出し]

[一次情報を交えた本文]

## [質問形式のH2見出し]

...
```

### 3.4 禁止事項

- クローキング（構造化データと可視コンテンツの不一致）
- 過剰なキーワード詰め込み（AI Overviews はスパム判定を強化中）
- 実在しない統計データの提示
- 「当社の〜」だけで根拠のない自己主張

## 4. 検索意図の仕分け表（Search Intent Classification Table）

AI Overviews がトリガーされる検索意図を分類し、各意図に最適なコンテンツ形式を定義する。

### 4.1 意図 × コンテンツ形式 マトリックス

| 意図タイプ | ユーザーの質問例 | 推奨コンテンツ形式 | タイトル型 | メタ説明のフック | 必須スキーマ |
|-----------|----------------|-------------------|-----------|-----------------|-------------|
| **知る（Know）** | 「展示会ブース 費用」「ブース制作 流れ」 | ガイド記事・FAQ | Type A / C | 「〜とは」「〜の費用は」 | FAQPage, Article |
| **比較する（Compare）** | 「オージャスト vs A社」「Re:ブース 従来 比較」 | 比較表・一覧記事 | Type D | 「〜の違い」「比較」 | Product, ItemList |
| **決める（Decide）** | 「展示会ブース 会社 選び方」「大阪 おすすめ」 | ランキング・選び方 | Type B / D | 「選び方」「おすすめ」 | ItemList, Review |
| **始める（Do）** | 「初めての展示会 準備」「ブース 発注 手順」 | ステップバイステップ | Type B / C | 「手順」「始め方」 | HowTo, Article |
| **解決する（Solve）** | 「予算少ない ブース」「短期間 制作 方法」 | ソリューション記事 | Type F / A | 「〜なら」「方法」 | Product, FAQPage |
| **事例を知る（Case）** | 「展示会 成功事例」「ブース デザイン 事例」 | 事例紹介 | Type E | 「事例」「実績」 | Article, Review |

### 4.2 orgiast.jp のページ × 意図マッピング

| ページ | 想定意図 | 最優先タイトル型 | 注力すべきメタ説明要素 |
|--------|---------|-----------------|----------------------|
| /booth | 知る・決める | Type A（質問回答） | 費用相場・対応地域・工法の種類 |
| /event | 知る・始める | Type C（完全ガイド） | イベント企画の流れ・サポート範囲 |
| /rebooth | 比較する・解決する | Type D（比較） | CO2削減率・コスト差・工期の違い |
| /works | 事例を知る | Type E（事例） | 業種別実績・成果数値 |
| /company | 知る・決める | Type C（完全ガイド） | 拠点数・年間実績・万博実績 |
| /blog/* | 各種（記事による） | Type B（数字入り） | 記事固有のキー数字 |

### 4.3 AI Overviews トリガー率の高いクエリパターン

AI Overviews は以下のクエリパターンで表示率が高い:

1. **「とは」「って何」** — 定義を求めるクエリ
2. **「なぜ」「理由」** — 原因・理由を問うクエリ
3. **「方法」「やり方」「手順」** — 手順を問うクエリ
4. **「比較」「違い」「vs」** — 比較クエリ
5. **「いくら」「費用」「料金」** — 価格クエリ
6. **「おすすめ」「ランキング」** — 推薦クエリ
7. **「最新」「2027」「今年」** — 鮮度要求クエリ

→ これらのパターンを含むページは優先的に AI Overviews 向け最適化を行う。

## 5. 14日間の測定ルール（14-Day Measurement Protocol）

変更の効果を14日間で測定し、AI Overviews からの露出変化を定量評価する。

### 5.1 測定の前提

| 項目 | 内容 |
|------|------|
| 測定期間 | 変更適用日から14日間（営業日のみの測定を避け週末も含める） |
| 対象プロパティ | orgiast.jp（Search Console） |
| 測定ツール | Google Search Console + 手動スポットチェック |
| 成功指標 | AI Overviews 表示回数増加 / AI Overviews 経由クリック数 / 掲載クエリ増加 |

### 5.2 測定サイクル

```
Day 0: ベースライン取得（変更適用直前の7日間データ）
Day 1-7: 第1週（変更反映・インデックス待ち）
Day 8: 中間チェック（手動スポットチェック + GSC 参照）
Day 14: 最終評価（ベースライン対比）
```

### 5.3 測定項目

| # | 項目 | 取得方法 | 判断基準 |
|---|------|---------|---------|
| 1 | AI Overviews 表示回数 | GSC → 検索外観フィルタ | 前週比 +10% 以上で効果あり |
| 2 | AI Overviews クリック数 | GSC → 検索外観フィルタ | クリック率 0.5% 以上を目標 |
| 3 | 掲載クエリ数 | GSC → クエリレポート | 新規クエリの出現を確認 |
| 4 | タイトル変更後のCTR | GSC → ページレポート | 変更前後のCTR比較 |
| 5 | メタ説明表示文字数 | 手動スポットチェック | フック部分が表示されているか |
| 6 | FAQリッチリザルト | GSC → 拡張結果 | FAQ 表示回数増加 |

### 5.4 手動スポットチェック手順

1. シークレットウィンドウで Google 検索
2. 上記 4.3 のクエリパターンで検索
3. AI Overviews が表示されるか確認
4. 表示された場合、自サイトが引用されているか確認
5. 引用されている場合、タイトル・メタ説明が正しく表示されているか確認
6. 結果を記録（表示有無・引用順位・表示テキスト）

### 5.5 効果なしの場合のアクション

Day 14 で改善が見られない場合:

| 原因仮説 | 確認方法 | 修正アクション |
|---------|---------|--------------|
| インデックス未反映 | GSC → URL検査 | インデックス登録をリクエスト |
| タイトルが長すぎる | 手動チェック | 55字以内に短縮 |
| メタ説明に回答がない | 手動チェック | 予告編形式に書き換え |
| 競合の権威が高い | GSC → クエリ分析 | 一次情報・外部引用を追加 |
| AI Overviews 自体の表示率低下 | 第三者ツール or 手動 | トレンドを確認し期間延長を判断 |

### 5.6 測定レポートテンプレート

```markdown
# AI Overviews 測定レポート — [期間]

## ベースライン（Day 0）
- AI Overviews 表示回数: [数字]
- AI Overviews クリック数: [数字]
- 掲載クエリ数: [数字]

## 中間チェック（Day 8）
- インデックス状況: [OK/NG]
- FAQリッチリザルト表示: [有/無]
- 手動スポット結果: [表示されたクエリ・引用の有無]

## 最終評価（Day 14）
- AI Overviews 表示回数: [数字]（対ベースライン [増減]%）
- AI Overviews クリック数: [数字]（対ベースライン [増減]%）
- 掲載クエリ数: [数字]（新規クエリ: [リスト]）
- タイトルCTR変化: [変更前]% → [変更後]%

## 結論
[効果あり/改善余地あり/効果なし]
- 継続する施策:
- 改善が必要な施策:
- 次回アクション:
```

## 適用計画（orgiast.jp）

### Phase 1: コア5ページ（即日適用可能）

| ページ | 現状の課題 | 適用する型 | 優先度 |
|--------|-----------|-----------|--------|
| /booth | タイトルがブランド名のみ | Type A 質問回答型 | 高 |
| /event | メタ説明が会社説明のみ | 予告編メタ説明 | 高 |
| /rebooth | 数値がメタ説明に出ていない | Type D 比較型 + 予告編 | 高 |
| /works | 実績が検索画面に伝わらない | Type E 事例型 | 中 |
| /company | 差別化要素が出ていない | Type C 完全ガイド型 | 中 |

### Phase 2: ブログ記事（週次ローテーション）

既存ブログ記事から選定基準に合致するものを1週間に3記事ずつ変換:
- 検索ボリュームがあるトピック
- AI Overviews トリガーパターン（4.3）を含む
- 一次情報を追加できるテーマ

### Phase 3: 測定

変更適用後、14日間の測定を自動化スクリプトで実行する。
