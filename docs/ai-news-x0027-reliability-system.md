# X-0027: AIコーディング信頼性システム — LangGraph永続ワークフロー + 検証チェーン

> AIニュース提案 2026-11-14
> 対象: Claude Code, LangGraph, OpenAI Evals, Promptfoo, Langfuse, Arize Phoenix, OpenEvals を統合したコード生成の信頼性保証

## 概要

AIコード生成（Claude Code / Codex / 各種LLM）の出力を「信頼しない」を前提に、**検証・回復・追跡**の3層で信頼性を保証するシステムを提案。イベントサイトのコード生成やUI関連自動化の品質を担保する。

```
生成（AI） → 検証（Eval Chain） → 合格 → デプロイ
                  ↓ 不合格
             回復（LangGraph Workflow）
                  ↓
             再生成・修正 → 再検証
```

## 1. 現状の問題

| 問題 | 影響 |
|------|------|
| AI生成コードの品質が不定 | 手動レビューが必須。レビュー漏れで障害 |
| 修正ループがアドホック | 何回目の修正か・何を修正したかの追跡なし |
| 評価基準が人依存 | レビュアーによって合格ラインが異なる |
| 障害発生時の原因特定が困難 | どのLLM呼び出しが問題だったか追跡不能 |
| 回復が手動 | 失敗→コード修正→再実行を人がやる |

## 2. システムアーキテクチャ

```
┌─────────────────────────────────────────────────────────┐
│                   LangGraph Workflow                     │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐   │
│  │ Generate│→│ Validate│→│ Evaluate│→│ Deploy  │   │
│  │  (Code) │  │ (Static)│  │ (Multi) │  │  Gate   │   │
│  └─────────┘  └─────────┘  └─────────┘  └─────────┘   │
│       ↑           ↑            ↑                         │
│       └───── Recovery (retry / fallback / human) ──────┘  │
│                                                           │
│  [Checkpoint: JSON永続化 - 中断/再開可能]                   │
└─────────────────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────────────────┐
│                  Observability Layer                      │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐               │
│  │ Langfuse │  │  Arize   │  │ Console  │               │

│  └──────────┘  └──────────┘  └──────────┘               │
└─────────────────────────────────────────────────────────┘
```

### 2.1 ワークフロー層（LangGraphパターン）

各ステップは「状態遷移＋チェックポイント」を持ち、中断・再開・回復が可能。

| ステップ | 責務 | 障害時 |
|---------|------|--------|
| **Generate** | AI（Claude/Codex）にコード生成指示 | リトライ（指数バックオフ） |
| **Validate** | 静的解析（lint, type-check, a11y） | 修正指示を添えて再生成 |
| **Evaluate** | 多段評価（ユニットテスト → スナップショット → AI評価） | テスト修正 or 再生成 |
| **DeployGate** | 品質閾値チェック | 保留・人判断へエスカレーション |

### 2.2 検証チェーン（Eval Chain）

複数の評価手法を直列に実行。前段を通過しないと次段に進まない（早期不合格でコスト節約）。

```
静的解析 (ESLint/HTMLHint)
    → 関数テスト (Node Test Runner)
        → 視覚評価 (Playwrightスクリーンショット比較)
            → AI評価 (OpenEvals/OpenAI Evals基準)
                → 観測可能 (Langfuse/Phoenixに全トレース)
```

### 2.3 評価基準（OpenEvals準拠）

| カテゴリ | 評価項目 | ツール |
|---------|---------|--------|
| コード品質 | シンタックス・型・lint | ESLint / TypeScript |
| 機能正確性 | テストが通るか | Node Test Runner |
| アクセシビリティ | Lighthouse / axe-core 基準 | axe-core (Playwright経由) |
| レスポンシブ | 3サイズでの描画 | Playwright |
| セマンティック | HTML構造・h1-h6順序・landmark | DOM解析 |
| モデル評価 | 要件充足・自然言語記述 | OpenEvals / 独自プロンプト |

### 2.4 回復戦略

| 失敗パターン | 回復戦略 | 最大試行 |
|-------------|---------|---------|
| lint エラー | エラーメッセージを添えて再生成 | 3回 |
| テスト失敗 | どのテストが落ちたか添えて再生成 | 3回 |
| 視覚的乖離 >10% | 想定スクリーンショットとの差分を添えて再生成 | 2回 |
| AI評価不合格 | 評価理由を添えて再生成 | 2回 |
| 全試行失敗 | 人判断へエスカレーション（Workflow保留） | - |

### 2.5 観測可能性（Observability）

各イベントは共通トレース形式で出力。Langfuse / Arize Phoenix / コンソールのいずれかに転送可能。

```json
{
  "traceId": "wf_abc123",
  "spanId": "gen_001",
  "parentSpanId": null,
  "name": "generate.code",
  "status": "ok" | "error" | "retry",
  "duration": 1234,
  "input": { "prompt": "..." },
  "output": { "files": ["index.html"] },
  "error": null,
  "attributes": { "model": "claude-sonnet-5-5", "tokens": 1500 }
}
```

## 3. オージャスト適用シナリオ

### イベントサイトのコード生成

オージャストが展示会・セミナー向けに毎月制作するイベントサイト（1〜3サイト/月）のコード生成に適用:

| 工程 | 従来 | 信頼性システム適用後 |
|------|------|-------------------|
| コード生成 | 手動コーディング 4〜8時間 | AI生成 10分 + 検証 5分 |
| HTML検証 | 目視確認 15分 | 自動検証（a11y + semantic） 2分 |
| レスポンシブ確認 | 手動リサイズ 10分 | Playwright 3サイズ自動チェック 1分 |
| 修正ループ | 人依存 不確実 | LangGraph自動回復 3回まで自動 |
| 品質記録 | なし（属人） | 全トレース記録 振り返り可能 |

### UI関連自動化の検証

既存の X-0018 UI評価ループ（`evaluation-ai`）と統合:

```
X-0018 従来: buildFn → evaluate → 終了（不合格でも理由だけ）
X-0027 拡張: buildFn → validate(static) → test → evaluate(visual+model) 
            → 不合格なら自動再生成 → checkpoint保存 → 再開可能
```

### 費用対効果

| 項目 | コスト |
|------|--------|
| 評価1回の実行費用 | $0.01〜0.05（静的解析は無料、AI評価のみ従量） |
| サイト品質不良の修正費用（従来） | 障害1回あたり30分〜2時間 = 1,500〜10,000円 |
| 月間想定節約 | 3サイト × (従来8h → 30min) = 22.5時間/月削減 |
| ROI | 初月で回収可能（AI評価費用 < 手動レビュー削減） |

## 4. 実装計画

### Phase 1: コアワークフローエンジン（今回）
- LangGraphパターンのState/Checkpoint実装
- 多段eval chain（Validate → Test → Visual → AI）
- 指数バックオフリトライ + 最大試行回数制限
- 共通トレース形式 + 簡易コンソール出力

### Phase 2: ツール連携（次回）
- ESLint / HTMLHint 統合（静的解析）
- Playwright スナップショット比較
- axe-core アクセシビリティチェック

### Phase 3: 観測基盤（次々回）
- Langfuse SDK連携（トレース送信）
- Arize Phoenix SDK連携
- Promptfoo評価テンプレート

### Phase 4: 既存統合
- X-0018 build-agent の評価ループをLangGraph Workflowに置き換え
- `evaluation-ai` のUI視覚評価をEval Chainに組み込み

## 5. 制約・注意点

| 制約 | 対策 |
|------|------|
| LangGraph本体はPython（JSネイティブなし） | パターンをJSで実装（状態機械＋チェックポイント） |
| OpenAI EvalsはPython | OpenEvals（JS）で代替。未対応は独自評価基準 |
| 外部ツール依存（Playwright） | 依存をオプショナルにし、フォールバック評価を用意 |
| 評価の実行時間 | 静的解析 → 最短経路で不合格を早期検出。コストは段階的 |

## 6. 関連ツール概要

| ツール | 用途 | 本システムでの役割 |
|--------|------|------------------|
| **LangGraph** | 永続ワークフロー・状態管理・回復 | ワークフローパターンの参照実装 |
| **OpenAI Evals / OpenEvals** | LLM出力の評価基準 | Eval Chainのモデル評価基準 |
| **Promptfoo** | プロンプトテスト・回帰検出 | プロンプト変更時の品質変化測定 |
| **Langfuse** | LLMトレース・監視 | トレース送信先（本番） |
| **Arize Phoenix** | LLM観測可能性 | トレース送信先（開発中代替） |
| **Claude Code / Codex** | コード生成AI | 検証対象のコード生成エンジン |

## 7. 期待効果

- AI生成コードの品質を**静的検証＋動的テスト＋AI評価**の3段階で保証
- 修正ループを**自動化し、試行履歴をすべて記録**
- 障害原因をトレースから**特定可能**に
- 人手レビューを**最小限の承認作業**に縮減
- **人的依存からの脱却**（担当者が変わっても品質基準が一定）
