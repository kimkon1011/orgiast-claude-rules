# X-0030: Claudeモデル使い分けで利用コスト削減 — Fableだけで回さない賢い選択

**AIニュース提案 X-0030**: Anthropic公式のHaiku 5.5・Sonnet 5.5・Opus 5.5・Fable 5.2の4モデルをタスクに応じて使い分けるだけで、品質を保ちながらAPIコストを最大73%削減できる。Fableが最高性能でも常に最適ではない。モデルの選び方を変えるだけで、株式会社オージャストの月間AI費用も大幅に圧縮可能。

観測日: 2026-11-13

---

## 1. 概要

**問題**: 多くの企業・開発者が「とにかく最高性能のモデル（Fable / Opus）を使う」ことで、本来不要なコストを支払っている。AnthropicのClaudeラインナップはHaiku（最軽量）→Sonnet（汎用）→Opus（高性能）→Fable（最高峰）の4階層で、入力価格に**80倍の差**がある（Haiku $0.10/MTok vs Fable $8/MTok）。

**解決策**: タスクの難易度に応じてモデルをルーティングする。簡単な分類・抽出はHaiku、日常的なコーディング・分析はSonnet、複雑な推論はOpus、長時間エージェント実行だけFableに。実際の事例では、これだけで**38〜73%のコスト削減**が達成されている。

| 指標 | Fable一本槍（改善前） | モデル使い分け（改善後） | 出典 |
|------|-------------------|---------------------|------|
| 月間API費用 | $47,000 | $12,690（**73%減**） | GatherHq事例 |
| 月間API費用 | $41,000 | $14,350（**65%減**） | LearnXOps事例 |
| 月間API費用 | $3,200 | $1,984（**38%減**） | Narayana Raj事例 |
| 品質（精度） | ベースライン | ±1%以内で維持 | 全事例共通 |

## 3. コスト削減の4つのレバー

### 3.1 モデルルーティング（最大の効果）

**仕組み**: 入力クエリの難易度を判定し、適切なモデルへ振り分ける。

```
[入力] → 分類器（Haiku自身でも可） → 難易度判定
    ├── 簡単 → Haiku 5.5（$0.10/MTok）
    ├── 標準 → Sonnet 5.5（$2/MTok）
    ├── 難しい → Opus 5.5（$4/MTok）
    └── 最難関 → Fable 5.2（$8/MTok）
```

**分類器の実装方法**:
- キーワードベース（「要約して」「分類して」→Haiku）
- プロンプト長ベース（短い→Haiku、長い→Sonnet以上）
- トークン数×複雑さヒューリスティック
- LLM自身に分類させる（`"このクエリの難易度を1-3で答えて"`）

**効果**: 全トラフィックをOpusに送っていたケースで**65〜73%削減**（精度差±1%未満）。

### 3.2 プロンプトキャッシュ（繰り返し処理で10〜40倍削減）

**仕組み**: システムプロンプト・ツール定義・コンテキストの先頭部分をキャッシュし、2回目以降は**キャッシュ読取価格**（通常入力の2.5〜10%）で処理。

| モデル | 通常入力価格 | キャッシュ読取価格 | 削減率 |
|--------|-----------|-----------------|--------|
| Haiku 5.5 | $0.10 / $0.50 | $0.01 / $0.05 | **90%** |
| Sonnet 5.5 | $2.00 | $0.10 | **95%** |
| Opus 5.5 | $4.00 | $0.20 | **95%** |
| Fable 5.2 | $8.00 | $0.20 | **97.5%** |

**実例**: 大きなシステムプロンプト（〜10K tokens）を持つチャットボットで、キャッシュ導入により**$180/日→$8/日**（実例）。

**活用ポイント**:
- システムプロンプトを先頭に置き、安定部分をキャッシュ対象に
- ツール定義・関数スキーマもキャッシュ対象
- 同じコンテキストを複数セッションで再利用する場合は効果大
- Fable 5.2は特にキャッシュ効果が大きい（2.5%）

### 3.3 バッチAPI（50%割引）

**仕組み**: 即時応答が不要な非同期処理を50%割引のバッチAPIで実行。プロンプトキャッシュと併用可能。

| 処理種別 | 通常API | バッチAPI（50%off） |
|---------|--------|------------------|
| Haiku 5.5 入力 | $0.10 | $0.05 |
| Sonnet 5.5 入力 | $2.00 | $1.00 |
| Opus 5.5 出力 | $20.00 | $10.00 |
| Fable 5.2 出力 | $40.00 | $20.00 |

**活用例**: 夜間バッチ処理・定期レポート生成・大量データの一括分類・ログ解析・バックオフィス処理。

### 3.4 effortパラメータ調整（同モデル内でコスト最適化）

**仕組み**: 各モデルにeffort（low/medium/high）パラメータがあり、推論の深さを調整できる。全部lowで回し、失敗したものだけhighで再実行する方式。

| effort | 用途 | コスト目安 |
|--------|------|----------|
| **low** | 単純な分類・定型抽出・軽い要約 | baseline |
| **medium**（デフォルト） | 標準的なタスク全般 | baseline ×1 |
| **high**（監督/深い推論） | 複雑な推論・設計・判断 | baseline ×2〜3 |

**実績**: 全部lowで回し失敗時のみhigh再実行で、**正解率97%・全部high比で約60%削減**（実事例あり）。

## 5. オージャストでの適用案

### 5.1 現状の推定利用パターン

オージャストでは現在、Claude Code（デスクトップ版・ヘッドレス自動セッション・Codex委譲）で主にOpus/Sonnetを使用。以下の領域にモデル使い分けを導入できる:

| 業務領域 | 現在の想定モデル | 推奨モデル切替 | コスト削減見込み |
|---------|---------------|--------------|--------------|
| テキスト分類・ラベル付（Gmail振分・タグ付け） | Opus/Sonnet | **Haiku 5.5** | 〜95% |
| ログ解析・監視メッセージ | Opus/Sonnet | **Haiku 5.5** | 〜95% |
| データ抽出（請求書・レシートOCR結果の構造化） | Opus/Sonnet | **Sonnet 5.5**（複雑）/ **Haiku 5.5**（定型） | 〜75〜95% |
| 日次レポート生成 | Sonnet | **Haiku 5.5（effort low）** | 〜95% |
| コード自動生成（経理ハブ・自動化スクリプト） | Fable/Opus | **Sonnet 5.5**（通常）/ **Opus 5.5**（複雑） | 〜50〜75% |
| コードレビュー・品質チェック | Fable | **Opus 5.5（effort high）** | 〜50% |
| 設計・アーキテクチャ | Fable | **Opus 5.5**（大半）/ **Fable 5.2**（複雑なもののみ） | 〜50% |
| AIニュース記事作成 | Sonnet | **Sonnet 5.5**（維持） | — |
| ブースデザイン生成（長時間エージェント） | Fable | **Fable 5.2**（維持）/ 一部Opusで代替 | 状況次第 |
| 夜間バッチ処理（定期実行タスク） | Opus/Sonnet | **バッチAPI + Sonnet/Haiku** | 〜75〜87% |

### 5.2 推奨導入ステップ

**Step 1: 利用実態の把握（Day 1-3）**
- Anthropicコンソールで直近1ヶ月のモデル別利用量・費用を確認
- 各タスクの「本当に必要なモデル」を洗い出す
- バッチ処理可能なタスク（夜間・定期）を特定

**Step 2: モデルルーターの導入（Day 4-7）**
- Haiku/Sonnet/Opus/Fableの振分ルールを実装
- まずは自動セッションのタスク割振から開始
- テスト期間で品質への影響を検証

**Step 3: キャッシュ最適化（Day 8-10）**
- 各セッションのシステムプロンプトを先頭に固定
- 繰り返し使うコンテキスト（案件テンプレート・仕様書）のキャッシュ活用
- Claude Codeの自動セッションにおけるキャッシュ維持戦略の策定

**Step 4: バッチAPI移行（Day 11-14）**
- 即時応答不要な処理（定期レポート・監視ログ解析・夜間バッチ）をバッチAPIへ
- 50%割引＋キャッシュでさらに圧縮

**Claudeモデルの使い分けは「導入しない理由がない」ほど簡単で効果的なコスト削減策である。** 最高性能のFableをすべてのタスクに使うのは、全員にマラソンランナーを雇うようなもの。データ抽出にはHaiku、コーディングにはSonnet、設計にはOpus、そして本当に難しい問題だけFableを使う。それだけで**40〜73%のコスト削減**が、品質を落とさずに実現できる。

まずは1週間のテスト期間を設け、自動セッションの一部タスクをHaiku/Sonnetに振り分けて品質を検証することから始めるのが現実的な第一歩である。
