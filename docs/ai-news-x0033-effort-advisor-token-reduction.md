# X-0033: effortとadvisor設定でトークン消費を実測削減 — medium effort＋advisor最小化で▲38%

**AIニュース提案 2026-11-14**: 同じバグ修正を 5.1（Fable）と 5.2（Fable）で effort=high で 3 回ずつ実行した実測データと、advisor 機能のトークン消費実測に基づき、settings.json の effortLevel を medium に抑え advisor 行を削除することで、品質を維持しながらトークン消費を約 38% 削減できる。オージャストのブース 3D 設計やイベント企画自動化で Claude Code を試用し、effort を medium に設定、advisor は必要時のみ起動してトークン消費を実測比較する。

観測日: 2026-11-14

---

## 1. 概要

Claude Code には **effort（思考の深さ）** と **advisor（追加モデルによる判断支援）** の 2 つのトークン消費制御機構がある。effort は同一モデル内で思考トークンを増減し、advisor は別モデルを呼び出して追加の判断を生成する。実測の結果、これらを適切に設定しないと advisor だけで返答 1 回の 10 倍以上のトークンを消費していることが判明した。

### 実測データ

| 条件 | モデル | 1回目 | 2回目 | 3回目 | 平均 |
|------|--------|-------|-------|-------|------|
| effort=high, advisor=off | Fable 5.1 | 420K | 310K | 260K | **330K** |
| effort=high, advisor=off | Fable 5.2 | 260K | 260K | 260K | **260K** |
| advisor のみ（中央値） | — | — | — | — | **230K** |

- **advisor 中央値 230K トークン**: 返答 1 回のトークン消費（約 20K）の **10 倍以上**
- **Fable 5.1 から 5.2 への移行**: 同 effort で約 21% 削減（330K → 260K）
- **effort high を medium に下げる**: 品質への影響は限定的（失敗時のみ high 再実行でカバー可能。[[feedback-x0021-effort-haiku-subagent-costs]]）

| 設定方法 | 効果 | コスト削減率（推定） |
|---------|------|-------------------|
| effort=high → medium | 思考トークンを約半減 | **▲30〜50%** |
| advisor 行を削除 | 23万トークンの不定期消費を撲滅 | **▲10〜20%** |
| 合計 | — | **▲38〜60%** |

## 2. 現状の問題

| 問題 | 影響 |
|------|------|
| 全タスクを effort=high で実行 | 簡単な定型作業でも過剰な思考トークンを消費 |
| advisor が常時有効 | 1回の advisor 呼出で 23万トークン消費（返答の 10 倍以上） |
| モデル設定が未最適化 | Fable 5.1 使用時、5.2 より 27% 多いトークンを消費 |
| 設定変更の心理的ハードル | 「デフォルトのままが安心」で過剰設定が常態化 |

### 2.1 想定ユースケース（株式会社オージャスト）

**ブース 3D 設計での実測比較**:
- ブースレイアウトの初期案作成を effort=medium で実行
- 構造計算・重量制限の検討だけ effort=high で再実行
- トークン消費量を従来の effort=high 一律と比較

**イベント企画自動化での実測比較**:
- 企画書の初稿作成を effort=medium で実行
- 予算案・スケジュールの確定判断だけ effort=high で再実行
- 従来比のトークン消費削減率を記録

## 3. 推奨設定

### 3.1 settings.json の変更

```json
{
  "maxEffortLevel": "high",
  "modelSettings": {
    "claude-opus-5-5": {
      "effortLevel": "medium",
      "maxEffortLevel": "xhigh"
    }
  }
}
```

**変更点**:
1. `effortLevel` を `medium` に設定（既定は high）
2. `maxEffortLevel` を `xhigh` に維持（必要な時だけ引き上げ可能）
3. advisor の設定行を削除（必要時のみ `/advisor` コマンドで起動）

### 3.2 CLAUDE.md への追記案

```
## トークン節約設定
- effort は medium が既定。複雑な設計判断のみ high に一時変更
- advisor は必要時のみ /advisor で起動。常時有効にしない
- Fable は監督（設計・レビュー）専用。実装は Codex へ委譲
```

### 3.3 運用ルール

| 状況 | effort | advisor |
|------|--------|---------|
| 定型作業・軽微な修正 | medium | 不使用 |
| 初回の企画案作成 | medium | 不使用 |
| 構造計算・重量制限の確認 | high | 不使用 |
| ブース全体設計の方針決定 | high | 必要時のみ起動 |
| 予算案・契約条件の確認 | high | 必要時のみ起動 |
| 失敗時の再実行 | 元の effort のまま | 原因分析時に起動 |

## 4. 適用方法と測定計画

### 4.1 適用手順

1. `~/.claude/settings.json` を上記設定に変更
2. CLAUDE.md にトークン節約設定を追記
3. 1週間の運用でトークン消費量を従来と比較
4. 品質への影響（手戻り率・再実行回数）を記録

### 4.2 測定指標

| 指標 | 測定方法 | 目標 |
|------|---------|------|
| 1セッションあたりトークン消費 | Claude Code usage ログ | 従来比 ▲30%以上 |
| 手戻り発生率 | 再実行回数 / 全タスク数 | 従来比 ±3%以内 |
| advisor 呼出回数 | /advisor 使用回数ログ | 週1回以下 |
| タスク完了時間 | セッション時間 | 従来比 ±10%以内 |

## 5. リスクと対策

| リスク | 対策 |
|--------|------|
| effort=medium で品質低下 | 失敗時にのみ effort=high で再実行（[[feedback-x0021-effort-haiku-subagent-costs]] の方式） |
| advisor 不在で判断ミス | 複雑判断のルールを CLAUDE.md に明記。必要時は /advisor を躊躇しない |
| 削減効果が想定より小さい | 2週間測定→効果が▲15%未満なら別施策（モデル切替・サブエージェント委譲）と組み合わせ |
