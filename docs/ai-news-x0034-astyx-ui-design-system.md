# X-0034: Astyx（実体は Astryx）オープンソースUIデザインシステムで AIコーディングの再現性を高める

**AIニュース提案 X-0034**: Astyxを導入（150+のReactコンポーネント、7つのテーマ、すぐに使えるテンプレート、AIコーディングエージェント内蔵サポート）。株式会社オージャストでは展示会ブース制作やイベントサイトのUIをAIでコーディングする際にこのツールキットを使い、再現可能な高品質コンポーネントベースのUIを生成する。

観測日: 2026-11-12

---

## 1. 概要

提案名「Astyx」の実体は、**Meta がオープンソース化した React デザインシステム「Astryx」**（GitHub: [meta/astryx](https://github.com/meta/astryx)、MIT ライセンス、24.4k stars、現在 Beta）。「Astyx」は誤記または正規化で、正式名称は **Astryx**・npm パッケージは `@astryxdesign/*` である。

| 項目 | 内容 |
|---|---|
| 提供元 | Meta（社内で8年間運用・13,000+ アプリで稼働した最大デザインシステムを公開） |
| 技術基盤 | React 19+ / StyleX、TypeScript フル対応 |
| コンポーネント | 150〜180+ のアクセシブルなコンポーネント |
| テーマ | **7つの既製テーマ**（neutral / butter / chocolate / matcha / stone / gothic / y2k）＝CSSカスタムプロパティ上書きで自由に変更 |
| テンプレート | すぐに使える production-ready テンプレート（テーブル・フォームウィザード・ナビゲーション等のパターン） |
| ダークモード | 標準対応（コンポーネント組み込みのスペーシング・ダークモード） |
| CLI / MCP | スキャフォールド・テンプレート閲覧・テーマ生成を CLI／MCP から実行可能 |
| **AIエージェント対応** | API・ドキュメント・CLI が「人とAIアシスタントが同じ方法でビルドする」前提で設計 |
| ライセンス | MIT / Beta |

## 2. AIコーディング対応の中身（本提案の核心）

### 2.1 Agent-ready 設計

- API・ドキュメント・CLI が**人間とAIアシスタントで同一の操作方法**になるよう一体設計されている
- **グローバル CLI インストール**で「すべてのコーディングエージェントが Astryx を知る」状態を作れる（プロジェクト側は `@astryxdesign/core` のピン留め版を併用）
- Playwright／MCP から **テンプレート閲覧・テーマ生成・プロジェクト生成** をコマンドラインで実行できる

### 2.2 再現性の仕組み

- コンポーネントは CSS カスタムプロパティでテーマ化 → **同一コンポーネント＋テーマ変数の差し替えだけで画面を再現**
- **swizzle**: 任意コンポーネントのソース全体をプロジェクトへ eject 可能（外注先・将来のメンテで中身を握れる）
- スタイリング非ロックイン: `className` で Tailwind / CSS modules / plain CSS に上書き可能

### 2.3 インストール手順（最小構成）

```bash
# React 19+ が必要（react/react-dom は peer dependency）
npm install @astryxdesign/core @astryxdesign/theme-neutral @stylexjs/stylex
npm install -D @astryxdesign/cli
```

- 設定は「CSS import 数行＋テーマプロバイダ」だけで、**ビルドプラグイン・PostCSS・Babel 設定が不要**
- AIエージェントが CLI を叩くときのパスエラー回避として、README は package.json の script ラッパーを推奨:
  `node node_modules/@astryxdesign/cli/clients/cli/bin/astryx.mjs`

## 3. オージャストへの適用判断

### 展示会ブース制作・イベントサイトの UI 生成（本提案）

**結論: 推奨（新規イベントサイト・顧客サイトの共通UI基盤）**

| 用途 | Astryx の活かし方 | 期待効果 |
|---|---|---|
| ブース・イベントサイトの再現可能UI | クライアントごとにテーマ（CSS変数）を切替、同じコンポーネント群で制作 | 案件間のUI再現コスト削減、納品品質の平準化 |
| AIでのUIコーディング | Claude Code／Codex が CLI でプロジェクト生成→テンプレートから実装 | 生成結果のばらつき軽減、再現可能なコンポーネントベースUIの量産 |
| ブースコンセプト表現 | gothic / y2k など7テーマ＋カスタム変数をコンセプト（近未来・ポップ等）に割当 | デザイン提案のバリエーションを低コストで提示 |
| アクセシビリティ対応 | 180+ コンポーネントが標準でアクセシブル（WCAG 意識）、ダークモード内蔵 | イベントサイトに求められる代替テキスト・コントラストを初期値で担保 |

### 併用判断（社内パイプライン）

- 既存の `X-0018`（構築エージェント＋評価エージェントの UI 改善ループ）の**構築レーンに Astryx を標準部品として差し込む**と、評価レーン（Playwright 実描画）との相性が良い
- イベント用 LP は Vercel 等への静的デプロイ（ビルド設定不要）と親和性が高い

## 4. 導入優先順位と推奨アクション

### Phase 1（即日〜1週間）: 評価環境の構築
1. 開発用PCに `@astryxdesign/core` + `@astryxdesign/theme-neutral` + `@astryxdesign/cli` を導入（React 19 環境を用意）
2. グローバル CLI を入れ、Claude Code／Codex から `astryx` コマンドが呼べることを確認（script ラッパーでパスエラー回避）
3. 7テーマ（gothic / y2k 等）を生成し、コンセプト別の見た目差分を1画面で確認

### Phase 2（1〜2週間）: パイロット実装
1. 社内イベント or 展示会 LP を1本、Astryx テンプレートから AI コーディングで実装
2. 評価エージェント（Playwright 実描画）でダークモード・レスポンシブ・代替テキストを自動検証
3. 生成指示（プロンプト）と出来栄えを記録し、再現手順として社内ナレッジ化

### Phase 3（2〜4週間）: 共通部品化と案件適用
1. ブース制作で頻出の UI 部品（日程・オプション選択・見積フォーム等）を Astryx コンポーネントで標準化
2. swizzle で必要な部分だけ eject し、クライアントブランドの CSS 変数に差し替えて再利用
3. 顧客サイト制作に適用し、案件間の再現性を実測（作成工数・修正回数を記録）

## 5. 注意点・リスク

- **Beta 版**: 破壊的変更の可能性がある。本番顧客サイト全面適用は Phase 2 のパイロット検証後
- **React 19+ 必須**: 既存 React 18 以前のプロジェクトはアップグレードが必要（移行コストを事前評価）
- **StyleX 前提**: `@stylexjs/stylex` が peer dependency。Stylex 未導入チームは学習コストが1点増える
- **Meta 由来テーマのブランド調整**: butter / matcha 等をそのまま顧客案件に出さず、ブランド色への調整が必須
- **和文タイポグラフィ**: Foundations（タイポグラフィ）は欧文前提の可能性が高い。日本語フォントスタックの調整を初期検証に含める
- **名称の扱い**: 提案文の「Astyx」は「Astryx」（`@astryxdesign/*`）の誤記。社内文書では Astryx に統一する

## 6. 結論

| 用途 | 推奨 | 開始方法 |
|---|---|---|
| ブース・イベントサイトの再現可能UI | **Astryx（テーマ切替＋swizzle）** | `npm i @astryxdesign/core @astryxdesign/theme-neutral @stylexjs/stylex` |
| AIコーディングの再現性向上 | **グローバルCLI + MCP でエージェント標準装備** | `@astryxdesign/cli` をグローバル導入、script ラッパー登録 |
| 既存UI改善ループ（X-0018） | 構築レーンの標準部品として組込み | Phase 2 のパイロットで評価 |

AI で生成する UI が案件ごとにばらつく問題は、**「コンポーネント＋テーマ＋CLI」を固定した Astryx を構築レーンに置くこと**で解消できる。まず Phase 1 の評価環境から着手し、パイロット1本の実績を取ってから顧客案件に展開するのが現実的なロードマップである。
