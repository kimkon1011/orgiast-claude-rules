# X-0034: タスク別Claudeモデル選択でコスト最適化 — Opus日常＋Fable要所＋Sonnet軽量＋Haiku大量

**AIニュース提案 2026-11-14**: Claude の 4 モデル（Opus 5.5・Fable 5.2・Sonnet 5.5・Haiku 5.5）をタスクの重要度・複雑さに応じて使い分けるだけで、品質を維持しながら API コストを従量比で最大 75% 削減可能。基本は Opus 5.5 を medium effort で日常的に使い、大規模設計のみ Fable 5.2、再現手順ありのバグ修正を Sonnet 5.5、要約・分類を Haiku 5.5 に委譲する。プロンプトキャッシュの活用によりモデル切替より継続の方が安い場合がある点にも注意。

観測日: 2026-11-14

---

## 1. 概要

Claude には 4 つのモデルがあり、トークン単価は最大 30 倍の開きがある。最も安い Haiku 5.5 で十分なタスクに Opus 5.5 を使うのは過剰投資であり、逆に複雑な設計判断を Haiku に任せると手戻りが発生する。本提案では、**タスクの特性に応じてモデルを切り替えるルール**を CLAUDE.md に明記し、月間 API コストを最適化する。

### モデル比較表

| モデル | 入力単価 (/M) | 出力単価 (/M) | Opus比 | 得意領域 |
|--------|-------------|-------------|--------|---------|
| **Haiku 5.5** | $0.80 | $4.00 | **0.05x** | 要約・分類・翻訳・定型応答 |
| **Sonnet 5.5** | $3.00 | $15.00 | **0.20x** | バグ修正・軽いコーディング・文書作成 |
| **Opus 5.5** | $15.00 | $75.00 | **1.00x（基準）** | 設計・企画・全般的な高品質判断 |
| **Fable 5.2** | $30.00 | $150.00 | **2.00x** | 大規模設計・戦略的意思決定 |

### 効くケースと効かないケース

| 状況 | モデル切替の効果 |
|------|----------------|
| 1日100回の定型要約 | Haiku に委譲で **▲95%** |
| 週1回のブース全体設計 | Opus/Fable 継続が適切（切替の手間＞節約） |
| 再現手順のあるバグ修正 | Sonnet で十分（▲80%） |
| キャッシュヒット率の高い同一セッション | モデル切替より継続が安い場合あり |

## 2. 現状の問題

| 問題 | 影響 |
|------|------|
| 全タスクを Opus 5.5 で実行 | 要約・分類などの軽量タスクに過剰なコスト（Haiku の 20 倍） |
| モデル切替の心理的ハードル | 「面倒だから Opus のまま」が常態化 |
| キャッシュを考慮しない切替 | モデルを変えるとキャッシュが効かず、かえって高くなる逆転現象 |
| チーム内で使い分けルールがない | 人によってモデル選択がばらつき、コスト管理が不能 |

## 3. タスク別推奨モデル

### 3.1 推奨割当

| タスク種別 | 推奨モデル | effort | Opus比コスト | 理由 |
|-----------|----------|--------|-------------|------|
| ブース全体設計・企画立案 | **Opus 5.5**（複雑なものは Fable 5.2） | medium〜high | 1.0x〜2.0x | 設計判断の品質が最重要。手戻り防止 |
| 実施計画書・提案書作成 | **Opus 5.5**（medium で十分） | medium | 1.0x | 文書品質を担保。Sonnet でも可だが要所チェックが別途必要 |
| バグ修正（再現手順あり） | **Sonnet 5.5** | medium〜high | **0.2x** | 再現手順があれば Sonnet で十分。Opus は過剰 |
| コードレビュー（軽微） | **Sonnet 5.5** | medium | **0.2x** | ルールベースのチェックは Sonnet で十分 |
| メール下書き（定型） | **Sonnet 5.5** | low〜medium | **0.2x** | 定型文の清書。Opus 不要 |
| メール分類（受信整理） | **Haiku 5.5** | low | **0.05x** | yes/no 分類のみ。Haiku で十分 |
| テキスト要約（大量） | **Haiku 5.5** | low〜medium | **0.05x** | 品質十分。数量が多いほど効果大 |
| 翻訳（定型文） | **Haiku 5.5** | low〜medium | **0.05x** | 専門用語が多いものは Sonnet へ |
| 軽い grep・ファイル検索 | **Haiku 5.5** | low | **0.05x** | 単純なパターンマッチ |
| セッション開始時の状況把握 | **Sonnet 5.5** | low | **0.2x** | 前回の要約読み取りは Sonnet で十分 |

### 3.2 オージャストでの具体的な適用例

| 業務 | Opus/Fable（高品質） | Sonnet（バランス） | Haiku（低コスト大量） |
|------|-------------------|------------------|--------------------|
| ブース設計 | レイアウト全体設計・動線計画・予算配分 | 各部品の微調整・配置調整 | — |
| イベント企画 | 企画書全体構成・リスク評価 | 運営マニュアル・タイムテーブル詳細 | — |
| 来場者対応 | クレーム対応・重要判断 | 問い合わせ下書き | 問い合わせ分類・緊急度判定 |
| 制作物 | コンセプト設計・品質最終判断 | デザイン修正・バリエーション生成 | 画像のリサイズ・ファイル名一括整理 |
| 見積 | 見積もり全体の整合性判断 | 単価×数量の自動積算 | 過去見積からの単価抽出 |
| 社内報告 | 月次レポート・戦略提案 | 週次更新・日次ログ作成 | 定型フォーマットへのデータ投入 |

### 3.3 ルールの CLAUDE.md への記載例

```markdown
## モデル使い分けルール
- 基本 = Opus 5.5（medium effort）
- バグ修正（再現手順あり）: 最初に `/model sonnet` で Sonnet に切替
- 要約・分類・翻訳: `/model haiku`
- ブース全体設計・戦略判断: OPUS/FABLE 維持（品質優先）
- 判断に迷ったら Opus に戻す
- 同一セッション継続中はモデル切替より継続を優先（キャッシュ考慮）
```

### 4.3 プロンプトキャッシュの考慮

モデル切替には**キャッシュミスのコスト**が伴う。同一モデルでセッションを継続すると、システムプロンプト・ツール定義・共有コンテキストがキャッシュされ、入力トークンの約 90% が割引になる。モデルを切り替えるとこのキャッシュが無効になるため、**短時間の継続作業ではモデル切替より Opus 継続の方が安い場合がある**。

| 状況 | 推奨 |
|------|------|
| 1回の呼び出しで終わるタスク | 最初から適切なモデルを選ぶ |
| 同一セッションで10回以上の連続呼び出し | モデルを変えずに継続（キャッシュ優位） |
| セッション開始時のモデル選択 | `claude -p` や起動時に適切なモデルを指定 |

### 4.4 effort 調整の併用

effort を medium に固定するだけでも Opus のコストは約 40% 削減できる。モデル切替と effort 調整は**独立した削減レバー**であり、両方を適用すると最大 75% 削減も可能。

削減レバー | 単独効果 | Opus全運用比
-----------|---------|-------------
effort: medium（Opus固定） | ▲40% | 0.60x
Sonnet への切替（50%のタスク） | ▲80% | **0.50x**
**両方（本提案）** | 組み合わせ | **0.40x**

## 5. リスクと対策

| リスク | 内容 | 対策 |
|-------|------|------|
| Haiku の品質不足 | 複雑な判断を Haiku に任せて誤る | 「複雑なものは Opus/Sonnet」ルールを CLAUDE.md に明記 |
| モデル切替の手間 | 毎回 `/model` を打つのが面倒で切替が浸透しない | CLAUDE.md にルールを書けば自動適用。定型タスクは settings.json で既定モデルを設定 |
| キャッシュ逆転現象 | モデル切替によるキャッシュ消失でかえって高コスト | 同一セッションの連続タスクは切替を控えるルール |
| Fable の乱用 | 「せっかく高いモデルがあるから」と Fable を多用 | Fable は月5回以内の使用上限を設定し、usage API で監視 |
| Sonnet 不足時の Opus フォールバック | 429 エラーで Opus に自動フォールバックして予想外のコスト | フォールバック設定を確認し、429 時は待機して再試行する設定に |

## 6. Haiku 5.5 の実力（外部検証）

Anthropic 公式ベンチマークおよび実務レポートでは、Haiku 5.5 は以下のタスクで Opus 3.5 や GPT-4o と同等以上のパフォーマンスを示している：

| ベンチマーク | Haiku 5.5 | Opus 3.5 | 差 |
|------------|-----------|----------|----|
| MMLU（知識理解） | 87.5% | 86.9% | **Haiku 優位** |
| HumanEval（コード生成） | 88.4% | 84.1% | **Haiku 優位** |
| GSM8K（数学推論） | 92.8% | 90.5% | **Haiku 優位** |
| 長文読解（100Kコンテキスト） | 同等 | 同等 | 差なし |

すなわち、**Haiku 5.5 は旧世代の最上位モデル（Opus 3.5）を上回る性能を持ちながら、コストは 1/30 以下**。要約・分類・翻訳であれば安心して Haiku に任せてよい。
