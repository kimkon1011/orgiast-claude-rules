# X-0036: Gemini Decision 1 で出力トークン課金ゼロ — 展示会問い合わせ分類・ブース仕様確認

**AIニュース提案 2026-11-14**: Google DeepMind が 2026-11-11 に発表した Gemini Decisions API（`gemini-decision-1`）は、従来の生成型 AI とは異なり**出力トークンがゼロ**で、最大 1,000 の質問を 1 パスで評価する。展示会来場者問い合わせの自動分類、ブース仕様 PDF の確認、顧客要件の合致判定など、オージャストの実業務で試用し、従来の生成 AI とコスト・精度を比較する。

観測日: 2026-11-14

---

## 1. 概要

Gemini Decisions API は、**テキストを生成せず**、入力されたコンテンツに対して事前定義された質問をスコアリングする API である。以下の特長を持つ：

| 特長 | 詳細 |
|------|------|
| **出力トークン課金ゼロ** | テキスト生成がないため `total_output_tokens = 0`。**入力トークンのみ課金** |
| **入力価格** | **$0.10 / 100万トークン**（テキスト・画像・音声・動画・PDF 共通） |
| **1,000 質問/リクエスト** | 最大 1,000 の yes/no・選択・ルーブリック評価を 1 回のフォワードパスで実行 |
| **レイテンシ** | **150〜250ms**（質問数 1〜100 でほぼフラット） |
| **マルチモーダル** | テキスト、画像、音声、動画、PDF を入力として受付 |
| **入力上限** | 256K トークン、100MB（PDF は 50MB） |
| **3 種類の質問** | `noul`（Yes/No）、`choice`（多肢選択）、`score`（ルーブリックスコアリング） |

### 価格比較

| モデル | 入力価格(/Mトークン) | 出力価格(/Mトークン) | 100質問あたりの実効コスト |
|--------|-------------------|-------------------|------------------------|
| Gemini Decision 1 | **$0.10** | **$0** | **$0.10**（共有入力 1000トークン想定） |
| Gemini 3.5 Flash | $1.50 | $9.00 | $0.20〜0.50（出力分が支配的） |
| Claude Sonnet 5.5 | $3.00 | $15.00 | $0.50〜1.00 |
| GPT-6 Luna (Decision) | $0.10 | $0 | $0.10（同額） |

Decision API は従来の生成 API と比較して**約 5 倍安い**（Google 公式ベンチマーク）。

## 2. 現状の問題

| 問題 | 影響 |
|------|------|
| 展示会来場者問い合わせの分類に生成 AI を使用 | 毎回の出力トークンが無駄（分類結果は「問い合わせ/見積依頼/キャンセル」の 1 単語で十分） |
| ブース仕様 PDF の確認に人手 | 仕様書の「寸法が合致するか」「重量制限を満たすか」の確認にエンジニアが 1 件 10〜30 分 |
| 顧客要件と自社提案の合致チェックが属人化 | 確認漏れが手戻りの原因に |
| 問い合わせの緊急度判定が担当者の経験任せ | 未対応の緊急問い合わせが埋もれる |

### 2.1 想定ユースケース（株式会社オージャスト）

**展示会来場者問い合わせの自動分類**:
- 来場者からの問い合わせメール本文を入力
- 以下の質問を 1 リクエストで評価：
  - 「これは見積依頼か？」(noul)
  - 「これはキャンセルか？」(noul)
  - 「緊急度は高いか？」(noul)
  - 「問い合わせ種別は？」(choice: 見積/在庫確認/キャンセル/ブース仕様/その他)
- 確信度 0.90 未満のものだけ人手確認 → 工数 80% 削減見込み

**ブース仕様 PDF の確認**:
- 会場から提供されるブース仕様書 PDF を入力
- 以下の質問を評価：
  - 「最大奥行き 3.6m 以内か？」(noul)
  - 「最大高さ 2.5m 以内か？」(noul)
  - 「重量制限 500kg 以内か？」(noul)
  - 「電源容量 1.5kVA 以上確保可能か？」(noul)
  - 「出展区分は？」(choice: 小間/特設/屋外)
- 全会場の仕様を統一フォーマットで確認 → 見落とし防止

**顧客要件合致チェック**:
- 顧客のヒアリングシートと提案書を入力
- 以下の質問を評価：
  - 「予算範囲内か？」(noul)
  - 「希望日程に合致するか？」(noul)
  - 「必須要件（音響・電源・サイズ）を満たすか？」(noul)
  - 「優先度は？」(score: 高/中/低)

## 3. Gemini Decision 1 の技術詳細

### 3.1 3 種類の質問

| タイプ | 用途 | 戻り値 |
|--------|------|--------|
| **`noul`** | Yes/No 判定（0.01〜0.99 の確率） | `noul`（確率）、`confidence`（確信度） |
| **`choice`** | 2〜255 の選択肢から 1 つを選択 | `choice`（選択肢）、`probabilities`（全選択肢の確率）、`confidence` |
| **`score`** | 順序付きルーブリックで評価 | `score`（加重スコア）、`probabilities`（各レベルの確率）、`confidence` |

### 3.2 リクエスト例

```json
{
  "model": "gemini-decision-1",
  "input": "展示会のブースを予約したいのですが、3m×3mの小間で11月20日からの展示会に参加可能でしょうか。予算は30万円以内で考えています。",
  "questions": {
    "is_inquiry_type_estimate": {
      "type": "noul",
      "instructions": "この問い合わせは見積依頼を含んでいますか？"
    },
    "is_urgent": {
      "type": "noul",
      "instructions": "この問い合わせは緊急対応が必要ですか？（開催日が2週間以内など）"
    },
    "inquiry_category": {
      "type": "choice",
      "choices": ["見積依頼", "在庫確認", "キャンセル", "ブース仕様", "その他"],
      "instructions": "この問い合わせの種別を選んでください。"
    }
  }
}
```

### 3.3 応答例

```json
{
  "answers": {
    "is_inquiry_type_estimate": {
      "type": "noul",
      "noul": 0.95,
      "confidence": 0.97
    },
    "is_urgent": {
      "type": "noul",
      "noul": 0.72,
      "confidence": 0.85
    },
    "inquiry_category": {
      "type": "choice",
      "choice": "見積依頼",
      "probabilities": {
        "見積依頼": 0.91,
        "在庫確認": 0.02,
        "キャンセル": 0.01,
        "ブース仕様": 0.04,
        "その他": 0.02
      },
      "confidence": 0.94
    }
  },
  "usage": {
    "total_input_tokens": 85,
    "total_output_tokens": 0,
    "total_tokens": 85
  }
}
```

### 3.4 重要制約

| 制約 | 詳細 |
|------|------|
| 利用可能 API | **v1beta のみ**（generativelanguage.googleapis.com/v1beta/decisions） |
| SDK | google-genai v3.2+（Python）/ @google/genai latest（JavaScript） |
| コンテキストキャッシュ | **非対応** |
| バッチ API | **非対応** |
| Flex/Priority | **非対応** |
| 質問の独立性 | 質問同士は**相互に参照不可**（各質問が独立して評価される） |
| yes/no 確率範囲 | 0.01〜0.99（1.0 や 0.0 は返らない） |

## 6. リスクと対策

| リスク | 対策 |
|--------|------|
| v1beta のみの提供（安定版未リリース） | 影響が軽微な分類タスクから試験導入。本番適用は GA 後 |
| コンテキストキャッシュ非対応 | 同一 PDF を複数質問で使い回す場合も入力課金は 1 回のみ（共有入力は 1 回課金） |
| 確信度 0.90 未満の判定が多い | 閾値の調整とプロンプト改善で対応。確信度が低いものは人手確認に回す設計 |
| PDF 処理の品質 | 50MB まで対応。文字認識は Gemini のマルチモーダル処理に依存。複雑な表組みは要注意 |
| Gemini API キーの管理 | 既存の Gemini キー（seisaku-team@ の AI Studio TrackPlanner）を流用。keyserve 未配布のため、利用の際はキーを環境変数で設定 |
