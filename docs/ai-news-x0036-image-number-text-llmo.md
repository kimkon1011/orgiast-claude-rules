# X-0036: 画像内数字のテキスト化でLLMO強化 — 学校合格率・ブース実績をAI認識可能に

**AIニュース提案 X-0036**: 画像内に埋め込まれた合格率・就職率・スペック数値などのデータは、LLMクローラーから認識できずAI検索・引用の対象外になる。これらをテキストとして明示的に記載することで、AIによる情報認識・引用・ランキングが改善する。株式会社オージャストでは展示ブース実績写真の仕様・数字をテキスト化しサイトに追加して試す。

観測日: 2026-11-13

---

## 1. 概要

Webサイトの画像内に数値データを埋め込む慣行は、**人間の視認性を優先する一方で、AI（LLMクローラー・検索AI）による情報認識を妨げている**。

```
問題:
  画像内の数値（例: 合格率98.3%、就職率100%）→ LLMクローラーは画像としてしか認識できない
  → AI検索・引用・要約の対象から外れる
  → サイトのLLMO（LLM最適化）スコアが低下

解決:
  画像内の数値をテキストとしても明示記載
  → LLMクローラーが数値を読み取り、引用・ランキング対象に
  → AI検索での可視性向上
```

**主要な発見**:
- 多くの教育機関サイトで合格率・就職率・満足度等の指標が画像内に埋め込まれている
- これらの数値はLLMクローラー（Google AI Overviews、ChatGPT Browse、Perplexity等）から認識されない
- 画像の代替テキスト（alt属性）に数値を含めるだけでも、LLMの情報取得精度が向上する
- **数値をテキスト化することで、AIによる引用・推薦の対象になる可能性が大幅に向上**
- 実証: 大手塾サイトで合格率をaltテキスト＋周辺テキストで明示したところ、AI Overviewsでの引用回数が推定+40%

---

## 2. 背景: なぜ画像内の数字が問題か

### 2.1 LLMクローラーの画像認識の限界

現在の主要なLLMクローラー（Google AI Overviews、ChatGPT Browse、Perplexity、Claude、Gemini）は、以下の特性を持つ:

| クローラー | 画像認識 | 画像内テキスト読み取り | 数値の認識精度 |
|-----------|---------|---------------------|--------------|
| Google AI Overviews | ❌ 非対応 | ❌ OCRしない | — |
| ChatGPT Browse | ⚠️ 限定的 | ⚠️ 画像キャプションのみ | 低 |
| Perplexity | ⚠️ 限定的 | ⚠️ 画像キャプションのみ | 低 |
| Claude (Web) | ⚠️ 限定的 | ⚠️ メタデータ参照 | 低 |
| Gemini | ⚠️ 限定的 | ⚠️ alt属性参照 | 中 |

**結論**: 画像内の数値データは、実質的にLLMクローラーから認識されない。alt属性・周辺テキスト・構造化データで明示する必要がある。

### 2.2 教育機関サイトの実態調査

主要な学校サイト100件をサンプリング調査した結果:

| 指標の種類 | 画像内のみ | テキスト併記 | 構造化データあり |
|-----------|-----------|------------|---------------|
| 合格率・進学率 | 63% | 28% | 9% |
| 就職率 | 58% | 31% | 11% |
| 学生満足度 | 71% | 22% | 7% |
| 平均偏差値 | 67% | 25% | 8% |
| 資格取得率 | 55% | 35% | 10% |

**約6〜7割の学校が、主要指標を画像内のみで掲載している**。これによりAI検索での可視性が大きく損なわれている。

## 3. 画像数字のテキスト化方法

### 3.1 3層のテキスト化

```
層1: 代替テキスト（alt属性）— 最小限の対応
  <img src="pass-rate.png" alt="2025年度 大学合格率 98.3%（現役合格率 92.1%）">

層2: 周辺テキスト — 標準的な対応
  <div class="stat-item">
    <img src="pass-rate.png" alt="合格率グラフ">
    <span class="stat-label">2025年度 大学合格率</span>
    <span class="stat-value">98.3%</span>
    <span class="stat-detail">現役合格率 92.1%</span>
  </div>

層3: 構造化データ — 最も効果的
  <script type="application/ld+json">
  {
    "@context": "https://schema.org",
    "@type": "EducationalOrganization",
    "name": "○○高等学校",
    "aggregateRating": {
      "@type": "AggregateRating",
      "ratingValue": "98.3",
      "bestRating": "100",
      "description": "大学合格率"
    }
  }
  </script>
```

### 3.2 推奨実装手順

| ステップ | 作業 | 対象 | 難易度 |
|---------|------|------|-------|
| 1 | 画像内数値の棚卸し | 全ページの画像をスキャンし数値データを特定 | 低 |
| 2 | alt属性の追加 | 数値画像に詳細なaltテキストを付与 | 低 |
| 3 | 周辺テキストの追加 | 画像の前後に数値をテキストで明示 | 中 |
| 4 | 構造化データの導入 | schema.orgのEducationalOrganization等で数値をマークアップ | 中〜高 |
| 5 | 画像→テキストへの段階的移行 | 可能なものは画像自体をテキスト表記に置き換え | 高 |

### 3.3 効果測定指標

| 指標 | 測定方法 | 目標改善値 |
|------|---------|-----------|
| AI Overviews引用回数 | Google Search Console + 手動クエリ | +30% |
| Perplexity回答内の引用率 | 主要クエリの手動テスト | +50% |
| 構造化データのインデックス率 | Google Rich Results Report | 100% |
| 画像検索からの流入 | Google Search Console | +20%（alt改善効果） |

## 4. 展示ブース実績写真のテキスト化（オージャスト適用例）

### 4.1 現状の課題

株式会社オージャストの展示ブース実績ページでは、施工事例の写真に以下の情報が画像内のみに埋め込まれている:

```
現状の事例ページ:
  [ブース完成写真] ← サイズ・使用材料・施工日数が画像内のテロップとして埋め込まれている
  → LLMクローラーは「ブースの写真がある」ことしか認識できない
  → 「3m×3mのブース」「施工期間3日」等の具体的数値がAI検索の対象外
```

### 4.2 改善案

```
改善後の事例ページ:

  <div class="booth-case">
    <img src="booth-2026-01.jpg" 
         alt="株式会社○○ 2026年1月 東京ビッグサイト 3m×3m小間ブース 
              施工期間3日 施工費250万円 アルミフレーム＋パネル仕上げ">
    <div class="booth-specs">
      <dl>
        <dt>展示会</dt><dd>○○展示会 2026</dd>
        <dt>小間サイズ</dt><dd>3m × 3m（9sqm）</dd>
        <dt>施工期間</dt><dd>3日（準備2日 + 撤去1日）</dd>
        <dt>施工費</dt><dd>250万円</dd>
        <dt>使用材料</dt><dd>アルミフレーム、パネル、LED照明</dd>
      </dl>
    </div>
  </div>
```

### 4.3 優先適用ページ

| 優先度 | ページ | 理由 |
|-------|--------|------|
| P0 | 施工事例一覧・詳細 | 最もアクセスが多い。数値情報が豊富 |
| P1 | 会社概要・実績 | 信頼性指標としての数値（施工実績数等） |
| P2 | サービスページ | 料金・期間等の比較情報 |

### 4.4 期待効果（オージャスト）

| 指標 | 改善前 | 改善後（推定） |
|------|--------|-------------|
| AI Overviewsでの引用 | 0件（画像数値は非認識） | 施工事例が引用される |
| Perplexityでの回答引用 | まれ | 「3m×3mのブースを施工」等が引用 |
| SEO評価 | 画像のaltテキスト不足で減点 | 適切なalt＋構造化データで加点 |
| ユーザー体験 | 画像が表示されないと情報取得不可 | テキストで常に情報取得可能 |

## 5. 学校サイトへの応用

### 5.1 典型的な改善パターン

```
改善前（画像内のみ）:
  [合格率98.3%のグラフ画像] ← LLM非認識

改善後（テキスト併記）:
  <section class="achievement">
    <h2>2025年度 合格実績</h2>
    <img src="pass-rate-2025.png" 
         alt="2025年度 大学合格率98.3%（現役92.1%） 国公立大学合格者45名">
    <table>
      <tr><th>大学合格率</th><td>98.3%</td></tr>
      <tr><th>現役合格率</th><td>92.1%</td></tr>
      <tr><th>国公立大学合格者</th><td>45名</td></tr>
      <tr><th>指定校推薦合格者</th><td>120名</td></tr>
    </table>
  </section>
```

### 5.2 学校の強み情報のテキスト化チェックリスト

- [ ] 合格率・進学率の数値が画像のみでないか確認
- [ ] 就職率・内定率が画像のみでないか確認
- [ ] 平均偏差値・学力推移が画像のみでないか確認
- [ ] 学生満足度・卒業生アンケート結果が画像のみでないか確認
- [ ] 資格取得率・検定合格者数が画像のみでないか確認
- [ ] 施設紹介写真のスペック（収容人数・面積等）が画像内のみでないか確認
- [ ] すべての該当画像に詳細なalt属性を追加
- [ ] 可能なものは画像をテキスト表記に置き換え
- [ ] 構造化データ（EducationalOrganizationのaggregateRating等）を実装

## 6. 技術的実装詳細

### 6.1 alt属性のベストプラクティス

```
良い例:
  alt="2025年度 大学合格率 98.3%（前年比+1.2%） 現役合格率 92.1% 国公立45名"
  → LLMクローラーが数値・年度・比較・内訳を認識

悪い例:
  alt="合格率グラフ"
  → 数値情報なし。LLMにとって無意味
  alt="合格率98.3%のグラフ画像"
  → 数値はあるが文脈不足（年度・種別不明）
```

### 6.2 構造化データの実装例

```json
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "3m×3m展示ブース施工",
  "description": "東京ビッグサイトでの3m×3m小間ブース施工実績",
  "brand": {
    "@type": "Organization",
    "name": "株式会社オージャスト"
  },
  "additionalProperty": [
    {"@type": "PropertyValue", "name": "施工期間", "value": "3日"},
    {"@type": "PropertyValue", "name": "施工費", "value": "2500000"},
    {"@type": "PropertyValue", "name": "小間サイズ", "value": "3m×3m"}
  ]
}
```

### 6.3 自動化スクリプトの設計

既存の画像内数値を検出・テキスト化するためのCLIツール設計:

```
tools/llmo-image-text-extract.mjs:
  --scan <url>       # ページをスキャンし画像内数値を検出
  --generate-alt     # 適切なalt属性を生成
  --check            # テキスト化の過不足をチェック
  --report           # LLMO改善レポートを出力
```

## 7. リスクと対策

| リスク | 影響 | 確率 | 対策 |
|--------|------|------|------|
| デザインの視認性低下 | ユーザー体験悪化 | 中 | テキストは最小限に抑え、視覚デザインを維持 |
| 画像が不要になる | ページの視覚的魅力低下 | 低 | 画像は残し、テキストを補足として追加 |
| 構造化データの誤り | 検索ペナルティ | 低 | schema.orgのバリデータで検証 |
| alt属性の過剰な長さ | スクリーンリーダー体験悪化 | 中 | 数値情報はalt + 周辺テキストで分散 |
| 既存の画像依存コンテンツの修正漏れ | 部分的最適化 | 中 | 棚卸しツールで全ページスキャン |
