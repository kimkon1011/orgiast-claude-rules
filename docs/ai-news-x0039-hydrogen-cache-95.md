# X-0039: Gemini 4 Hydrogen × キャッシュ95%割引で低コスト推論

**AIニュース提案 2026-11-14**: Gemini 4 の軽量モデル Hydrogen と、Gemini 4 固有の implicit caching（最大95%割引）を組み合わせ、ブース動画分析・イベント資料生成を Claude/Sonnet より格安で実行する。

## 1. 概要

Google DeepMind が 2026年11月12日に発表した **Gemini 4 モデルファミリー** には、3つの主要モデルがある：

| モデル | 役割 | 速度 | 価格帯 | 利用プラン |
|--------|------|------|--------|-----------|
| **Carbon** | 最強推論（SWE / 科学 / セキュリティ） | 遅い | 最高 | Ultra / Enterprise |
| **Argon** | 高精度推論 | 中程度 | 高 | Pro / Ultra |
| **Hydrogen** | 軽量高速実行（日常のコーディング・分析） | **高速** | **低** | 全プラン（Free含む） |

さらに、**Orchestrator** 機能により Carbon（計画）→ Hydrogen（実行）の動的連携が可能で、Terminal-Bench 4.1 では **24% 消費削減・19% 高速化** を達成している。

### Gemimi 4 のキャッシュ割引

| モデル世代 | 明示的キャッシュ | 暗黙的キャッシュ | 最大割引率 |
|-----------|----------------|----------------|-----------|
| Gemini 2.0 | 75% off | - | 75% |
| Gemini 2.5 Pro/Flash | 90% off | 90% off | 90% |
| **Gemini 4 (Carbon/Argon/Hydrogen)** | **非対応** | **最大95% off** | **95%** |

**Gemini 4 では明示的キャッシュ（Context Caching API）には非対応だが、暗黙的キャッシュ（implicit caching）が最大 95% 割引で動作する。**

## 2. 現状の問題

| 問題 | 影響 |
|------|------|
| ブース動画分析（ウォークスルー動画の30秒〜3分クリップ）を Claude API で処理 | 動画フレーム大量入力でトークン爆発 → 1分析あたり $2〜10 |
| イベント資料生成（企画書・施工手順書）に毎回同じブランドガイドラインを送信 | 同一コンテキストの再送でキャッシュ未活用、無駄な入力トークン |
| 全タスクを Claude API（$3〜15/Mトークン）に依存 | 月間 API 費の約60%が入力トークン |
| 軽量な分析（文字起こし・分類・抽出）に高額モデルを使いすぎ | 品質に対して過剰支出 |

### 2.1 キャッシュ前提と前提（なぜ今なのか）

従来の課題:
- Claude の prompt caching は最大 90% 割引だが **キャッシュ有効期限が5分（無操作時）** → 夜間バッチ・無人処理でキャッシュが効かない
- Gemini 2.5 の context caching は 90% 割引で **24時間キャッシュ保持** だが明示的 API（ContextCache.create）が必要

Gemini 4 の implicit caching:
- **明示的 API 不要** — 同一プレフィックスを自動検出して割引適用
- **最大95%割引** — キャッシュヒット時に入力トークンが 5% のコストに
- **Orchestrator + Hydrogen** の軽量モデルと組み合わせれば、総コストは Carbon 比で **2〜5%** に抑えられる

### 3.4 Orchestrator 連携（Carbon + Hydrogen）

Carbon（計画）+ Hydrogen（実行）+ キャッシュ（共通プレフィックス）の 3 段最適化：

```
[Carbon: 戦略設計] ← 企画の構成・評価指標を策定（1回のみ）
       ↓  企画書テンプレート（〜2,000トークン）をキャッシュ登録
[Hydrogen: 一括実行 × N回] ← キャッシュヒットで入力 95% off
       ↓
[検証: Carbon または Claude] ← 重要サンプルのみ高精度検証
```

- Carbon は 1回のみ使用（$2.00〜5.00）
- Hydrogen で N 回の実作業（キャッシュ最大95% off）
- 最終検証のみ高精度モデル

## 4. オージャストでの活用シナリオ

### 4.1 ブース動画分析パイプライン

**入力**: 展示会ブースのウォークスルー動画（スマホ撮影、30秒〜3分）
**出力**: 什器配置レイアウト / 装飾材の識別 / 改善提案

```
動画アップロード → フレーム抽出（5〜10fpsに間引き）
                → Gemini 4 Hydrogen（implicit cache on 分析プロンプト）
                → レイアウトJSON / 改善コメント
                → （必要時のみ）Claudeで最終品質チェック
```

**コスト試算（月20本の動画分析）**:
- Claude API 全依存: $25〜50/月（入力トークン主体）
- Hydrogen + キャッシュ: **$1〜3/月**（▲94〜96%）

### 4.2 イベント資料一括生成

**入力**: 案件情報（会場サイズ・予算・ブランドガイドライン）
**出力**: 企画書案 / 施工手順書 / 見積書の下書き

```
ブランドガイドライン（固定）→ implicit cache
案件情報（可変）× N件 → Hydrogen で並列生成
```

### 4.3 類似過去事例検索 + 生成

```
過去事例DB（週次更新）→ Gemini 4 Hydrogen でベクトル化+キャッシュ
新規案件 → 類似事例検索（キャッシュヒット）→ 企画草案
```

### 4.4 夜間バッチ処理（キャッシュ最大活用）

```
毎晩04:00:
  1. 新規案件データ読込
  2. 同一プレフィックス（分析手順・出力フォーマット）→ キャッシュ 95% off
  3. Hydrogen で全案件を一括分析
  4. 結果を Drive へ保存
```

Gemini 4 の implicit caching は **明示的 ContextCache.create 不要** なので、キャッシュ有効期限（従来 Claude の 5 分制限）を気にせず夜間バッチで活用できる。

## 5. リスクと対策

| リスク | 対策 |
|--------|------|
| Gemini 4 Hydrogen の品質が Claude Sonnet に劣る（特に日本語とブース専門用語） | 重要な出力（顧客提出用）は Claude で検証。下書き・分析・分類は Hydrogen に任せ、最終品質は従来モデルで担保 |
| implicit caching の実効割引率が常時 95% とは限らない | 実際のキャッシュヒット率を計測しながら移行。ヒット率 80% でも実効 70% 以上の削減 |
| Gemini API の利用制限・レートリミット | 同一プロジェクトキー内での割当管理。複数プロジェクトへの分散も検討 |
| Gemini 4 が日本リージョンで未提供 | us-central1 経由で先行利用。日本語品質は実測して確認 |
| 動画分析のフレーム処理が Gemini 4 の制限（コンテキスト長）に抵触 | フレーム間引き（1fps）、動画分割、重要区間のみ抽出で対応 |
| 社内機密データが Google API に流れる | 現状 Claude API でも同様。汎用的な分析のみ Hydrogen に委譲し、顧客固有情報はマスク |
