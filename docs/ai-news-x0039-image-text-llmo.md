# X-0039: 画像内数字のテキスト化でLLMO — 強み情報をテキストで掲載しAIにサイト情報を認識させる

**AIニュース提案 X-0039**: 画像内に掲載していた合格率・実績数・施工事例数などの数字をテキストとして記載するよう見直す。強み情報をテキストで掲載しAIにサイト情報を認識させる。株式会社オージャストではブース実績や施工事例の数値を画像だけでなく本文テキストで記載しLLMOを試す。

観測日: 2026-11-13

---

## 1. 概要

**LLMO（Large Language Model Optimization）** では、AIがサイトをクロールして情報を引用する際、**画像内のテキストは読み取れない**という根本的な制約がある。ChatGPT / Perplexity / Google AI Overviews / Claude 等のAIは、画像の代替テキスト��alt）や周辺テキストから推測するしかなく、画像内にのみ存在する数値（合格率・実績数・施工面積・価格帯など）はAIの回答生成に一切利用されない。

本提案では、自社サイトに掲載している強みの数値情報を**画像依存からテキスト化**し、AIが引用可能な状態にすることでLLMO効果を高める方法を提示する。

### なぜ画像内数字のテキスト化がLLMOに効くか

| 要素 | 画像内のみ | テキスト化後 |
|------|-----------|-------------|
| AIの読み取り | ✗ 不可（alt属性に依存） | ✓ 全文読み取り・引用可能 |
| 検索エンジンの認識 | △ 限定的（alt / ファイル名） | ✓ 本文としてインデックス |
| 引用時の正確性 | ✗ AIが推測・誤認するリスク | ✓ 正確な数値が伝わる |
| 構造化データ連携 | ✗ 不可能 | ✓ 数値をスキーマに埋め込み可能 |

### 参考: 数値がある情報とない情報のAI回答品質の差

| 指標 | 数値なし | 数値あり | 出典 |
|------|---------|---------|------|
| AI回答での引用率 | 低い（抽象的説明のみ） | 高い（具体的根拠として引用） | LLMO実践事例 |
| ユーザーの信頼度 | 低い | 高い（具体的数値は信頼性向上） | 行動経済学研究 |
| 競合との差別化 | 困難 | 容易（固有の数値は差別化要因） | SEO実践知 |

## 2. 現状分析: オージャストサイトの画像内数字

### 2.1 実測調査（2026-11-13）

株式会社オージャストの2サイト（orgiast.jp / rebooth.co.jp）を調査した結果:

| サイト | 画像内に存在する可能性がある数値 | テキスト化状況 | LLMO影響 |
|--------|-------------------------------|---------------|---------|
| orgiast.jp（イベント） | イベント参加人数・実績数・満足度 | 一部テキストあり（海外実績500以上）だが、大半の実績数値は画像のみ | △ 部分的 |
| rebooth.co.jp（Re:ブース） | 施工面積・価格帯・削減率・リユース回数 | フィルター条件（3m×3m / 50万〜100万円等）はテキストだが、個別実績の数値はなし | ✗ 不十分 |
| orgiast.jp 実績一覧 | 各事例の具体的数値（参加者数・面積・費用） | タイトル・日付のみテキスト、詳細数値は個別ページでも未確認 | ✗ 不十分 |

| 年間制作本数 | 掲載なし | ✗ 未掲載 |

| 項目 | 現在の状態 | 画像/テキスト |
|------|-----------|-------------|

| 価格帯（プラン別） | フィルター条件としてテキストあり | ✓ テキスト |
| 各施工事例の面積・費用 | 未掲載（個別ページでも未確認） | ✗ 未掲載 |

### 2.3 問題点の整理

1. **数値情報そのものが不足**: 画像内に数値があるというより、そもそも数値情報自体がサイトに少ない
2. **強みを裏付ける定量データがない**: 「選ばれる理由」が定性表現のみで、AIが「なぜ選ばれるか」を数値で回答できない
3. **画像代替テキストも未最適化**: 実績画像のalt属性に数値情報が含まれていない可能性が高い
4. **競合との差別化機会損失**: 競合（乃村工藝社・丹青社など）は実績数値をテキストで公開しており、AI引用で優位に立っている

## 4. 実施計画（2週間）

### Phase 1: 現状調査と数値収集（Day 1-3）

1. **既存画像の棚卸し**: 全ページの画像を調査し、画像内に数値が含まれているものを特定
2. **数値データの収集**: 社内資料・実績データからテキスト化すべき数値を収集（施工実績数・リピート率・満足度など）
3. **優先順位付け**: LLMO効果 × 入手容易性で優先度を決定

**ツール**: `tools/ai-query-extract.mjs --llmo --image-audit`（拡張予定）

### Phase 2: テキスト化実装（Day 4-10）

| 優先度 | 修正内容 | 対象 | 期待するLLMO効果 |
|--------|---------|------|-----------------|
| **P0** | トップページ・実績一覧に累計施工実績数をテキスト追加 | orgiast.jp + rebooth.co.jp | 即座にAI引用可能に |
| **P1** | 「選ばれる理由」にリピート率・顧客満足度をテキスト追加 | rebooth.co.jp | 比較クエリでの差別化 |
| **P1** | 各実績ページに施工面積・参加人数・費用帯をテキスト追加 | 両サイト | 個別クエリでの引用率向上 |
| **P2** | 画像のalt属性に数値情報を含める（全画像） | 両サイト | 画像内容のAI認識向上 |
| **P2** | 数値情報を含む構造化データの導入（Organization + 定量データ） | 両サイト | AIの引用判断に影響 |

### Phase 3: 効果測定（Day 11-14）

1. **LLMO定点観測**: ChatGPT / Perplexity / Google AI Overviews / Claude で同一クエリ実行、表示率・引用率を記録
2. **比較**: テキスト化前後の表示率変化を集計（目標: 改善前→改善後 +40%）
3. **レポート**: 結果をドキュメント化し、継続的な数値テキスト化サイクルを確立

## 6. 注意点・リスク

- **数値の正確性と更新**: 公開した数値は最新に保つ必要がある。古い数値は逆効果。定期的な見直しサイクルが必須
- **過剰な数値盛り込み**: 数値が多すぎるとユーザー体験を損なう。重要な数値に絞る
- **競合に数値を知られるリスク**: 公開する数値は競合分析に使われる可能性を考慮。差別化になる数値のみ公開
- **画像内数値の完全除去は不要**: 視覚的訴求力のある画像は残し、補足としてテキストを追加するハイブリッド方式が現実的
- **alt属性の最適化だけでは不十分**: AIによってalt属性の扱いが異なるため、本文テキストでの記載が基本
