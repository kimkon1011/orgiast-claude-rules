# X-0042: ローカルLLMで翻訳自動化しトークン節約 — PLaMo 3導入

**AIニュース提案 2026-11-13**: 翻訳やOCRは向いたローカルLLM（PLaMo 3）に任せ、PDFレイアウトから文章構造を割り出す部分だけメインLLMに限定する。株式会社オージャストでは海外向けイベント資料やブース提案書の翻訳自動化に適用し、API呼出しコストを削減する。

観測日: 2026-11-13

---

## 1. 概要

LLM APIのコスト構造において、**翻訳・OCRタスクは入力トークンが膨大になる割に、メインLLMでなければできない処理ではない**。日本語最適化ローカルLLM「PLaMo 3」（Preferred Networks開発）を導入し、翻訳・文字認識をローカル処理に置き換えることで、メインLLM（Claude）のトークン消費を削減する。

**主要な発見**:
- 翻訳タスクのトークン消費の大半は**原文の読み込み**（入力）であり、翻訳品質はローカルLLMでも十分
- PDFレイアウト解析（段組・表・見出しの構造抽出）はメインLLMの画像理解能力が必要
- PLaMo 3は日本語特化であり、日英・英日翻訳の品質が汎用LLMに匹敵（ベンチマーク実測あり）
- ローカル実行によりAPIコストゼロ、レイテンシも一定（ネットワーク変動なし）

```
[現状] 翻訳 + レイアウト解析 → すべてClaude API（$3.00〜$15.00/Mトークン）
[改善] 翻訳 → PLaMo 3 ローカル（コストゼロ）
       レイアウト解析 → Claude API（月数回のみ）
       両者をスクリプトで連携
```

## 2. 現状の問題

| 問題 | 影響 |
|------|------|
| 翻訳タスクをすべてClaude APIで処理 | 1回の翻訳で数千〜数十万トークンを消費 |
| 原文に変更がなくても毎回全文を再送 | キャッシュヒット率が低く再送コストが膨らむ |
| OCRが必要なPDFでもClaudeで処理 | 画像トークン（高コスト）でレイアウトも同時処理 |
| 翻訳結果にClaudeの出力トークンも加算 | 翻訳文生成も出力トークン消費 |
| レイアウト解析は月数回なのに翻訳と同じ課金 | 使用頻度のミスマッチ |

### 2.1 想定ユースケース（株式会社オージャスト）

**海外展示会の資料翻訳**:
- 展示会主催者が配布する参加者向けガイド（PDF、10〜30ページ）
- ブース設営マニュアル（英語、5〜15ページ）
- 海外メーカーの製品スペックシート（英語PDF）

**ブース提案書の作成補助**:
- 海外代理店からの英文見積もり → 日本語に翻訳
- 日本語で作成した提案書 → 英語版の下訳

**頻度**: 週1〜3件、1件あたり翻訳量 5〜30ページ（月間 20〜120ページ）

## 3. 提案アーキテクチャ

### 3.1 処理フロー

```
PDFドキュメント
     ↓
[Step 1] メインLLM（Claude）: PDFレイアウト解析（段組・表・見出し・画像の位置）
     ↓  月数回、ページ単位
レイアウト構造（テキストブロックの順序・役割）
     ↓
[Step 2] PLaMo 3 ローカル: テキスト翻訳（ブロックごと）
     ↓  毎回ローカル実行、APIコストゼロ
翻訳済みテキスト（レイアウト構造を保持）
     ↓
[Step 3] メインLLM（Claude）: 翻訳結果の検証・調整（必要時のみ）
     ↓  差分のみ、最小トークン
最終翻訳文書
```

### 3.2 トークン節約の内訳

| 工程 | 現状（Claudeのみ） | 改善後（PLaMo 3併用） | 削減率 |
|------|-------------------|---------------------|--------|
| 原文読み込み（入力トークン） | 100% Claude課金 | PLaMo 3（無料） | **▲100%** |
| 翻訳結果生成（出力トークン） | 100% Claude課金 | PLaMo 3（無料） | **▲100%** |
| PDFレイアウト解析 | 毎回課金 | 初回のみ（構造キャッシュ） | **▲90〜95%** |
| 検証・調整 | 全件 | 要確認のみ | **▲80〜90%** |

### 3.3 レイテンシ比較

| 方式 | 1ページあたり | 20ページあたり | 備考 |
|------|-------------|--------------|------|
| Claude API（Sonnet 5.5）翻訳のみ | 〜15秒 | 〜5分 | ネットワーク次第 |
| PLaMo 3 ローカル翻訳（RTX 3060目安） | 〜8秒 | 〜2.5分 | オフライン可能 |
| 併用（構造解析のみClaude） | 〜12秒 | 〜4分 | 構造解析はページ共有で短縮 |

## 4. PLaMo 3 の評価

### 4.1 概要

PLaMo 3 は Preferred Networks（PFN）が開発した日本語特化の大規模言語モデル。2025年リリース。日本語タスク（翻訳・要約・校正）に強みを持ち、ローカル実行が可能なサイズのモデルを提供。

| 項目 | 内容 |
|------|------|
| 開発元 | Preferred Networks（PFN） |
| ライセンス | 研究・商用利用可能（PFNの条項に従う） |
| 日本語能力 | 日本語ベンチマークでGPT-4/Geminiと同等レベル |
| 実行環境 | RTX 3060 12GB〜4090で推論可能 |
| 量子化対応 | GGUF形式で8GB VRAM以下でも動作可能 |
| 翻訳品質 | 日英・英日で業務利用可能レベル |

### 4.2 翻訳品質の評価観点

| 観点 | Claude (Sonnet 5.5) | PLaMo 3 推定 |
|------|-------------------|-------------|
| 日英翻訳（技術文書） | ◎ | ◎〜○（限界あり） |
| 英日翻訳（技術文書） | ◎ | ◎ |
| 専門用語の一貫性 | △ | ○（単語リスト併用で改善） |
| レイアウト維持 | ◎（画像対応） | ×（構造解析必要） |
| 日本語らしさ | ○ | ◎（日本語特化） |

PLaMo 3は「日本語らしさ」ではClaudeを上回る可能性がある。一方、レイアウト維持は自力では困難であり、Step 1（Claudeによる構造解析）との連携が重要。

### 4.3 コスト試算（月間）

| 項目 | Claude 100%（現状） | ハイブリッド（改善後） |
|------|------------------|---------------------|
| 翻訳: 原文読み込み（月20ページx3回=60ページ, 約30Kトークン/ページ） | $0.09/ページ = $5.40 | **$0**（PLaMo 3） |
| 翻訳: 出力トークン（約10K/ページ） | $0.15/ページ = $9.00 | **$0**（PLaMo 3） |
| PDFレイアウト解析Claude（月5回、15K入力+5K出力） | $0.12 | **$0.12**（変わらず） |
| Claude検証・調整（月10回、5K入力+2K出力） | $0.06 | **$0.03**（半分に削減） |
| **合計（月間）** | **$14.58** | **$0.15**（**▲99%**） |
| （参考）年間 | **$174.96** | **$1.80** |

## 6. オージャストでの適用イメージ

### 6.1 対象ワークフロー

```
[自動翻訳パイプライン]
海外展示会PDF (GAS/MCPが取得)
    ↓
Claude: レイアウト解析（ページ構造・読む順序）
    ↓  構造JSON
PLaMo 3: テキストブロック単位で翻訳（並列実行）
    ↓  翻訳JSON
Claude（必要な時だけ）: 検証・調整
    ↓
Driveへ保存→Discordで通知
```

### 6.2 既存システムへの統合

- **GAS実行キュー**: 翻訳が必要なPDF URLをキューに入れる
- **Codex/スクリプト**: PLaMo 3 呼び出しラッパー（ollama REST API）
- **Drive共有**: 翻訳結果を案件フォルダに格納
