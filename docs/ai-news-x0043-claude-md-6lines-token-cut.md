# X-0043: CLAUDE.md6行追加でトークン消費67%削減 — ファイル読取・指示の効率化ルール

**AIニュース提案 X-0043**: CLAUDE.mdに6行のトークン効率化ルールを追加するだけで、1セッションあたりのトークン消費を約67%削減可能。ファイルの丸読みをgrepに置き換え、サブエージェントに要約させ、差分のみ表示し、既知の決定を繰り返さないという単純な指示が、コンテキスト肥大化を根本から抑制する。

観測日: 2026-11-13

---

## 1. 概要

Claude Codeのセッションにおけるトークン消費の大部分は、**入力コンテキスト（ファイル内容・会話履歴・システムプロンプト）** が占める。出力トークンは限られているのに対し、Claudeがファイルを丸ごと読み、既知の決定を再説明し、全履歴を保持し続けることでコンテキストは急速に肥大化する。

本提案では、**CLAUDE.mdに6行の指示を追加するだけ**で、この肥大化を根本から抑制する方法を示す。コード変更不要・追加ツール不要・学習コストゼロで実装可能。

### 1.1 6行のルール

```
# トークン効率化ルール（以下の6行をCLAUDE.mdに追加）
1. ファイルを丸ごと読む前にまずgrepで必要な所だけ読む
2. プロジェクト全体の把握はサブエージェントに任せて要約だけ持ち帰らせる
3. ファイル全体ではなく差分だけ見せる
4. このセッションで決めたことを繰り返さない
5. 作業が変わったら/compactか新しいセッションを提案する
6. 返事は基本短く
```

### 1.2 なぜ6行で67%削減できるのか

| 削減要素 | 削減率（目安） | 仕組み |
|---------|--------------|--------|
| ① ファイル丸読み→grep | −40〜60% | ファイル全体(数百〜数千行)を読まず、必要な行だけ検索 |
| ② サブエージェント委譲 | −10〜20% | 大規模プロジェクト把握を外部委譲、要約のみコンテキストへ |
| ③ 差分のみ表示 | −15〜25% | 全ファイル再表示を避け、変更箇所だけ提示 |
| ④ 既知決定の非反復 | −5〜10% | 前セッションで決まったことを再説明しない |
| ⑤ セッション分割 | −10〜15% | 肥大化したコンテキストをリセット |
| ⑥ 短文返答 | −3〜5% | 不要な前置き・解説を削減 |
| **合計効果** | **−60〜75%（中央67%）** | 相乗効果により単純合計以上の削減 |

## 2. 各ルールの詳細と効果

### 2.1 ルール①: grep優先（ファイル丸読み防止）

**指示文**: 「ファイルを丸ごと読む前にまずgrepで必要な所だけ読む」

**問題**: Claudeは問題解決のためにファイル全体をReadツールで読み込む習慣がある。300行のファイルを読めば300行分のトークンが入力に加わる。

**対策**: `Grep` ツールを優先させる。必要なシンボル・キーワードだけを検索し、該当行だけを読む。

**効果**:
- 300行のファイル: 全読取=約2,400トークン → grep(5行)=約40トークン → **−98%**
- 1ファイルあたりの平均節約: 1,500〜5,000トークン
- 1セッションで10〜30ファイル読むとして: 15,000〜150,000トークン削減

### 2.2 ルール②: サブエージェント委譲（探索の外部化）

**指示文**: 「プロジェクト全体の把握はサブエージェントに任せて要約だけ持ち帰らせる」

**問題**: プロジェクト全体を把握しようと多くのファイルを読むと、大量のトークンを消費する。

**対策**: 探索専用のサブエージェント（`Explore` や `general-purpose`）に調査を委譲し、結果だけを要約として持ち帰らせる。

**効果**:
- 20ファイルの探索（〜50,000トークン）→ サブエージェントに委譲（消費は別セッション）→ **親セッションでは要約のみ（〜500トークン）**
- サブエージェントの消費は親に加算されないため、見かけのトークン消費を大幅削減

### 2.3 ルール③: 差分のみ表示

**指示文**: 「ファイル全体ではなく差分だけ見せる」

**問題**: コードレビューや変更確認時にファイル全体を出力すると、変更がない部分も含めて全トークンを消費する。

**対策**: `git diff` や変更行のみを表示する。

**効果**:
- 500行のファイルで5行変更: 全表示=4,000トークン → 差分のみ=40トークン → **−99%**

### 2.4 ルール④: 既知決定の非反復

**指示文**: 「このセッションで決めたことを繰り返さない」

**問題**: 同じセッション内で過去の決定・調査結果を再説明するクセがあり、同じ情報が複数回コンテキストに現れる。

**対策**: 一度決定したことは参照のみで再説明しない。

**効果**:
- 1決定あたり200〜500トークンの重複削減
- セッション後半ほど効果が大きい（累積）

### 2.5 ルール⑤: セッション分割

**指示文**: 「作業が変わったら/compactか新しいセッションを提案する」

**問題**: 1セッションで複数の異種タスクを扱うと、過去タスクのコンテキストが残ったまま次のタスクを処理する。

**対策**: 作業が変わったら `/compact` で要約するか、新しいセッションを提案する。

**効果**:
- タスク切替時に古いコンテキストの50〜80%を削減
- 新しいセッションなら100%削減（ゼロベース）

### 2.6 ルール⑥: 短文返答

**指示文**: 「返事は基本短く」

**問題**: Claudeは丁寧な前置き・説明・要約・次のステップの列挙などを出力し、出力トークンを消費する。

**対策**: 前置きを省き、結論を簡潔に述べる。

**効果**:
- 1応答あたり100〜300トークン削減
- 1セッション20〜100応答で2,000〜30,000トークン削減

## 3. 実装: CLAUDE.mdへの追加方法

### 3.1 追加する6行

CLAUDE.mdの末尾、または既存のルールセクションの最後に以下を追加:

```markdown
### トークン効率化（追加ルール）
- **🔴 ファイルを丸ごと読む前にまずgrepで必要な所だけ読む** — Grepツールを優先し、Readは必要な範囲のみ
- **🔴 プロジェクト全体の把握はサブエージェントに任せて要約だけ持ち帰らせる** — 探索はExplore/general-purposeへ委譲
- **🔴 ファイル全体ではなく差分だけ見せる** — 変更行のみ表示、git diffを活用
- **🔴 このセッションで決めたことを繰り返さない** — 既知決定は参照のみ
- **🔴 作業が変わったら/compactか新しいセッションを提案する** — コンテキスト肥大化を防止
- **🔴 返事は基本短く** — 前置き・解説を省略
```

## 4. 株式会社オージャストでの適用

### 4.1 現在のCLAUDE.md構成

既存のCLAUDE.mdは高度に構造化されており、トークン効率化ルールは独立したセクションとして追加可能。

### 4.2 予想される効果

オージャストのCLAUDE.mdは約200行・15,000文字以上と大規模であり、セッション起動時のシステムプロンプトとして常に読み込まれる。ここにトークン効率化ルールを追加することで:

1. **ファイル丸読み防止**: 経理データ・freee API応答・GASコードの全読取を防止（特にkeiri-hubプロジェクトで効果大）
2. **サブエージェント委譲**: 複数アカウントのGmail調査・freee API探索をサブエージェントに委譲
3. **差分表示**: PRレビュー時の全ファイル再表示を防止
4. **既知決定の非反復**: 経理ルール・freee設定・GAS構成など、過去セッションで決定済みの事項を再説明しない
5. **セッション分割**: 経理処理・開発・調査が混在するセッションを適切に分割
6. **短文返答**: 日次報告・定期確認を簡潔に

### 4.3 適用順序

1. CLAUDE.mdに6行を追加（所要時間: 1分）
2. 1週間のトークン消費量を計測（GitHub API / Anthropic APIログ）
3. 効果を検証し、必要に応じてルールを調整

## 6. リスクと対策

| リスク | 対策 |
|--------|------|
| grepのみではファイル構造を把握できない | 最初の1回のみファイルの構造（関数一覧・クラス定義）を読むことを許容 |
| サブエージェント委譲のオーバーヘッド | 小規模ファイル（50行未満）は直接読んでよいルールを追加 |
| 短文返答で情報不足 | 完了報告・検証結果は従来通りの詳細さを維持 |
| セッション分割で文脈を失う | /compactで引き継ぎ情報を要約して保持 |
| ルールを守らないモデルもある | 各ルールに🔴（最重要）マークを付けて優先順位を明示 |
