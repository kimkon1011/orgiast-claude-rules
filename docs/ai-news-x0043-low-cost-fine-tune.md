# X-0043: 小型モデル低コストファインチューン — 9Bモデルをunder $100でファインチューン

**AIニュース提案 X-0043**: Qwen2.5 7B/9Bクラスの小型オープンモデルを、Unsloth + QLoRAで$100未満のコストでファインチューンし、特定ドメイン（展示会ブースデザイン・イベント企画）に特化した軽量生成モデルを構築する。株式会社オージャストでは過去のブース制作事例・イベント企画データでファインチューンし、新規ブースデザイン案やイベント進行生成に試用して大型モデル比のコスト削減を実測する。

観測日: 2026-11-15

---

## 1. 概要

### 1.1 背景

大規模言語モデル（GPT-6, Claude Opus 5, Grok 4等）は高品質な出力を生成するが、**1回の推論あたりのコストが高い**。特に展示会ブースのデザイン案生成やイベント企画の進行表作成など、**ドメイン特化・反復的な生成タスク**では、毎回フロンティアモデルを呼ぶ必要はない。

一方、Qwen2.5 7B/9Bクラスの小型オープンモデルは：
- 1回の推論コストがフロンティアモデルの **1/50〜1/100**
- 量子化（Q4_K_M）すれば **6〜8GB VRAM** で動作
- オープンウェイトのため **データ漏洩リスクなし**
- LoRA/QLoRAファインチューンで **ドメイン知識を注入可能**

### 1.2 提案の核

**Qwen2.5 7B/9BをQLoRAファインチューンし、展示会ブース制作・イベント企画に特化させて、フロンティアモデル同等の品質を安価な推論で実現する。**

| 項目 | 値 |
|------|-----|
| ベースモデル | Qwen2.5-7B-Instruct / Qwen2.5-Coder-7B |
| ファインチューン手法 | Unsloth QLoRA（4ビット量子化LoRA） |
| 学習データ | オージャスト過去事例50〜200件 + 設計パターン |
| 推定トレーニングコスト | **$8〜$50**（GPU時間貸し） |
| 推定推論コスト（API比） | **1/50〜1/100** |
| ハードウェア要件 | T4 16GB（Colab無料可）〜 A100 80GB |
| 目標 | ブースデザイン案・イベント進行生成でフロンティアモデルの85%以上の品質を達成 |

## 2. なぜ9Bモデルなのか

### 2.1 モデルサイズと必要VRAM

| モデル | パラメータ | 量子化 | VRAM | 推論速度 | 品質 |
|--------|-----------|--------|------|---------|------|
| Qwen2.5-0.5B | 0.5B | Q4 | 1GB | 超高速 | 低 |
| **Qwen2.5-7B** | **7B** | **Q4_K_M** | **5〜6GB** | **高速** | **実用域** |
| Qwen2.5-14B | 14B | Q4_K_M | 10〜12GB | 中速 | 高 |
| Qwen2.5-32B | 32B | Q4_K_M | 20〜24GB | 低速 | 非常に高い |
| Qwen2.5-72B | 72B | Q4_K_M | 45〜50GB | 非常に低速 | 最高 |

**7B/9Bがスイートスポット**:
- T4 GPU（16GB、Colab無料枠）でQLoRA学習可能
- Mac Mini M6（32GB）で推論可能（6〜8 tok/s）
- 1回の推論コストが極小（クラウドAPIでも$0.0001/回未満）
- 特定ドメインの知識注入で品質が大きく向上する

### 2.2 なぜファインチューンが必要か

ベースのQwen2.5-7Bは汎用モデルであり、展示会ブースの専門知識（トレンド・素材・レイアウトパターン・施工方法・予算感覚）を持たない。ファインチューンにより：

1. **専門用語の理解**: トラス構造、アルミフレーム、バックウォール、アイキャッチャー等
2. **フォーマット習得**: ブース企画書の定型フォーマット、見積項目、図面記号
3. **デザインパターン**: 過去の成功事例から、よく使われるレイアウト・配色・素材の組み合わせ
4. **制約条件の理解**: 会場ルール、予算範囲、施工可能日数

## 5. 技術詳細

### 5.1 Unsloth QLoRA設定（推奨）

```python
from unsloth import FastLanguageModel
import torch

model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="Qwen/Qwen2.5-7B-Instruct",
    max_seq_length=2048,
    dtype=torch.bfloat16,  # T4の場合は torch.float16
    load_in_4bit=True,
)

model = FastLanguageModel.get_peft_model(
    model,
    r=16,  # LoRAランク
    target_modules=["q_proj", "v_proj", "k_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj"],
    lora_alpha=16,
    lora_dropout=0,
    bias="none",
    use_gradient_checkpointing="unsloth",
    random_state=42,
    use_rslora=False,
    loftq_config=None,
)
```

## 7. リスクと対策

| リスク | 確率 | 影響 | 対策 |
|--------|------|------|------|
| データ不足で品質不足 | 中 | 大 | 50件のPoCで検証→拡張判断。データ拡張には合成データ生成 |
| オーバーフィッティング | 中 | 中 | 学習エポック制限（3以下）、評価セットでの早期停止 |
| ベースモデルの性能限界 | 低 | 中 | 7Bで不十分なら14B/32Bへ段階的アップグレード |

| モデル量子化による品質劣化 | 低 | 小 | Q4_K_Mは品質低下1〜3%に抑制可能 |
| 現在のAPI支出が少額でROIが小さい | 中 | 小 | **コスト削減より能力拡張と自立性が主目的**。API依存低減・データ漏洩防止・オフライン対応も価値 |

## 8. オージャストでの適用シナリオ

### 8.1 ブースデザイン案生成（最優先）

**現状**: 新規ブースのデザイン案は人間のデザイナーが1案あたり2〜4時間かけて作成。フロンティアAIに生成させると1案$0.05〜$0.50。

**FT後**: 過去事例を学習したモデルが、与えられた条件（企業・業種・予算・サイズ）から即座にデザイン案を生成。人間デザイナーがブラッシュアップ。

**期待効果**: 初期案作成時間を80%削減（2〜4時間→20〜30分）

### 8.2 イベント進行表生成

**現状**: イ��ントのタイムライン・タスク一覧を毎回手動作成。

**FT後**: 過去のイベント進行パターンを学習したモデルが、会期・規模・会場から進行表を自動生成。

### 8.3 見積原案生成

**現状**: 見積はテンプレートから手動調整。

**FT後**: ブース仕様から標準単価を適用した見積原案を自動生成。人間が確認・調整。

**現状**: 見積書の適正チェックに時間がかかる。
