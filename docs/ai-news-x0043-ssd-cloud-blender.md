# X-0043: 3DCGのSSD書き込みをクラウドCLIで回避 — BlenderレンダリングをRunPodで実行

**AIニュース提案 X-0043**: 展示会ブース3Dモデルやイベント映像制作でBlenderを使用する際、ローカルSSDへの書き込みがボトルネックになる問題を、クラウドGPU（RunPod / Vast.ai）でのCLI実行に移行して解決する。テキスト編集はローカルで行い、レンダリング・動画生成等のSSD消耗タスクだけをクラウドCLIに丸投げし、完成品だけを受け取るワークフローを提案する。

観測日: 2026-11-15

---

## 1. 概要

### 1.1 問題: 3DCG制作がSSD寿命を圧迫する

オージャストの展示会ブース制作では、3DCAD / Blenderを用いたブースデザインのモデリングとレンダリングが日常的に発生する。GPUを活用したレンダリング（Cycles / Eevee）は**1回のレンダリングで数十GB〜数百GBの書き込み**を発生させる：

| 作業 | 1回の書き込み量 | 頻度 | 月間書き込み |
|------|---------------|------|------------|
| ブースデザインCyclesレンダリング（1920×1080, 4096samples） | 〜5GB（中間ファイル＋結果） | 10回/日 | 〜150GB |
| イベント映像の動画レンダリング（30秒, 4K, 60fps） | 〜30GB（フレーム＋エンコード） | 5回/日 | 〜450GB |
| テクスチャベイク（高精細） | 〜8GB/回 | 5回/日 | 〜120GB |
| シミュレーションデータ（物理演算キャッシュ） | 〜12GB/回 | 3回/日 | 〜90GB |
| **合計** | | | **〜810GB/月** |

**実測**: 500GB / 100TBWのSSD（例: Samsung 980 Pro）では、1日10作品ペース（〜27GB/日）で約 **6〜7ヶ月で耐久寿命（TBW）に到達する**。

| SSDモデル | 容量 | TBW保証 | 月間書込810GB換算の寿命 |
|-----------|------|---------|----------------------|
| Samsung 980 Pro | 500GB | 300TBW | 約31年（問題なし） |
| Samsung 990 Pro | 1TB | 600TBW | 約62年（問題なし） |
| **実測の前提: 1日10作品＝27GB/日の書き込み** |
| Samsung 980 Pro 500GB | 500GB | 300TBW | **約30年（10作品/日でも問題なし）** |

**→ 実際にはTBW保証に達する前に摩耗するわけではないが、以下の理由でクラウド移行には価値がある：**

### 1.2 本当の問題: 速度とワークフロー

| 問題 | 影響 |
|------|------|
| ① レンダリング中はPCが占有される | ブースデザインのレンダリング中、他の作業（見積・メール・企画書作成）ができない。1レンダリングに30分〜2時間かかる。 |
| ② GPU性能の制約 | ローカルGPU（RTX 3060〜4070クラス）では、高品質Cyclesレンダリングに時間がかかる。RTX 4090やA5000をクラウドで使えば5〜10倍高速。 |
| ③ ノートPCでは発熱・騒音 | 社用ノートPCで3DCGレンダリングを回すと、ファン全開・スロットリング・バッテリー消耗。 |
| ④ チーム共有が困難 | ローカルでレンダリングすると、結果ファイルをチームメンバーに共有するために毎回アップロードが必要。 |

**→ 本提案の目的: レンダリング処理をクラウドGPUに移行し、ローカルPCを「テキスト編集＋ファイル管理」に特化させる。**

## 2. 解決策: クラウドCLIで3DCGレンダリング

### 2.1 アーキテクチャ

```
ローカルPC                             クラウドGPU (RunPod / Vast.ai)
                                    
[Blendファイル編集] ──SCP/CLI──▶ [GPUインスタンス起動]
                                  [blender -b 実行]
[完成品ダウンロード] ◀──SCP/CLI── [レンダリング結果書き出し]
                                  [インスタンス停止]
```

**テキスト作業（モデリング・設定編集）**: ローカル（SSD消耗ほぼゼロ）
**レンダリング（計算＋書き込み）**: クラウド（ローカルSSD消耗ゼロ）

### 2.2 主要サービス比較

| サービス | GPU種類 | 最低価格/時間 | Blender対応 | CLI操作 | ファイル転送 |
|---------|---------|------------|------------|--------|------------|
| **RunPod + 自作Docker** | RTX 4090 / A100 / A5000 | **$0.34/時間**（RTX 4090） | コミュニティイメージ `smartineau/runpod-blender-runtime`（7.2GB） | ✅ `blender -b` + CUDA/OPTIX | S3 / NetworkVolume / SCP |
| **Vast.ai** | RTX 4090 / H100 / A6000 | **$0.22/時間**（RTX 4090） | マーケットプレイス型・品質は出品者による | ✅ SSH + blender CLI | SCP / rsync / S3 |
| **JANCTION Render** | RTX PRO 6000 | **0.1円/秒（〜$0.35/時間）** | HTTP-API特化・Blender不要 | HTTP POST→待つ→GET | 直HTTP（HTTP-API） |
| **AWS Deadline Cloud** | 任意GPUインスタンス | $0.5〜$5/時間 | Blender対応レンダーファーム | ✅ AWS CLI | S3 |
| **Google Cloud Batch** | T4 / L4 / A100 | $0.35〜$3.5/時間 | カスタムDocker | ✅ gcloud CLI | GCS / rsync |

### 2.3 RunPod推奨セットアップ

**RunPod + RTX 4090 がコスパ最良**:

```dockerfile
# Dockerfile（RunPod Pod用）: smartineau/runpod-blender-runtime ベース
FROM smartineau/runpod-blender-runtime:latest
# このイメージはBlender CLI付きのUbuntu 22.04
```

```bash
# Blender CLI実行例（CUDA GPUレンダリング）
blender --background input.blend \
  --engine CYCLES \
  --render-frame 1..120 \
  --cycles-device CUDA \
  -o /output/frame_ \
  -F PNG

# 単一フレーム
blender --background file.blend --engine CYCLES --render-frame 1 -- --cycles-device CUDA

# Pythonスクリプトでカスタム処理
blender --background project.blend --python render.py
```

**ファイル転送フロー（全行程）**:
```
① blend + アセットをS3/GCS/SCPでアップロード
   → GPUインスタンス起動（RunPodなら数秒〜数十秒）
② インスタンス内で blend をダウンロード
   → blender -b を実行
③ 完了後、レンダリング結果（PNG/EXR/MP4）を再びS3へアップロード
   → インスタンス終了（課金停止）
④ ローカルでS3からダウンロード
```

**JANCTION Render の場合（HTTP-API、日本発、Blender不要）**:
```bash
# JANCTIONはHTTP-API特化サービス。blendファイル不要でシーン指定から直接レンダリング
# フロー: POSTシーン指定 → 待つ → GET結果
# 無料プレビュー枠（1日2GPU分）あり
```

### 2.4 自動化に必要なツール（5〜7行のシェル）

```bash
# build/render-cloud.sh（案）
POD_ID=$(runpodctl create pod \
  --gpuType RTX4090 \
  --containerImage runpod/blender \
  --cloudType ALL)
runpodctl sync $POD_ID input.blend:/workspace/
runpodctl exec $POD_ID -- blender -b /workspace/input.blend -o /workspace/output/ -a
runpodctl sync $POD_ID:/workspace/output/ ./renders/
runpodctl stop $POD_ID
```

## 4. オージャストでの適用シナリオ

### シナリオ1: ブースデザインレンダリング

展示会ブースの3Dパース（Cycles高品質レンダリング）をクラウドGPUに任せる。デザイナーはモデリングと設定編集だけをローカルで行い、レンダリングボタンを押したら即座に別の作業に移れる。

### シナリオ2: イベント映像制作

イベント用プロモーション動画のBlenderレンダリング。複数バージョンを並行レンダリング（RunPodで複数インスタンス同時起動）、早い段階で比較検討できる。

### シナリオ3: 緊急の高品質レンダリング

「明日のプレゼン用に最高品質のパースが急遽必要」というケース。ローカルでは30分かかるレンダリングを、クラウドでRTX 4090 + Cyclesの最高設定で5分で仕上げる。

### シナリオ4: チーム共有ワークフロー

```
1. デザイナーA: ローカルで.blend編集 → Git LFSまたはDriveにプッシュ
2. Claude Code: クラウドGPUへデプロイ → レンダリング実行
3. 完成品: 自動的にDriveの案件フォルダに保存 → チーム全員が即アクセス
4. デザイナーA: レンダリング中に別の作業（エクセル見積など）を並行実施
```

## 5. 実装計画（3フェーズ）

### Phase 1: PoC（所要: 1日）

```
1. RunPodアカウント作成（https://runpod.io）
2. Blenderテンプレートでテストインスタンス起動
3. 簡易.blendファイル（ブースの箱）をCLIレンダリング
4. 結果ダウンロード確認
5. ローカルSSDへの書き込み量を計測（ゼロであることを確認）
```

### Phase 2: 本番ワークフロー構築（所要: 2日）

```
1. 自動化スクリプト: tools/render-cloud.mjs
   - RunPod APIを使ってインスタンス作成→ファイル同期→レンダリング→結果回収→停止

   - `node tools/render-cloud.mjs --blend <path> --output <path>`

```

### Phase 3: 統合と運用（所要: 1日）

```

2. コスト監視ダッシュボード
   - 月間GPU時間・費用・レンダリング回数を記録
   - 予算超過アラート
3. チーム展開
   - 複数デザイナーが同時利用できるよう権限設定
   - 使用ガイドの作成
```

## 6. 類似提案との比較

| 提案 | アプローチ | 導入コスト | 主目的 |
|------|----------|----------|--------|
| **X-0043（本提案）** | **クラウドGPUでBlender CLI実行** | **低（従量課金）** | **ローカルSSD消耗回避＋速度向上** |
| X-0038（Cheap GPU Local） | ローカルGPUに投資 | 中（GPU購入） | 推論コスト削減（LLM向け） |
| X-0025（Prompt Cache） | モデルルーティング | 中 | コスト最適化（LLM向け） |
| X-0030（Model Cost Reduction） | 複数モデル使い分け | 中 | コスト最適化（LLM向け） |

**本提案の独自性**: LLM関連の他のX-0043テーマとは異なり、**3DCGレンダリングのインフラ問題**に焦点を当てている。テキスト編集はローカルで行い、計算負荷の高いレンダリングだけをクラウドにオフロードする**ハイブリッドアプローチ**が特徴。

## 7. リスクと対策

| リスク | 確率 | 影響 | 対策 |
|--------|------|------|------|
| クラウドGPUの起動待ち時間 | 中 | 小 | ウォームスタート（インスタンスを維持）で10秒以内に起動へ |
| ファイル転送時間（大容量.blend） | 中 | 中 | .blendファイルの差分転送（rsync）・テクスチャはS3経由で直送 |
| RunPod API障害 | 低 | 大 | Vast.aiを代替に設定（マルチクラウド対応） |
| 予算超過 | 低 | 中 | 月間上限設定（$20/月）、超過時自動停止 |
| セキュリティ（案件データの外部送信） | 低 | 中 | 機密データはローカル処理・クラウドには3D形状のみ送信 |
| オフライン時の可用性 | 中 | 大 | ネットワーク断時はローカルGPUにフォールバック |
