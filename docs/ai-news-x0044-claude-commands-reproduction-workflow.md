# X-0044: Claude公式20コマンドの再現ワークフロー — /init→/run→/code-review→/verify を連鎖

**AIニュース提案 2026-11-13**: Claude Codeが標準搭載する20のスラッシュコマンドを「プロジェクト起動→アプリ実行→コードレビュー→検証」の順に連鎖させることで、開発サイクル全体を1セッション内で再現可能にするワークフロー。株式会社オージャストでは展示会・イベント用ウェブサイトの開発時にこれらのコマンドを使い、ブース予約フォームなどのUIをブラウザ連携でテスト・最適化する。

観測日: 2026-11-13

## 1. 概要

Claude Codeは `/init`・`/run`・`/code-review`・`/verify` をはじめとする**20のスラッシュコマンド**を標準搭載している。それぞれが独立した機能として設計されているが、これらをワークフローの一部として順序立てて使うことで、開発サイクル全体を1セッション内で完結させることができる。

本提案では、20コマンドの中でも開発ワークフローの中核をなす4コマンドを連鎖させる方法と、それを展示会・イベントサイトの開発に適用する実践パターンを解説する。

### 1.2 4コマンド連鎖ワークフロー

開発サイクルの中核をなす4コマンドを以下の順序で連鎖させる:

```
/init ─→ /run ─→ /code-review ─→ /verify
  │         │          │              │
  │         │          │              └── 合格 → 完了報告
  │         │          │                   │
  │         │          └── 修正 → /run ←──┘
  │         │                            （再起動）
  │         └── エラー → 修正 → /run（再起動）
  │
  └── プロジェクトテンプレート → 修正 → /init（再実行）
```

1. **`/init`**: プロジェクトガイド（CLAUDE.md）を作成し設計意図を記録
2. **`/run`**: アプリケーションを起動して実際の動作を確認
3. **`/code-review`**: コード全体のバグ・改善点を検出
4. **`/verify`**: 単体テスト・E2Eテストを実行し合格を確認

この連鎖により「設計→実装→レビュー→検証」のサイクルがコマンド1つずつで完結する。

## 2. 各コマンドの詳細と連鎖手順

### 2.1 `/init`: プロジェクトガイド作成

**機能**: プロジェクトの CLAUDE.md を作成し、リポジトリの目的・構成・ルールを定義する。

**効果的な使い方**:
- 新規プロジェクトの最初に実行する
- `/init` 実行後にブラウザ連携（`/run`）の設定を追記すると次工程がスムーズ

**オージャストでの活用**: 展示会・イベントサイト用リポジトリで最初に `/init` を実行し、CLAUDE.md にフォーム仕様・テスト方針・デザインルールを記録する。

### 2.2 `/run`: アプリケーション起動

**機能**: プロジェクトの開発サーバを起動し、ブラウザプレビューを提供する。

**効果的な使い方**:
- `/init` の直後に `/run` で起動確認
- 修正後も `/run`（再起動）で変更を即時確認
- ポート競合時は自動的に別ポートでフォールバック

**オージャストでの活用**: 展示会ブース予約フォームのローカル開発サーバを起動し、フォーム入力→送信→確認画面のフローをブラウザで動作確認する。

### 2.3 `/code-review`: コードレビュー

**機能**: 現在の変更を分析し、バグ・改善点・ベストプラクティス違反を検出する。

**効果的な使い方**:
- 実装完了後に必ず `/code-review` を実行
- 検出された修正はすぐに適用し、再レビュー

**オージャストでの活用**: フォームバリデーション・レスポンシブ対応・アクセシビリティの観点でレビューを実行。展示会予約フォームの入力エラー処理・スマホ表示・タブ順序をチェック。

### 2.4 `/verify`: テスト検証

**機能**: プロジェクトのテストスイートを実行し、すべてのテストが通過することを確認する。

**効果的な使い方**:
- `/code-review` の修正後に実行
- テストが通らない場合は `/run` で実動作確認と並行してデバッグ

**オージャストでの活用**: フォーム入力→バリデーション→確認画面→送信完了の一連のテストを自動実行し、UI変更による後退バグを防止する。

## 3. ブラウザ連携によるUIテスト最適化

### 3.1 `/run` のブラウザ機能

`/run` は開発サーバの起動に加えて、ブラウザ操作機能を提供する:

```javascript
// 例: ブース予約フォームの自動テスト
// 1. /run で開発サーバ起動
// 2. ブラウザでフォームにアクセス
// 3. 各フィールドに入力して送信
// 4. バリデーションメッセージの表示を確認
// 5. 正常送信時の確認画面遷移を確認
```

### 3.2 テスト自動化との連携

| コマンド | 役割 | ブラウザ連携 |
|---------|------|------------|
| `/init` | プロジェクト定義 | — |
| `/run` | サーバ起動＋プレビュー | ブラウザで実UI確認 |
| `/code-review` | 静的解析 | — |
| `/verify` | 自動テスト実行 | ヘッドレスブラウザでE2Eテスト |

## 4. 株式会社オージャストでの適用

### 4.1 展示会・イベントサイト開発

オージャストの展示会用ウェブサイトの開発では、以下のワークフローが標準化できる:

```
ステップ0: git clone <リポジトリ>
ステップ1: /init        → CLAUDE.md作成、プロジェクト構成確認
ステップ2: /run         → 開発サーバ起動、ブラウザでトップ表示確認
ステップ3: 実装（フォーム・デザイン・コンテンツ）
ステップ4: /run（再起動）→ 変更をブラウザで確認
ステップ5: /code-review  → バグ・改善点の検出と修正
ステップ6: /verify       → 全テスト通過確認
ステップ7: 完了報告
```

### 4.2 ブース予約フォームの開発パターン

ブース予約フォームのようなUI開発では、ブラウザ連携を活用して:

1. **`/run`** でフォームを表示
2. **実データ入力**: 各フィールドに実際の値を入力して送信フローを確認
3. **異常系テスト**: 必須項目未入力・不正形式・最大文字数超過をテスト
4. ****`/code-review`でエラー処理の網羅性を確認
5. **`/verify`** で単体テスト＋E2Eテストを一括実行

### 4.3 既存サイトへの適用

既存の展示会サイトリポジトリでも、CLAUDE.mdの追加から始める:

```
/claude-code があるディレクトリで
  /init         → 既存プロジェクトのCLAUDE.md更新
  /run          → 既存アプリの起動確認
  /code-review  → 既存コードの問題点洗い出し
  /verify       → 既存テストの実行・状態把握
```

## 6. リスクと対策

| リスク | 対策 |
|--------|------|
| `/run` の起動に失敗する | `package.json` の start スクリプトを事前確認 / `/doctor` で環境診断 |
| ブラウザが使えない環境 | `/verify` のE2Eテスト（ヘッドレスモード）で代替 |
| コマンドの組み合わせを忘れる | CLAUDE.mdにワークフロー手順を記録 |
| レビュー指摘が多すぎて作業停滞 | `/effort low` で簡易レビュー→修正後 `/effort high` で最終レビュー |
| テストが通らない | `/code-review` で原因箇所を特定 → 修正 → `/run` で動作確認 → `/verify` で再実行 |
