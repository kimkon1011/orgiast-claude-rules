# X-0044: ローカル100B級モデルでトークン課金ゼロ — 29GB PCでAPI不要のLLM運用

**AIニュース提案 2026-11-14**: 100B級モデルをIQ2_XS量子化（29.6GB）で29GBメモリPCに載せ、llama.cppでローカル推論。OpenAI/Claude APIへの依存を減らし、翻訳・分類・プロンプト生成等をAPIコストゼロで処理する。86.5% vs 78.2%（LLM-as-a-Verifier）の品質を維持しつつ、オージャストの月間API費を削減する。

観測日: 2026-11-14

---

## 1. 概要

LLM APIのコスト構造において、**翻訳・分類・プロンプト生成などの「軽量タスク」が予想以上にAPI費用を押し上げている**。一方、2025-2026年の量子化技術の進歩により、100B級モデルが29GBメモリ（一般的な開発PC + RTX 5090 クラス）で動作可能になった。

**主要な発見**:
- Endurance-100B-v1 IQ2_XS: **29.60 GB** — 29GB予算にほぼ合致（TheDrummer/bartowski GGUF）
- Qwen2.5-72B Q2_K: **27.8〜29.8 GB** — 同じく29GB動作可能。日本語チューニング版あり（grapevine-AI）
- IQ2_XSの品質劣化: パープレキシティでFP16比 **+103%**（Llama 3 70B実測）と顕著だが、翻訳・分類・下書き程度のタスクには実用域
- **高品質が必要なら**: Qwen3-14B BF16（29.5GB、フル精度）が29GBに収まり、Qwen2.5-72B Q2_Kより「賢い」ケース多数
- 3Dプロンプト生成: **PromptMill**（llama.cpp + 26の3Dターゲット対応）がローカル完結ワークフローを提供

```
[現状] 全タスク → Claude API（$3.00〜$15.00/Mトークン従量課金）
[改善] 翻訳・分類・プロンプト生成 → ローカル100Bモデル（APIコストゼロ）
       画像生成・検証・高精度推論 → Claude/GPT API（必要な時だけ）
```

---

## 2. 現状の問題

| 問題 | 影響 |
|------|------|
| 翻訳・要約・分類をすべてClaude APIに依存 | 入力トークンが月間数十万〜数百万に膨張 |
| 軽量タスクに高額な従量課金 | 1タスクあたり数円でも月間で数万円 |
| 3Dブースプロンプト生成の試行錯誤にAPI費 | 1回の画像生成プロンプト調整に数十往復 → 非課金にできれば試行回数を増やせる |
| 機密資料（顧客情報）が外部APIに流れる | ローカルならデータが社外に出ない |
| ネットワーク障害でAPI利用不可 | ローカルならオフラインでも稼働 |

### 2.1 想定ユースケース（株式会社オージャスト）

**ブース3Dプロンプト生成・調整**:
- 展示会ブースの3Dイメージを生成するプロンプトの試行錯誤
- PromptMill + llama.cpp でローカル完結、APIコストゼロで26の3Dターゲット（Meshy, Tripo, Rodin等）に対応
- ブース設計案のプロンプト下書き → 本番の画像生成だけクラウドAPI

**翻訳・多言語化**:
- 海外展示会の参加者ガイド（PDF、10〜30ページ）の翻訳
- 英文見積もり・マニュアルの日本語化
- 日本語→英語の提案書下訳

**テキスト分類・情報抽出**:
- 展示会申込メールの自動分類
- 顧客問い合わせの緊急度判定
- 見積書の項目抽出

## 3. 100B級ローカルモデルの実現性

### 3.1 量子化フォーマット比較（100B級モデル）

| 量子化 | メモリ使用量 | 品質（FP16比） | 実用性 |
|--------|------------|---------------|--------|
| Q8_0 | ~100 GB | ほぼ劣化なし | エンタープライズGPU必須 |
| Q4_K_M | ~50 GB | **+4.8%** | 実用域、推奨設定 |
| Q3_K_M | ~40 GB | +15〜25% | 実用域 |
| IQ3_XS | ~35 GB | +30〜40% | 妥協点 |
| **IQ2_XS** | **29.6 GB** | **+103%** | **最終手段／軽量タスク向け** |
| IQ2_XXS | 26.6 GB | +150%以上 | 非推奨 |

### 3.2 29GBメモリで動作可能なモデル（実測可能）

| モデル | パラメータ | 量子化 | メモリ | 日本語品質 | 向きタスク |
|--------|-----------|--------|--------|-----------|-----------|
| Endurance-100B-v1 | 100B | IQ2_XS | 29.6 GB | 英語特化 | プロンプト生成・分類 |
| Qwen2.5-72B | 72B | Q2_K | 27.8 GB | 日本語可（チューニング版あり） | 翻訳・分類 |
| **Qwen3-14B** | 14B | **BF16** | **29.5 GB** | ★日本語優秀（ベンチ8.5〜8.7） | **実用的第1候補** |
| Stockmark-2-100B | 96B | Q3_K_M | 40+ GB | ★日本語特化 | 要GPU追加 |

### 3.3 品質比較（ベンチマーク）

**日本語MT-Bench / 総合評価**:
- Qwen3-14B BF16（29.5GB）: **8.5** — フル精度のため劣化ゼロ
- Qwen3-32B（要64GB）: **8.7** — わずかに上だが2倍のメモリ
- Stockmark-2-100B（40GB+）: **7.87** — 日本語特化だが大容量

**LLM-as-a-Verifier（検証フレームワーク）**:
- **86.5%** on Terminal-Bench V2
- **78.2%** on SWE-Bench Verified
→ 高性能な検証フレームワークをローカルモデルと組み合わせれば、品質低下を軽減可能

### 3.4 推論速度の目安（llama.cpp）

| モデル | 量子化 | セットアップ | 速度（トークン/秒） | 実用評価 |
|--------|--------|-------------|-------------------|---------|
| Qwen3-14B | BF16 | RTX 5090 32GB | 30〜50 t/s | ★快適 |
| Qwen2.5-72B | Q2_K | RTX 5090 + CPU offload | 5〜15 t/s | 低速だが使える |
| Endurance-100B | IQ2_XS | CPU only / partial GPU | 2〜5 t/s | バッチ処理向き |

## 4. 提案アーキテクチャ

### 4.1 処理フロー

```
                    ┌──────────────────────┐
                    │ ローカルLLM（llama.cpp）│
                    │ 29GBメモリ / API課金ゼロ  │
                    │ Qwen3-14B BF16 推奨     │
                    └──────┬───────────────┘
                           │
            ┌──────────────┼──────────────┐
            ▼              ▼              ▼
      ┌──────────┐  ┌──────────┐  ┌──────────────┐
      │ 翻訳      │  │ 分類     │  │ プロンプト生成  │
      │ 要約      │  │ 抽出     │  │ （3Dブース等） │
      │ 下書き    │  │ 仕分け   │  │ 文案作成       │
      └──────────┘  └──────────┘  └──────┬───────┘
                                          │
                              ┌───────────▼───────────┐
                              │ クラウドAPI（必要な時だけ）│
                              │ Claude/GPT:            │
                              │ ・画像生成指示          │
                              │ ・高精度検証            │
                              │ ・最終確認              │
                              └───────────────────────┘
```

### 4.2 セットアップ

**最小構成（29GBメモリPC、要GPU）**:
```
llama.cpp + Qwen3-14B BF16 (29.5GB)
→ 翻訳・分類・プロンプト生成をAPIコストゼロ
→ 3D画像生成プロンプト調整もローカル完結
```

**推奨構成（2台分離）**:
```
[PC1: 開発用] Qwen2.5-72B Q2_K (27.8GB) + GPU
   → 翻訳・分類・バッチ処理
[PC2: ブース設計用] RTX 5090 + PromptMill
   → 3Dプロンプト生成・画像生成制御
```

### 4.4 PromptMill統合（ブース3Dプロンプト生成）

PromptMill + llama.cpp で以下をローカル完結：
- ブース設計コンセプト → 3Dプロンプト自動生成
- Meshy / Tripo / Rodin / Hunyuan3D など26の3Dターゲットに対応
- REST API提供 → 既存のブース設計パイプライン（BuildBooth等）に組み込み可能
- 全プロンプトログをローカルに保存 → ナレッジ蓄積とABテストに活用

## 5. リスクと対策

| リスク | 対策 |
|--------|------|
| IQ2_XS品質が翻訳や分類に不十分 | Qwen3-14B BF16（29.5GB）が高品質な代替案。日本語ベンチ8.5と実用的 |
| GPUメモリ不足 | CPUオフロード（llama.cpp --cpu-moe）でシステムRAMを活用。速度は落ちるが動作可 |
| 初期セットアップ工数 | llama.cpp + HuggingFaceモデルDLのみ。Ollamaならさらに簡単（1コマンド） |
| モデルの陳腐化 | Open Source LLMは3ヶ月ごとに新モデル。切り替えはGGUFファイル差し替えのみ |
| 社内GPUの調達 | 現行PCにRTX 5090追加（約40万円）でも3ヶ月でAPI費削減額が初期投資を上回る |
