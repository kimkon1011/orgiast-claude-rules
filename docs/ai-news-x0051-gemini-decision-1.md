# X-0051: Gemini Decision 1 — 超低コスト高速分類・判断API、100万トークン$0.10

**AIニュース提案 2026-11-15**: Googleが2026年11月11日に発表したGemini Decisions API（gemini-decision-1）は、**入力100万トークンあたり$0.10、出力トークン課金なし、1リクエスト最大1000問、E2E 150〜250ms**の決定特化モデル。Yes/No・多肢選択・ルーブリックスコアの3種の質問を、テキスト・画像・音声・動画・PDF（最大256Kトークン）に対して一度に評価し、確率付きで返す。テキスト生成を一切行わないためコストとレイテンシが劇的に低い。オージャストでは展示会来場予約の緊急度判定・問い合わせ自動仕分け・ブース提案書の品質チェックに応用可能。

観測日: 2026-11-15

## 1. 概要

**Gemini Decision 1**（モデルID: `gemini-decision-1`）は、Googleが2026年11月11日に一般提供を開始した、**分類・判定・スコアリングに特化したマルチモーダルモデル**である。通常のLLMのようにテキストを生成せず、定義された質問に対する確率的な判定結果のみを返す。

| 項目 | 内容 |
|------|------|
| 発表日 | 2026-11-11 |
| 提供形態 | Gemini Decisions API（Vertex AI / Google AI Studio） |
| モデルID | `gemini-decision-1` |
| 最大入力 | 262,144 トークン（約20万文字＋画像等） |
| 出力トークン | **0**（テキスト生成なし、確率のみ返す） |
| 同時質問数 | 最大1,000問 |
| E2Eレイテンシ | 150〜250ms（モデル演算 50〜100ms） |
| 価格 | **入力 $0.10/100万トークン、出力 $0** |
| 無料枠 | Google AI Studio でプロトタイピング可 |

### 1.1 質問の3タイプ

| タイプ | 説明 | 戻り値 |
|--------|------|--------|
| **Yes/No** (`nout`) | 条件に対する真偽判定 | 確率 0.01〜0.99 + 信頼度 |
| **多肢選択** (`choice`) | 2〜255選択肢から最適を選ぶ | 選択肢ごとの正規化確率 |
| **ルーブリックスコア** (`score`) | 順序付き評価段階から加重スコア | 確率加重期待値スコア |

```json
// 問い合わせメールを1発で分類する例
{
  "contents": {...},  // 問い合わせメール本文（テキスト+添付PDF）
  "questions": [
    // Yes/No — 緊急度
    {"type": "nout", "text": "この問い合わせは展示会出展に関するものか？"},
    {"type": "nout", "text": "24時間以内の返答が必要な緊急案件か？"},

    // 多肢選択 — カテゴリ
    {"type": "choice", "text": "問い合わせの種類は？",
     "options": ["見積依頼", "仕様確認", "納期問合せ", "クレーム", "その他"]},

    // ルーブリック — 難易度
    {"type": "score", "text": "対応難易度を5段階で評価",
     "options": ["非常に簡単", "簡単", "普通", "難しい", "非常に難しい"]}
  ]
}
```

→ 4つの質問を1リクエストで同時評価。課金は **入力トークンのみ**。

## 3. オージャストでのユースケース

### 3.1 展示会来場予約の自動仕分け（最優先）

**現状**: `fleet-mail` を通じて届く「来場予約」メールを人手で確認→対応。Claude Code のゲートを通じて判定しているが、生成モデルの呼び出しがオーバーヘッド。

**Gemini Decision 1適用後**:
1. メールを受信 → 本文 + 添付PDFを Gemini Decision 1に投げる
2. 一発で以下3質問を評価:
   - 「このメールは展示会来場予約に関するものか？」(Yes/No)
   - 「催事の種類は？」(choice: [MF-Tokyo, 名古屋EV展, その他展示会, 非展示会])
   - 「対応期限は？」(score: [1日以内, 3日以内, 1週間以内, 緊急でない])
3. 確率が0.7以上のものだけ自動ルーティング
4. 0.7未満の判定は人間確認にエスカレーション

**予測効果**: 分類部分のAPIコスト **99%削減**（Claude Sonnet比）、レイテンシ **10分の1**。

### 3.2 問い合わせメールの部署振り分け

**現状**: 顧客からの問い合わせメールを人手で担当者に振り分け。

**適用後**: メール本文 + 添付資料を Gemini Decision 1 に投げ、以下を同時判定:
1. 「この問い合わせのカテゴリは？」(choice: [見積, 仕様, 納期, クレーム, その他])
2. 「担当部署は？」(choice: [営業, 設計, 製造, 経理])
3. 「クレームか？」(Yes/No) → 0.5以上で自動タグ付け
4. 「難易度」(score: 5段階) → 高難度はベテランにルーティング

→ **すべて 1 APIコール・150ms・$0.0008 で完了**。

### 3.3 ブース提案書の品質チェック

**現状**: ブース提案書のチェックは人手。フォーマット・必須項目・ブランド一貫性の確認に時間がかかる。

**適用後**: 生成された提案書PDFを Gemini Decision 1 に読み込ませ、以下を一発チェック:
1. 「出展要項の高さ制約を守っているか？」(Yes/No)
2. 「会社ロゴ画面が含まれているか？」(Yes/No)
3. 「必須項目（ブースサイズ・備品リスト・予算）が全て記載されているか？」(Yes/No)
4. 「全体的な品質評価」(score: 5段階)

→ 検品チェックが **自動化・定量化・即時** になる。

### 3.4 コードレビューの優先度判定

Codex に実装を委譲する前の事前判定:
1. 「この変更はバグ修正か？」(Yes/No)
2. 「クリティカルなコアに影響するか？」(Yes/No)
3. 「優先度」(score: 3段階)

→ **$0.0004 で最適なレーン割り当てに使える**（現状はラベルのみ）。

## 4. 既存生成モデルとの使い分け方針

`Gemini Decision 1` はテキスト生成ができない。分類・判定・スコアリングに **特化** しているため、既存 LLM（Claude, GPT, Grok）と選択的に使い分ける。

| タスク種 | 使うべきモデル | 理由 |
|---------|--------------|------|
| 分類・判定・ルーティング | **Gemini Decision 1** | コスト 1/100、レイテンシ 1/10 |
| テキスト生成（返信文・提案書）| Claude / GPT | 品質優先 |
| コーディング実装 | Codex | 特化エージェント |
| セッションの自律運用 | Grok（安い） | 長時間セッション向け |

**具体のハイブリッド例（問い合わせ対応フロー）**:

```
メール受信
  ↓
[Gemini Decision 1] ← $0.0004, 150ms
  緊急度・カテゴリ・担当部署を判定
  ↓
[Claude Sonnet]    ← 必要な場合のみ（クレーム・見積等）
  返信ドラフト生成
  ↓
[人間確認・送信]
```

分類だけでコスト99%削減 + 必要な時だけClaudeを使う → **総コスト100分の1 以下が現実的**。

## 5. 導入手順

### 5.1 APIの有効化

```bash
# Vertex AI の場合
gcloud services enable aiplatform.googleapis.com

# 認証
gcloud auth application-default login
```

### 5.2 Node.js から利用（`@google/genai` SDK）

```javascript
import { GoogleGenAI } from "@google/genai";

const genAI = new GoogleGenAI({ apiKey: process.env.GOOGLE_API_KEY });
const model = "gemini-decision-1";

// 問い合わせメールの自動仕分け
async function classifyInquiry(textContent: string, pdfBase64: string) {
  const res = await genAI.models.decisions({
    model,
    contents: [
      { text: textContent },
      { inlineData: { mimeType: "application/pdf", data: pdfBase64 } }
    ],
    questions: [
      { type: "nout", text: "この問い合わせはクレームに関するものか?" },
      { type: "choice", text: "カテゴリは?",
        options: ["見積", "仕様", "納期", "クレーム", "その他"] },
      { type: "score", text: "優先度を5段階で評価",
        options: ["極低", "低い", "普通", "高い", "緊急"] }
    ]
  });
  return res.decisions;
}
```

### 5.3 OpenRouter 経由でも利用可能

Gemini Decision 1 は OpenRouter からも利用可能。既存の OpenRouter 統合コードを流用できる。

### 5.4 既存ワークフローへの組込み方針

- **フェーズ1**: fleet-mail の仕分けに試験導入（1週間、無料枠で十分）
- **フェーズ2**: 問い合わせ自動仕分けのバックエンドに組込み（目標: 分類の自動化率80%）

## 6. 既知の制約とリスク

| 制約・リスク | 影響 | 対策 |
|------------|------|------|
| テキスト生成不可 | 分類結果を元の動作（返信等）は別モデルが必要 | ハイブリッド構成が前提 |
| 質問間の依存関係なし | 「質問AでYesなら質問B」のような分岐不可 | コード側で if 文でつなぐ |
| Google Cloud 依存 | 可用性・レートリミットの管理 | OpenRouter経由でフェールオーバー |
| 256Kトークン制限 | 超大規模ドキュメントの分析不可 | 分割して投げるか、事前に要約 |
| まだ API のみ（2026-11-15時点） | SDKは @google/genai 最新版が必要 | npm install @google/genai@latest |
| 分類精度の検証が必要 | 初回は人手レビューとの併用が必須 | 3〜7日間の並行運用で基準値作成 |
