# X-0054: AI記事に独自性を出す20〜25の質問抽出 — 構造化インタビュー質問セットの設計方法論

**AIニュース提案 X-0054**: 「記事の差別化は質問の質で決まる」——AIが公開情報をいくら検索しても決して答えられない質問を20〜25問設計し、社内の専門家に投げる構造化インタビュー手法。株式会社オージャストのブース制作ノウハウを素材に、汎用的な質問抽出フレームワークを提供する。

観測日: 2026-11-15

---

## 1. なぜ「質問の引き出し」が記事の独自性を決めるのか

### 1.1 AI時代のコンテンツ差別化

2026年現在、ChatGPT Search・Perplexity・Google AI Overview・Gemini・Claude等のAI検索が、複数の情報源を横断して要約を提供する。この環境で「一般的な解説記事」は検索価値をほぼ失っている。

```
 AI検索ができること:
   複数サイトの公開情報を収集 → 要約 → ユーザーに提示
   ∴ 「公開情報を再構成しただけの記事」の価値は限りなくゼロに近い

 AI検索ができないこと:
   特定の個人・企業が持つ一次データ・体験・判断基準を引き出す
   ∴ 「組織の中の人にしか書けない内容」だけが検索価値を保持する
```

**「組織の中の人」から独自情報を引き出すカギは「質問の質」にある。** ChatGPT等にそのまま聞けば答えが返ってくる質問（＝公開情報で調べられる質問）では、取材相手からも独自情報は引き出せない。

### 1.2 質問抽出 ≠ 質問作成

X-0045 が **「ブース制作の専門家に聞く22の質問セット」** という完成品を提供するのに対し、本稿（X-0054）は **「どのようにしてその22問を設計するか」** という方法論——質問の抽出（引き出し）技術——に焦点を当てる。

| | X-0045 | X-0054（本稿） |
|---|---|---|
| 提供するもの | 完成した質問22問 | 質問を設計するフレームワーク |
| 対象読者 | 記事を量産する編集担当 | 質問セットを設計する編集ディレクター |
| 再利用性 | 展示会ブース特化 | あらゆる業種・テーマに適用可能 |
| 質問数 | 固定22問 | 20〜25問に収める技法 |
| 更新頻度 | 年に1回程度の見直し | 取材対象・テーマごとに再設計 |

## 2. 質問抽出フレームワーク: 「5層ピラミッド」

質問設計は「思いつき」で行うと、偏りが出る・独自性が不足する・質問数が収まらない。以下の5層ピラミッドで系統的に質問を引き出す。

```
                ┌──────────────────────┐
                │   ⑥ アドバイス      │  2〜3問
                │  読者が持ち帰る価値  │
                ├──────────────────────┤
                │   ⑤ トレンド・変化  │  3〜4問
                │  業界の流れ・将来    │
                ├──────────────────────┤
                │  ④ 比較・対比       │  3〜4問
                │  差別化の明確化      │
                ├──────────────────────┤
                │  ③ 数字・データ     │  3〜4問
                │  検証可能な定量情報  │
                ├──────────────────────┤
                │ ② 課題・失敗        │  4〜5問
                │  独自の困難と克服    │
                ├──────────────────────┤
                │ ① 経験・実績        │  4〜5問
                │  実体験の具体化      │
                └──────────────────────┘
```

### 2.1 各層の抽出テクニック

#### ① 経験・実績（4〜5問）— 記憶を「解凍」する

この層の目的: 相手の頭の中で「ひとくくり」になっている経験を、具体的なエピソードに分解させる。

| 手法 | 質問パターン | 引き出せる情報 |
|------|------------|--------------|
| **最大級** | 「最も〜だった案件は？」 | 成功・失敗の基準がわかる |
| **対比時系列** | 「初めて担当したときと現在で、最も変わったことは？」 | 成長・変化のストーリー |
| **限界値** | 「最も短期間でやった案件は？」 | 通常と異常の境界値がわかる |
| **制約下** | 「予算が限られていた案件でどう工夫した？」 | 創造的問題解決能力 |

**悪い質問**: 「どんな経験がありますか？」→ 一般的な答えが返る
**良い質問**: 「昨年手がけた案件で、予算が想定の半分だったプロジェクトは？ どう乗り越えましたか？」→ 具体的なストーリーが返る

#### ② 課題・失敗（4〜5問）— 独自性の金鉱脈

この層が最も独自性を生む。「うまくいった話」より「うまくいかなかった話」の方が他社が書けない。

| 手法 | 質問パターン | 引き出せる情報 |
|------|------------|--------------|
| **想定外** | 「想定外のトラブルは？ どう対処した？」 | 創意工夫・実戦知 |
| **認識齟齬** | 「お客様との認識違いで苦労した経験は？」 | 顧客対応ノウハウ |
| **物理的制約** | 「搬入で最も大変だったケースは？」 | 現場知（公開情報では得られない） |
| **トレードオフ** | 「デザインと施工性の間で妥協したポイントは？」 | 判断基準・優先順位 |
| **振り返り** | 「これは失敗だったと振り返る案件は？」 | 改善サイクル・学習 |

**悪い質問**: 「失敗したことはありますか？」→ 「特にありません」（相手が防御的になる）
**良い質問**: 「過去5年で、もしもう一度同じ案件をやるとしたら唯一変えるとしたら何ですか？」→ 間接的に失敗／課題を引き出す

#### ③ 数字・データ（3〜4問）— E-E-A-Tの裏付け

AI検索が最も好むのは「検証可能な数字」。感嘆詞ではなく定量情報を引き出す。

| 手法 | 質問パターン | 引き出せる情報 |
|------|------------|--------------|
| **範囲** | 「平均工期と最短・最長は？」 | 現実的な幅がわかる |
| **予算帯** | 「規模ごとの予算帯は？」 | 価値判断の基準 |
| **比率** | 「リピート率・成約率は？」 | ビジネス健全性 |
| **頻度** | 「年間何件担当？ 新規とリピートの割合は？」 | 市場ポジション |

**悪い質問**: 「どれくらいの仕事量ですか？」→ 「まあまあ多いです」
**良い質問**: 「先月だけで何件の引き合いがありました？ そのうち成約は何件？」→ 検証可能な数字

#### ④ 比較・対比（3〜4問）— 読者の意思決定を助ける

比較情報は購入検討者が最も求める情報。AI検索でも比較クエリで引用されやすい。

| 手法 | 質問パターン | 引き出せる情報 |
|------|------------|--------------|
| **会場比較** | 「A会場とB会場の違いは？」 | 選択基準 |
| **新旧比較** | 「10年前と最近で最も変わった点は？」 | 業界進化 |
| **規模比較** | 「小規模と大規模の考え方の違いは？」 | スケーリング知見 |
| **競合比較** | 「御社と競合の決定的な違いは？」 | 差別化要因 |

**悪い質問**: 「他社と比べてどうですか？」 → 「うちが一番です」（根拠がない）
**良い質問**: 「クライアントがA社ではなく御社を選んだ決め手は何でした？ 具体的な事例で教えてください」 → 具体的な差別化要因

#### ⑤ トレンド・変化（3〜4問）— 更新頻度を高める

トレンド情報は記事の鮮度を示すシグナル。四半期ごとに同じ質問ができると「定点観測記事」にもなる。

| 手法 | 質問パターン | 引き出せる情報 |
|------|------------|--------------|
| **新素材・技術** | 「最近よく使われるようになった素材や技術は？」 | イノベーション |
| **業界全体** | 「業界全体で大きく変わったことは？」 | マクロトレンド |
| **予算配分** | 「クライアントの予算配分の変化は？」 | 市場ニーズの変化 |
| **AI影響** | 「AIやデジタルツールで業務がどう変わった？」 | 将来予測 |

**悪い質問**: 「最近のトレンドは何ですか？」→ 「DXです」（一般的）
**良い質問**: 「2025年と2026年で、クライアントから最も要求が増えたものを3つ挙げてください」→ 具体的な変化

#### ⑥ アドバイス（2〜3問）— 読者の検索意図に応える

最後の層は、読者が実際に検索する「どうすればいいか」に直接答える。

| 手法 | 質問パターン | 引き出せる情報 |
|------|------------|--------------|
| **初めての人向け** | 「これから始める人に最初に伝えたいことは？」 | 導入障壁の下げ方 |
| **選び方** | 「業者を選ぶときの見るべきポイントは？」 | 意思決定基準 |
| **やってはいけない** | 「初心者がやりがちな失敗は？」 | 失敗回避ノウハウ |
| **理想** | 「予算制限がなければ実現したいことは？」 | ビジョン・方向性 |

## 3. 質問抽出の「5つのフィルター」

質問を設計したら、以下の5フィルターで「AIでも答えられる質問」を除去する。

### フィルター #1: Googleテスト
**その質問をGoogleで検索したら、答えが出ますか？**
- YES → その質問は記事の独自性に貢献しない（除くか、より具体的に）
- NO → 良い質問（社内にしか答えがない）

### フィルター #2: ChatGPTテスト
**ChatGPT（または同程度のLLM）に聞いたら、それなりの答えが返ってきますか？**
- YES → その情報で差別化できない（除くか、より深掘りする）
- NO → 良い質問（AIの訓練データに含まれていない）

### フィルター #3: 「なぜ」の3段階
**答えの後ろに「なぜ？」を3回続けて聞いても、まだ新しい情報が出ますか？**
- 1回目の「なぜ？」で終わり → 質問が浅い（具体化が必要）
- 3回目の「なぜ？」まで新しい情報 → 良い質問

### フィルター #4: 数量テスト
**その質問の答えに「とても」「すごく」「いろいろ」などの曖昧語が含まれそうですか？**
- YES → 定量化が必要（「いくつ」「どのくらい」「何%」に変換する）
- NO → 良い質問

### フィルター #5: ストーリーテスト
**その質問に「ある時、こんなことがあって…」というストーリーで答えられそうですか？**
- YES → 良い質問（具体的なエピソードが独特の価値を生む）
- NO → もっと具体化できないか検討する

### フィルター適用例

| 質問（フィルター前） | #1 | #2 | #3 | #4 | #5 | 判定 |
|---|---|---|---|---|---|---|
| 「展示会の効果は？」 | × | × | × | × | △ | **不適** — すべてのフィルターで不合格 |
| 「2026年のJapan DIY ...での成約率は？」 | ○ | ○ | ○ | ○ | ○ | **適** — 全フィルター通過 |
| 「クライアントの予算は？」 | × | × | △ | △ | △ | **不適** — 一般的過ぎる |
| 「予算500万円未満で最大の効果を出した展示会と、その具体的な施策は？」 | ○ | ○ | ○ | ○ | ○ | **適** — 具体的・独自 |

## 4. 実践: オージャストのスタッフから質問を抽出する（事例）

### 4.1 取材前の準備（15分）

1. **そのスタッフの「得意領域」を決める**
   - 施工担当者 → 現場のリアルな課題・搬入ノウハウ
   - デザイナー → デザインコンセプト・素材選びの基準
   - ディレクター → プロジェクト全体の進め方・顧客対応

2. **ターゲットキーワードを決める**
   - 「展示会ブース 費用 相場 2027」の記事なら③数字・④比較を多めに
   - 「展示会 成功させる方法」の記事なら②課題・⑥アドバイスを多めに

3. **5層から均等に配分して20〜25問に収める**

### 4.2 取材の進め方（40〜60分）

| 時間 | フェーズ | 質問数 |
|------|---------|--------|
| 0:00〜0:05 | アイスブレイク・目的説明 | — |
| 0:05〜0:15 | ①経験・実績（4〜5問） | 4〜5 |
| 0:15〜0:25 | ②課題・失敗（4〜5問） | 4〜5 |
| 0:25〜0:32 | ③数字・データ（3〜4問） | 3〜4 |
| 0:32〜0:40 | ④比較・対比（3〜4問） | 3〜4 |
| 0:40〜0:47 | ⑤トレンド・変化（3〜4問） | 3〜4 |
| 0:47〜0:52 | ⑥アドバイス（2〜3問） | 2〜3 |
| 0:52〜0:60 | 振り返り・追加の深掘り | — |

### 4.3 深掘り質問の技術

相手が答えた後に、さらに独自性を引き出す「フォローアップ質問」:

| 相手の発言 | フォローアップ | 狙い |
|-----------|--------------|------|
| 「予算が足りなくて…」 | 「具体的にいくら足りなかった？ 何を削った？」 | 定量化 |
| 「クライアントが…」 | 「そのクライアントは業界・規模・初めて？」 | 属性の具体化 |
| 「大変でした」 | 「最も大変だった瞬間は何時ごろ？ どう解決した？」 | エピソードの具体化 |
| 「他社と違います」 | 「他社の具体的な社名と、御社の具体的な違いを3つ」 | 比較の具体化 |
| 「最近変わった」 | 「2025年と2026年の違いを、数字で言うと？」 | 定量的比較 |

### 4.4 回答の記録と整形

取材後、以下のフォーマットで記録を残す:

```markdown
## 取材メモ: [スタッフ名] / [日付]

### Q1: [質問]
A: [回答原文]
→ 記事で使える独自情報: [具体的な数字・固有名詞・エピソードを箇条書き]

### Q2: ...
```

**AI生成時のルール**: この回答テキストのみをAIに渡し、一般知識で補完させない。

## 5. 質問抽出の「7つの悪い習慣」と改善策

| # | 悪い習慣 | 具体例 | なぜ悪いか | 改善策 |
|---|---------|--------|-----------|--------|
| 1 | 抽象質問 | 「御社の強みは？」 | テンプレ回答しか出ない | 「直近の案件で、競合に負けたと思った決め手は？」 |
| 2 | 誘導質問 | 「やはり品質が一番ですよね？」 | 本音が出ない | 「価格・品質・納期の優先順位を教えてください」 |
| 3 | 知識自慢 | 「最近の◯◯技術についてどう思いますか？」 | 相手が引く | 平易な言葉で |
| 4 | 質問の連続注入 | 質問を立て続けに5問読む | 回答が薄くなる | 1問ごとに相手の回答を待つ・深掘りする |
| 5 | 否定しやすい質問 | 「失敗したことは？」 | 「特にない」で終わる | 「直近で改善したかった点は？」と言い換える |
| 6 | タイムマシン質問 | 「5年後どうなっていると思いますか？」 | 想像で答えていい加減になる | 「今年と去年で変わったことは？」 |
| 7 | 20問超え | 30〜40問詰め込む | 回答が疲れる・質が下がる | 20〜25問に厳選する。「それ以外で言い残したこと」を最後に聞く |

## 7. 期待効果

### 7.1 SEO/LLMO効果

| 指標 | 一般的な質問セット | 本フレームワーク適用後（推定） | 根拠 |
|------|------------------|-----------------------------|------|
| AI Overview引用率 | 低い（公開情報と重複） | 2〜3倍 | 5フィルター通過質問は公開情報で答えられない |
| 検索順位（中難度） | 10〜30位 | 3〜10位 | 一次データのE-E-A-T評価 |
| 記事のリライト頻度 | 3ヶ月ごと | 6〜12ヶ月 | 公開情報で陳腐化しない |
| 被リンク獲得 | ほぼなし | 月1〜3本 | 独自調査データとして引用 |

### 7.2 制作効率

| 要素 | 従来の自由取材 | 本フレームワーク |
|------|-------------|----------------|
| 質問セット設計時間 | 1〜2時間（毎回0から） | 15〜30分（5層に当てはめるだけ） |
| 取材時間 | まちまち（1時間前後） | 40〜60分（質問数20〜25に制御） |
| 記事の独自性 | 質問の質に依存（不安定） | 安定（フィルターで品質保証） |
| フレームワークの使い回し | できない | ■できる（業種を問わない） |

### 7.3 属人化防止

本フレームワークの最大の価値は **「ベテランのノウハウを質問で引き出し、形式知化する」** 点にある。

- 取材を受けたスタッフの回答は構造化テキストとして蓄積される
- 同じフレームワークを使えば別のスタッフでも比較可能なデータが取れる
- スタッフの退職・異動後も取材記録は記事として残る
- 新入社員の教育素材としても活用できる

## 9. リスクと対策

| リスク | 確度 | 対策 |
|--------|------|------|
| フィルター通過後も質問の質が安定しない | 中 | 2回目以降は「前回の取材で特に良い回答が出た質問」をベースに改良する |
| スタッフの協力が得られない | 中 | 「自身の知見が社の資産として残る」と説明、取材時間を勤務時間に含める |
| 5フィルターで全滅して質問が残らない | 低 | フィルターは「絶対評価」ではなく「気づきの道具」。通過しなかった質問も具体化すれば通過できる |
| 20問に収められない | 中 | 「20〜25」に収まらない質問は「次回の取材用」としてプールする。1回の取材で全部聞こうとしない |
