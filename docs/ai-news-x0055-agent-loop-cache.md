## 1. エージェントループのコスト構造とキャッシュの効果

### 1.1 エージェントループは入力トークンが支配的

エージェント型のAIワークロード（Claude Codeの自律セッション・Codexの実装委譲・監視ループ）では、以下の特徴がある:

| 指標 | 一般的なチャット | エージェントループ |
|------|----------------|------------------|
| 入力:出力トークン比 | 1:1〜3:1 | **5:1〜20:1** |
| 1セッションあたりターン数 | 5〜20 | **50〜500+** |
| コストに占める入力の割合 | 30〜50% | **80〜95%** |
| プロンプトの重複率（同一セッション内） | 低い | **非常に高い**（システム指示・ツール定義・履歴の再送） |

エージェントループでは毎ターン同じシステムプロンプト・ツール定義・過去の履歴を再送するため、**入力トークンがコストの大部分**を占める。

### 1.2 キャッシュの効果

| モデル | 通常価格（入力 $/1M Tok） | キャッシュ書き込み（初回） | キャッシュ読み取り（2回目以降） |
|--------|--------------------------|------------------------|--------------------------|
| Fable 5.2 | $8.00 | $10.00（1.25x） | **$2.00（0.25x）** |
| Opus 5.5 | $3.00 | $3.75（1.25x） | **$0.75（0.25x）** |
| Sonnet 5.5 | $1.25 | $1.56（1.25x） | **$0.31（0.25x）** |
| Haiku 5.5 | $0.10 | $0.125（1.25x） | **$0.025（0.25x）** |

**キャッシュヒット時は入力コストが75%オフ。** 初回の1.25xプレミアムは2ターン目以降で回収できる。

### 1.3 キャッシュTTLとエージェントループの関係

Claude APIのプロンプトキャッシュTTLは **約5分**（2026年11月現在の実測値）。これは:

```
キャッシュが生きている間（5分以内のターン）
  └─ 入力コスト 0.25x（75%オフ）

キャッシュが切れた後（5分以上空いたターン）
  └─ 入力コスト 1.0x（フルプライス、再書き込みが必要）
```

つまり **5分以内に次のターンを開始すればキャッシュが維持され続ける**。

## 3. キャッシュ維持のための設計パターン

### 3.1 基本パターン: 安定プレフィックス + 短い出力

```
[キャッシュ対象: 不変部分]
システムプロンプト
ツール定義（全ツール）
共有コンテキスト（ブランド基準・デザインポリシー）
過去の重要な決定事項

[キャッシュ非対象: 可変部分 ← 末尾に配置]
現在のターンの指示
最新のユーザー入力
現在のターンのツール結果
```

**ルール**: 発言のたびに変更される部分は末尾に置き、先頭の不変部分をキャッシュに乗せる。

### 3.2 ターン時間の管理

キャッシュTTLの5分を維持するための実践:

| プラクティス | 内容 | 効果 |
|------------|------|------|
| **出力を短く** | エージェントの応答を1〜3行＋必要情報のみに制限 | 読み取り＋次の入力準備が早くなる |
| **不変部分を先頭に固定** | CLAUDE.mdにルール化、毎セッション同じ順序で書く | キャッシュキーの一致率向上 |
| **ターン間隔を3分以内に** | 5分を切る目安として3分を目標に | キャッシュ消失のバッファ確保 |
| **長い処理は分割** | 1ターンで長い検索・実装をするより、複数ターンに分割 | 各ターンを短くしキャッシュ維持 |
| **定期ハートビート** | アイドル時に短いpingを送る | 5分を超えるアイドル防止 |

### 3.3 オージャストでの適用パターン

**パターン1: 展示会ブースデザインのバリエーション生成**


## 7. 制約と注意点

| 制約 | 影響 | 対策 |
|------|------|------|
| TTLはプロバイダ依存（Claude: 5分） | OpenAI/Geminiでも同様の戦略は有効だがTTLが異なる | プロバイダごとにTTLを実測 |
| キャッシュ書き込みは1.25x | 初回のみ割高 | 2ターン目以降で回収、長期セッションほど効果大 |
| 履歴が蓄積するとキャッシュ効率低下 | 50ターン超で履歴が数万トークンに | /compact で定期的に要約 |
| Fast modeの影響未測定 | Fast modeでTTLが短くなる可能性 | 通常モードで検証後、Fast modeも実測 |
| モデル切替でキャッシュ消失 | 途中でOpus→Sonnetに変えるとキャッシュリセット | セッション内ではモデル固定が原則 |

## 8. 結論

エージェントループは本質的に **入力トークンが支配的** であり、Claudeのプロンプトキャッシュ（5分TTL）の **キープアライブ戦略** によってコストを **57〜75%削減** できる。実践の鍵は:

1. **出力を短くする** — エージェントの応答が長いと読み取りに時間がかかり、次ターンが5分を超えるリスク
2. **不変部分を先頭に固定** — システムプロンプト・ツール定義を毎回同じ順序で
3. **ターン間隔を3分以内に** — 5分TTLにバッファを持たせる
4. **安定したモデル** — セッション内でモデルを変更しない

これにより、**展示会ブースデザイン生成で74%減、イベント企画の繰り返し提案で75%減、Grok委譲ループで75%減** のコスト削減が現実的な目標となる。
