# X-0055: オージャスト実測 — Claudeモデル使い分け＋プロンプトキャッシュでコスト最適化

**AIニュース提案 X-0055**: Fable 5.2（入力$8/MTok）とHaiku 5.5（入力$0.10/MTok）には80倍の価格差がある。一般論のモデルルーティングではなく、株式会社オージャストの展示会ブース制作案件における実測値に基づく使い分けルールを確立する。Opus 5.5 mediumを基本とし、タスク特性・キャッシュ状態・切り替えコストを考慮した最適なモデル選択戦略を定義する。

## 1. 概要

### 1.1 問題: オージャストのAI費用構造

オージャストではClaude Codeを全PCで運用しており、以下の構造的課題がある:

| 課題 | 実態 | 影響 |
|------|------|------|
| **Opus一択の慣習** | CLAUDE.md既定がOpus 5.5（§1.13 effortLevelの既定値もmedium） | 単純タスクまでOpus従量で処理 |
| **Fableの過剰利用** | Fable 5.1/5.2がOpusの2倍（$8 vs $4/MTok入力）だが、設計以外でも使われがち | 1.16の用途制限が効いているが、監督時も含め高コスト |
| **キャッシュ非活用** | プロンプトキャッシュ読取時0.25xで済むのに、毎回フル書き込み | X-0035の知見がオージャスト運用に浸透していない |
| **モデル切替コストの無視** | 1回の切替でキャッシュがリセットされ、次回書き込み1.25x〜2x | 短時間の切替ではかえって高コスト |

### 1.2 解決: キャッシュ状態を考慮したモデル選択

```
[従来] とにかくOpus（キャッシュ考慮なし）
  Opus 5.5 で全タスク → キャッシュ0ヒット → $4.00/MTok（入力）

[改善] キャッシュ状態＋タスク難易度で判断
  ① 長期セッション（キャッシュ温存）→ Opus継続（$0.20/MTok読取）
  ② 範囲明確な修正 → Sonnet新規（$2.00/MTok書込、単価半分）
  ③ バリエーション量産 → Haiku（$0.10/MTok書込）
  ④ 複雑設計のみFable（$8.00/MTok、限定）
```

### 1.3 オージャスト案件特性とモデル選定への影響

| 案件特性 | 該当するタスク | 推奨モデル | 理由 |
|---------|-------------|-----------|------|
| **長期連続セッション** | ブース設計〜図面生成〜施工手順書 | **Opus継続**（キャッシュ温存） | 5分TTL内の連続呼出で$0.20/MTok |

## 3. モデル選択ルール（オージャスト実践版）

### 3.1 決定木

```
タスク発生
  │
  ├─ 現在Opusでキャッシュ活性化中？
  │   ├─ YES: Opus継続（切り替え損）
  │   │   └─ 例外: キャッシュTTL切れそうなら完了後いったん完了
  │   └─ NO: 次の判断へ
  │
  ├─ 複数ファイルにまたがる設計・実装？
  │   ├─ YES: Opus 5.5（精度優先、キャッシュは後で効く）
  │   └─ NO: 次の判断へ
  │
  ├─ 範囲が明確な単一修正？
  │   ├─ YES: Sonnet 5.5（単価半分）
  │   └─ NO: 次の判断へ
  │
  ├─ 大量の同種処理（10件以上）？
  │   ├─ 分類・抽出 → Haiku 5.5（最安）
  │   ├─ バリエーション生成 → Haiku 5.5（同一指示で内容変更）
  │   └─ 要約 → Haiku 5.5（品質確認必要）
  │
  ├─ 最高品質の設計判断？
  │   ├─ 案件全体の設計方針 → Opus 5.5
  │   └─ 多段階研究・推論 → Fable 5.2（※要根拠）
  │
  └─ 上記いずれでもない → Opus 5.5（デフォルト）
```

### 3.2 定量基準

| ルール | 条件 | 選択 |
|-------|------|------|
| **キャッシュ温存** | 同一セッション内で前回から5分以内の連続呼出 | 現在のモデルを**継続**（切り替えない） |
| **キャッシュ切替閾値** | キャッシュが切れたor別セッション | タスクに最適なモデルを**選び直し** |
| **複雑設計** | 3ファイル以上の同時変更 or アーキテクチャ判断含む | **Opus** |
| **範囲明確** | 影響範囲が1関数・1ファイル内 | **Sonnet**（検証含め単価半分） |
| **大量同種（10〜）** | 10件以上の同指示処理 | **Haiku**（サンプル確認のみOpus） |
| **大量同種（100〜）** | バッチ処理可能 | **Haiku + バッチ50%オフ** |
| **Fable利用** | X-0036の「Sonnet本体+Fable advisor」、または多段階研究 | **Fable**（§1.16の用途制限を遵守） |

### 3.3 切り替えコストの定量モデル

モデル切り替えの判断は以下の計算で行う:

```
切り替え判断コスト = 新しいモデルの書込コスト - 現在のモデルの読取コスト
```

**実例（Opus→Sonnetへの切替）**:
- Opus継続10回: $0.20×10 = **$2.00**（初回書込$5.00は既に支払済み）
- Sonnet切替10回: $2.50（初回書込）+ $0.10×9 = **$3.40**
- → **切替で+$1.40（70%増）**。切替は非合理

**実例（キャッシュクリア後の新規）**:
- Opus新規1回: $4.00（書込）+ $20.00（出力）= **$24.00**
- Sonnet新規1回: $2.00（書込）+ $10.00（出力）= **$12.00**
- → 新規ならSonnetが**半額**

## 8. 結論

- **最重要発見**: Opusのキャッシュ読取$0.20/MTokはSonnetの通常書込$2.00/MTokより**10倍安い** → キャッシュ温存中は切り替えずOpus継続が最適
- **即効性**: 範囲明確な修正はSonnet（単価半分）、大量同種はHaiku（1/40）
- **オージャスト特有**: ブース設計→図面→手順書の連続セッションはOpus一貫（切り替えると+35%）
- **期待効果**: モデル選最適化＋キャッシュで1案件あたり**▲40%**、量産は**▲90%以上**も可能

**「最高のモデル」は一種類ではない。「今のキャッシュ状態で何が最適か」を判断することこそが、真のコスト最適化である。**
