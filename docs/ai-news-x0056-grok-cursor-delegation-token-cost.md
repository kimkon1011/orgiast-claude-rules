# X-0056: Grok Bot → Claude/Cursor委譲でトークンコスト管理 — 用途別AIレーンで制限突破とコスト安定

**AIニュース提案 X-0056**: Grok Bot（xAI）のトークン制限問題を、用途に応じたAIレーン切り替えで解決する。Grok Botでリサーチ・収集（安価）、Cursor Projectsでチーム開発（定額）、Claude Codeで高難易度タスク（従量）と委譲し、各AIの強みとコスト限界に応じて自動的にレーンを切り替える。オージャストの展示会ブース企画リサーチ（Grok）→図面・デザインコード生成（Claude）の委譲パターンでトークン使用を実測する。

観測日: 2026-11-15

---

## 1. 概要

### 1.1 問題: Grok Bot のトークン制限がボトルネックに

Grok Bot はリサーチ・情報収集に優れるが、以下の制約がある:

| 制約 | 実態 | 影響 |
|------|------|------|
| **トークン制限** | Grok 3 のコンテキストウィンドウに上限あり | 大規模リサーチ結果を一度に処理できない |
| **API従量課金** | xAI API は従量制 / SuperGrok $30/月固定 | 大規模処理で予算超過リスク |
| **ファイル連携** | 外部コードと直接連携不可（出力を手動で渡す） | 自動パイプラインを途切れさせる |
| **長時間タスク** | 1セッションの継続時間に暗黙の制限 | 大規模実装が途中で止まる |

一方、オージャストでは既に複数のAIレーンが稼働しており、Grok Bot に依存し続けるより、**レーン切り替えで継続性を確保する**方が安定する。

### 1.2 解決: 5段階委譲パイプライン

```
┌─────────────────────────────────────────────────────────────┐
│ Phase 1: リサーチ・情報収集                                  │
│ Grok Bot (xAI) — 安価・高速・Web検索強・スマホ可             │
│ 制限突破 → Cursor Projects (OpenAI GPT/Claude)              │
│ さらに制限 → Claude CLIまたはClaude Code Projectsへ         │
└──────────┬──────────────────────────────────────────────────┘
           │ リサーチ結果（JSON/指示書）
           ▼
┌─────────────────────────────────────────────────────────────┐
│ Phase 2: 実装・開発                                          │
│ Cursor Projects（基本） — チーム招待可・定額安定             │
│ トークン制限 → Claude Code Projects / Cloud Sessions        │
│ 高難易度 → Claude Code 直接（柔軟性最大）                   │
└──────────┬──────────────────────────────────────────────────┘
           │ コード変更
           ▼
┌─────────────────────────────────────────────────────────────┐
│ Phase 3: 検証・QA                                            │
│ Grok Bot（別視点） + Claude（テスト実行）                     │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 各レーンの特性

| レーン | 用途 | コスト構造 | 制限 | チーム連携 | オージャスト実績 |
|--------|------|----------|------|----------|--------------|
| **Grok Bot (xAI)** | リサーチ、情報収集、監視、バックオフィス | SuperGrok $30/月固定 or API従量 | トークン制限あり・ファイルI/O不可 | — | X-0032/X-0014/X-0020 実績あり |
| **Cursor Projects (Free/Pro)** | コード実装（基本）、チーム開発 | Free: 月2000回補完 / Pro: $20/月（無制限） | Freeは制限あり / Proは安定 | **チーム招待可** | — |
| **Cursor Projects + Claude API** | Cursor内で Claude 3.5 Sonnet / Opus / Fable | Cursorにトークンパック課金 | Cursorの契約範囲内 | 同上 | — |
| **Claude Code Projects** | 高品質コード、複雑設計 | Claude Code 従量課金 | トークン従量（高コスト） | **Cloud Sessions**で共有可 | オージャスト全自動化で実績多数 |
| **Claude Code 直接** | 高難易度・長時間エージェント | 従量（Fable/Sonnet切替） | トークン従量（予算管理要） | — | CLAUDE.md §1.17 の委譲ルール |

## 2. 委譲パターンとトークンコスト比較

### 2.1 5段階の委譲トリガー


### 2.3 トークン制限を考慮した実質コスト

```
[従来] Grok Bot で全てやろうとする
  リサーチまでは良好 → トークン制限で中断 → 手動でClaudeに貼り付け
  → 作業継続できるが、手動作業の発生で実質コスト増

[本提案] 最初から委譲レーンを設計
  Grok Bot でリサーチ → 結果を自動JSON保存
  → Cursor Projects がJSONを読んで実装（制限少ない）
  → 必要に応じて Claude Code がバックアップ
  → 手動作業ゼロ・コスト予測可能
```

## 3. Cursor Projects の利点（オージャスト視点）

### 3.1 チーム開発への適合

| 観点 | Claude Code | Cursor Projects |

| チーム招待 | 不可（個人契約） | **可（Organization招待）** |

| 自動補完 | チャットベース | **エディタ内蔵で高速** |
| 定額運用 | 不可（従量のみ） | **Pro $20/月で制限緩和** |

### 3.2 Cursor のトークンパック（2026年11月）

Cursor は **Usage-based プラン** で、以下のモデルに対応:

| モデル | Cursor内での利用 | 料金体系 |
|--------|----------------|---------|
| GPT-4o / GPT-4o-mini | 標準搭載 | リクエストベース（Fast Premium） |
| Claude 3.5 Sonnet / Opus | 追加設定 | トークンパック消費 |
| Claude Fable | Cursor内で利用可能 | 高トークン消費 |
| Gemini 2.5 Flash/Pro | 追加設定 | トークンパック消費 |

**Pro プランの実質コスト**: $20/月（固定）＋ 追加トークンパック（従量）
→ 月2000回の操作なら **$20固定で収まる**（Claude Code従量の 1/10〜1/5）

| プラン | 制限 | 実測目安 |
|--------|------|---------|
| Cursor Free | 月2000回の補完 + 50回のチャット | 軽い開発のみ |

## 4. オージャスト適用パターン

### 4.1 展示会ブース企画リサーチ→実装パイプライン

```
Step 1: Grok Bot が競合リサーチ
  └─ x_search + Sandbox で競合5社のブース構成・料金を調査
  └─ JSON 出力（grok-bot-prompt-bridge.mjs で自動変換）

Step 2: Cursor Projects が実装（基本）
  └─ リサーチJSONを読み込み、ブース提案ページを生成
  └─ 既存WordPressテーマに沿ったコーディング
  └─ チームメンバーがCursor内でレビュー

Step 3: Cursor 制限時 → Claude Code Projects
  └─ codex-do.mjs 経由で Claude Code に実装継続
  └─ 結果を同一リポジトリへコミット

Step 4: Grok Bot QA（別視点検証）
  └─ 実装結果を Grok に送信 → 第三者検証
  └─ 合格 or 修正指示
```

### 4.2 図面・デザインコード生成（Claudeに特化）

展示会ブースの図面コード生成やデザイン指示はClaudeに直接送る:

| タスク | 使用AI | 理由 |
|-------|--------|------|
| ブースレイアウト図の生成（SVG/HTML） | **Claude Code** | コード品質が安定（X-0014実績） |
| 3Dパースのコード生成 | **Claude + Codex** | 高品質な図面コードが必要 |
| 施工手順書の自動生成 | **Claude（監督）+ Codex** | 複数ファイルの整合性が必要 |
| デザイン指示書の作成 | **Grok Bot → Claude** | Grokで調査→Claudeで組版 |

### 4.3 バックオフィス連携（Grok Bot メイン）

| 業務 | 使用AI | コスト |
|------|--------|-------|
| 会計データ取得（freee API） | Grok Bot | SuperGrok $30/月内 |
| LINE問い合わせ一次応答 | Grok Bot | SuperGrok内 |
| スカウト業務 | Grok Bot Scout | SuperGrok内 |
| **問い合わせ内容の実装案件化** | **Grok → Cursor** | **GPT $0.01/回** |
| **帳票テンプレート生成** | **Grok → Claude** | **従量$0.05/回** |

### 4.4 Cursor → Claude Code のトークン制限委譲ロジック

```
Cursor で開発中:
  1. Cursor のトークン制限（Slow Premium Request の制限）に到達
  2. ここまでの進捗を保存（git commit）
  3. codex-do.mjs に指示を送信:
     node tools/codex-do.mjs \
       "指示書: X-0056 cursor 委譲。作業内容は <cursorで書いていた内容>" \
       --cwd "<repo>" \
       --origin unattended
  4. Claude Code が残りを実装
  5. 結果を PR 提出 → Cursor で最終調整
```

**検出条件**:
- Cursor の Fast Premium 残クレジット < 50
- Cursor チャットの応答が遅延（Slow Premium Request に切り替わった）
- PR レビューをチーム全体で行いたい

## 8. リスクと対策

| リスク | 確度 | 影響 | 対策 |
|-------|------|------|------|
| Cursor Pro でも制限に頻繁に当たる | 中 | 中 | 追加トークンパックか Claude Code へ委譲 |

| アクション | 優先度 | 担当 | 期間 | 期待効果 |

| Cursor Pro 契約 + チーム招待 | P0 | kim | 1日 | チーム開発基盤確立 |

**Grok Bot のトークン制限は「避けられない障害」ではなく「適切な委譲レーンを設計する合図」である。** xAI, Cursor, Claude の3レーンを用途で切り替えれば、各AIの長所を活かしながら全体のコストを予測可能な範囲に抑えられる。特にCursor Projectsはチーム招待可能な開発環境として、オージャストの複数PC/アカウント運用に適合する。

まずは1案件でGrok Bot リサーチ→Cursor Projects 実装→Claude Code 補完のパイプラインを試行し、トークン制限の実測値と委譲トリガーを確定することから始める。
