# X-0057: AIコーディングの再現可能ハーネス — AGENTS.md でルール定義・状態保存・テスト強制・役割分離

**AIニュース提案 X-0057**: Claude Code の AGENTS.md サブエージェントシステムを「Supervisor → Implementer 委譲パターン」で統一し、テスト実行義務・LEARNING-LEDGER 状態保存・レビューゲートを組み込んだ再現可能なAIコーディングハーネスを構築する。learn-taste スキルによるデザイン修正のルール化（第1段階）に続き、全エージェントの責務境界と状態永続化を体系化する第2段階。

観測日: 2026-11-16

---

## 1. 概要

AIコーディングエージェント（Claude Code, Codex, Gemini CLI 等）は同じタスクを実行しても、制御フレームワーク（ハーネス）の選択によって成功率・コスト・再現性が大きく変わる。X-0022 で実証された通り、Claude Code は OpenClaw 比で約半額だが、それはハーネスが適切に状態管理とキャッシュ制御をしているからである。

X-0057 はこの知見を AGENTS.md の定義レベルで体系化し、以下の4軸を満たすハーネスを実装する：

| 軸 | 課題 | 本ハーネスの対策 | 実装箇所 |
|----|------|-----------------|---------|
| **ルール定義** | エージェントに役割と制約が明文化されていない | AGENTS.md の frontmatter + 責務セクションで定義 | 全6エージェント |
| **状態保存** | セッション間で学習が失われる | LEARNING-LEDGER プロトコル + memory ファイルへの自動書き込み | Supervisor/Implementer 他 |
| **テスト強制** | 実装後テストが省略される | 「テスト条件の受領→実行→報告」を Implementer 委譲パターンに組込み | Supervisor+Implementer |
| **役割分離** | 何でもやる万能エージェント | 読み取り専用/分類専用/抽出専用/実装専用/統括を分離 | Agent 種別ごとの責務境界 |

## 2. ハーネスのアーキテクチャ

### 2.1 Agent 構成

```
Supervisor (sonnet) ── 統括・計画・レビュー・状態保存
   │
   ├── Implementer (sonnet) ── 実装・修正・テスト実行・知見報告
   │
   ├── Explore (haiku) ── 読み取り専用・横断探索（結果を Supervisor へ）
   ├── Extractor (haiku) ── 読み取り専用・構造化抽出（結果を Supervisor へ）
   ├── Classifier (haiku) ── 読み取り専用・分類推奨（最終判断は Supervisor）
   └── LogReader (haiku) ── 読み取り専用・ログ解析（確度明示義務）
```

### 2.2 ワークフロー

```
Supervisor がタスクを受け取る
  ↓
作業を工程に分解
  ↓
各工程を Implementer へ委譲（テスト条件を添える）
  ↓
Implementer: 実装 → テスト実行 → 結果報告（テスト成功/失敗・知見）
  ↓
Supervisor: レビュー（テスト通過・仕様充足・副作用）
  ↓
合格 → 知見を LEARNING-LEDGER へ保存 → 完了宣言
不合格 → 修正指示を付けて再委譲
```

### 2.3 テスト強制ゲート

Implementer の制約に以下を追加：

```
- **テスト実行義務**: 実装後、既存テストを実行するか新規テストを記述して
  グリーンを確認してから完了宣言すること
- **Testing**: 実装後、`node --test tools/*.test.mjs` または同等のテスト
  コマンドを実行し、グリーンを確認すること
```

Supervisor はこれをレビューで確認し、テスト未実施の成果物は受け入れない。

### 2.4 状態保存（LEARNING-LEDGER）

全エージェントに以下の状態保存責務を追加：

| Agent | 保存対象パターン | 保存先 |
|-------|-----------------|--------|
| Supervisor | 設計判断・品質基準・統括知見 | memory ファイル (LEARNING-LEDGER 昇格) |
| Implementer | バグパターン・実装注意点 | memory ファイル (Supervisor 経由) |
| Explore | 命名規則・共通エラー原因 | 発見パターンの報告 (Supervisor が判断) |
| Extractor | 日付書式・金額表記マッピング | プロモーション候補報告 |
| Classifier | 顧客種別傾向・業界優先度 | 反復パターンのプロモーション提案 |
| LogReader | エラー原因・ログ-障害相関 | 根本原因の記録候補報告 |

## 5. オージャストサイト更新への適用

本ハーネスをオージャストの Web サイト更新に適用するワークフロー：

1. Supervisor が「サイト更新タスク」を受け取る（どのページをどう修正するか）
2. Explore が該当ページの現状構造を調査
3. Implementer が修正を実装 + テスト実行
4. Supervisor がレビュー + 知見を LEARNING-LEDGER に保存
5. 次回同種タスクでは保存された知見を自動ロードして再現

14レッスン（14の Web 更新ワークフローステップ）を逐次適用することで、更新のたびに品質が向上するサイクルが確立される。
