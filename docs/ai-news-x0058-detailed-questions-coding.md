# AIニュース提案 X-0058: 超詳細質問でAIコーディングを20倍高速化 — 計画駆動開発の実証

> 作成: 2026-11-18 | ステータス: 分析 / 提案

## 概要

プロンプト「**I want to build out [機能詳細]. Ask as many questions you need of me to fully understand every detail of what I want to build out. Then take everything you learn, and create super focused and detailed Linear issues. Then begin work**」を用いることで、AIに100+の質問をさせ、40+の詳細Linearタスクに分解させてから実装を開始する手法。この「**計画駆動開発（Plan-Driven Development）**」により、従来の曖昧な1行指示でのコーディングと比較して**20倍の高速化**が報告されている。

### なぜ20倍速くなるのか

| 従来の手法 | 計画駆動開発（本手法） |
|-----------|----------------------|
| 曖昧な1行指示「ブース見積フォーム作って」 | 100+質問で全要件を事前確定 |
| 実装中に「あ、これも必要だった」が発生 | 40+タスクに分解済みで抜けがない |
| 途中で方向転換で手戻り | 設計段階ですべての判断を済ませる |
| AIが「適当に」実装して後で修正 | 各タスクが極めて具体的で再実行不要 |
| 複数ファイルの整合性を後追い確認 | タスク間の依存関係が事前定義済み |

### 出典

- AI News: "I will ask you hundreds of questions" prompt pattern
- 実践レポート: 100+質問、40+Linearタスクでコーディングが20x高速化
- 類似手法: Vercel v0 の要件ヒアリング、Anthropic の prompt engineering guide の「詳細な指示」

## 現状: オージャストの開発プロセス

### 既存の取り組み

| 項目 | 内容 | 状態 |
|------|------|------|
| ✅ SPEC.md | 各アプリにSPEC.md（設計書）を配置 | 標準化済み |
| ✅ codex-prompt.md | Codex用の詳細指示ファイル | 一部アプリで使用 |
| ✅ テストファースト | spec-cache.test.mjs 等のテスト | 定着 |
| ⚠️ タスク分解粒度 | 機能単位で大きく、サブタスクに未分割 | 改善余地あり |
| ⚠️ 前提条件の確認 | 「当然」と思い込んで省略する傾向 | 改善余地あり |
| ❌ 事前質問プロセス | 設計前に全ステークホルダーの前提を収集する仕組みがない | 未導入 |

### 課題

1. **暗黙の前提**: 開発者が「これは当然わかっているはず」と省略した要件が、レビューで指摘される
2. **実装中の発見**: コードを書き始めてから「このケースはどうする？」と判断が必要になる
3. **手戻り**: 方向修正が発生し、既存コードの書き直しが生じる
4. **タスクの粒度の粗さ**: 1タスクに複数の責務が混在し、進捗が見えにくい

## 提案: 計画駆動開発（Plan-Driven Development）の導入

### フェーズ構成

```
フェーズ1: 超詳細質問（100+質問）
  → ドメイン・ユーザー・技術・非機能・エッジケースの全側面を質問
  → 回答を要件定義書として構造化

フェーズ2: タスク分解（40+ Linear Issues）
  → 質問回答からタスクを抽出
  → タスク間の依存関係を定義
  → 優先順位付け（P0/P1/P2）

フェーズ3: 実装
  → 各タスクを1コミット単位で実装
  → 依存関係に従って順次進行
  → 各タ���ク完了時に自動テスト

フェーズ4: 検証
  → 全タスク完了後に統合テスト
  → ユーザー受け入れテスト
  → デプロイ
```

### テンプレート: 超詳細質問のカテゴリ

プロジェクト開始時にAIに質問させるべき7つのカテゴリ:

| # | カテゴリ | 質問例 | 想定質問数 |
|---|---------|--------|-----------|
| 1 | **ビジネスドメイン** | 誰が使う？何が嬉しい？ビジネスゴールは？ | 15-20問 |
| 2 | **ユーザー体験** | どんな画面？操作フローは？モバイル対応は？ | 20-25問 |
| 3 | **データモデル** | どんなデータを扱う？保存先は？バリデーションルールは？ | 15-20問 |
| 4 | **技術スタック** | 言語・フレームワーク・外部サービスは？ | 10-15問 |
| 5 | **非機能要件** | パフォーマンス目標は？セキュリティ要件は？アクセシビリティは？ | 10-15問 |
| 6 | **エッジケース** | エラー時の振る舞いは？オフライン対応は？レート制限は？ | 15-20問 |
| 7 | **運用・デプロイ** | ホスティング先は？監視は？バックアップは？更新フローは？ | 10-15問 |
