## 記事1: Claude Code に通知機能を追加（2026-09-02）

### 概要
Claude Code の標準フック機構（UserPromptSubmit / Notification / Stop）を PowerShell の Windows トースト通知と組み合わせ、セッションの「確認待ち」「完了」「エラー」を OS 通知で受け取る仕組み。

### 技術的ポイント
| 要素 | 詳細 |
|------|------|
| **トリガー条件** | 完了通知は開始から60秒以上経過した場合のみ発報（短い応答での過剰通知を防止） |
| **権限モード別制御** | auto / bypassPermissions では「確認待ち」通知を鳴らし、default / plan では鳴らさない |
| **エラー検出** | 応答末尾のテキストマッチング（不完全性を許容し「音だけ変わる」設計） |
| **二重設計** | 音＝即時性、トースト（scenario="reminder"）＝操作されるまで残る |

### オージャストへの適用可能性
- **既存**: 018 PC の hooks に `notify.ps1` 相当の仕組みは既にあるが、権限モード別の出し分けは未実装
- **提案**: `UserPromptSubmit` で permission_mode を一時ファイルに書き、`Notification` フックで読み分けるパターンを `~/.claude/hooks/notify-mode.ps1` として実装。3種類の通知音の割り当ては応用可能

## 記事2: Claude Code で環境構築 — 二層構成（2026-07-15）

### 概要
手元の Claude Code（VSCode拡張）を「伴走役」、AWS EC2 上の Claude Code を「実行役」とする二層アーキテクチャ。伴走役は設計相談・エラー解析・司令塔に専念し、実行役は手順実行・キー生成・検証を自走。

### 鍵となる実装ディテール
| 項目 | 内容 |
|------|------|
| **二層の分離** | 手元（伴走）＝VSCode拡張、EC2（実行）＝SSHターミナル越しCLI |
| **セキュリティ4軸** | 権限制限・秘密非表示・暗号化退避（SSM Parameter Store）・入口閉塞（鍵レス管理） |
| **委譲範囲** | 手順実行・キー生成と整合性検証・シークレット保存・事故時自己修復（画面誤出力→検知→即ローテーション） |
| **障害2種と対策** | docker 権限エラー（グループ再読込）・管理エージェントの状態固着（ロール付与後に再起動が必要） |

### オージャストへの応用
- **既存の類似**: Grok Bot への実装委譲パターン（tools/codex-do.mjs）は概念的には同じ二層構成
- **差異点**: 記事では両方とも Claude Code 同士だが、オージャストは Codex/Grok など別モデルへ委譲
- **学べる点**: 「制約の明示が品質を決める」— 権限・秘密・整合性を言語化して渡すと検証まで返す。codex-do の指示書品質に直結

## 記事3: アプリ→API→AI Skill — 3層開発フロー（2026-05-14）

### 概要
Next.js + Supabase のカレンダーアプリを、3ステップ（UI→API→Skill）で発展させる開発フロー。各層が独立した価値を持ち、最終的に AI が API の使い方を Skill として記述し、AI がそれを解釈して実行する自己言及的構造。

### 重要な設計判断

| 判断 | 根拠 |
|------|------|
| **MCP非採用・Skill方式を選択** | MCPは常時接続によるトークン消費が懸念。Skillは明示的なコマンド入力時のみAPI呼び出し → コスト管理が容易 |
| **認証機構の使い回し** | HMACトークンをそのまま Bearer 認証に流用。DB変更ゼロでAPIレイヤー追加 |
| **APIが転換点** | API整備により「閉じたツールから開いたプラットフォーム」に変化。curlが使える全プログラムから操作可能に |
| **クロスプラットフォーム考慮** | 日本語文字化けに対し `--data-binary @file.json` を Skill ファイルに明記 |

### オージャストへの応用

オージャスト内では既に似たパターンが散見される:
| 例 | 該当 |
|----|------|
| Discord MCP コネクタ | アプリ→API層まで整備済み（ただし MCP 方式） |
| secretary API | `/api/public/free` エンドポイントで curl 操作可能 |
| gmail-draft.mjs | CLI 操作（Skill 方式に近い） |

**提案**: 「APIを整備すればAIが操作手順を自分で書いて実行する」というループを、新規プロジェクトの標準設計パターンとして確立する。新規機能は「まずAPIを生やす」を第一優先に。
