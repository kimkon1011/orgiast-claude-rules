# AIニュース提案 X-0058: 無制限エージェント委任でコスト爆発を回避 — 再帰サブエージェント制限と監視

> 作成: 2026-11-21 | ステータス: 分析 / 提案

## 概要

2026年半ば、AIエージェントフレームワーク（Claude Code・OpenAI Codex・Hermes Agent・OpenCode）で**再帰的なサブエージェント委任によるコスト爆発**が相次いで報告された。単一のリクエストが数十〜数百のサブエージェントを無制限に生成し、数億〜数十億トークンを消費する事例が現実化している。

| 事例 | フレームワーク | 発生日 | 被害規模 |
|------|-------------|--------|---------|
| GitHub #68110 | Claude Code | 2026-06 | 1つのAgent呼び出しで**48+サブエージェント**、**1.5M+トークン** |
| GitHub #38989 | OpenAI Codex MultiAgentV2 | 2026-08 | **74サブエージェント**、**5.39Bトークン**（サブエージェントだけで4.98B） |
| GitHub #52484 | Hermes Agent | 2026年 | **44サブエージェント**、53分間（1分間に最大8生成） |
| GitHub #18100 | OpenCode | 2026年 | **深さ20レベル**、47セッション（18レベルが意味のないexplore→explore再帰） |

### なぜコスト爆発が起きるのか

| 要因 | 仕組み | 被害例 |
|------|--------|--------|
| **幅の無制限** | サブエージェントがさらに子サブエージェントを生成。深さ制限はあっても「1階層あたり何体まで」という幅制限がない | 深さ3でも24〜40+体に拡大（Claude Code #68110） |
| **再帰委任のループ** | 探索エージェントが「より詳細な調査」を繰り返し、同じ作業を深掘りし続ける | 20レベルのうち18が空転（OpenCode #18100） |
| **背景エージェントの継続** | 予算上限到達後も、すでに起動した背景エージェントが稼働し続ける | v2.1.224で修正されるまで予算超えが止まらなかった |
| **合計数制限の不存在** | セッション全体のサブエージェント総数に上限がない（200体の旧上限は削除された） | 1研究リクエストで74体（Codex #38989） |

## 現状: 各フレームワークの対策

### Claude Code v2.1.219+ の制御機構

| 制限 | 環境変数 / オプション | 既定値 | 到達時の挙動 |
|------|---------------------|--------|-------------|
| 深さ上限 | `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` | 3階層 | 末端のサブエージェントは子を生成できず自力で作業 |
| 同時実行数上限 | `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` | 20 | 新規生成を拒否（`Concurrent subagent limit reached`） |
| 予算上限 | `maxBudgetUsd` / `max_budget_usd` | **無し** | 新規生成拒否 + 背景エージェント停止 + クエリ終了 |
| スポーン上限 | spawn cap（v2.1.224+） | 設定時のみ | セッション全体のサブエージェント総数を制限 |

### 既知のギャップ

1. **予算上限に既定値がない**: 設定しないと無制限に課金される
2. **対話型セッションに日次上限がない**: `--max-budget-usd` は `claude -p`（printモード）のみ有効
3. **幅の制限が未整備**: 深さ制限はあるが「1階層x体」の制御は各フレームワークとも不十分
4. **モデル混在時の予測困難**: HaikuからOpusまでサブエージェントごとにモデルが異なり、トークン単価の予測が難しい

## 提案: 5層のコスト防衛線

### 第1層: 深さ上限の明示設定

```json
// .claude/settings.json または Agent SDK
{
  "maxSubagentSpawnDepth": 3,
  "subagentDepthLimit": 3
}
```

**効果**: 深さ無制限の再帰を防止。深さ3でほとんどの実用的な委任パターンをカバーできる。

### 第2層: 同時実行数上限の最適化

```json
{
  "maxConcurrentSubagents": 10
}
```

**効果**: 同時に走るサブエージェント数を制限。既定値20は大きすぎる場合があり、10程度で十分な並列性を得られる。

### 第3層: 予算上限の強制

```json
{
  "maxBudgetUsd": 5.0
}
```

**効果**: ダラー単位の絶対上限。`claude -p` で `--max-budget-usd 5.0` としても機能する。v2.1.224以降は背景エージェントも停止するため、無人実行でも安全。

### 第4層: サブエージェントモデルのモデル格下げ

```json
// .claude/agents/reviewer.json の例
{
  "model": "haiku",
  "tools": ["Read", "Grep", "Glob"],
  "maxSubagentSpawnDepth": 1
}
```

**効果**: 単純な調査・収集タスクをHaikuに委譲し、Opusの消費を抑制。ツール制限により「調査だけ」の責務を強制。

### 第5層: 使用量監視とアラート

**日常的な監視**:
- `claude /usage` でサブエージェント種別ごとの消費を確認
- 異常なスポーンレート（1分間に5体以上）を検知したら通知
- 週次のコストレポートでサブエージェント消費比率を追跡

## 実証: オージャスト「ブースバリエーション生成エージェント」への適用

### 現状のリスク

オージャストの展示会ブース見積もりシステムでは、AIエージェントがバリエーション生成（サイズ・オプション・金額パターン）を担当している。このエージェントがサブエージェントを無制限に生成すると：

1. バリエーションの組み合わせ爆発（サイズxオプションx価格帯 = 数百パターン）
2. 各パターンの検証をサブエージェントに委任 → さらに子サブエージェント
3. 1回の「バリエーション生成」依頼が数十万トークンに拡大

### 適用計画

| Phase | 内容 | 期間 |
|-------|------|------|
| **Phase 1: 制限設定** | サブエージェント数上限（深さ2・同時5・予算$2）を `agent-config.json` に設定 | 即日 |
| **Phase 2: モデル最適化** | バリエーション一覧生成はHaiku、最終検証のみSonnet/Opusに割り振り | 今週 |
| **Phase 3: 監視導入** | 週次コストレポートにサブエージェント消費セクションを追加し、異常検知を設定 | 今週 |
| **Phase 4: ツール制限** | バリエーション生成エージェントのツールを Read/Call のみに制限（Write/Edit/Agent を禁止） | 来週 |

### 期待される効果

| 指標 | 現状（無制限） | 対策後 | 削減率 |
|------|-------------|-------|--------|
| 1依頼あたりのサブエージェント数 | 最大48+体 | 最大10体 | **79%削減** |
| 1依頼あたりのトークン消費 | 最大1.5M+ | 最大150K | **90%削減** |
| 予算超過リスク | 高い（上限なし） | 低い（$2キャップ） | **回避可能** |
| 異常検知までの時間 | なし（事後確認のみ） | 5分以内 | **即時検知** |
| 運用コスト予測精度 | 低い（外れ値が月額を圧迫） | 高い（予算上限で固定） | **予測可能に** |

## 期待される効果（全社）

1. **コストの予測可能性向上**: 予算上限とスポーン制限により、月額費用の外れ値を防止
2. **異常検知の迅速化**: サブエージェント消費の監視により、コスト爆発を発生前に検知
3. **モデル費用の最適化**: タスク粒度に応じたモデル割り振りで、Opusを本質的な判断だけに限定
4. **セキュリティ向上**: ツール制限により、サブエージェントの暴走による意図しないファイル変更を防止
5. **知見の共有**: 制限設定と監視のテンプレート化により、全社の全プロジェクトに展開可能

## リスクと対策

| リスク | 対策 |
|--------|------|
| 制限が厳しすぎてタスクが完了しない | 段階的に緩和（深さ3→5、予算$2→$5）し、効果測定後に調整 |
| サブエージェント数上限で並列性が低下 | 同時実行数は段階的に調整（5→10→15） |
| `maxBudgetUsd` の設定を忘れる | deploy-verify ゲートに予算上限チェックを追加 |
| モデル格下げで品質が低下 | 格下げ対象は「調査・収集」のみに限定し、判断は従来モデルを維持 |
