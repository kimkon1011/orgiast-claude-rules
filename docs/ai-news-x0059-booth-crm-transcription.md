# X-0059: ブース会話AI文字起こしとCRM連携 — 来場者会話を録音しAIスコアリング・フォローアップ自動生成

**AIニュース提案 X-0059**: 展示会ブースで来場者との会話を録音し、Web Speech APIでリアルタイム文字起こし、AIスコアリング（0-100点）でリードをHOT/WARM/COLD分類、CSV/JSONエクスポートでCRM連携、実会話ワードをもとにフォローアップメールを生成する。オージャストのブース運営で80人セミナーデモを想定。Claudeで2時間で構築したプロトタイプ。

観測日: 2026-11-16

---

## 1. なぜ「ブース会話AI文字起こしとCRM連携」が重要なのか

### 1.1 展示会ブースの課題

| 課題 | 従来の対応 | X-0059の解決 |
|------|-----------|-------------|
| 名刺だけでは会話内容が消える | スタッフの記憶頼み・メモが断片的 | 会話全文を録音＋文字起こしで保存 |
| リードの温度感を定量化できない | 経験と勘でHOT/COLD分類 | 会話時間＋キーワード検出で客観スコア化 |
| フォローアップが定型文になる | 「先日はありがとうございました」のみ | 実際の会話ワードを反映したパーソナライズメール |
| 会話データが社内に蓄積されない | イベント終了とともに散逸 | CSV/JSONエクスポートでCRMに統合 |

### 1.2 オージャストの展示会ブースでの価値

オージャストでは毎年複数の展示会（MF-TOKYO、オートモーティブワールド等）に出展し、ブース装飾制作の提案を行っている。ブーススタッフと来場者の会話には以下の情報が含まれる：

- **顕在ニーズ**: 「今度こういうブースを作りたい」「予算は500万」
- **検討中の課題**: 「自社のブースが地味で集客できない」
- **意思決定プロセス**: 「役員に見せて決裁をもらう必要がある」
- **競合情報**: 「A社のブースが良かったと社内で話題に」

これらの会話をテキスト化・スコアリング・CRM連携することで、展示会後のフォローアップ精度が飛躍的に向上する。

## 3. AI機能（実装詳細）

### 3.1 リードスコアリングアルゴリズム

スコアは0-100点で算出。3つの要素から構成：

| 要素 | 最大加点 | 検出方法 |
|------|---------|---------|
| **会話時間** | 60pt | MediaRecorder APIの経過時間。30秒=20pt, 60秒=40pt, 120秒以上=60pt |
| **関心キーワード** | 40pt | 文字起こしテキストからキーワード検出（後述） |
| **意思決定キーワード** | 20pt | 決裁プロセスに関する単語検出 |

**キーワード検出テーブル**:

| カテゴリ | キーワード例 | 加点 |
|---------|------------|------|
| **意思決定 (decision)** | 決裁, 稟議, 上長, 役員, 承認 | +15pt |
| **高意向 (high)** | 見積, 導入, 予算, デモ, PO, 発注 | +20pt |
| **中意向 (medium)** | 興味, 検討, 比較, 評価, パイロット | +10pt |
| **低意向 (low)** | いいですね, 魅力的, 素晴らしい, 使いたい | +5pt |

**カテゴリ分類**: HOT(>=70点) / WARM(40-69点) / COLD(<40点)

### 3.2 フォローアップメール生成

実際の会話ワードを反映したテンプレート生成を実現：

| テンプレート | 内容 | 活用シーン |
|-------------|------|-----------|
| お礼メール (thankyou) | 来場御礼＋会話内容への言及 | 全リード共通の初動フォロー |
| 資料送付 (materials) | 会話で話題になった製品の資料送付 | 製品興味を示したリード |
| デモ案内 (demo) | オンラインデモの日程調整提案 | デモ希望リード |
| 見積確認 (quote) | 見積もり依頼の確認＋詳細ヒアリング | 見積依頼リード |

## 4. 実装（apps/booth-lead/）

本提案のプロトタイプは既に `apps/booth-lead/` に実装済み。

### 4.1 ファイル構成

```
apps/booth-lead/
├── README.md      — アプリ概要・使い方
├── SPEC.md        — 実装仕様書
├── index.html     — シングルページアプリケーション
├── style.css      — スタイリング（タブレット対応・ダークモード対応）
└── app.js         — アプリケーションロジック
```

### 4.2 技術スタック

| 技術 | 用途 |
|------|------|
| Pure HTML/CSS/JS | フレームワーク不要、CDNホスティング可能 |
| html5-qrcode (CDN) | QRコード読み取り（バッジスキャン） |
| MediaRecorder API | ブース会話録音 |
| Web Speech API (SpeechRecognition) | リアルタイム文字起こし |
| Canvas API | 音声波形ビジュアライザー |
| localStorage | リードデータ永続化（オフライン対応） |
| File API | CSV/JSON エクスポート・インポート |

### 4.3 80人セミナーデモ手順

1. **事前準備**: PC + 外付けマイク + プロジェクターでアプリ表示
2. **デモシナリオ**:
   - スタッフAが来場者役でブース来訪（3分の模擬商談）
   - スタッフBがタブレットでQRスキャン → リード登録
   - 「会話」タブで録音開始 → 模擬商談実施
   - 録音停止 → 即座に文字起こし表示
   - AIスコアが自動算出（例: 72pt = HOT）
   - 「キャンペーン」タブでフォローアップメールプレビュー
3. **所要時間**: デモ通しで約5分

## 7. 注意点

- **プライバシー**: 録音・文字起こしデータは来場者同意のもとで取得すること
- **オフライン**: 展示会場のWi-Fi環境によってWeb Speech APIが利用できない場合がある。その場合は手動文字起こし（テキストエリア）で代替
- **デモ環境**: html5-qrcode CDNの読み込みにはインターネット接続が必要
- **ブラウザ対応**: Web Speech APIはChrome/Edgeで動作。Safari/Firefoxは未対応のため注意
