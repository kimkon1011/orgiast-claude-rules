# X-0063: Claude Code でエージェント自動チューニング

> AIニュース提案 2026-11-16
> 対象: リポジトリ内のエージェント定義（スキル・プロンプト）を Claude Code で自動チューニングし、未見会話でテストして品質を向上させるワークフロー
> 基: [X-0023 サブエージェント委譲とeffort調整](ai-news-x0023-subagent-delegation-effort-tuning.md)

## 概要

Claude Code のスキル定義やプロンプトを手動で調整する代わりに、**自動チューニングパイプライン**で評価→改善をループさせる。エージェントの出力をテストセットで評価し、スコアが低い項目のプロンプトを自動修正、改善を実測する。

```
[エージェント定義] → テストセットで実行 → 出力評価（スコア）
   ↓                     ↑
  スコア不足の定義を自動修正 ─┘
      ↓
  改善後の定義で再実行 → スコア比較
      ↓
  改善確認 → PR作成 → マージ
```

### 実装コンポーネント

| コンポーネント | 役割 | 実装先 |
|---|---|---|
| **評価ランナー** | テストセットでエージェントを実行し出力を評価 | `tools/agent-auto-tuner.mjs` |
| **プロンプト最適化** | スコア不足項目のプロンプトを自動修正 | `tools/agent-auto-tuner.mjs --optimize` |
| **テストセット管理** | 未見クエリのテストセットを保持・更新 | `tests/agent-tuning/` |
| **CI連携** | PR作成時に自動チューニングを実行 | `.github/workflows/agent-tuning.yml` |
| **SEOパイプライン適用** | ブース関連ページ生成エージェントに適用 | `seo/` + `tools/` |

## 1. なぜエージェント自動チューニングか

### 1.1 課題

- スキル定義やプロンプトの調整は**手動試行錯誤**になりがち
- 1回の調整で品質が改善したかの判断が**主観的**
- 時間が経つとエージェントの応答品質が**知らぬ間に劣化**
- 新しいユースケースが出たときに**プロンプトが追いつかない**

### 1.2 解決策

Claude Code 自身に**評価と改善を任せる**ことで、以下のループを回す：

1. テストセット（未見の質問/タスク）を用意
2. エージェントを実行し、出力を採点（正確性・完全性・有用性）
3. スコアが低い定義を Claude Code が分析し改善案を生成
4. 改善案を適用して再評価
5. スコアが向上したら PR を作成

### 1.3 自動化で削減される手作業

| 工程 | 従来（手動） | 自動化後 |
|------|------------|---------|
| プロンプト調整 | 人が試行錯誤 | Claude Code が自動 |
| 品質評価 | 人の主観 | スコアリング自動化 |
| 回帰テスト | 忘れられがち | 毎回自動実行 |
| PR作成 | 人が手動 | CIで自動生成 |

## 2. 実装: エージェント自動チューナー

### 2.1 ツール: `tools/agent-auto-tuner.mjs`

```bash
# エージェントの出力を評価
node tools/agent-auto-tuner.mjs --evaluate --agent skills/seo-blog-images/SKILL.md --test-set tests/agent-tuning/seo-images.json

# 低スコア項目のプロンプトを自動最適化
node tools/agent-auto-tuner.mjs --optimize --agent skills/seo-blog-images/SKILL.md --test-set tests/agent-tuning/seo-images.json

# 評価＋最適化を連続実行
node tools/agent-auto-tuner.mjs --full --agent skills/seo-blog-images/SKILL.md --test-set tests/agent-tuning/seo-images.json

# 全エージェントを一括チューニング
node tools/agent-auto-tuner.mjs --sweep
```

### 2.2 評価基準

各テストケースで以下の3軸をスコアリング（1-5）：

| 軸 | 評価内容 | 判定方法 |
|----|---------|---------|
| **正確性** | 指示内容を正しく実行しているか | キーワード一致・構造チェック |
| **完全性** | 必要な要素をすべて含んでいるか | 必須項目の網羅チェック |
| **有用性** | 実際の業務で使える出力か | 長さ・具体性・フォーマット |

### 2.3 最適化アルゴリズム

```
1. テストセットの各ケースでエージェントを実行
2. 3軸スコアリング（各1-5、合計3-15）
3. 平均スコア < 12 のエージェント定義を特定
4. 低スコアケースの出力と期待値を比較
5. 差分からプロンプト改善案を生成
6. 改善案を適用して再実行
7. スコアが向上したら確定、しなければ別案を試行
8. 最大3回試行して改善なければ現状維持で報告
```

## 3. オージャストへの適用

### 3.1 適用対象: 展示会ブースSEOコンテンツ生成パイプライン

既存の SEO コンテンツパイプライン（`seo/x0018-seo-content-pipeline.mjs`）に本チューニング機構を組み込み、ブース関連ページの生成品質を向上させる。

**現状の課題**:
- 生成されるブース関連コンテンツの業界知識の深さにばらつき
- 価格帯・事例・地域情報の正確性が安定しない
- 競合との差別化ポイントの提示が弱い

**チューニングで改善する点**:
- 展示会ブース制作の業界知識ベース（`INDUSTRY_KNOWLEDGE`）の精度
- 価格帯・規模感の提示の正確性
- 地域・業種別の事例マッチング精度
- SEOキーワードとの整合性

### 3.2 テストセット（例）

| クエリ | 期待する出力要素 | 評価軸 |
|--------|----------------|--------|
| 「展示会ブース 制作 費用 相場」 | 価格帯・規模別・CTA | 正確性・完全性 |
| 「大阪 展示会 ブース 制作 会社」 | 地域情報・事例・比較 | 正確性・有用性 |
| 「初めての展示会 ブース レイアウト」 | 初心者向け・ステップ・図解 | 完全性・有用性 |
| 「小規模ブース 集客 アイデア」 | 具体策・事例・予算感 | 有用性・完全性 |

### 3.3 期待効果

| 指標 | チューニング前（推定） | チューニング後（目標） |
|------|---------------------|---------------------|
| 正確性スコア | 2.5/5 | 4.0/5 |
| 完全性スコア | 3.0/5 | 4.5/5 |
| 有用性スコア | 3.0/5 | 4.0/5 |
| 平均スコア | 2.8/5 | 4.2/5 |
| 手動調整工数 | 2時間/回 | 0分（自動） |

## 4. CI/CD 統合

GitHub Actions で週次自動チューニングを実行：

```yaml
# .github/workflows/agent-tuning.yml（設計案）
name: Agent Auto-Tuning
on:
  schedule:
    - cron: '0 6 * * 1'  # 毎週月曜
  workflow_dispatch:

jobs:
  tune:
    runs-on: ubuntu-latest
    steps:
      - run: node tools/agent-auto-tuner.mjs --sweep
      - if: improvement detected
        run: node tools/agent-auto-tuner.mjs --pr
```

## 5. 制約・注意点

### 5.1 過学習の防止

- テストセットは**毎回同じものを使わず**、一定割合を入れ替える
- 評価セットと開発セットを分け、**未見データでのスコア**を正とする
- 同一クエリでのスコア向上が 3 回連続で止まったら**打ち切り**

### 5.2 コスト

| 工程 | 推定コスト（1回のチューニング） |
|------|-------------------------------|
| 評価実行（10テストケース） | $0.05〜0.15（Haiku） |
| 最適化（低スコア項目の分析） | $0.10〜0.30（Sonnet） |
| 改善案の適用と再実行 | $0.10〜0.30（Sonnet） |
| 週次合計 | **$0.25〜0.75/週** |

### 5.3 品質保証

- チューニング後のスコアが**低下した場合は自動ロールバック**
- 改善案の適用は**PR 経由**で行い、人のレビューを受けてからマージ
- 週次レポートで**スコア推移**を可視化

## 7. 結論

X-0063 は **「エージェントのチューニングを Claude Code 自身に任せる」** という新しいアプローチを提案する。人の手動調整に依存せず、テストセットによる客観評価と自動改善のループで、エージェント品質を継続的に向上させる。

オージャストの展示会ブースSEOコンテンツ生成に適用することで、従来の手動調整（2時間/回）をゼロにし、出力品質の平均スコアを 2.8→4.2/5 へ改善することを目標とする。
