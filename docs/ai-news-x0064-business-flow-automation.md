## 0. エグゼクティブサマリ

オージャストのブース制作・イベント企画業務において、**見積作成・サイト更新・案件進捗管理**の3業務に集中的な工数がかかっており、これらをAI自動化することで**月間約30〜50時間の削減**が見込める。

| 業務 | 現状工数/月 | 自動化後 | 削減率 | 着手優先度 |
|------|-----------|---------|-------|-----------|
| ① 見積書作成（企画提案含む） | 15〜20h | 3〜5h | 75% | **P0（今週）** |
| ② 案件進捗管理・報告 | 8〜12h | 1〜2h | 85% | **P0（今週）** |
| ③ サイト更新（事例・ブログ） | 6〜10h | 2〜3h | 65% | **P1（来週）** |
| ④ メール問い合わせ対応 | 5〜8h | 1〜2h | 75% | **P1（来週）** |
| ⑤ 出展者募集・発送業務 | 4〜6h | 1h | 80% | **P2（今月）** |
| **合計** | **38〜56h/月** | **8〜13h/月** | **70〜80%** | |

## 2. ボトルネック詳細分析

### 2.1 見積書作成（最大の工数源）

**症状**:
- 同じ情報（会社名・住所・日時・会場）を企画書・見積・請求書で毎回再入力
- 協力会社から取り寄せた見積を手作業で転記・集計
- パース画像・図面を別ツールで作成→貼り付け
- 割引率・手数料率（パススルー20%）の計算が手計算

**同じ情報を何度も入力している例**:
| 情報 | 企画書 | 見積書 | 請求書 | 実施計画書 |
|------|--------|--------|--------|-----------|
| 案件名 | ○ | ○ | ○ | ○ |
| 顧客名 | ○ | ○ | ○ | ○ |
| 日時・会場 | ○ | ○ | ○ | ○ |
| 金額 |  | ○ | ○ |  |
| 品目リスト | ○ | ○ |  | ○ |

→ **5項目 × 4書類 = 20回の入力機会のうち、少なくとも12回が重複**

### 2.2 確認・承認の滞留

**現状の承認チェーン**:
```
担当者 作成 → 佐藤さん 確認 → kim 承認 → 顧客へ送付
           ↑                          ↑
       滞留しやすい（1〜2日）     滞留しやすい（半日〜1日）
```

**滞留原因**:
- kim の確認が必要な文面が散発的に発生（判断待ち）
- 過去の類似案件との比較が手作業
- 金額・割引の根拠をその都度説明

### 2.3 担当者による進め方の違い

| プロセス | 佐藤さん | 他の担当者（想定） |
|---------|---------|-----------------|
| 見積フォーマット | 案件のGrowiマニュアル参照 | 過去事例のコピー改変 |
| 手数料計算 | パススルー20%を手計算 | ルールを知らない場合あり |
| 協力会社への発注 | 電話＋メール | メールのみ |
| 完了報告 | 案件フォルダに集約 | 口頭のみ |

### 2.4 本当に必要な作業の精査

**実は不要または削減可能な作業**:
1. **手計算の見積合計**: シートの自動計算が有効なら手作業不要
2. **同じ内容の口頭説明**: メール＋チャットで済む報告を口頭で説明
3. **過去事例の手動検索**: Growi/Driveで管理されているが、どこにあるか探す時間がかかる
4. **印刷・スキャン・PDF変換**: デジタル完結可能な工程

## 3. AI自動化提案

### 3.1 【P0】見積書自動作成エージェント

**概要**: Claude Code + Google Sheets API で見積書作成を自動化

**自動化する工程**:
1. ヒアリングシートの入力 → 企画書のドラフト生成（Claude Code）
2. 過去の類似案件から単価を自動参照（Growi/Drive検索）
3. パススルー20%を含む見積計算（自動計算）
4. 企画書・見積書のGoogle Docs/Sheets作成（GAS）
5. 社内確認依頼の自動通知（Discord）

**必要な既存アセット**:
- 見積ルール: `reference-estimate-proposal-rulebook.md`（Drive）
- Growiマニュアル: p0890/p2608
- 案件一覧マスター

**工数見積もり**:
| 工程 | 現状（手動） | 自動化後 | ツール |
|------|-----------|---------|-------|
| 企画書ドラフト | 2〜3h | 5min | Claude Code |
| 見積計算 | 1〜2h | 1min | Google Sheets |
| 書類作成 | 1〜2h | 3min | GAS + Drive API |
| 社内確認依頼 | 0.5h | 0min | Discord自動通知 |
| **合計** | **4.5〜7.5h** | **約10min** | |

### 3.2 【P0】案件進捗管理自動化

**概要**: 案件の状態を自動追跡し、次アクションを提案

**現在の課題**:
- 案件一覧マスターの更新が手作業（GASボタン操作が必要）
- 次に何をすべきかが曖昧
- 期限切れの判断依頼が放置される

**自動化案**:
1. **進捗状態の自動更新**: Claude Code が案件フォルダの最新ファイルから状態を読み取り、一覧を更新
2. **次アクション提案**: 案件の状態に応じて「次にやること」を自動生成
3. **期限アラート**: 期限が近い案件の自動通知（Discord）
4. **判断依頼の追跡**: kim-inbox の未回収項目を自動リマインド

**既存の活用可能なツール**:
- `case-handoff.mjs` — 案件の引継ぎ・状態管理
- `case-progress-digest.mjs` — 進捗ダイジェスト生成
- `kim-inbox.mjs` — kim への判断依頼管理
- `auto-progress-ledger.mjs` — 自動進捗管理

### 3.3 【P1】サイト更新ワークフロー自動化

**概要**: 事例記事・ブログ記事の作成から公開までを半自動化

**自動化案**:
1. **取材メモ→記事原稿**: Claude Code が取材メモから記事ドラフトを生成
2. **画像自動加工**: 画像のリサイズ・WebP変換・altテキスト生成
3. **CMS入力補助**: 構造化データ・meta description の自動生成
4. **SEO設定**: タイトル・H1・内部リンクの最適化提案
5. **SNS告知文生成**: X・LinkedIn投稿文の自動生成

**活用可能な既存アセット**:
- `docs/ai-news-x0063-seo-ai-search-checklist.md` — SEOチェックリスト
- `seo-blog-images` skill — 画像SEO
- `youtube-seo` skill — 動画SEO
- `internal-linking` skill — 内部リンク最適化

### 3.4 【P1】メール問い合わせ対応自動化

**概要**: 定型問い合わせの一次回答をAIで自動生成

**自動化案**:
1. **問い合わせ分類**: 問い合わせ内容を自動分類（見積依頼/質問/クレーム/その他）
2. **FAQ自動回答**: 定型質問への回答を自動生成（確認後送信）
3. **見積依頼のヒアリングシート自動作成**: 必要な情報をリスト化

**注意**: 社外送信はkim承認必須。自動生成＋人間確認のハイブリッド。

### 3.5 【P2】出展者募集・発送業務の自動化

**概要**: 催事の出展者募集から発送案内までを自動化

**自動化案**:
1. **募集メールの一括生成**: 出展候補企業への個別文面を自動生成
2. **出展者管理シートの自動更新**: 申込状況・入金状況の自動追跡
3. **発送案内の自動生成**: 配送先・日程の個別案内

## 4. 自動化ロードマップ

### 4.1 フェーズ分け

```
Week 1-2 (今週〜来週)     Week 3-4               Week 5-8
├── P0: 見積自動化 ──────→ 検証・改善 ──────→ 本番定着
├── P0: 進捗管理自動化 ──→ 検証・改善 ──────→ 本番定着
│                           ├── P1: サイト更新 ─→ 検証・改善
│                           ├── P1: メール対応 ─→ 検証・改善
│                           │                     ├── P2: 出展者業務
```

### 4.2 週次マイルストーン

| 週 | やること | 成果物 |
|----|---------|--------|
| 1 | ①見積プロセスの棚卸（Phase 1）②頻度・優先度の確定 ③既存ツールの棚卸 | 業務インベントリ（20項目以上） |
| 2 | ①見積書作成の文書化（Phase 2）②進捗管理の文書化 ③最初の自動化プロトタイプ | 文書化された手順書、プロトタイプ |
| 3 | ①品質安定化の計測（Phase 3）②2名で手順書の検証 ③手戻り率の記録 | 安定化指標の計測結果 |
| 4 | ①見積エージェントの実装開始（Phase 4）②進捗管理エージェントの実装 | AIエージェントv1 |
| 5〜8 | ①実運用での検証 ②フィードバック反映 ③サイト更新・メール対応の順次着手 | 運用定着、拡張 |

### 4.3 まず今週やること

```
□ 1. 見積書作成の工程を1件分、ステップ単位で書き出す（30分）
□ 2. 過去3件の見積書を比較し、共通パターン・変動パターンを抽出（1時間）
□ 3. Growiマニュアル（p0890/p2608）と照合して判断基準を整理（30分）
□ 4. 案件進捗管理の「次にやること」を自動生成するプロトタイプを作成（2時間）
□ 5. 週次の作業ログを取り、工数実測を開始（随時）
```

## 6. リスクと対策

| リスク | 対策 |
|--------|------|
| AIが間違った金額を出力 | 社内確認フローを維持（AI生成→人間確認→送信） |
| 過去データの品質不足 | 自動化対象を「ルール明確な業務」から開始 |
| 担当者の抵抗 | 補助ツールとして導入し、強制置き換えはしない |
| セキュリティ（顧客情報の漏洩） | API経由のデータは最小限に、ローカル処理を基本 |
| モデルの品質変動 | 出力の自動チェック（金額の桁・フォーマット）を実装 |
