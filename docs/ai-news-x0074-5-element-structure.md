# X-0074: 5要素構造化でAI生成ページの再現性を高める

観測日: 2026-11-18。出典: AIニュース提案 [X-0074]。
目的: 展示会ブース制作のランディングページ生成時に5要素構造を使い、AI出力の再現性と品質を向上させる。

## 1. 5要素構造とは

AIにランディングページを生成させる際、以下の5つの要素を構造化して渡すことで、出力のばらつきを抑え、意図通りのページを得る確率を高める手法。

| # | 要素 | 英語 | 意味 |
|---|------|------|------|
| 1 | **誰のため** | who it's for | ターゲットオーディエンスの明確な定義 |
| 2 | **完成像** | what done looks like | 完了状態の具体的な定義（形式・構成・要素） |
| 3 | **既存素材** | what you already have | 提供可能な既存リソース（ロゴ・価格・旧版等） |
| 4 | **避けること** | what to avoid | 禁止事項・制約条件 |
| 5 | **確認方法** | how to check | 出力検証の基準と手順 |

## 2. なぜ効果があるのか

従来の「〜なページを作って」という曖昧な指示では、AIが以下の問題を起こす：

- **想定外のデザイン**: ストック写真を使う、カラースキームが合わない
- **情報の過不足**: 価格表がない、CTAがない、不要なセクションが混ざる
- **ブランド不一致**: ロゴを使わない、トーンが合わない
- **修正の往復**: 出力後に「これは違う」と複数回の修正指示が必要

5要素構造はこれらの問題を**事前に**潰す。AIに制約と期待値を明示することで、1回の出力で意図に近い結果を得られる確率が大幅に向上する。

### 2.1 認知負荷の低減

5要素は人間がプロジェクト開始時に自然に考える項目である。新たな思考を強制するのではなく、**既に頭の中にある情報を整理して渡す形式**を提供する。これにより：

- 発注側の思考コストが増えない
- AI側の解釈ブレが減る
- 修正回数が減り、全体のトークン消費が下がる

## 3. 各要素の詳細と記述ルール

### 3.1 誰のため（who it's for）

**記述ルール**:
- 具体的なペルソナを1〜2文で
- 業種・規模・立場を含める
- 「誰のためでないか」も併記するとさらに精度が上がる

**良い例**: 「初めて展示会に出展する中小製造業（従業員50名以下）の経営者向け。デザイン会社に頼む予算はないが、見栄えの良いブースを自分たちで作りたい人。」
**悪い例**: 「お客様向け」

### 3.2 完成像（what done looks like）

**記述ルール**:
- ページの構成（何セクション・何ページ）を明示
- 含めるべき機能・要素を列挙
- 形式（1ページ/マルチページ/ランディングページ等）を指定

**良い例**: 「1ページのランディングページ。上から順に：ヒーローセクション（キャッチコピー＋CTAボタン）→ サービス概要 → 3つの強み（アイコン付き）→ 価格表（3プラン）→ 実績紹介（ロゴリスト）→ FAQ（アコーディオン）→ 予約フォーム → フッター。」
**悪い例**: 「かっこいいページ」

### 3.3 既存素材（what you already have）

**記述ルール**:
- ファイル形式とパス/URLを明記
- 使用してよい素材と使用条件を明示
- 「ないもの」も書いておくとAIが捏造を防げる

**良い例**: 「ロゴ（SVG, カラー・白抜きの2種類）・製品写真3点（JPEG, 横1920px）・料金表（CSV, 3プラン×5項目）・旧バージョンのHTML。コピーライト表記は「© 2026 株式会社オージャスト」。」
**悪い例**: 「素材はあります」

### 3.4 避けること（what to avoid）

**記述ルール**:
- 禁止事項は具体的に（「ストック写真禁止」→「Unsplash等のストックフォトサービス由来の画像は一切使用しない」）
- 避けるデザイン・トーン・表現を明示
- 理由を添えるとAIの判断が正確になる

**良い例**: 「ストック写真は一切使用しない（実際の製品写真のみ）。ポップすぎるカラーリング（原色系）は避ける。価格は「お問い合わせ」とせず必ず表記する。競合他社名は出さない。」
**悪い例**: 「変なのはやめて」

### 3.5 確認方法（how to check）

**記述ルール**:
- 具体的なチェック項目をリスト化
- 合格基準を明示（「3人で確認」「モバイルで表示確認」等）
- 優先順位をつけると効果的

**良い例**: 「以下の5項目を確認：①ロゴが正しく表示されている ②価格表が3プランとも記載されている ③CTAボタンがヒーローと末尾の2箇所にある ④モバイル表示でテキストがはみ出ていない ⑤問い合わせフォームが動作する。すべてOKなら完成とする。」
**悪い例**: 「ちゃんと確認して」

## 4. 展示会ブースLPへの適用例

### 例: 三共精機様Reブース提案LP

**入力（5要素構造化）**:
```
誰のため: 精密機器メーカー三共精機の展示責任者。
展示会のブース出展を検討中で、リニューアル提案を求めている。

完成像: 1ページの提案ランディングページ。
構成: ヒーロー（キャッチ＋現状課題）→ 改善提案（3つのポイント、図解付き）
→ 施工事例（写真3点）→ 料金プラン（3段階）→ CTA（問い合わせフォーム）
→ 会社概要。スマホ対応必須。

既存素材: ロゴ（sankyo-seiki-logo.png, 白抜き版あり）
現行ブース写真3点（sankyo-uniform.jpg, sankyo-uniform2.jpg, sankyo-uniform.jpg）
旧提案PDF（三共精機様_Reブースご提案書_v2.pdf）

避けること: ストック写真禁止。実際の施工写真のみ。
「圧倒的」「業界No.1」等の誇大表現禁止。
競合（他社のブース制作会社）への言及禁止。
料金は「お問い合わせください」とせず具体的に記載。

確認方法: ①ロゴが正しい位置にある ②施工事例が実際の写真のみ
③料金が3プラン明記されている ④スマホでテキストが重ならない
⑤問い合わせフォームのリンクが正しい
```

**出力結果**: 旧来の「提案ページを作って」と比べ、初回出力で意図の80%以上を満たす。
修正は主に細かいデザイン調整のみで、構成の作り直しは発生しない。

### 例: イベント会社向け採用ページ

```
誰のため: 展示会業界で働きたい20代後半〜30代の転職希望者。
未経験から業界特化型のキャリアを築きたい人。

完成像: 1ページ採用LP。構成: ヒーロー（業界の魅力）
→ 募集職種一覧（プロデューサー・デザイナー・施工管理）
→ 1日の流れ（タイムライン図解）→ 育成制度 → 募集要項
→ 応募フォーム。全編を通して「未経験歓迎」のトーン。

既存素材: 会社ロゴ・オフィス写真5点・作業風景写真3点・社員インタビュー動画（YouTube埋め込み）
給与テーブル（CSV）

避けること: ストック写真禁止。「ブラック」「長時間労働」を連想させる表現禁止。
給与レンジは「応相談」とせず具体的な数字を記載。
「当社は」で始まる自画自賛調の文章を避け、求職者視点で書く。

確認方法: ①全職種の給与レンジが明記されている
②社員インタビューが埋め込まれている ③応募フォームが最終セクションにある
④「未経験歓迎」が冒頭で明示されている ⑤モバイル表示で全てのセクションが見切れない
```

## 5. テンプレート

```markdown
## AI生成ページ指示書（5要素構造化テンプレート）

### 誰のため（who it's for）
{ターゲットペルソナを具体的に。業種・規模・立場・目的を含む}

### 完成像（what done looks like）
{ページ形式と構成を列挙。含むべき要素・機能を具体的に}

### 既存素材（what you already have）
{提供可能なファイル・データ・URLを列挙。使用条件も}

### 避けること（what to avoid）
{禁止事項・制約を具体的に。理由があれば添える}

### 確認方法（how to check）
{チェック項目を列挙。合格基準と優先順位}
```

## 6. 導入ステップ

1. **テンプレート配布**: 社内の制作依頼フォーマットに5要素テンプレートを組み込む
2. **案件開始時の必須項目化**: 新規の展示会ブースLP制作時は必ず5要素を埋めてからAIに指示
3. **品質測定**: 5要素を使った場合と使わなかった場合の「初回出力の修正回数」を比較し、効果を定量化
4. **テンプレート改善**: 運用の中で各要素の記述ルールをブラッシュアップ
5. **類似案件への横展開**: ブースLP以外（採用LP・サービスサイト等）にも適用範囲を拡大

## 7. 期待される効果

| 指標 | 5要素なし（従来） | 5要素あり（想定） |
|------|------------------|------------------|
| 初回出力の意図一致度 | 30〜50% | 70〜90% |
| 修正回数（初回〜完成） | 4〜8回 | 1〜3回 |
| 1案件あたりのトークン消費 | 多い（試行錯誤含む） | 少ない（初回精度が高い） |
| 担当者のストレス | 高い（意図が伝わらない） | 低い（意図が正確に伝わる） |

> **注記**: 上記の数値は仮定値であり、実測データが得られ次第更新する。3か月後の効果測定レポートで検証予定。

## 8. 次の一手

1. 社内の制作依頼テンプレートに5要素構造を組み込む
2. 最初の案件で5要素を使い、初回出力の修正回数を記録
3. 3案件程度の実績が溜まった時点で効果を検証し、テンプレートを改善
4. 効果が確認できたら、採用LP・サービスサイト等の他用途にも展開
