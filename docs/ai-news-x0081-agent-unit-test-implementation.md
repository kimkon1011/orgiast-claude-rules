# X-0081: AIエージェント機能単位実装＋テスト — 1機能ごとに実装し即座にテストコード生成するワークフロー

観測日: 2026-11-18。出典: AIニュース提案 [X-0081]。
目的: AIエージェントの機能を小さな単位に分解し、1機能実装するごとに即座にテストコードを生成するワークフローを確立する。株式会社オージャストではイベント管理ツールやウェブサイト機能追加において、この「実装→即テスト」サイクルをAIエージェントに委譲し、品質を保ちながら開発速度を向上させる。

## 1. 問題: AIエージェントの実装はテストが後回しになる

AIエージェントに機能実装を委譲する際、以下の問題が頻発する:

| 問題 | 実害 |
|------|------|
| 実装後にテストを「後で書く」と先送り | テストが永遠に書かれない |
| 全機能を一括実装してからテスト | どの機能が壊れているか特定困難 |
| テストコードの生成を別タスクに分離 | コンテキスト切替で非効率 |
| 手動テストのみで済ませる | 回帰バグを検出できない |

これらの問題の根本原因は **「実装」と「テスト」を別々のタスクとして扱う** ことにある。

## 2. 解決策: 機能単位実装＋即テストワークフロー

### 2.1 基本原則

```
1機能 = 1実装 + 1テスト
```

1機能の実装が終わったら、**次の機能に移る前に** その機能のテストコードを生成する。この順序を厳守することで:

- 各機能が独立して検証可能になる
- どの機能で不具合が出たか即座に特定できる
- 回帰テストが自動的に蓄積される
- テストがない状態が生まれない

### 2.2 ワークフロー

```
機能Aの実装 → 機能Aのテスト生成 → テスト実行・合格確認
  ↓
機能Bの実装 → 機能Bのテスト生成 → テスト実行・合格確認
  ↓
...
```

各サイクルは **3分以内** で完了する小単位に分割する。

### 2.3 機能分割の基準

1機能は以下の条件を満たす:

- **入出力が明確**: 関数の引数と戻り値が定義できる
- **副作用が最小**: ファイルIO・ネットワークを含まない（モック可能）
- **テストが高速**: ミリ秒単位で完了する
- **単一責任**: 「1つのこと」だけをする

## 3. 実践例: イベントリマインダー機能の実装

オージャストの内部イベント管理ツールを例に、実際のワークフローを示す。

### 3.1 機能分割

```
機能1: リマインダー種別の判定（daysUntilから種別を返す）
  → テスト: 残日数ごとの期待種別を検証

機能2: リマインダーメッセージの生成（種別＋イベント名から文面生成）
  → テスト: 種別ごとの期待メッセージを検証

機能3: 通知対象イベントのフィルタリング（日付条件で絞り込み）
  → テスト: 境界値（当日・期限切れ・未来）を検証
```

### 3.2 テスト構造

各テストは以下の構造に従う:

```javascript
import { describe, it } from 'node:test';
import assert from 'node:assert/strict';

describe('機能名', () => {
  it('正常系: 期待する動作', () => {
    // Arrange（準備）
    // Act（実行）
    // Assert（検証）
  });

  it('異常系: エッジケース', () => {
    // 境界値・エラーケース
  });
});
```

## 4. オージャストでの適用対象

以下の領域で本ワークフローを適用する:

| 領域 | 対象機能 | 期待効果 |
|------|---------|---------|
| イベント管理 | リマインダー・通知・スケジュール調整 | 機能追加時の品質担保・回帰防止 |
| ウェブサイト機能 | 問い合わせフォーム・コンテンツ管理 | リリース前のテスト網羅 |
| AIエージェント | タスク実行・分類・抽出 | 実装と同時に検証可能に |

## 5. 成功定義

- [ ] 1機能の実装→テスト完了までの時間が3分以内
- [ ] 機能単位のテストが独立して実行可能（他機能の状態に依存しない）
- [ ] 全テストが `node --test` で緑になる
- [ ] 新規機能追加時にテストが同時に生成される習慣が定着する
