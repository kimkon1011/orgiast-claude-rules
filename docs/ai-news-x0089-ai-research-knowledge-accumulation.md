# X-0089: AIリサーチを知識蓄積型に進化 — 競合ブース制作会社事例を横断リサーチしSEO/LLMO改善へ

観測日: 2026-11-19。出典: AIニュース提案 [X-0089]。
目的: Webサイト・学術論文・企業開示資料を横断的に徹底情報収集し、質問分解からレポート作成まで最大16ステップで深掘り、4つのAIが異なる視点からダメ出し・改善、引用元が主張を裏付けているか検証、収集情報を検索可能なデータベースに保存し再利用するワークフローを構築する。株式会社オージャストでは競合ブース制作会社の事例をリサーチし自社サイトのSEO/LLMO改善に使う。

## 1. 問題: AIリサーチが1回限りの使い捨てになっている

現在、展示会ブース制作業界におけるAIを活用したリサーチには以下の問題がある:

| 問題 | 実害 |
|------|------|
| リサーチ結果がセッション内で消費され、次に活かせない | 同じ調査を繰り返す。業界知識が蓄積されない |
| 単一AIの出力をそのまま受け入れる | 視点の偏り・ハルシネーションを見過ごす |
| 引用元を検証しない | 存在しないURLや誤った主張をそのまま使う（AIニュース提案リンクの67/311=22%が404の実例） |
| 競合リサーチが属人的で再現性がない | 担当者ごとに品質がばらつく |

これらの根本原因は **「リサーチを一回限りのタスクとして扱い、知識を蓄積・再利用する仕組みがない」** ことにある。

### 業界背景: 展示会ブース制作のAI検索市場が急拡大

2026年の調査では展示会ブース制作会社は**119社**がAI回答に登場する分散型市場であり、AIが根拠とする情報源の**74.9%が自社公式サイト**である（AI検索パートナーズ, 2026年11月）。ナレッジホールディングスはAI引用を3件→19件（+533%）、DRを12→27に向上させており、ランクエスト×TRAアートは施策開始1ヶ月で「展示会ブース 制作」の検索順位を16位→6位に改善している。競合が本格着手する前に、自社サイトの作例ページに小間数・工法・業種・施工日数などのテキスト情報を充実させ、外部メディアからの被リンクを獲得し、Q&A形式のコラムを整備するのが効果的である。

## 2. 解決策: 知識蓄積型AIリサーチワークフロー

### 2.1 基本原則

```
1リサーチ = 徹底収集 + 多視点評価 + 検証 + データベース蓄積
```

各リサーチを「発見した知識を永続的に蓄積する装置」として設計する。

### 2.2 アーキテクチャ全体像

学術研究（AutoKD, AI-Supervisor, FS-Researcher, FlowSearch, paperKB, Sage Research）で確立された共通アーキテクチャを採用する:

```
[Phase 1] 質問分解 (Question Decomposition)
  1つの大きな質問を5〜8のサブ質問に分解
  Planner/Supervisor AI が構造化
       ↓
[Phase 2] 並列収集 (Parallel Research)
  各サブ質問を独立したAIエージェントが担当
  Webサイト・学術論文・企業開示資料を横断
       ↓
[Phase 3] 多視点評価 (Multi-AI Critique)
  4つの異なるAIが成果物にダメ出し
  観点: 正確性・網羅性・実用性・リスク
       ↓
[Phase 4] 引用検証 (Source Verification)
  全引用元のURLに機械的に到達確認
  主張と引用の整合性を検証
       ↓
[Phase 5] 知識蓄積 (Knowledge Persistence)
  検証済みの知見を検索可能なデータベースに保存
  洞察グラフ（Insight Graph）として構造化
       ↓
[Phase 6] レポート生成 (Report Assembly)
  蓄積された知識からSEO/LLMO改善レポートを出力
```

### 2.3 各Phaseの詳細

#### Phase 1: 質問分解

入力: 1つの大きなリサーチクエリ（例: 「競合ブース制作会社5社のSEO戦略を調査」）

出力: 5〜8のサブ質問（例: 「各社のコアコンテンツ戦略」「被リンク獲得元」「AI検索での引用状況」「構造化データの実装有無」「作例ページのテキスト充実度」「サイト構造と内部リンク」「ソーシャルシグナル」「採用しているCMS/テクノロジー」）

実装: Supervisor AI（Opus/Fable）が分解し、各サブ質問に優先度と依存関係を付与。独立したサブ質問は並列実行、依存関係のあるものは直列実行。

#### Phase 2: 並列収集

各サブ質問に対して:
1. **Web検索**: Brave Search / WebSearch API で該当ページを収集
2. **深掘り**: 該当ページの全文を取得し、該当箇所を抽出
3. **学術論文検索**: arXiv等から関連論文を検索（ブース制作のリサーチでは二次的に活用）
4. **企業開示資料**: 該当企業のプレスリリース・IR情報を収集

出力: サブ質問ごとの調査ノート（引用元付き）

#### Phase 3: 多視点評価

4つのAIが異なる観点から成果物を評価:

| AI | 観点 | チェック項目 |
|----|------|------------|
| AI 1 | 正確性 | 事実誤認・数値の誤り・時代遅れの情報 |
| AI 2 | 網羅性 | 見落としている競合・視点・データソース |
| AI 3 | 実用性 | オージャストで実際に使えるか・優先順位 |
| AI 4 | リスク | 競合に気づかれる・法的リスク・コスト対効果 |

各AIは「改善提案」と「その根拠」を構造化して出力する。

#### Phase 4: 引用検証

全引用元のURLに対して:
1. **到達確認**: HTTPステータスコード確認（AIニュース提案リンクの22%が404だった実例を踏まえる）
2. **内容一致**: 引用箇所の前後文脈を取得し、主張と一致するか確認
3. **重複排除**: 同じ情報源からの複数引用を統合

検証結果を「✅ 検証済み / ⚠️ 一部一致 / ❌ 不一致 / 🔗 到達不能」でタグ付け。

#### Phase 5: 知識蓄積

検証済みの知見を永続的データベースに保存:

1. **洞察グラフ（Insight Graph）**: ノード=知見、エッジ=関係性（深掘り・拡張・矛盾）で構造化。AutoKD方式を採用し、発見がラウンドを超えて蓄積される。
2. **ファイルシステム保管（FS-Researcher方式）**: 階層的なMarkdownノートとしてファイルシステムに保存。コンテキストウィンドウ制限を超えてスケール可能。
3. **検索インターフェース**: 保存された知識を後続のリサーチで再利用可能にする。

#### Phase 6: レポート生成

蓄積された知識から:
1. **SEO改善レポート**: 競合比較から自社の改善点を抽出
2. **LLMO対策レポート**: AI検索での自社引用状況と改善策
3. **コンテンツ企画**: 競合にない差別化コンテンツの提案

### 2.4 オージャストでの適用: 競合ブース制作会社リサーチ

#### 初期ターゲット（フリーランス名鑑で比較対象となった5社）

| 会社 | 特徴 | リサーチ観点 |
|------|------|------------|
| エイチリンク | AIO対策の実績 | 施策内容・効果・コスト |
| PLAN-B | ブース制作特化 | 作例ページ構成・テキスト量 |
| Mesut | デザイン重視 | ポートフォリオ��造・SEO |
| StockSun | 施工実績多数 | サイト規模・被リンク |
| LANY | 空間デザイン | メディア掲載・引用状況 |

#### リサーチクエリ例

1. 「展示会ブース制作会社トップ10のSEO戦力比較」
2. 「各社の作例ページに含まれるテキスト情報の充実度」
3. 「各社のAI検索（ChatGPT/Perplexity/Google AI Overviews/Copilot）での引用状況」
4. 「各社の被リンクプロファイルと獲得元メディア」
5. 「各社の構造化データ（JSON-LD）実装状況」
6. 「各社のQ&Aコラム・FAQページの有無と内容」
7. 「各社のサイト速度・コアウェブバイタル」
8. 「ブース制作業界全体のAI検索トレンドと今後の変化」

#### 期待効果

- 競合のSEO戦略を体系的に把握し、自社の差別化ポイントを特定
- AI検索で自社が引用される条件を特定し、サイト改善に反映
- 業界知識がデータベースに蓄積され、新規企画・見積・提案の品質が向上
- リサーチの再現性が確保され、担当者変更の影響を受けない

## 3. 学術的基盤

本提案は以下の学術研究で確立されたアーキテクチャを実用化する:

| 研究 | 発表年 | 主要貢献 | オージャストでの活用箇所 |
|------|--------|---------|----------------------|
| AutoKD (arXiv 2609.06366) | 2026 | 6エージェント協調＋洞察グラフ永続化 | Phase 3（多視点評価）＋ Phase 5（知識蓄積） |
| FS-Researcher (arXiv 2602.01566) | 2026 | ファイルシステムベース外部記憶 | Phase 5（知識蓄積のファイルシステム保管） |

## 4. 実装計画

### Phase 1: プロトタイプ（1〜2週間）

1. 質問分解エージェントの実装（Supervisor AIでサブ質問生成）
2. Web検索エージェントの実装（Brave Search / WebSearch API）
3. 単一サブ質問の調査→レポート生成のパイプライン

### Phase 2: 多視点評価の導入（2〜3週間）

4. 4AI評価システムの実装（正確性・網羅性・実用性・リスク）
5. 引用検証エンジンの実装（URL到達確認＋内容一致チェック）
6. 競合5社の初期リサーチ実行

### Phase 3: 知識蓄積基盤（3〜4週間）

7. 洞察グラフの設計と実装（AutoKD方式）
8. 検索インターフェースの実装
9. リサーチ結果のデータベース蓄積

### Phase 4: 本番運用（4〜6週間）

10. 競合リサーチの定期実行（月次サイクル）
11. SEO/LLMO改善レポートの自動生成
12. 蓄積知識のサイト改善へのフィードバックループ

## 5. 成功定義

- [ ] 競合5社のSEO戦略を体系的に比較したレポートが生成できる
- [ ] 各リサーチの引用元検証率が100%（到達不能は赤タグ）
- [ ] 4AI評価で修正された最終成果物の品質が単一AI比で向上
- [ ] 蓄積された知識を後続リサーチで再利用できる
- [ ] リサーチ結果から実際のサイト改善（作例ページテキスト充実・Q&Aコラム追加）に繋がる
- [ ] 月次サイクルで競合の変化を追跡できる
