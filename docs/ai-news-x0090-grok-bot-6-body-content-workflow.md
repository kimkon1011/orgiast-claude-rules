# X-0090: Grok Bot 6体で再現可能コンテンツワークフロー — 展示会トーク録音をSEOコンテンツ量産へ

**AIニュース提案 X-0090**: 41分の未編集トークと12の保存リンクを入力として、6体のGrok Botエージェントが分担してフルスタックのコンテンツパッケージ（4アングル抽出・全文書き起こし・3縦クリップ・5投稿＋1ニュースレター・20通りバリエーション）を生成する再現可能ワークフロー。1ボット1ジョブのルールと下書きのみの安全設計で、無断投稿ゼロを担保する。株式会社オージャストでは展示会トーク録音をイベントサイト用SEOコンテンツ生成に応用する。

観測日: 2026-11-19

---

## 1. 概要

### 1.1 問題: 展示会・イベントのトーク録音が活用されない

展示会やイベントでのトーク・セミナー録音は、当日の配信やアーカイブだけで終わり、SEOコンテンツとして再利用されることは稀である。

| 課題 | 実態 | 影響 |
|------|------|------|
| **手作業の多さ** | 書き起こし→編集→クリップ作成→投稿まで全て人手 | 1本のトークから複数コンテンツを作る余力がない |
| **品質のバラつき** | 担当者ごとに編集方針・切り口が異なる | ブランドの一貫性が損なわれる |
| **再現性の欠如** | 毎回イチからの作業フロー設計 | 属人化し、担当交代で停止する |
| **タイムラグ** | イベントからコンテンツ公開まで数週間〜数ヶ月 | 検索需要のピークを逃す |

**従来の代替案**:
- 人力で書き起こし・編集（1本あたり3〜5時間）
- 動画編集ツール（Adobe Premiere / DaVinci Resolve）で手作業クリップ作成
- SNS運用ツール（Buffer / Hootsuite）で個別投稿スケジュール
- いずれも**人件費が高く、再現性が低い**

### 1.2 解決: 6体のGrok Botが分担するコンテンツパイプライン

6体のGrok Botエージェントが1ジョブずつ担当し、直列パイプラインでコンテンツを生成する。

```
[入力] 41分未編集トーク音声 + 12保存リンク
  │
  ├─ Agent 1: リンクから4アングル抽出 ──────────→ 4つの切り口
  ├─ Agent 2: 全文書き起こし ──────────────────→ 文字起こし全文
  ├─ Agent 3: 縦クリップ×3（キャプション・フック付き）→ 3本のショート動画原稿
  ├─ Agent 4: SNS投稿×5 ─────────────────────→ 5つの投稿下書き
  ├─ Agent 5: ニュースレター×1 ───────────────→ メルマガ原稿
  └─ Agent 6: 20通りパッケージ化 ─────────────→ フォーマット別完成品
```

**3つの運用ルール**:
1. **1ボット1ジョブ** — 各エージェントの役割を初回メッセージに明示し、混同を防ぐ
2. **スキル保存→テスト→スケジュール** — ワークフローをGrok Botのスキルとして保存し、テスト実行後に定期実行を設定
3. **下書きのみ・承認待ち** — 生成されたコンテンツはすべて下書き状態で、無断投稿ゼロを担保

**実績**: 41分トーク＋12リンクから、8件の下書き（5投稿＋1ニュースレター＋2クリップ台本）を0件の無断投稿で生成。20通りのフォーマットバリエーションに対応。

## 3. 3つの運用ルール（無断投稿ゼロの鍵）

### ルール1: 1ボット1ジョブ

**内容**: 各Grok Botエージェントには1つのジョブだけを割り当て、初回メッセージに役割を明示する。

```
❌ 悪い例: 「このリンクを分析して、書き起こして、クリップも作って」
✅ 良い例: 「あなたの役割はリンク解析です。12のリンクから4つのアングルを抽出してください。」
```

**なぜ必要か**: 複数ジョブを1体に任せると、トークン制限に達して後半のジョブが未完了になる。また、出力フォーマットが混在して後続エージェントが処理できない。

### ルール2: スキル保存 → テスト → スケジュール

**流れ**:
1. ワークフローをGrok Botのスキルとして保存する
2. テスト実行で全エージェントが正常に連携することを確認する
3. スケジュール実行を設定し、定期運用を開始する

**スキル保存のテンプレート**:
```
スキル名: Exhibition Talk → Content Package
トリガー: 「[トーク音声ファイル]と[関連リンク]からコンテンツパッケージを生成」
手順:
  1. Agent 1 (アングル抽出) を起動: [指示文]
  2. Agent 1の出力をAgent 2 (書き起こし) に渡す: [指示文]
  3. Agent 1+2の出力をAgent 3 (縦クリップ) に渡す: [指示文]
  4. Agent 1+2+3の出力をAgent 4 (SNS投稿) に渡す: [指示文]
  5. Agent 1+2+3+4の出力をAgent 5 (ニュースレター) に渡す: [指示文]
  6. 全出力をAgent 6 (パッケージング) に渡す: [指示文]
出力: 下書きフォルダに全コンテンツを保存
```

### ルール3: 下書きのみ・承認待ち

**内容**: 生成されたコンテンツはすべて下書き状態で保存し、自動投稿は行わない。人間の承認を経て公開する。

| 状態 | 説明 | 次のアクション |
|------|------|--------------|
| **下書き** | Grok Botが生成した初期状態 | 人間が確認・編集 |
| **レビュー中** | 品質チェック・事実確認中 | 編集者が修正・承認 |
| **公開準備完了** | 承認済み・スケジュール待ち | 公開日時に自動投稿 |
| **公開済み** | 各プラットフォームで公開完了 | パフォーマンス測定 |

**安全設計の根拠**: 無断投稿はブランド毀損・法的リスクを伴う。AIの自動投稿は業界でも事故が相次いでおり、**下書き停止は必須のガードレール**である。

## 5. 株式会社オージャストでの適用案

### 5.1 展示会トーク録音 → イベントサイトSEOコンテンツ

オージャストの展示会ブースで収録したトーク（来場者トーク・スタッフ解説・ゲストスピーカー）を、以下の流れでイベントサイト用SEOコンテンツに変換する。

```
[展示会当日] トーク録音（10〜30分）
  │
  ├── Grok Bot Agent 1: トーク内容から4つのSEOキーワードアングルを抽出
  │     └── 展示会名・ブーステーマ・製品名・業界課題
  │
  ├── Grok Bot Agent 2: 全文書き起こし → イベントレポートのベース
  │
  ├── Grok Bot Agent 3: 縦クリップ×3 → Instagram Reels / TikTok / YouTube Shorts
  │
  ├── Grok Bot Agent 4: SNS投稿×5 → 展示会ライブ感の演出
  │
  ├── Grok Bot Agent 5: ニュースレター → リード獲得
  │
  └── Grok Bot Agent 6: パッケージング → イベントサイトの20ページ分のコンテンツ

[イベントサイト]
  ├── ブログ記事（フル・要約）
  ├── FAQ（来場者からよく聞かれる質問）
  ├── ランディングページ（次回展示会の誘導）
  └── メディアキット（プレス向け）
```

### 5.2 SEO効果の期待値

| 指標 | 改善前（録音放置） | 改善後（コンテンツ化） |
