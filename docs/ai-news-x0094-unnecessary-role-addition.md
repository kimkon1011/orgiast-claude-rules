# X-0094: 余分な役割追加を測って止める — サブエージェント乱用防止とトークン監視

**AIニュース提案 X-0094**: サブエージェント・役割（ロール）を追加するたびにトークン消費が跳ね上がり、成功率が下がる実測データに基づき、役割追加の前に効果とコストを測定するルールを確立する。

観測日: 2026-11-20

---

## 1. 問題: 役割追加が無意識にコスト爆発と品質低下を招く

AIエージェントに「〇〇役」「△△レビュアー」などの役割（ロール）を追加すると、プロンプトが長くなりトークン消費が増えるだけでなく、かえって成功率が低下する実測がある。

| 比較 | トークン消費 (相対値) | 成功率 |
|------|----------------------|--------|
| チャット (役割なし) | 1× (基準) | — |
| エージェント (単一役割) | 約4× | — |
| マルチエージェント (複数役割) | 約15× | — |
| 単一エージェント (4役チーム) | — | 72.2% |
| 単一エージェント (役割なし) | — | 71.8% |
| レビュー役追加 | 増加 | ▲8%低下 |

**重要な発見:**
- **4役チーム72.2% vs 単一71.8%** → ほぼ同じ。役割を増やしても成功率は上がらない
- **レビュー役を追加すると成功率が約8%低下** → 余計な役割は害になる
- **マルチエージェントはチャットの約15倍のトークン** → コストが桁違い

### 根本原因

「役割を増やせば品質が上がる」という直感に反し、実際は:

1. **プロンプトの長大化**: 「あなたは〇〇の専門家です」等の役割定義が入力量を押し上げ、キャッシュを汚染する
2. **コンテキスト競合**: 複数役割が同じ問題に異なる視点で干渉し、判断がぶれる
3. **過剰検証**: レビュー役が存在しない問題を捏造し、本来不要な修正ループに入る
4. **自己検証より他者検証が劣る**: 同じモデルが自分でやる検証より、別モデル/別役割に任せた方が確率は上がらない

## 2. サブエージェントの本質的価値: コンテキスト分離

マルチエージェントが唯一勝る点は **「調べた途中のごみをメインのコンテキストに入れず、要約だけ返す」** こと。これはコンテキスト汚染防止の手段であって、品質向上の手段ではない。

| 手段 | 価値 | コスト |
|------|------|--------|
| サブエージェント (調査役) | メインコンテキストを汚染しない | トークン約4倍 |
| 単一エージェント (全工程) | コンテキストが一貫する | トークン1倍 |
| マルチエージェント (調査+検証+報告) | 役割分離で並列化 | トークン約15倍 |

**結論**: サブエージェントの利点はコンテキスト分離にあって、品質向上にはない。

## 3. 解決策: 役割追加の前に測定するルール

### 3.1 基本原則

```
役割追加 = トークン消費増加(4〜15倍)
効果 = 特定の失敗が消えたか？
追加基準 = 「消したい失敗の型」が特定できている
```

### 3.2 追加判断フローチャート

```
[ステップ1] 消したい失敗の型を特定する
  ├─ YES → ステップ2へ
  └─ NO  → 役割を追加しない（抽象的な「品質向上」は理由にならない）

[ステップ2] 役割なしのトークン量を計測する
  ├─ 基準値を記録
  └─ → ステップ3へ

[ステップ3] 役割追加後のトークン量を予測する
  ├─ 4倍(サブエージェント) / 15倍(マルチエージェント) を基準に見積もる
  └─ → ステップ4へ

[ステップ4] コスト増に見合う効果が期待できるか？
  ├─ YES → 実装し、効果を測定する
  └─ NO  → 役割を追加しない
```

### 3.3 測定項目

役割を追加した後は必ず以下を計測する:

1. **トークン消費量の変化** (入力 + 出力 + キャッシュ)
2. **成功率の変化** (同じ評価セットで比較)
3. **特定の失敗型の発生率** (追加理由とした失敗が消えたか)
4. **平均応答時間** (役割追加が増やすオーバーヘッド)

### 3.4 オージャストでの適用

| 役割 | 現状 | 判定 |
|------|------|------|
| 見積検索の調査役分離 | ✅ 導入済み | 調査結果だけを受け取り、経路を汚染しないため効果的 |
| 企画・積算・校正を4役に分割 | ❌ 不採用 | トークン15倍で効果は証明されていない |
| 新規役割の追加 | ⚠️ 事前計測必須 | 増やす前にトークン量を比較し、特定の型エラー対策としてのみ許可 |

## 4. 期待効果

| 指標 | 現在 | 目標 | 効果 |
|------|------|------|------|
| 無駄な役割追加 | 随時発生 | 0件（発生的に停止） | — |
| セッションあたりのトークン消費 | — | ▲最大80%削減 | サブエージェント4倍→単一1倍 |
| 成功率 | 役割追加で▲8% | ベースライン維持 | 役割追加による低下を防止 |

## 5. 実装案

1. **測定ツール**: `tools/role-cost-measure.mjs` — 役割追加前後のトークン消費・成功率を計測するCLI
2. **ゲート**: `gate-unnecessary-role` — 役割追加を検出し、事前計測レポートの提出を要求
3. **ルール追記**: 判断基準として「消したい失敗の型」と「トークン量の比較」を明文化
4. **定期監査**: 月1回、全AIワークフローの役割構成を見直し、不要な役割を削除
