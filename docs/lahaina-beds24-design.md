## 1. 目的とKPI

### 1.1 経営目標との接続
ラハイナは2026年10月16日の事業譲受を経て、**2027年1月から「月50万円黒字」の安定的達成**を必達目標とする。
本目標達成に向けた月次数値モデルおよび必要指標は下表の通りである。

| 項目 | 計画値（月額） | 根拠・算定内訳 |
| :--- | :--- | :--- |
| **計画固定費** | 2,490,000円 | 11月〜3月の計画固定費 |
| **変動費率** | 16.0% | リネン、水道光熱費変動分、アメニティ等 |
| **目標経常利益** | **500,000円** | 2027年1月以降の月次黒字目標 |
| **必要売上高（試算）** | **約3,560,000円** | (固定費249万 + 利益50万) ÷ (1 - 0.16) = 355.95万円 |

#### 現状単価での課題
現状の客室単価（2名1室・1泊2食付 税込27,500円〜）を前提とした場合、必要売上356万円の達成には月間**約129.5室泊**の販売が必要となる。
全6室×31日＝186室泊に対する**必要稼働率は約69.6%（〜79%相当）**となるが、過去の最高稼働率は**46%**にとどまっており、現状単価のまま稼働率のみで黒字化を達成することは現実的ではない。

#### 目標ツリー（単価 × 稼働 ＋ 付加価値）
単価と稼働率の双方を改善し、固定費圧縮と副収入を組み合わせた以下の構造によって月50万円黒字を実現する。
- **目標客室平均単価（ADR）**: **32,500円**
- **目標稼働率**: **55.0%**（全6室 × 30日 × 55% ＝ **月間99室泊** → 宿泊売上: **約3,217,500円**）
- **副収入目標**: **300,000円/月**（愛犬宿泊料、飲食追加、物販、アクティビティ等）
- **固定費圧縮**: **▲250,000円/月**（計画249万円 → 224万円へ圧縮）
- **達成見込利益**: (宿泊321.75万 + 副収入30万) × (1 - 0.16) - 224万 = 295.47万 - 224万 = **+71.47万円/月**（安全余裕を含め50万円黒字を確保）

## 3. あるべき構成（Beds24 を中核に）

Beds24を宿運営の「単一の真実（Single Source of Truth: SSOT）」として中央に配置し、在庫・料金・予約情報をリアルタイムに同期・集約する。

```
                     ┌──────────────────────────────────────────────┐
                     │           Beds24 (PMS / Channel Manager)     │
                     │  - マスター在庫 (全6室)                      │
                     │  - マスター料金 (基本客室単価)               │
                     │  - 予約台帳・顧客データ一元管理              │
                     └───────┬──────────────┬──────────────┬────────┘
                             │              │              │
       ┌─────────────────────┘              │              └─────────────────────┐
       ▼ 双方向連動                         ▼ 双方向連動                         ▼ 埋め込み連動
┌──────────────┐                     ┌──────────────┐                     ┌──────────────┐
│  国内 OTA    │                     │  海外 OTA    │                     │  自社直販    │
│ - じゃらん   │                     │ - Booking.com│                     │ - lahaina.jp │
│ - 楽天トラベル│                     │ - Airbnb     │                     │   (WordPress)│
│ - 一休/Yahoo │                     │              │                     │              │
└──────────────┘                     └──────────────┘                     └──────────────┘
 (残室/料金送信 ◀▶ 予約自動取込)       (残室/料金送信 ◀▶ 予約自動取込)       (予約エンジン/即時決済)
```

### 3.1 在庫・料金の一元管理
1. **在庫管理（双方向）**:
   - Beds24上の残室数がマスターとなり、いずれかのチャネルで予約が発生すると、Beds24が自動減算した上で、残りの全接続OTAへ即座に残室更新を通知する。
   - 休館・メンテナンス売り止めもBeds24カレンダー上の操作1回で全チャネルに即時反映。
2. **料金管理（片方向: Beds24 → OTA）**:
   - 2023年1月12日以降、Beds24は国内OTA（じゃらん・楽天等）への価格連動に正式対応済み。
   - Beds24から各OTAへ1日1本の基本室料マスターを送信。OTA側での手動料金変更を不要とする。

### 3.2 直販予約エンジン（Booking Engine）の役割
- 公式HP（`lahaina.jp`）訪問者を逃さず獲得するため、Beds24標準の高機能予約エンジン（レスポンシブWeb、多言語・多通貨対応）を埋め込む。
- クレジットカード決済（Stripe連携等）による事前決済を標準化し、現地決済時の未収リスクおよび直前無断キャンセル（No-show）を排除する。

### 3.3 連動の向きと仕様上の制約
- **双方向連動**: 在庫（残室数）および予約データ（確定予約・キャンセル）は完全双方向。
- **制約（API仕様）**:
  - 送信価格は**「1日につき1本（基本料金）」**のみ（Beds24 / OTA間API仕様）。
  - **「追加人数料金」「愛犬宿泊料（頭数別）」「最小/最大泊数制限」はAPIエクスポート不可**。
  - 対応方針: 愛犬宿泊料や人数加算は、各OTA側のプラン設定マスターおよびBeds24予約エンジンのオプション項目（Upsell機能）で個別設定する。

## 6. 移行手順

切替時の**二重予約（オーバーブッキング）を絶対に発生させない**ため、以下の順序を厳格に遵守して移行を実施する。

```
[Step 1] アカウント・基本マスター設定 (Beds24上)
   │
[Step 2] 既存予約の棚卸しと突合 (OTA管理画面よりCSV抽出)
   │
[Step 3] 既存予約の登録 (3か月超の将来予約を手動登録)
   │
[Step 4] ★【重要】Beds24側の在庫を「完全な正(SSOT)」に確定
   │
[Step 5] OTA連携の承認・接続有効化 (夜間・低トラフィック帯)
   │
[Step 6] Beds24から全OTAへ在庫・料金を初期プッシュ送信
   │
[Step 7] 残室数一致確認 & 疎通テスト
```

### 6.1 各ステップの詳細手順
1. **Step 1: アカウント開設とマスター設定**:
   - Beds24アカウント開設、プロパティ（宿情報）作成。
   - 部屋タイプ設定（室数、定員、ベッド構成）。
   - 基本料金（1泊2名料金、食事条件等）の設定。
2. **Step 2: 既存予約の棚卸しと制限ルールの考慮（最重要）**:
   - **OTA取込制限の厳守**:
     - **楽天トラベル・じゃらん**: **「接続前3か月以内に確定した予約」のみ自動取込可能**。
     - **Expedia**: 接続前30日以内の予約のみ取込可能。
     - **Airbnb・Booking.com**: 全件取込可能。
   - **対策**: 各OTA管理画面から「将来の全予約データ」をCSVダウンロードし、**「接続前3か月より前に確定した将来予約」をリストアップ**する。
3. **Step 3: Beds24への既存予約事前登録**:
   - 自動取込対象外となる将来予約を、Beds24へ手動（代理予約）として先行登録する。
4. **Step 4: 在庫の確定（Single Source of Truthの確立）**:
   - **大原則: 在庫は必ずBeds24側を「正」にしてから各OTAを接続する。**
   - Beds24カレンダー上の残室数が、実際のリアルタイム空室状況と1室の狂いもなく完全一致していることを確認する。
5. **Step 5: チャネル接続の有効化**:
   - 深夜帯等の予約が入りにくい時間帯を選定し、各OTA管理画面にてシステム連携（Beds24）を有効化。
   - 直前3か月以内の予約をBeds24へ取り込ませ、重複がないか即時突合。
6. **Step 6: 在庫・料金のプッシュ送信**:
   - Beds24から全接続チャネルへ向けて、最新在庫・料金データを一括送信。
7. **Step 7: 稼働検証**:
   - 各OTAの公開画面および管理画面を開き、カレンダーの空室表示がBeds24と完全一致していることを目視確認。

## 7. 直販予約エンジンの導線

### 7.1 WordPress (`lahaina.jp`) の現状と制約
- **現状**: REST API が無効化されている（`rest_disabled`）。
- **最優先セキュリティ原則**: **社内事故防止ルールに基づき、自動ブラウザによるパスワード入力・ログイン代行は行わない**。
- **方針**: 代表者（kim）の作業負担を最小化（1回・数分で完了）する導入手順を採用する。

### 7.2 埋め込み方式の比較と推奨案

| 方式 | 内容 | kim の作業工数 | メリット | デメリット | 判定 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **案A: iframe / ウィジェット埋め込み** | Beds24が発行するHTML/iframeコードをWP固定ページに貼る | **極小**（WP管理画面でコードを1回コピペするのみ） | ・**REST APIの有効化が不要**<br>・デザイン崩れのリスク極小<br>・即日公開可能 | 直販画面の独自CSSカスタマイズに一部制限あり | **推奨**（Phase 1最短導入） |
| **案B: REST API 有効化＋独自実装** | WPのApplication Passwordsを発行し外部からAPI連携 | **中**（WP設定変更＋PW発行＋外部開発） | ・サイトデザインと完全一体化が可能 | ・開発・テスト工数が大きい<br>・API管理の保守負担増 | Phase 3以降の検討 |

### 7.3 案Aにおける kim の最小操作手順（所要時間: 約3分）
1. Beds24管理画面より「Booking Engine 埋め込みコード（iframe）」を発行・取得（担当またはAIが準備）。
