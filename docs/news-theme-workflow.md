# AIニューステーマ提案ワークフロー（プロセス手順書）

> **X-0062 ④** | 作成: 2026-11-18 | 更新: 2026-11-18 | ステータス: 初版

## 概要

本ドキュメントは、AIニュース提案プロセス全体を定義する手順書である。Google Trends から自社事業に関連する急上昇キーワードを収集し、ChatGPT で検索意図を分析・分類し、記事化すべきテーマを提案するまでの一連の流れを体系化する。

### プロセス全体像

```
月1回実行（推奨サイクル）

[Phase 1] キーワード収集
  Google Trends → 急上昇KWリスト取得
       ↓
[Phase 2] 評価・分類
  ChatGPT に候補KWを投入 → 検索意図・記事化可否を判定
       ↓
[Phase 3] 提案生成
  分類結果を提案ファイルとして出力 → レビュー
       ↓
[Phase 4] 記事化判断
  新規記事 / 既存記事への追記 を判断 → 執筆着手
       ↓
[Phase 5] 記事公開・効果検証
  公開後、SEO効果を測定 → 次回サイクルへフィードバック
```

---

## Phase 1: キーワード収集（Google Trends）

### 1.1 目的
自社事業（展示会ブース制作・イベント企画・空間デザイン）に関連する、現在検索需要が上昇しているキーワードを発見する。

### 1.2 使用ツール
- **Google Trends API**（`google-trends-api` npm パッケージ）
- **パイプラインスクリプト**: `seo/x0057-ai-news-pipeline.mjs`
- **シードキーワード定義**: `seo/data/x0057-seed-keywords.json`

### 1.3 実行手順

```bash
# フル実行（KW収集 → LLM分類 → 提案出力）
node seo/x0057-ai-news-pipeline.mjs --mode full

# KW収集のみ（LLM分類は別途手動）
node seo/x0057-ai-news-pipeline.mjs --mode research --dry-run
```

### 1.4 シードキーワード一覧（既定）

シードキーワードは `seo/data/x0057-seed-keywords.json` で管理。既定値：

```json
[
  "展示会 ブース 制作",
  "ブース デザイン",
  "イベント 企画 運営",
  "展示会 出展 ノウハウ",
  "空間 デザイン 施工",
  "小間ブース レイアウト",
  "展示会 トレンド",
  "ブース 費用 相場"
]
```

### 1.5 出力データ

| 項目 | 内容 |
|------|------|
| 急上昇KWリスト | `relatedQueries` の `rising` クエリ一覧 |
| トレンド方向 | `interestOverTime` の時系列変化（上昇/下降/横ばい） |
| 出力ファイル | `outputs/X-0057/YYYY-MM-DD-proposals.json` |

## Phase 2: 評価・分類（ChatGPT）

### 2.1 目的
収集したキーワード候補を、ChatGPT を用いて検索意図・記事化の可否・優先度で分類する。

### 2.2 入力フォーマット

ChatGPT への入力は以下の3要素を連結して送る：

1. **自社説明文（固定テンプレート）** — 会社とサイトのコンテクスト
2. **既存記事一覧（都度更新）** — 重複・追記先の判定材料
3. **候補KWリスト（変動部分）** — 評価対象キーワード

詳細フォーマットは `data/chatgpt-input-format-x0062.md` を参照。

### 2.3 分類指示（システムプロンプト）

```
あなたはSEOに詳しいコンテンツストラテジストです。
以下の会社情報と既存コンテンツを踏まえて、候補キーワードを評価してください。

評価の方針:
- 「検索需要の変化を捉えた記事テーマ抽出」が目的
- 既存コンテンツとの重複は「追記向き」または「対象外」と判定
- 検索意図がサイトの提供価値と合致しないものは「対象外」
- 会社の強み（展示会ブース制作・イベント企画・空間デザイン）と関連するKWを優先
```

### 2.4 出力フォーマット（JSON）

```json
{
  "keyword": "評価するキーワード",
  "searchIntent": {
    "type": "情報収集 | 比較検討 | 取引・購入 | ナビゲーション",
    "detail": "検索意図の解説（40字以内）"
  },
  "verdict": "新規記事向き | 追記向き | 対象外",
  "verdictReason": "判断理由（60字以内）",
  "priority": "高 | 中 | 低",
  "suggestedTitle": "新規記事向きの場合の推奨タイトル（任意）"
}
```

### 2.5 判定基準

| 判定 | 条件 | 対応 |
|------|------|------|
| 新規記事向き | KWに対する既存コンテンツが不足しており、かつ自社の強み・実績と関連がある | 新規記事として執筆 |
| 追記向き | 既存の特定記事・事例に追記することでSEO効果とユーザー価値を高められる | 該当記事を指定して追記 |
| 対象外 | 検索意図と自社の提供価値のミスマッチ、ニッチすぎる、または需要が極小 | 執筆しない |

**優先度の目安:**
- **高**: 月間検索ボリュームがあり、自社の強みと直結。すぐに着手すべき。
- **中**: 需要はあるが、タイミングやリソースを要調整。
- **低**: 将来的な可能性はあるが、現時点では優先度が低い。

### 2.6 実行手順

```
1. Phase 1 で収集したKWリストを取得
2. `data/chatgpt-input-format-x0062.md` のテンプレートに従い、
   自社説明文 + 既存記事一覧 + 候補KWリスト を連結
3. 連結した全文を ChatGPT に送信
4. JSON配列形式の出力を受け取る
5. 出力を検証（フォーマット・妥当性）
```

## Phase 3: 提案生成

### 3.1 目的
ChatGPT の評価結果を元に、実際の記事化判断のための提案ファイルを生成する。

### 3.2 提案ファイルの構成

```
outputs/X-0057/YYYY-MM-DD-proposals.json
```

各提案エントリの構造：

```json
{
  "generatedAt": "2026-11-18T00:00:00Z",
  "sourceSeed": "展示会 ブース 制作",
  "proposals": [
    {
      "keyword": "展示会ブース トレンド 2027",
      "verdict": "新規記事向き",
      "priority": "高",
      "suggestedTitle": "2027年 展示会ブースのトレンド予測",
      "searchIntent": {
        "type": "情報収集",
        "detail": "最新トレンドを知りたい来場者・出展者"
      },
      "targetAudience": "展示会出展を検討中のマーケティング担当者",
      "estimatedImpact": "中（季節性のある検索需要）",
      "notes": "年末に需要が高まる。11月〜12月に公開推奨"
    }
  ]
}
```

### 3.3 レビュープロセス

1. **機械検証**: JSON フォーマットの妥当性、必須フィールドの存在確認
2. **人間レビュー**: 「本当に記事として成立するか」を最終確認
3. **優先順位付け**: リソースと時期を考慮して着手順を決定

## Phase 4: 記事化判断

### 4.1 判断基準

| 条件 | 判断 |
|------|------|
| 優先度「高」かつ自社の強みと直結 | 即時着手（今月の記事として割り当て） |
| 優先度「中」かつ季節性あり | 適切なタイミングで公開（例：年末需要なら11月公開） |
| 優先度「中」で季節性なし | リソースに余裕があれば着手 |
| 優先度「低」 | 月1回の見直し時に再評価 |

### 4.2 記事化フロー

```
提案テーマの決定
    ↓
AIニュース提案ドキュメント作成（docs/ai-news-x-*.md）
    ↓
記事本文の執筆（LLM支援あり）
    ↓
レビュー・校正
    ↓
サイトへの公開
    ↓
既存記事一覧の更新
```

## Phase 5: 効果検証

### 5.1 測定指標

| 指標 | 測定方法 | 頻度 |
|------|---------|------|
| 検索順位変動 | Google Search Console / GSC API | 週次 |
| AI検索での引用有無 | Claude/Perplexity/Gemini でテスト検索 | 四半期 |
| 記事への流入 | GA4 ページ別トラフィック | 月次 |
| 既存記事への相乗効果 | 関連ページのトラフィック変動 | 月次 |

### 5.2 フィードバックループ

1. 効果測定結果を次回のシードキーワード選定に反映
2. 効果の高かった記事テーマタイプを特定し、類似テーマを優先
3. 効果の低かったテーマは「対象外」判定の閾値調整に活用
