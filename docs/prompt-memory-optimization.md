# プロンプトとメモリ最適化ガイドライン

<!-- tools/prompt-memory-guideline.json から tools/prompt-memory-guideline.mjs --write で生成。手で編集しない。 -->

トークン消費を抑えつつ応答品質を落とさないための、プロンプト設計・メモリ統合・キャッシュ保護・委譲の規範。全PC・全アカウントに適用する。

## 原則
- 効果の順序は 測定 → プロンプトキャッシュ → コンテキスト削減 → バッチ → モデル格下げ。品質を落とす節約（effortLevel low 等）は最上位制約違反であり、節約手段として使わない。
- 削減対象は「毎回同じものを送り直している分」と「想起に使われない記憶」。判断に必要な情報を削らない。
- 機械で検査できる規則は機械で検査する（本カタログの check 定義）。検査できない規則は check: null とし、人が読む規範として残す。

## 規則
### PM-01 出力は Caveman（前置きなし・完了報告は1〜3行）
- 規則: 挨拶・前置き・要約の重複を書かない。完了報告は「やったこと / 検証したこと / 残ったこと」の3行以内に収める。
- 理由: 出力トークンは入力より高単価で、冗長な前置きは全応答に積み上がる。読み手の判断にも寄与しない。
- 適用: output-styles/caveman.md を全セッションで有効にする。 / 長い説明が必要なときは本文ではなくファイルに書き、チャットには1行の参照だけ出す。
- 検査: 手動（規範）
- 根拠: ~/.claude/output-styles/caveman.md（全セッション適用済み）

### PM-02 手順・ルールは常時ロードせず、必要時に Read する
- 規則: 詳細手順は rules/ や docs/ に置き、CLAUDE.md 本文には恒久ルールと参照1行だけを残す。
- 理由: CLAUDE.md は全リクエストに自動ロードされる。rules/ 配下も paths: 指定が無いと全リクエストに乗る（実測 23,288 tok/req）。
- 適用: 新しい手順は rules/<topic>.md か docs/<topic>.md に書き、CLAUDE.md からは1行リンクで参照する。 / 「迷ったら Read ツールで該当節を読む」と明記し、常時ロードを前提にしない。
- 検査: 手動（規範）
- 根拠: tools/onboarding-sync.mjs のコメント: rules/ 配下は paths: が無いと全リクエストで自動ロード（実測 23,288 tok/req）

### PM-03 CLAUDE.md に揮発値を書かない（キャッシュ保護）
- 規則: 実行中タスク・当日の数字・進行中障害・今日の日付を CLAUDE.md に書かない。上部ほど静的に保つ。
- 理由: 先頭が変わるとプロンプトキャッシュが全破棄され、以降の全リクエストが定価になる。
- 適用: 進捗・当日の数値は ~/.claude/next-session.md / open-work.md / memory 側に書く。 / キャッシュヒット率は tools/usage-stats.mjs と tools/cache-audit.mjs で確認する。
- 検査: 自動（claude-md-no-current-date）
- 根拠: CLAUDE.md のユーザーグローバル節「キャッシュ保護」 / 実測キャッシュヒット率 94.9%（2026-09-22 時点）

### PM-04 セッション中のモデル切替を乱発しない
- 規則: 1セッション内でモデルを頻繁に切り替えない。切替は用途の境界（設計→実装委譲など）でのみ行う。
- 理由: モデルが変わるとキャッシュが無効化され、同一内容の入力が定価で再送される。
- 適用: セッション開始時にモデルを決め、途中変更は目的変更時だけにする。
- 検査: 手動（規範）

### PM-05 重い探索はサブエージェント・安い経路へ委譲し、親コンテキストを守る
- 規則: 「配下を全部読んで◯◯」型の調査は Explore / general-purpose・安いLLM に投げ、親には結論だけ返す。
- 理由: 親コンテキストに入った全文は以後の全ターンで再送される。子の探索コストは1回で消える。
- 適用: 委譲時に「結果は200字以内・コード本体は含めない」と出力形式を指定する。 / 分類・抽出・整形は tools/llm-ask.mjs（安いプロバイダ）、実装は tools/codex-do.mjs に流す。
- 検査: 手動（規範）
- 根拠: CLAUDE.md ユーザーグローバル節「重い探索はサブエージェント委譲」

### PM-06 委譲プロンプトはファイルで渡す
- 規則: Codex 等への指示はファイルに書き、--prompt-file で渡す。シェルを1層も通さない・TTYなし・パイプなし。
- 理由: argv 経由は引用符・バッククォートがシェルに解釈され、指示の欠落や事故になる。ファイル渡しは再実行も容易。
- 適用: node tools/codex-do.mjs --prompt-file <指示ファイル> --cwd <対象> --timeout <秒> を前景で実行する。
- 検査: 手動（規範）

### PM-07 MEMORY.md は索引だけ。1行は index/<domain>.md に足す
- 規則: 新規 memory の索引1行は index/<domain>.md へ追加する。MEMORY.md 本文は索引とヘッダのみに保つ。
- 理由: MEMORY.md は全セッションにロードされる。閾値 24,985B を超えると切り捨てられ、後方の索引が想起不能になる。
- 適用: 追加先はドメイン別 index/*.md。MEMORY.md には足さない。 / 超過時は tools/memory-index-compact.mjs / memory-index-split.mjs --apply で再生成し、memory-index-split-verify.mjs で照合する。
- 検査: 自動（memory-index-byte-cap）
- 根拠: memory/feedback_memory_index_is_byte_capped.md（閾値 24,985B）

### PM-08 memory は1ファイル1事実、frontmatter を必ず埋める
- 規則: name / description / metadata.type（user・feedback・project・reference）を必ず書き、本文は1つの事実に絞る。
- 理由: description が無いと想起判定に使えず、全文を読む羽目になる。1ファイルに複数事実を混ぜると部分適用できない。
- 適用: feedback/project は **Why:** と **How to apply:** を続けて書く。 / 関連は [[name]] で相互リンクする。
- 検査: 自動（memory-frontmatter）

### PM-09 同名・同趣旨の memory を増やさず、既存を更新する
- 規則: 保存前に既存ファイルを確認し、同じ事実を扱うものがあれば更新する。誤りと判明したものは削除する。
- 理由: 重複は索引を太らせ、矛盾した2つの記述が同時に想起されて判断を誤らせる。
- 適用: 保存前に memory/ を Grep し、name と description の重複を確認する。
- 検査: 手動（規範）

### PM-10 索引はドメイン別に分割し、MEMORY.md から参照する
- 規則: 記憶は index/<domain>.md に分割し、MEMORY.md にはドメイン索引の1行だけを置く。
- 理由: 全件を MEMORY.md に置くと毎回全件分のトークンを払う。ドメイン分割なら必要な索引だけを追加で読める。
- 適用: v2 split を正本とする（docs/memory-index.md）。予算/グラフ方式は採用しない。
- 検査: 自動（memory-domain-index-present）
- 根拠: docs/memory-index.md（実セッション24本のA/Bで想起成功率は同等・v2 はサブ索引の追加読み込み 0/12）

### PM-11 同一内容の再掲をやめ、参照で済ませる
- 規則: 既にファイルにある内容をチャットや指示書に再掲しない。パスと1行要約で参照する。
- 理由: 再掲は入力トークンを二重に払い、以後の全ターンで再送され続ける。
- 適用: 指示書はファイルに置き、チャットにはファイルパス・ID・URL だけを出す。
- 検査: 手動（規範）

### PM-12 長い入力は先頭を固定し、差分を末尾に置く
- 規則: 同一セッションで繰り返し送る資料は、順序と先頭を変えない。追記は末尾に行う。
- 理由: プレフィックスが一致する範囲だけがキャッシュに当たる。途中挿入は以降を全部無効化する。
- 適用: 資料の更新は末尾追記を原則とし、途中編集が必要なら別ファイルとして新規に置く。
- 検査: 手動（規範）

### PM-13 最適化の順序を守る（測定→キャッシュ→コンテキスト→バッチ→モデル格下げ）
- 規則: 品質を落とさずに費用だけ下げる。モデル格下げを最初に選ばない。
- 理由: 順序を誤ると、品質劣化と再作業で総コストが増える。上位制約（コストは下げても開発品質は下げない）に反する。
- 適用: まず tools/usage-stats.mjs・cache-audit.mjs・bulk-context-audit.mjs で実測する。 / 遅延可能な処理は tools/batch-enqueue.mjs で夜間（半額・翌朝）へ回す。 / effortLevel の既定は medium。low は禁止、high は設計・横断調査のセッションのみ。
- 検査: 手動（規範）
- 根拠: CLAUDE.md ユーザーグローバル節「トークン効率」

## 既存ツールとの対応
- `tools/usage-stats.mjs` — 対象期間の入力・出力・キャッシュヒット率の実測
- `tools/cache-audit.mjs` — キャッシュヒット率の監査
- `tools/bulk-context-audit.mjs` — コンテキスト肥大の監査
- `tools/context-retention-bench.mjs` — コンテキスト保持のベンチ
- `tools/hook-budget-check.mjs` — フックが毎リクエストに足すトークンの予算検査
- `tools/memory-index-split.mjs` — MEMORY.md と index/*.md の再生成（--apply）
- `tools/memory-index-split-verify.mjs` — 索引の独立照合
- `tools/memory-index-compact.mjs` — 索引の圧縮
- `tools/llm-ask.mjs` — 分類・抽出・整形の安い経路
- `tools/codex-do.mjs` — 実装の委譲

## 実測から得た教訓
- MEMORY.md の索引を分割せずに足し続けると 24,985B で切り捨てられ、後方の索引が黙って想起不能になる（実際に発生）。
- ルールを CLAUDE.md に書き足すほど全リクエストの入力が増える。追加は「常時ロードすべき恒久ルールか」を毎回問う。
- 節約を理由にモデルや effortLevel を下げるのは禁止。削減は委譲・レスポンス数削減・無人ジョブの非Claude化・キャッシュ維持で行う。
