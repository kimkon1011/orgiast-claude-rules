### 2. 書き込み行の実在（本番で実際に効いている）

**両タブの3行目＝ヘッダー直下**に、同一の案件行が入っている。

```
デザイナー様用 3行目  : ["", "マイクロウェーブ展2026", "", "百瀬かなう", ...]   ← 非空セル 2
ディレクター様用 3行目: ["", "", "マイクロウェーブ展2026", "", "", "百瀬かなう", ...] ← 非空セル 2
```

この形は実装（`src/lib/seisaku-sheet-sync.ts` @ `95626df`）の書き込みシグネチャと完全一致する:

- `insertDimension` で `startIndex: 2`（= 3行目）に挿入 → **ヘッダー直下** ✅
- 書き込む値は `deal_title` / `sales_owner` / `event_date` の3つだけ。他は `Array(columnCount).fill("")` で空欄
- この案件は `event_date` が空 → 非空セルが **案件名 + 担当 の2つだけ**になる ✅

→ **「テストで作った行」ではなく、本番 UI からの実書き込みが成功している証拠。**
（元セッションは「テスト行は原状復帰済み」と報告しており、この行はその後に入った実案件。）

## 残った論点（記録のみ・変更なし）

1. **重複防止は案件名の完全一致**（`String(row[0] ?? "") === deal.deal_title`）。
   - 同名で別案件が2件あると、3件目は `already` で弾かれる（上記 ESSEN のケースが該当しうる）。
   - 逆に表記ゆれ（全角/半角・末尾スペース）があると重複行が増える。正規化は未実装。
   - **判定を「重複行の有無」でやると誤診する**ので、行の中身が別物かで見ること。
2. **アプリは event_date が空だと2セルしか書かない。** 運用上「行が薄い」と見えるが仕様どおり
   （営業アプリに無い列は空欄にする、という確定仕様）。
3. 対象 SS には未使用タブ `シート2` / `シート3` が同居している（gid 1984666523 / 1875802895）。
   今回の機能は触っていない。
