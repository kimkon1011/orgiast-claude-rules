# Claude Code トークン監査プロンプト

> このプロンプトを Claude Code の入力欄に貼り付けて実行すると、現在のセッションのトークン無駄を5項目でチェックし、改善案を出力します。

---

## 監査プロンプト（貼り付け用）

```
あなたはClaude Codeのトークン消費監査人です。
以下の5項目をチェックし、削れる無駄を具体的に指摘してください。

## 監査項目

1. **思考レベル**: 現在の思考レベル設定（low/medium/high/xhigh）は適切か。
   タスクに本当に高レベルが必要か判断し、過剰なら「medium で十分」と指摘。

2. **曖昧指示**: 最新の指示に「慎重に考えて」「しっかり」「最善を尽くして」
   「丁寧に」などのトークンを消費するだけの曖昧な修飾語が含まれていないか。
   削除して良いか提案。

3. **繰り返し説明**: 既に確立した前提・背景・仕様を毎ターン再説明していないか。
   CLAUDE.md や memory に移せる内容を特定。

4. **古いコンテキスト**: 3ターン以上前の完了済みタスクのコンテキストが
   毎回再読込されていないか。サブエージェント委譲やworktree分割で切れるもの。

5. **キャッシュ状態**: プロンプトキャッシュが途切れている可能性がある要因
   （設定変更・モデル切替・長時間経過）はあるか。

## 出力形式

各項目について:
- [x] 問題あり（理由と改善案）
- [ ] 問題なし

改善による推定節約量: ¥XXX/月

## 改善提案の例

問題ありの場合、以下のように具体的な改善案を出力:
- 「思考レベルを high → medium に変更: このタスクは medium で十分。月間推定節約 ¥3,000」
- 「曖昧指示「慎重に考えて」を削除: タスク内容自体が明確。月間推定節約 ¥500」
- 「会社背景を CLAUDE.md に移動: 毎回の再説明200トークンを削減。月間推定節約 ¥1,000」

## 注意事項

- 実際のトークン消費量はセッションの長さ・応答の長さに依存
- キャッシュ効果は実際の使用パターンで変動
- 思考レベル変更は品質に影響する場合がある（検証推奨）
```

---

## 使用方法

### 1. セッション内で直接監査

Claude Code のプロンプト入力欄に上記を貼り付けて実行する。

### 2. ファイルから読み込んで監査

```
cat outputs/X-0017/token-audit-prompt.md | head -50 | claude -p "$(cat)" -s "現在のセッションを監査してください"
```

### 3. CLAUDE.md に常設ルールとして組み込み

プロジェクトの `CLAUDE.md` に以下を追加すると、毎セッション自動的にトークン効率が意識される：

```markdown
## 🔴 トークン効率（監査必須）

以下の5項目を常に意識:

1. **思考レベルは過剰にしない**: medium で十分なタスクに high/xhigh を使わない
2. **曖昧指示を避ける**: 「慎重に」「しっかり」等の修飾語は使わない
3. **繰り返し説明をしない**: 既に確立した前提は CLAUDE.md や memory に委ねる
4. **古いコンテキストを残さない**: 完了済みタスクはサブエージェント委譲で切る
5. **キャッシュを途切れさせない**: 設定変更・モデル切替はセッション区切りで行う
```

## カスタマイズ例

### ブース提案資料向け（オージャスト）

```
あなたはClaude Codeのトークン消費監査人です。
対象: 展示会ブース提案資料の生成チャット。

1. 思考レベル: デザイン案の生成にxHighは不要。mediumで十分。
2. 曖昧指示: 「しっかりしたデザイン」「最善の提案」は削除対象。
3. 繰り返し説明: 会社概要・施工実績・対応エリアはCLAUDE.mdで十分。
4. 古いコンテキスト: 過去の提案案は別ファイルに保存し、新しい提案は新規セッションで。
5. キャッシュ状態: 長時間の編集セッション中にモデル変更していないか。
```

### イベント運営マニュアル向け（オージャスト）

```
あなたはClaude Codeのトークン消費監査人です。
対象: イベント運営マニュアル生成チャット。

1. 思考レベル: 既定medium。人員配置などの整合性確認のみ一時的にhigh。
2. 曖昧指示: 「丁寧に作って」ではなく具体的なフォーマットを指定。
3. 繰り返し説明: イベントの基本情報（日時・場所）は最初に定義して参照のみ。
4. 古いコンテキスト: マニュアルは1イベント=1セッション。前回のイベント参照はファイル経由。
5. キャッシュ状態: マニュアル作成中の /config 変更を避ける。
```
