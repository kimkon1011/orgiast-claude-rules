# 10工程一括ワークフロー

このワークフローは、AIエージェントが1回の指示で記事制作から公開までを完了するための手順書です。
各工程は原則として順番に実行します（前工程の成果を次工程が利用するため）。

---

## 入力

以下の情報を与えられたら、10工程を一括で実行する：

```
テーマ: <記事のテーマ>
クライアント名: <事例のクライアント>
イベント名: <イベント名>
キーワード: <メインターゲットキーワード>
公開予定日: <日付>
```

---

## 工程1: ニーズ分析と見出し構成

### 目的
記事のテーマに基づき、検索意図を分析し、SEOに強い見出し構成を作成する。

### 手順
1. テーマから検索意図を推定（情報収集・比較検討・取引のいずれか）
2. メインキーワードの検索ボリュームと難易度を推定
3. 記事の目的を明確にする（リード獲得・ブランド訴求・ナレッジ共有）
4. 以下の見出し構成を作成する：
   - H1: タイトル（30〜40字、キーワードを含む）
   - H2: 大見出し（4〜6個）
   - H3: 中見出し（各H2の下に2〜3個）
   - リード文: 冒頭100〜150字で記事の要約と価値提案
5. 見出し構成を `output/headline.json` に出力する

### 出力例
```json
{
  "title": "【施工事例】〇〇展示会 ブース制作レポート｜株式会社オージャスト",
  "keywords": ["展示会 ブース 制作", "施工事例", "ブースデザイン"],
  "intent": "商業調査",
  "headings": [
    {"level": "H2", "text": "イベント概要"},
    {"level": "H2", "text": "クライアントの課題"},
    {"level": "H3", "text": "課題1: ブランド認知度の向上"},
    {"level": "H2", "text": "デザインコンセプト"},
    {"level": "H2", "text": "施工プロセス"},
    {"level": "H2", "text": "施工写真"},
    {"level": "H2", "text": "成果と反響"},
    {"level": "H2", "text": "制作のポイント"},
    {"level": "H2", "text": "よくある質問"}
  ]
}
```

## 工程2: 記事本文執筆

### 目的
見出し構成に従い、記事本文をMarkdown形式で執筆する。

### 手順
1. `sample-booth-case.md` を参照し、同水準の品質・構成で執筆する
2. 各見出しに200〜400字の本文を書く
3. 以下の要素を含める：
   - 具体的な数値（予算・期間・来場者数等）
   - クライアントの課題→解決のストーリー
   - 施工プロセスの具体的な説明
   - 成果を裏付ける数字
4. 記事全体で2,000〜3,000字を目安にする
5. 本文中に画像プレースホルダーを `![alt](PLACEHOLDER:説明)` 形式で入れる
6. `output/article.md` に出力する

### 品質チェック
- □ リード文で読者の興味を引けているか
- □ 各見出しが本文と一致しているか
- □ 数値・固有名詞のハルシネーションがないか
- □ CTA（問い合わせ誘導）が自然に入っているか

## 工程3: サムネイル作成

### 目的
記事のアイキャッチ画像（サムネイル）を作成する。

### 手順
1. 記事のテーマ・見出しから、サムネイルのデザインコンセプトを決める
2. 以下の要素を考慮する：
   - 1200×630px（OGP推奨サイズ）
   - 記事タイトルが視認できる大きさ
   - オージャストのブランドカラーを活用
   - 文字は白背景に濃色、または濃色背景に白文字
3. 画像生成AI（Gemini/DALL-E）用のプロンプトを作成する
4. 生成した画像を `output/thumbnail.png` に保存する

### プロンプト例
```
Generate a professional thumbnail for a trade show booth construction case study article.
Show a modern, well-lit exhibition booth with clean lines and professional finish.
Text overlay area should be on the left side. Style: clean, corporate, Japanese business.
Size: 1200x630px. No people faces visible.
```

## 工程4: 挿入画像選定・生成

### 目的
記事本文に挿入する画像を生成または選定する。

### 手順
1. 記事内の画像プレースホルダーを特定する
2. 以下の画像を優先的に用意する：
   - ブース全景写真（正面・斜めから）
   - 商談スペースの様子
   - 施工中の様子
   - 使用した素材・工法の詳細
   - 完成後の全景
3. 各画像に適切なalt属性を設定する
4. 画像生成AI用のプロンプトを作成し、生成する
5. 画像を `output/images/` に保存し、ファイル名とMarkdownのパスを対応付ける
6. `output/image-manifest.json` に画像一覧を出力する

### 出力例
```json
{
  "images": [
    {"file": "booth-overview.jpg", "alt": "ブース全景（正面から見た様子）", "placement": "イベント概要の後"},
    {"file": "meeting-space.jpg", "alt": "商談スペースの様子", "placement": "施工プロセスの後"}
  ]
}
```

## 工程5: スクリーンショット・図版作成

### 目的
記事の理解を助ける図版・スクリーンショットを作成する。

### 手順
1. 記事内で図解が必要な箇所を特定する
2. 以下の種類の図版を作成する：
   - ブースの間取り図（ゾーニング）
   - 施工スケジュール（タイムライン図）
   - 予算配分（円グラフ・棒グラフ）
   - 比較表（施工前/施工後）
3. 各図版を `output/diagrams/` に保存する
4. 図版の説明文をMarkdownに追加する

## 工程6: 口コミ・Xポスト収集

### 目的
記事の信頼性を高めるため、ソーシャルプルーフ（口コミ・Xポスト）を収集する。

### 手順
1. 記事テーマに関連する口コミ・評判を検索する
2. X（Twitter）で関連ポストを検索する
3. 以下の基準で選別する：
   - 実在するユーザーの声であること
   - 記事のテーマと関連があること
   - 引用に適した長さ（100字以内）
   - ネガティブな内容でないこと
4. 収集した素材を `output/social-proof.json` に保存する
5. 記事内の適切な箇所に引用として埋め込む

### 出力例
```json
{
  "quotes": [
    {"source": "X", "author": "@username", "text": "ブースのクオリティが高くて驚きました", "url": "https://x.com/...", "date": "2026-10-20"}
  ]
}
```

## 工程7: WordPress投稿

### 目的
作成した記事をWordPressに投稿する。

### 手順
1. WordPressのREST APIまたは管理画面にアクセスする
2. 以下の設定で新規投稿を作成する：
   - タイトル: 工程1で決定したタイトル
   - 本文: 工程2のMarkdownをHTMLに変換して入力
   - カテゴリ: 「施工事例」または関連カテゴリ
   - タグ: キーワードから3〜5個設定
   - アイキャッチ画像: 工程3のサムネイルを設定
3. ステータスは「下書き」で保存する（公開は工程10の完了後）
4. 投稿IDを `output/wordpress-post-id.txt` に保存する

### WordPress REST API例
```bash
# 投稿作成（Bearer Token認証）
curl -X POST https://www.orgiast.jp/wp-json/wp/v2/posts \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "記事タイトル",
    "content": "<p>本文HTML</p>",
    "status": "draft",
    "categories": [5],
    "tags": [12, 34, 56]
  }'
```

## 工程8: 文字装飾・見出し設定

### 目的
WordPress投稿内の文字装飾と見出し構造を最適化する。

### 手順
1. 記事本文のHTMLを見出しレベル（H2/H3/H4）で適切に構造化する
2. 以下の装飾を適用する：
   - 強調箇所: `<strong>` タグ（太字）
   - 重要なキーワード: 初出のみ `<strong>`
   - 引用: `<blockquote>` タグ
   - リスト: `<ul>` / `<ol>` タグ
   - テーブル: `<table>` タグ（見やすいヘッダー付き）
3. 箇条書き・数字リストで読みやすくする
4. 長文は適切な長さで区切り、空白行で視認性を確保する
5. 装飾を施した完全なHTMLを `output/article-formatted.html` に出力する

## 工程9: 内部リンク・外部リンク設定

### 目的
記事内に適切な内部リンク・外部リンクを設定し、SEO価値を高める。

### 手順
1. **内部リンク**: 以下の関連記事・ページへのリンクを自然な文脈で設置する
   - https://www.orgiast.jp/topics/ 配下の関連記事（2〜3本）
   - https://rebooth.co.jp/ （リブース特設サイト）
   - https://rebooth.co.jp/works-top/ （実績一覧）
   - https://www.orgiast.jp/contact/ （問い合わせページ）
2. **外部リンク**: 必要に応じて信頼性のある外部サイトへのリンク
   - 展示会公式サイト
   - 業界団体サイト
3. 各リンクに適切なアンカーテキストを設定する
4. 外部リンクは `target="_blank" rel="noopener noreferrer"` を付ける
5. リンク設定後の記事HTMLを `output/article-with-links.html` に出力する

## 工程10: メタ設定・SEO最適化

### 目的
記事のメタデータを設定し、検索エンジンでの表示を最適化する。

### 手順
1. **タイトルタグ**: 30〜40字、キーワードを含む、クリック率が高い表現
2. **メタディスクリプション**: 100〜120字、記事の要約と価値提案を含む
3. **OGP設定**:
   - og:title: タイトルタグと同一または補完
   - og:description: メタディスクリプションと同一
   - og:image: 工程3のサムネイルURL
   - og:type: article
4. **構造化データ**: 以下のJSON-LDを生成する
   ```json
   {
     "@context": "https://schema.org",
     "@type": "Article",
     "headline": "記事タイトル",
     "description": "メタディスクリプション",
     "image": "サムネイルURL",
     "datePublished": "公開予定日",
     "author": {
       "@type": "Organization",
       "name": "株式会社オージャスト",
       "url": "https://www.orgiast.jp"
     }
   }
   ```
5. **URLスラッグ**: 英数字とハイフンのみ、キーワードを含める
6. **canonical URL**: 設定する
7. 全メタデータを `output/meta.json` に出力する
8. WordPress投稿のメタデータを更新する
9. ステータスを「公開」に変更する（確認後）

### 出力例
```json
{
  "title": "【施工事例】〇〇展示会 ブース制作レポート｜株式会社オージャスト",
  "metaDescription": "〇〇展示会に出展した際のブース制作事例を詳しく紹介。課題からデザインコンセプト、施工プロセス、成果まで、実際のデータと写真で解説します。",
  "slug": "booth-construction-case-event-name",
  "ogp": {
    "title": "【施工事例】〇〇展示会 ブース制作レポート",
    "description": "〇〇展示会のブース制作事例を詳しく解説。実際の施工プロセスや成果を紹介。",
    "image": "https://www.orgiast.jp/wp-content/uploads/thumbnail.jpg"
  },
  "structuredData": { "@context": "https://schema.org", "@type": "Article", ... }
}
```
