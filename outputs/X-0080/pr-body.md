# AIニュース提案 X-0080: 再現ベンチマークでモデルルーティング最適化

## 概要

X-0082で提案したモデルルーティングの枠組みを、**再現可能なベンチマーク**に基づいて最適化する方法論を解説する。同一タスクセットを複数LLMで反復実行し、コスト・品質・スタイル適合を定量比較することで、タスクごとの最適モデルをエビデンスベースで決定。ルーティング導入判断に確かなデータを与える。

## キーファクト

| 指標 | 値 |
|------|------|
| RADW-Bench 評価モデル数 | **8モデル**（27タスク） |
| RECE 4段階評価プロセス | Phase 1〜4（ベースライン→比較→決定→監視） |
| RSI-Router 進化世代数 | **6世代**の反復最適化 |
| 最低評価サンプル数 | **20〜30**（大まかな比較）・**50〜100**（実用的判断） |
| 期待コスト削減（ブース基本文） | Opus→Haikuで**97.5%減** |
| 期待コスト削減（全タスク平均） | **約85%減**（$20→~$3/1Mトークン） |

## 提案の核

### なぜこの提案が重要なのか

X-0082で示したルーティングの枠組みは強力だが、実際に導入するには「このタスクを安価モデルに回して本当に大丈夫か」という問いにエビデンスで答える必要がある。本提案は、**再現可能なベンチマーク**によってこの問いに答える方法論を提供する:

1. **客観的エビデンス**: 勘や思い込みではなく、実測データに基づいてルーティングを決定
2. **継続的改善**: 新モデルが出るたびに同一タスクセットで再実行→ルーティング更新
3. **コスト対品質の定量トレードオフ**: グラフ化して可視化、チーム全体で共通認識
4. **ベンチマーク駆動型ルーティング**: コード化可能なルールとしてルーティング定義をバージョン管理

### オージャストでの応用

過去のブース提案生成タスクから**代表タスクセット（最低20種）** を収集し、以下のプロセスで最適ルーティング構成を決定する:

- **P0（即日）**: 手動サンプリング5〜10件で大まかなルーティング感覚を掴む
- **P1（1〜3日）**: 20タスク + LLM-as-Judge自動評価でタスクごとの最適モデル推定
- **P2（1〜2週間）**: 50タスク + 固定シード + 自動評価パイプラインで再現可能なエビデンス
- **P3（2〜4週間）**: CI連携 + モデル更新時自動再実行で陳腐化しないルーティング

これにより、ブース基本説明文生成コストを**97.5%削減**（Opus→Haiku）、全タスク平均で**約85%削減**（$20→~$3/1Mトークン）を見込む。
