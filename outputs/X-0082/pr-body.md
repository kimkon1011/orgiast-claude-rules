# AIニュース提案 X-0082: 過大モデルへの無駄をルーティングで削減

## 概要

高性能モデル（Fable/Opus）を全タスクに使う「過大モデル問題」を、**モデルルーティング**で解決する。タスクの難易度に応じて適切なサイズのモデルにクエリを振り分けることで、品質を維持しながら推論コストを50〜80%以上削減する手法を解説する。

## キーファクト

| 指標 | 値 |
|------|------|
| RSI-Router 最大削減率 | **82.2%**（精度も向上） |
| LangChain Switchyard 削減率 | **74%**（精度低下わずか6pt） |
| 安価モデル処理割合（Switchyard） | 全呼び出しの**93%** |
| LiteLLM classifier トレーニング時間 | **0.18秒**（220KB） |
| モデル間価格差（Fable vs Haiku） | **80倍** |
| 定型タスクの割合（想定） | 全タスクの**70〜80%** |

## 提案の核

### なぜこの提案が重要なのか

「削減」というとプロンプトキャッシュ（X-0084）や役割分担（X-0068）が先に想起されるが、モデルルーティングは**それらと独立した削減軸**であり、併用で総コストを70〜95%削減できる。かつ、RSI-Routerのように**小モデルを使うと精度が向上するタスクが存在する**ことが学術的に示されており、品質とコストがトレードオフにならない場合がある。

### オージャストでの応用

当面は**手動ルーティング（コード分岐）** から開始:
- ブース基本テキスト生成 → Haiku/DeepSeek（Fable比 80分の1）
- 見積案・スケジュール → Sonnet（Opus比 半額）
- デザインコンセプト・クライアント提案 → Opus/Fable（適正）
- 分類・タグ付け → Haiku/DeepSeek（Opus比 40分の1）

これだけで**全体コストを最低30〜50%削減**可能。キャッシュ（X-0084）と組み合わせれば最大70〜95%の削減が見込める。
