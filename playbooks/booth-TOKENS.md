# ブースマルチエージェント TOKENS.md — エージェントトークンをチャットの4倍に抑える

ブースデザイン生成マルチエージェントシステムの固定入力トークンを実測し、無駄を特定して削減する。

## 実測（2026-11-18）

ブースシステムの各コンポーネントが消費するトークン:

| コンポーネント | バイト数 | 概算トークン | 備考 |
|---|---|---|---|
| playbooks/booth-website-agent-skills-workflow.md | 8,399 | 約 2,100 | 毎セッション注入 |
| apps/booth-spec-generator/cache-prefix.md | 4,570 | 約 1,140 | プロンプト固定部 + コード重複 |
| apps/booth-spec-generator/generate-spec.mjs | 13,166 | 約 3,300 | 表示コード40% |
| tools/booth-proposal-prompt-builder.mjs | 14,829 | 約 3,700 | キャッシュ最適化済み |
| tools/booth-3d/build-booth.mjs | 3,876 | 約 970 | Blender非LLM系 |

**ブースエージェントセッションの固定費は約 5,300 トークン**（playbook + スキルコンテキスト）。提案API呼び出し時のプロンプトは約 3,700 トークン。

## 6つのトークンリーク

### リーク1: cache-prefix.md と generate-spec.mjs の二重記述

- **症状**: `cache-prefix.md`（4,570 bytes）の標準ブースサイズ・アセット一覧・予算配分基準が、`generate-spec.mjs` 内の `BOOTH_SIZE_MAP` / `ASSET_TEMPLATES` / `budgetBreakdown()` と完全重複している。同一データがコードとプロンプトの両方で保持されている。
- **実測**: 約 1,140 トークン相当の重複。ただし cache-prefix.md はプロンプトキャッシュに乗るため、初回のみのペナルティ。コード側の重複はファイルサイズ肥大（約 3KB 相当）として毎回のコンテキスト読み込みで課金される。
- **なぜ起きたか**: プロンプトキャッシュ導入（X-0044）時に、コード内のハードコードされたデータをそのまま残し、cache-prefix.md に同じ内容をコピーした。リファクタリングが追いついていない。
- **直し方**: `BOOTH_SIZE_MAP` / `ASSET_TEMPLATES` / `budgetBreakdown` を共通の JSON データファイルに外出しし、コ��ドとプロンプトの両方から参照する。コード内のハードコード重複を削除する。

### リーク2: プレイブックのナラティブ肥大

- **症状**: `booth-website-agent-skills-workflow.md`（8,399 bytes）の 70% が addyosmani/agent-skills パッケージの汎用スキル説明（Spec-Driven Development / TDD / Code Review 等）。これらの説明は各スキルの公式ドキュメントに既に存在する。
- **実測**: 約 5,900 bytes（約 1,500 トークン）がブース固有でない汎用説明。
- **なぜ起きたか**: 「1ファイルで完結」を優先し、汎用スキル説明もすべて含めた。参照先があればリンクで済む。
- **直し方**: 汎用スキル説明を 1 行の参照に置き換え、ブース固有の適用ノートのみ残す。8.4KB → 3KB に圧縮。

### リーク3: generate-spec.mjs の表示コードとロジックの混在

- **症状**: `generate-spec.mjs`（13KB）のうち、`printSummary` / `printBatchComparison` / `assemblePrompt` / `specSkeleton` の表示系関数が約 40%（5KB）を占める。コアロジック（`generateSpec` / `selectAssetsForBudget`）は約 20%。
- **実測**: 約 5KB（約 1,300 トークン）がエージェント間通信では不要な表示コード。
- **なぜ起きたか**: 単一ファイル CLI ツールとして設計されたため、ロジックと表示が混在。
- **直し方**: 表示関数を別ファイル `spec-display.mjs` に分離。generate-spec.mjs のコアサイズを 13KB → 8KB に削減。エージェントがロードするコンテキストが減る。

### リーク4: CLI 出力の冗長フォーマット

- **症状**: `generate-spec.mjs` の CLI 出力は人間向けの整形済みテーブル（Markdown表組・カテゴリ別改行）で、エージェントが読むには過剰にフォーマットされている。
- **実測**: 1 回の生成で約 1,500 bytes の出力（約 380 トークン）。JSON Lines なら 300 bytes（約 75 トークン）で済む。出力トークンは入力の 5 倍の単価（§2.8.1）。
- **なぜ起きたか**: CLI ツールのデフォルト出力が人間向けフォーマットのまま。
- **直し方**: `--compact` モードを追加。エージェント間呼び出し時は JSON Lines 出力で 75% 削減。

### リーク5: プレイブック内の開発フロー図の非効率

- **症状**: `booth-website-agent-skills-workflow.md` の開発フロー図（ASCII 矢印図）は 25 行を超え、可読性とトークン消費のトレードオフが取れていない。
- **実測**: 約 25 行（約 600 bytes）。シンプルなテキストリストで 5 行（約 150 bytes）に圧縮可能。
- **なぜ起きたか**: 「図解は理解を助ける」という前提で長い ASCII アートを入れた。
- **直し方**: ASCII 図を簡潔な 1 行リストに置き換える。

### リーク6: 重複セクションコメントの肥大

- **症状**: `generate-spec.mjs` 内のセクション区切り（`// === ===` 装飾コメント + 空行）が各関数の前に入っている。1 セクションあたり 3〜5 行（約 200 bytes）のオーバーヘッド。
- **実測**: 8 セクション × 約 200 bytes = 約 1,600 bytes（約 400 トークン）。
- **なぜ起きたか**: 可読性重視のコーディングスタイル。エージェントが読むコンテキストでは不要。
- **直し方**: セクションコメントを簡潔な `// section-name` 1 行に統一。

## 6つのレバー

### レバー1: cache-prefix.md とコードのデータ統合（重複排除）

- **やること**: `cache-prefix.md` と `generate-spec.mjs` で重複するデータ（BOOTH_SIZE_MAP / ASSET_TEMPLATES / 予算配分）を JSON データファイルに統合。コード側のハードコード重複を削除し、`cache-prefix.md` の内容はデータファイルから動的生成する。
- **期待削減**: ファイルサイズ約 3KB 削減（コード重複排除）、プロンプトの二重注入防止。
- **検証方法**: 統合後も `generate-spec.mjs --sample` が同じ出力を生成することを確認。

### レバー2: プレイブック圧縮（参照リンク化）

- **やること**: `booth-website-agent-skills-workflow.md` の汎用スキル説明を 1 行リンクに置き換え、ブース固有適用ノートのみ残す。ASCII フロー図を簡潔リストに置き換え。
- **期待削減**: 8.4KB → 3KB（約 1,350 トークン削減、約 64% 削減）。
- **検証方法**: 圧縮後も各スキルの呼び出し方（`/spec`, `/plan` 等）が明確に伝わることを確認。

### レバー3: 表示コードの分離

- **やること**: `generate-spec.mjs` から表示関数を `spec-display.mjs` に分離。コアモジュールのサイズを 13KB → 8KB に削減。
- **期待削減**: エージェントコンテキストに読み込まれるコアファイルが約 5KB 削減（約 1,300 トークン）。
- **検証方法**: 分離後も `node generate-spec.mjs --help` と `node generate-spec.mjs --client X` が同じ出力を生成することを確認。

### レバー4: コンパクト出力モード追加

- **やること**: `--compact` フラグを追加。JSON Lines 形式で case_id + item_count + budget のみ出力。エージェント間の自動呼び出しで使用。
- **期待削減**: 出力トークン 75% 削減（380 → 75 トークン）。出力単価は入力の 5 倍なので、費用効果は 15 倍。
- **検証方法**: `--compact` の出力が有効な JSON Lines であることを確認。

### レバー5: セクションコメント圧縮

- **やること**: `generate-spec.mjs` の装飾コメント（`// ============`）を `// section-name` 1 行に統一。
- **期待削減**: 約 400 トークン削減。
- **検証方法**: 圧縮後も `node --test` が全件 PASS。

### レバー6: エージェント間出力圧縮規約

- **やること**: ブースエージェント間で受け渡すデータは常に `--compact` モードを使用する規約を設定。人間が読むときだけフル出力。
- **期待削減**: エージェントチェーン全体で出力トークン 75% 削減。
- **検証方法**: エージェントチェーン実行時の出力トークン量を測定。

## 削減目標

| レバー | 削減対象 | 削減量(トークン) | 削減率 |
|---|---|---|---|
| 1 | コード-プロンプト重複 | ~1,140 | 22% |
| 2 | プレイブック圧縮 | ~1,350 | 25% |
| 3 | 表示コード分離 | ~1,300 | 25% |
| 4 | コンパクト出力 | ~300 | 6% |
| 5 | セクションコメント | ~400 | 8% |
| 6 | エージェント間出力 | ~285 | 5% |
| **合計** | | **~4,775** | **90%** |

**目標**: 固定費 5,300 トークンを 1,200 トークンに削減（約 4.4 倍抑制）。

## やってはいけない

- キャッシュ済みの `cache-prefix.md` を削除してプロンプトキャッシュを破壊する。
- 人間の可読性を完全に無視した圧縮（開発メンテナンス困難になる）。
- 複数レバーを同時に適用して原因特定不能になる。
- Blender（非LLM）パイプラインにトークン最適化を適用しようとする。
