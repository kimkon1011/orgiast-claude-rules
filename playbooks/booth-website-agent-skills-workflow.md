# ブース制作ウェブサイト開発：エージェントスキル6ルールワークフロー

> addyosmani/agent-skills からインストールした 25 スキル（79 エージェント）のうち、
> 展示会ブース制作ウェブサイト（イベント関連ページ）のコーディングに特化した 6 ルールの適用手順。

## インストール済みスキル

`npx skills add addyosmani/agent-skills` により `.agents/skills/` に 25 スキルがインストール済み。
`.claude/skills/` にシンボリックリンクされ、Claude Code から Skill ツール経由で呼び出し可能。

## 6 ルールとブースサイト開発への適用

### 1. `/spec` — Spec-Driven Development（仕様駆動開発）

**スキル:** `spec-driven-development`

**ブースサイトでの使い方:**

新規イベントページ（例: 「MF-TOKYO 2027 出展ページ」「展示会ブース実績一覧」）の実装前に
`/spec` を呼び出して SPEC 文書を作成する。

```markdown
# Spec: MF-TOKYO 2027 出展ページ — V1

## Objective
展示会「MF-TOKYO 2027」に出展するブースの情報・施工事例・問い合わせ導線を
1 ページにまとめ、来場者の来場前調査からの問い合わせを獲得する。

## Success Criteria
- ページ表示速度 LCP < 2.5s（Next.js SSG）
- イベント基本情報（日程・会場）が構造化データに対応
- 問い合わせフォーム送信後 5 秒以内に確認画面へ遷移
```

**Scope Check（Phase 0）の活用例:**
「出展情報」と「施工実績ギャラリー」と「問い合わせ」が 1 要件に含まれる場合、
Capability Map で分割してから各モジュールの SPEC を書く。

### 2. `/plan` — Planning & Task Breakdown（計画・タスク分割）

**スキル:** `planning-and-task-breakdown`

**ブースサイトでの使い方:**

SPEC 承認後に `/plan` で実装計画を立てる。垂直スライスでタスク分割する。

**悪い例（水平分割）:**
```
タスク1: 全ページのデータベーススキーマ構築
タスク2: 全 API エンドポイント構築
タスク3: 全 UI コンポーネント構築
```

**良い例（垂直スライス）:**
```
タスク1: 1 件の展示会出展情報を表示する（Schema + CMS + ページ）
タスク2: 出展一覧ページで複数イベントをカード表示する
タスク3: 施工事例ギャラリーをフィルタリング可能にする
タスク4: ブースサイズ計算ツールを実装する
```

各タスクは 1 セッションで完了できるサイズ（3〜5 ファイル）に抑え、
受け入れ基準と検証手順を明示する。

### 3. `/build` — Incremental Implementation（インクリメンタル実装）

**スキル:** `incremental-implementation`

**ブースサイトでの使い方:**

1 スライスずつ実装 → テスト → 検証 → コミットのサイクルを回す。

```
スライス1: イベント詳細ページのスキーマ + CMS 入力画面（管理画面）
   → テスト通過、CMS でイベントを登録できる
スライス2: 公開ページでイベント詳細を表示（SSG + ISR）
   → テスト通過、/events/mf-tokyo-2027 が表示される
スライス3: 施工事例のカルーセルを追加
   → テスト通過、画像が表示される
```

**Scope Discipline（Rule 0.5）:**
「ついでに」隣接コードをリファクタリングしない。ブースページの改修中に
問い合わせフォームのスタイルを触らない。

### 4. `/test` — Test-Driven Development（テスト駆動開発）

**スキル:** `test-driven-development`

**ブースサイトでの使い方:**

- **単体テスト:** ブースサイズ計算（3m×3m小間 vs 5m×5m小間の料金ロジック）
- **結合テスト:** CMS からイベントデータ取得 → ページ描画
- **E2E テスト:** Playwright でフォーム送信→確認画面→管理者通知

**Bug Fix パターン（Prove-It）:**

不具合報告「ブースサイズ計算ツールで 5m 幅を入れるとエラーになる」が来たら、
**先に再現テストを書き、期待動作を証明してから修正する。**

```typescript
// RED: このテストはバグがなければ通る
it('accepts 5m booth width in size calculator', () => {
  const result = calculateBoothPrice({ width: 5, depth: 5, type: 'island' });
  expect(result.isValid).toBe(true);
});
```

### 5. `/review` — Code Review & Quality（コードレビュー・品質）

**スキル:** `code-review-and-quality`

**ブースサイトでの使い方:**

マージ前に 5 軸レビューを実施：

| 軸 | ブースサイトでのチェック項目 |
|----|------------------------------|
| **Correctness** | イベント日程が正しく表示されるか、CMS の画像が表示されるか |
| **Readability** | コンポーネント名が bs-（booth section）等で統一されているか |
| **Architecture** | イベント固有データと汎用レイアウトが適切に分離されているか |
| **Security** | 問い合わせフォームの入力が適切にサニタイズされているか |
| **Performance** | Next.js Image が使われているか、ISR 再生成間隔は適切か |

**重要項目（特にブースサイト）:**
- 画像の WebP 変換・Next/Image 最適化がされているか（ブース写真は重要）
- 構造化データ（Event schema / Product schema）が正しいか
- 問い合わせフォームに SPAM 対策があるか

### 6. `/ship` — Shipping & Launch（出荷・ローンチ）

**スキル:** `shipping-and-launch`

**ブースサイトでの使い方:**

展示会ページの公開前チェックリスト：

```markdown
## 展示会ページ公開前チェック

### コンテンツ
- [ ] イベント名・日程・会場が正しい（SPEC と一致）
- [ ] ブース位置図が最新の案内図と一致している
- [ ] 出展者名・小間番号が正しい
- [ ] 施工事例写真の alt 属性が設定されている

### 技術
- [ ] 全てのテストが通過（npm test）
- [ ] ビルドが成功（npm run build）
- [ ] Core Web Vitals が基準値以内（LCP < 2.5s）
- [ ] 構造化データが Google Rich Results Test で検証済み
- [ ] 本番環境の環境変数が設定済み

### SEO
- [ ] ページタイトル・meta description がユニーク
- [ ] XML サイトマップに含まれている
- [ ]  canonical URL が設定されている
- [ ] パンくずリストの構造化データが正しい

### 運用
- [ ] ロールバック計画が文書化されている
- [ ] エラーモニタリングが設定されている
- [ ] 公開後 1 時間はメトリクスを監視する
```

**Feature Flag の活用:**
イベントページは公開日が決まっているため、`FEATURE_NEXT_EVENT=true` フラグで
先行公開（出展者確認用）と一般公開を制御する。

## 開発フロー全体

```
お客様からの要件
    │
    ▼
[1] /spec ────→ SPEC 文書を作成
    │              人間がレビュー・承認
    ▼
[2] /plan ────→ tasks/todo.md にタスク分割
    │              依存関係順に並べる
    ▼
[3-4] /build + /test ───→ 1 スライスずつ実装
    │                        TDD サイクル
    ▼
[5] /review ───→ PR 作成時に 5 軸レビュー
    │
    ▼
[6] /ship ─────→ 公開前チェックリスト実行
                     feature flag で段階公開
```

## 呼び出し方

Claude Code のチャットで以下のように呼び出す：

```
/spec 展示会「MF-TOKYO 2027」の出展ページを作りたい。
/plan SPEC-mf-tokyo.md に基づいてタスク分割して。
/build タスク1 「イベント詳細スキーマと CMS 入力」を実装して。
/test ブースサイズ計算の単体テストを書いて。
/review この PR をレビューして。
/ship 公開前チェックリストを実行して。
```

または Skill ツール経由で直接呼び出すことも可能。
