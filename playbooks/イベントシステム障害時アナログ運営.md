# イベントでシステムを使う案件 — 障害時アナログ運営（会社必須条件）

正本ルール: ONBOARDING §2.12（kim 2026-10-20 厳命）。案件相談スキル: `case-consult-sources`。
事故: 2026-10-20 上海ラクトコンサルティング様 JINS様決起会（261020RA）で当日システム（抽選・クイズ進行）が遅延し、代替が無く運営に支障。事前に「動かなくなったら」を何度も話したが準備物と練習に落としていなかった。

## Claude が案件に触れたら必ずやること

1. **システム利用の有無を判定**: 抽選・クイズ・投票・受付/QR・来場者登録・スコア表示・映像/スライド切替・配信・決済・Web アプリ。読めなければ「システム利用の有無: 未確認」と書いて確認項目にする。
2. 利用ありなら、回答・提案・見積・実施計画に **「障害時アナログ運営」** を必ず入れる。実施計画書スプレッドシートに同名タブを作る（§2.9。別ファイルにしない）。
3. 回答の最後に1行: `障害時アナログ運営: システム利用なし / 準備済み（タブ: …）/ 未準備（不足: …）`。未準備なら下のひな形で Claude が中身を作って出す（user に作らせない）。

## 「障害時アナログ運営」タブのひな形

| 項目 | 書く内容 |
|---|---|
| 切替条件 | 例: 応答30秒超／2回連続失敗／画面停止／回線断。迷ったら切り替える |
| 判断者・時間 | 当日責任者の氏名、判断から切替完了まで何分（例: 3分） |
| 代替手段 | システムの機能ごとに紙・人手の代替（下の例） |
| 持ち込み物リスト | 印刷物・文具・予備機材を数量付きで。前日までに準備・積込確認 |
| 進行台本の分岐 | 司会が読む停止時アナウンス文＋アナログ版の進行手順 |
| データ退避 | 名簿・問題/正答・当選条件・景品リストを紙と別端末（オフライン）に保存 |
| 担当 | 切替担当・集計担当・司会連絡担当の氏名 |
| リハ実施 | アナログ切替を通した日時と結果（システムのリハだけでは未完了） |
| 費用 | 印刷・予備機材の追加費用（見積に含める） |

## 機能別の代替例

- **抽選**: 番号入り抽選券を事前配布＋くじ箱、または印刷名簿からの番号くじ。当選番号はホワイトボード/スケッチブックで掲示
- **クイズ・投票**: 色付き回答札（A/B/C/D）や挙手、紙の回答用紙＋集計係。問題・正答は印刷した台本で司会が読み上げ
- **受付/QR/登録**: 印刷名簿にチェック、手書き受付票、名札の事前印刷
- **スコア・結果表示**: 手書き集計表、模造紙/ホワイトボード
- **映像・スライド**: 予備PCにローカル保存（USB 2本）、印刷資料、司会の口頭進行
- **回線**: テザリング用スマホ/ポケット Wi-Fi を別キャリアで用意
- **配信**: ローカル録画を並行し、後日アップで代替

## 停止時アナウンス文（ひな形）

「ただいまシステムの調子が悪いため、ここからは紙（○○）で進めさせていただきます。お手元の○○をご用意ください。」

## 禁止

- 「システムが止まったら対応します」とだけ書いて、準備物・判断者・台本を書かない
- システムのリハだけでアナログ切替のリハをせずに「準備完了」と報告する
- 準備未完了のまま当日を迎える案件を、問題なしとして報告する
