# 名刺発注（AI共通ノウハウ）

> **このドキュメントの使い方（AIへ）**: ユーザーから「名刺発注」「名刺を注文」「○○さんの名刺」等の依頼があった場合の手順です。マヒトデザインのクラウド法人名刺サービスを使います。

## 専用スクリプト

`node tools/meishi-order.mjs` が使える環境ではこれを使います。

```sh
# 確認
node tools/meishi-order.mjs check {名前}

# 申請
node tools/meishi-order.mjs apply {名前} --qty {枚数}

# 注文（dry-run → ユーザーOK後）
node tools/meishi-order.mjs order {名前}
node tools/meishi-order.mjs order {名前} --yes
```

## 手順（この順番を厳守）

### 1. 確認
- `check {名前}` を実行し、役職・URL・裏面・申請状況をユーザーに報告する
- **役職や住所に変更がないかユーザーに確認する**（OKをもらうまで次に進まない）

### 2. 申請
- まだ申請中でなければ `apply {名前} --qty {枚数}`（既定100枚）
- 既に申請中なら何もせず終了

### 3. Dry-run
- `order {名前}` を実行する。確認画面の内容を表示する
- **この時点では注文は確定していない**

### 4. 確定（ユーザー承認後）
- ユーザーの「OK」を得てから `order {名前} --yes`
- **OK前に --yes を付けない**。注文は取り消せない外部システムへの実発注

### 5. 報告
- 発送予定日・注文番号を添えて完了報告をする

## 配送・用紙オプション

| オプション | 既定値 |
|---|---|
| 用紙 | マットポスト 180kg |
| コーナーカット | なし |
| 配送方法 | メール便（500枚以上は自動で宅配便） |
| 枚数 | 100枚（`--qty` で指定） |

## やってはいけないこと

- `--yes` をユーザーのOKより先に付けない
- パスワードを引数やログに出さない（envファイルからのみ読む）
- `apply` と `order --yes` は本番に副作用がある。ユーザーの合意なしに実行しない
