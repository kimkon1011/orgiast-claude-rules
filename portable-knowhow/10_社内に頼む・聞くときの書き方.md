# 社内に頼む・聞くときの書き方（AI共通ノウハウ）

> **このドキュメントの使い方（AIへ）**: 社内のメンバーに作業を依頼したり、確認を求めたりするときのルールです。受け手の手間を最小にする書き方を徹底します。

## 基本原則: 「その1通だけで用が済む」

受け手がそのメッセージ1通だけで **何を・なぜ・いつまでに・どうやって** を理解し、行動できるように書きます。

**悪い例（受け手が遡る必要がある）:**
```
> さっきの件、お願いします。
> 例のあれ、どうなった？
> B案でお願い。
```

**良い例（1通で完結）:**
```
田中さん

お疲れさまです。先日の打ち合わせの議事にあった「△△の見積書」についてですが、
11/10(火) 17時までに A社・B社の2社分の比較見積をメールで送っていただけますか？

添付のフォーマットに金額と納期を記載いただければ、こちらで比較表にまとめます。
対象: https://docs.google.com/...（kim@orgiast.jp で開いてください）

よろしくお願いします。
```

## メッセージの構成

1. **誰宛か**: 冒頭に名前（「田中さん」）
2. **用件**: 何をしてほしいか（「△△の見積書の送付」）
3. **期限**: いつまでに（「11/10 17時まで」）
4. **理由/背景**: なぜ必要か（1行で）
5. **詳細**: 具体的な対象・フォーマット・手順
6. **完了条件**: 何をもって完了とするか

## ラベルで指さない

「前回の案」「上記の通り」「B案」「①」などのラベルだけで指さず、同じ文に中身も書きます。

| ラベルだけ | 改善例 |
|---|---|
| 「B案でお願い」 | 「予算200万円のB案（提案書の2ページ目、展示台＋モニター2台の構成）でお願いします」 |
| 「先ほどの件」 | 「11/10の打ち合わせで話した△△の移設作業について」 |

## 作業依頼の書き方

依頼メッセージの中に以下をすべて含めます（別の場所を探させない）:

| 項目 | 含めるもの |
|---|---|
| 対象 | ファイル/フォルダのパスと名前、またはURL＋開くアカウント |
| 手順 | コマンド全文、画面の場所と正確なラベル |
| 完了条件 | 終わった後の返答方法や確認ポイント |
| 期限 | 具体的な日時 |

## やってはいけないこと

- 「前回と同じ」「さっきの」「先ほどの」「例の」「上記の」で省略しない
- 過去の会話や別のドキュメントを探させる書き方をしない
- 1つのメッセージに複数の独立した依頼を詰め込みすぎない（分割して送る）
- 「送っときました」だけで本文を載せない（送った内容を引用する）
