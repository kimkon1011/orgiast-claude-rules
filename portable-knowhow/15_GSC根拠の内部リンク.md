# GSC根拠つき新規記事プリフライト（X-0101適用）

## 目的

新規記事（コラム・ブログ等）の制作を始める前に、Google Search Console（GSC）の実データで既存ページがその主クエリで上位に入っていないかを確認し、無駄な重複コンテンツを防ぐ。

既存ページが1〜30位で流入を得ているなら**新規記事を止め、その既存ページのリライト**を優先する。内部リンクはGSCに実在するURLのみを使う。

## 手順

### 1. GSCデータを準備する

Search Consoleから3ヶ月分のクエリデータをエクスポートする（CSV形式、またはAPI経由のJSON）。必要な列:

- Query（クエリ文字列）
- Page（着地URL）
- Clicks（クリック数）
- Impressions（表示回数）
- Position（平均掲載順位）

### 2. 主クエリを決める

予定している新規記事のテーマから、検索されるであろう**主クエリ（1〜3語の組み合わせ）**を2〜6件決める。

例: 「展示会ブース 費用」「ブース デザイン」「再利用 ブース」

### 3. プリフライト判定を実行する

次のロジックで判定する:

1. **URL正規化**: `#`・`?`・末尾`/`を除去、`http→https`、`www.`統一で同一ページを統合する
2. **ボット除外**: `site:`・`url:`・`inurl:`・`filetype:`・UUID・ハッシュ風16文字以上のクエリを除外する
3. **語単位照合**: 主クエリの語がすべてGSCクエリに含まれる行を抽出する（NFKC正規化・空白除去後、部分一致ではなく語単位の全包含）
4. **ページ別集計**: 一致した行をページURLで統合し、表示回数・クリック数・平均順位を加重平均で計算する
5. **表示下限フィルタ**: ページ別合計表示回数が10未満のページは判定根拠から外す（`INSUFFICIENT`）
6. **順位判定**:
   - 表示下限以上の最良ページが1〜30位 → `REWRITE`（新規記事を止め、そのページをリライト）
   - 表示下限以上のページが31位以下 → `NEW_OK`（新規記事作成可）
   - 主クエリ一致行なし → `NEW_OK`（新規記事作成可）

### 4. REWRITEの場合の作業

既存ページに対して:

1. **即答をH1直下に500字以内で書く**: 主クエリに直接答える要約段落をH1の直後（冒頭）に追加する。自己紹介・前置きは入れず、結論から始める。
2. **内部リンクを追加する**: GSCに実在するURLだけをリンク先にする。プリフライトで抽出した内部リンク候補（実績ページ・料金ページ等）から選ぶ。
3. **自己QAは別パス**: Q&A形式のコンテンツは即答とは別のセクション（記事後半やFAQブロック）に配置し、H1直下の即答と混ぜない。

### 5. オージャスト固有の適用ルール

展示会ブース制作の新規コラムを書く前に:

1. ブース制作サイト（rebooth.co.jp / orgiast.jp）のGSCデータを確認する
2. 主クエリ（例: 「展示会ブース 制作」「展示会ブース 費用」「ブース デザイン」）が既存サービスページで1〜30位に入っていないか確認する
3. 1〜30位に入っている場合 → 新規コラムを中止し、その既存サービスページに即答500字以内 + 内部リンクを追加する
4. 内部リンク先はGSCに出ている実績ページ・料金ページのみとする（GSCに出現しないURLへのリンクは禁止）

## 使用例

```text
主クエリ: 展示会ブース 費用
判定: REWRITE
最良ページ: https://rebooth.co.jp/exhibition/1563
順位: 13位（表示14回）
作業: 1563ページのH1直下に341字の即答を追加 + 内部リンク補強
```

```text
主クエリ: ブース デザイン
判定: REWRITE
最良ページ: https://orgiast.jp/topics/7660 → https://rebooth.co.jp/exhibition/1344/（301転送）
順位: 22.3位（表示11回）
作業: 着地先ページのH1直下に310字の即答を追加 + rebooth.co.jp（表示36）への内部リンク追加
```

## 補足

- このルールは「AIニュース提案 X-0101」に基づく
- ツール実装: `tools/gsc-preflight.mjs`（CLIでも実行可能）
- 表示回数下限の既定値は10回。状況に応じて `--min-impressions` で変更可能
- 判定結果が `INSUFFICIENT` の場合は、表示回数が増えてから再判定するか、根拠不足として保留する
