# 手間チェック（AI共通ノウハウ）

## 背景

人に頼む前に電子・オンライン・AI代行を比較せず、紙作業や追加連絡を増やす事故を防ぐ。相手の手順数と読む量を最小にする。

## 手順

1. スマホ署名、電子署名、電子提出、オンライン手続き、AI代行、まとめて1回を含む候補を2つ以上比較する。
2. 紙・郵送・来所を選ぶ場合は法令または相手指定の理由を書く。
3. 手順数、読む通数と文字数を数える。訂正・取消し・念のための連絡は送らずに済ませるか次回へまとめる。
4. 所在・勤務形態、期限と所要時間、アシスタント→予備の順番を確認する。
5. 下書きへ記録し `node tools/tema-check.mjs --file <下書き>` で検査する。

## 記録例

```text
[TEMA-CHECK]
候補: スマホ署名（手順3・読む量1通200字） / 紙に書き直して写真（手順6）
選択: スマホ署名
紙理由: なし
手順数: 3
読む量: 1通・約200字
追加連絡: 次の連絡にまとめる
前提: 所在=大阪事務所近く / 期限=12/2必着・所要2日 / 順番=アシスタント確認済み→予備
AI代行: 不可（本人の署名が必要）
サインイン: 出どころ=既存セッション→1Password / 禁止=旧保存パスワード / 失敗時=出どころ切替→経路切替→本人の一点
[/TEMA-CHECK]
```

## サインイン委任

出どころは既存セッション、連携済み1Password、保存ログインの順。古い拒否済み資格情報は禁止する。失敗時は出どころ切替、経路切替、本人にしかできない一点の順とし、公共Wi-Fiでパスワード入力を求めない。

## 再発事例

2026-11-27、陳述書の日付訂正で紙への書き直しと写真を案内しスマホ署名を比較しなかった。予備の人へ発送を先に頼み、訂正連絡まで増やしかけた。ブラウザ委任では資格情報の出どころを運ばず、拒否済みの古い保存パスワードと本人手入力が先に使われた。
