# 送信前の整合性チェック

**▶ 送信前の整合性チェック（全送信の必須ステップ）（kim 2026-11-27 22:41・22:43 厳命）**

社外・社内を問わず、すべての送信の直前に次の8項目を通す。1つでも通らなければ送らずに止め、食い違い箇所を報告する。照合データの取得不能を「問題なし」にしない。

1. 同じ相手・同じ用件を既に送っていないか（全アカウントの送信済み・依頼台帳）。
2. 他PC・他アカウント・自動再確認タスク（タスクスケジューラ等）に同じ下書き・送信予定が残っていないか。
3. 日付・曜日・候補日・氏名・宛先・CCが過去のやり取りやカレンダーと食い違わないか。
4. 過去の送信内容と矛盾しないか。
5. 金さんの最新指示（例: AI注記を外す）が反映されているか。
6. 候補日・締切・イベント日が、送る時点で過ぎていないか。
7. 送る直前にそのスレッド・DMの新着を読み直し、相手から新しく届いた情報と食い違わないか。
8. グロボ・PC が、ユーザーに見せている承認カードや下書きの中身をコネクタなどで送ったときは、送ったという報告の中で「送信済みなのでカードは押さないで」と伝える。送る直前には送信済みフォルダをキャッシュなしで読み直し、ユーザーがカードなどからすでに送っていないかを確かめる。送っていれば止める。

送信後は元の下書きと再送予定を必ず消し（sent-registryに記録し）、消えたことを読み戻す。再確認手順の本文は書き換えず、同じdraftIdの送信済み記録を共通入口で検査して再送を止める。入口は `node tools/send-consistency-check.mjs`。既存の `--ack-consistency` ではこの検査を迂回できない。他PCやツールへの依頼文・ルール文はUTF-8（BOMなし）のファイルで渡す（PowerShell 5で日本語が化けるため）。再発事例: 2026-11-27 008の0:00/7:00再確認タスクに送信済み5通が残り、二重送信しかけた。

## データと運用

純関数 `checkSendConsistency(input, opts)` は取得不能を `unverified` に入れる。理由付きの `opts.allowUnverified` と `opts.unverifiedReasons` に明示した項目だけ警告になる。CLIに一括迂回オプションは設けない。

全PCの下書き・予定・送信記録は `~/.claude/send-consistency-fleet.json` に `checkedAt`, `labels`（fleet-pc-mapの全PC）, `sentHistory`, `scheduledSends`, `otherDrafts` を持つスナップショットを収集して渡す。5分を超えたもの・PC欠落は照合不能。利用できない場合は送信を止める。テストは収集関数を注入する。

`draftReadAt` は下書き作成または実際の読み直し時刻。新着取得時刻を自動で代入して新着を既読扱いにしない。読み直し後にCLIの `--draft-read-at` で渡すか、同じ宛先・本文の既存履歴照合マーカーを更新する。

`afterSendCleanup` は送信成功IDがある場合だけ記録・削除を実施する。Gmailは元draftIdのみを削除して404を再確認する。後始末が失敗しても送信済み記録を残し、再送しない。

`node tools/tema-rollout-check.mjs --out <結果.md>` は全PCの実ファイル読み戻しビーコンを表示する。未報告とオフラインを反映済みに数えない。

## 相手発言の照合（項目7の強化・2026-11-28 追加）

結論: 送る前に、相手がすでに済ませたことや変更したことを確かめる。同じ相手がいる別チャットと、本文のない写真も対象にする。使い捨てスクリプトからは送信しない。

1. 送信先と同じ相手がいる別チャットの直近24時間を読む。
2. 画像・添付の実物を開き、内容を説明として記録する。読めない（説明の無い）画像があれば送信を止める。
3. 下書きの各指示について、置き場所・日時・部数・宛先・手順を相手の発言と1文ずつ照合する。済んだことの再指示や矛盾する文は、相手の発言に合わせるか削る。
4. 照合に通した本文を、承認・整合性チェックのある共通送信入口（`tools/beeper-send.mjs` 等）で送る。合格マーカーは宛先と本文に結びつき、5分で失効する。`beeper-api.mjs` の `sendMessage` はマーカーが無いと送らない。リポジトリの tools/ 外の使い捨てスクリプトから送信 API を叩く実行は `oneoff-send-gate` が止める。

読み取りと判定だけを行い送信しないコマンド（画像説明は実物を読んだ内容をメッセージIDごとにJSONで渡す）:

```powershell
node tools/pre-send-reply-check.mjs --channel beeper --chat <チャットID> --text-file <本文ファイル> --image-notes <画像説明JSON> --json --write-pass
```

過去時刻の再現には `--now 2026-11-28T01:25:00Z` を付ける（その時刻より後の発言は使わない）。各PCの `~/.claude/CLAUDE.md` へは、更新を取得した後に `node tools/claude-md-block.mjs --all-default` で反映する（2回目は `unchanged`）。

再発事例: 2026-11-28、東邦ハイツ301で、相手の別チャットに「控えここ入れてます」と写真があり、送信先にも「乙第12号証」記入済みの写真（本文空）と「投函しておきます」があった。それを見ずに使い捨てスクリプトから記入と持ち帰りを再指示した（10:28 訂正）。検査が無言で効かなかった故障なので、1回目で仕組みを直した。
