## 止まった作業は必ず追いかけ台帳に載せる

作業が中断・停止・金さん待ちのまま終わったら、その場で台帳に1行作る。

```bash
node tools/ledger-open-item.mjs open \
  --id "GB-OPEN-<安定ID>" \
  --task "<タスクの説明／残件>" \
  --owner-pc "<担当PC>" \
  --status 止まった \
  --reason "<停止理由: exit非0/上限/金さん待ち等>" \
  --kim-wait \
  --due "YYYY-MM-DD 09:00"
```

- `--id` は安定ID（英数字・ハイフン・アンダースコアのみ80文字以内）。`stableId()` 関数（tools/ledger-open-item.mjs）がフォルダ名から生成するのと同じものを手で書くか省略すると自動生成される。
- `--task` には残件だけを書く（全体の作業説明でなく、次に誰かがやること）。`--kim-wait` は金さんの判断待ちの時に付ける。
- `--status 止まった` で追加すると、channel=manual になる（催促メッセージは送られず、kim-inbox にエスカレーションされるのみ）。
- `--reason` は必須。止まった理由を書く。

## 自動巡回（008 の check に内蔵）

008 の `node tools/followup-ledger.mjs check`（`cmdCheck`）に、gb-reports の未完了ディレクトリを走査する `scanReports` が内蔵されている。

- hubPc（既定 008）のみ実行。失敗しても check を止めない。
- `--no-scan` フラグで無効化できる。
- `~/.claude/config/gb-reports-roots.json` に追加のルートを書ける。

scan が拾う条件:
1. DONE.txt / DONE.md がある → 完了（スキップ）
2. EXIT.txt の値が非0 → 未完了
3. STATUS.txt / REPORT.md に未完了キーワード（待ち・未復旧・残件・中断・上限等）がある → 未完了
4. session-status/STATUS-<PC>.md で「金さん待ち」「停止」とマーク → 未完了（同名ディレクトリの DONE 確認後に登録）
