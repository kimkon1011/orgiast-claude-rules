# R640 初回起動の手順

対象はPERC H330 Mini、2.5インチ10ベイの実機。ラックはなく棚に横置きする。**まだメモリ・SSD・トレイ・OS用RJ45 NICが未購入なので、この時点では導入を実行しない。** この文書は準備完了後の手順で、実機での成功を示すものではない。

## 管理担当が先に用意するもの

kimに設定ファイル作成やコマンド入力を依頼しない。管理担当が次を整え、実際の接続URLを案内してから開始する。

| 項目 | 準備内容 |
| --- | --- |
| ハード装着 | 16GB RDIMM×8＝128GB（各CPU4枚）、2.5インチSATA SSD×2とトレイ、Intel I350-T2を装着。X520-DA2はSFP+×2でRJ45ケーブルを挿せない |
| 設置 | 重量を支えられる棚で筐体全体を支持し、前後の吸排気とケーブルを妨げない。10ベイ筐体は取手等を含め奥行き約80cmのため「約73cm」を棚選びの根拠にしない |
| サイト設定 | [site.example.json](../site.example.json)から実際のDNS名、管理/社内LAN、SSDの正確な2シリアル、容量下限、age公開鍵、管理SSH公開鍵、バックアップ先、RAMと同時数を設定 |
| 社員 | [employees.example.csv](../employees.example.csv)の4列を維持して正本から生成。実データをGitへ入れない |
| keyserve | 管理端末とサーバーの登録、DB/restic秘密情報、iDRAC情報、通知先を準備。初期PW入力は既存の安全な登録経路を使い、チャットやログには貼らない |
| iDRAC | 専用ポートの到達性、信頼できるTLS証明書、Virtual Mediaを使用できるライセンスとファームウェアを確認。ブラウザでログインできるだけではNode側のkeyserve連携は完了しない |
| ISO | 公式Ubuntu Server **24.04 LTS amd64** ISOのSHA256を正本と照合。2種類の専用ISOを準備する手順は[operations.md](operations.md)。keyserve登録情報を含むため管理LAN限定HTTPSで提供 |
| バックアップ | 別ホスト/NASへの保存先を用意し、resticのリポジトリを初期化。ローカルマウントならマウント確認も設定 |

筐体寸法と各部の図は[Dell R640 Technical Guide](https://i.dell.com/sites/csdocuments/shared-content_data-sheets_documents/en/us/poweredge-r640-technical-guide.pdf)の図3（10ベイ前面）、図4〜6（背面）、図13〜17（10ベイ寸法）を参照。

## kimの操作① 電源とLANをつなぐ

1. 管理担当の「部品装着・導入準備完了」を確認する。前面にメモリ不足などの異常がある段階では先に進めない。
2. 背面の電源ユニットに電源コードを接続する。2基とも使用する構成では両方接続する。
3. 管理担当が示した **iDRAC専用RJ45** に管理LANケーブルを挿す。次に **増設I350-T2のRJ45** に社内LANケーブルを挿す。管理ポートだけでは社員用デスクトップは通信できない。
4. 前面の電源マークのボタンを1回押す。起動中のファン音は大きくなることがある。繰り返し電源を切らず、管理担当の確認を待つ。

> 写真差し込み位置①：実機背面。iDRAC専用RJ45、I350-T2のRJ45、X520のSFP+、電源2基にラベルを付ける。現時点では写真未挿入。
>
> 写真差し込み位置②：10ベイ前面。電源ボタンと引き出し式情報タグを囲む。

## iDRACの初期IPの確認（管理担当側）

管理担当は管理LANのDHCP割当一覧と情報タグのMAC/サービスタグを突き合わせ、到達するiDRACを識別してURLを渡す。中古機は旧IP・旧認証が残る可能性があり、特定IPや`calvin`を決め打ちしない。

DHCPで見つからなければ管理担当が現地画面を使い、起動中のDellロゴで **F2 → System Setup → iDRAC Settings → Network → IPv4 Settings** を開き、DHCPか固定IPかと表示アドレスを確認する。ネットワーク変更は管理担当が行う。LCDベゼルが付いている場合は表示メニューのiDRAC IPv4でも確認できるが、LCDの存在を前提にしない。[DellのR640マニュアル集](https://www.dell.com/support/product-details/en-us/product/poweredge-r640/docs)の「Initial system setup」「Options to set up iDRAC IP address」を参照。

この代替作業が必要な場合、物理操作2つだけという目標はまだ満たせない。kimに追加操作を当然の前提として渡さず、管理担当が原因と必要な対応を整理する。

## kimの操作② iDRACの初期パスワードを入力する

1. 管理担当が案内した正確なiDRACのHTTPS画面を開く。証明書警告が出た場合は、管理担当が端末・証明書を照合して信頼設定するまで資格情報を入力しない。
2. 本体前面の細い引き出し式 **Information Tag（情報タグ）** を引く。Secure Default Passwordが設定された個体ではタグに固有パスワードがある。[Dellの説明](https://www.dell.com/support/manuals/en-us/poweredge-r640/idrac_3.31.31.31_ug/secure-default-password?guid=guid-a60a7699-584f-4245-b7e7-9a447dd4229f&lang=en-us)を参照。
3. 案内された安全な入力画面に初期パスワードを入力する。標準のユーザー名は`root`だが、中古機で変更されていれば管理担当が既存情報を照会する。既にkeyserveへ登録済みなら再入力しない。
4. 認証失敗時は連続して試さない。管理担当が保存情報・中古機の変更状況を確認する。タグにパスワードが無い場合も、推測で初期化しない。

> 写真差し込み位置③：情報タグの所在だけを撮影。パスワード部分を必ず完全に伏せる。
>
> 写真差し込み位置④：iDRACログイン画面。パスワード欄は空、URL・機器名は実機確認後に記載。

**現状の制限：本成果物にはパスワード入力Web画面や、入力イベントからbootstrapを起動する常駐オーケストレーターは含まれない。** 既存keyserve登録経路で資格情報が使えることを確認した後、管理担当が導入コマンドを開始する。「パスワードを入力しただけで全自動開始済み」とは扱わない。

## 管理担当の開始後に自動で進むこと

電源/LANと初期認証の確認後、管理担当が対象SSDの消去を承認し`--confirm-wipe`付きで開始する。このフラグ無しではiDRAC接続・ディスク操作へ進まない。ISO作成自体にも同フラグが必要で、作成済みISOは破壊的インストール媒体として扱う。

1. keyserveから資格情報を取得し、H330とSSD2台のシリアル・状態を検査する。
2. HBAへ遠隔変更できればHBA＋mdadm、できないことが検出された場合はハードRAID1用ISOを選ぶ。ジョブと変更後の状態を読み戻す。
3. iDRACのVirtual MediaへISOをマウントし、1回だけUEFIの仮想CDから起動する。
4. Ubuntuがリンクアップした最初の物理有線NICをMACで選び、対象SSDだけにインストールする。選択はインターフェース名の固定や単なるdriverワイルドカードではない。
5. 初回起動のsystemdがXFCE・日本語入力・アプリ・社員アカウント・Guacamole・防御設定・バックアップtimerを構築する。
6. `verify-on-host.sh`が合否表を作り、登録済み通知先へ件数を通知する。初期PWは暗号化保存され、社員への送信は自動では行わない。

## 完了の見分け方

管理担当は通知の `PASS / FAIL / PENDING` と `/var/log/orgiast-provision/verify.txt` を照合する。**FAIL=0でもPENDINGが残れば、利用開始の検証は未完了**。導入マーカーの存在やGuacamoleログイン画面だけで全体完了にしない。

社員用URLはサイト設定の `https://実際のホスト名/guacamole/`。ログイン画面→社員ID/PW→自分のdesktop接続でXFCEが表示されることを担当が確認する。ウィンドウを開いたままブラウザを閉じ、再接続で同じウィンドウ・同じXorg PIDに戻ること、日本語入力・コピー/貼付け・リサイズを検証する。

自己署名証明書を使った初期構築では、管理担当が信頼済み経路で証明書の指紋を照合し、Windowsの「ローカルコンピューター → 信頼されたルート証明機関」へ配布するか、社内CA発行証明書へ置換する。社員に警告の無視を習慣化させない。アクセス名は証明書のDNS名と一致させる。配布作業と実ブラウザでの信頼確認は未実施。

> 写真差し込み位置⑤：Guacamoleログイン画面とXFCEデスクトップの実機スクリーンショット。社員名やPWを写さない。
