## 1. エグゼクティブサマリ

Claude Code のコストは3つの施策で約30%削減可能。さらに外部AIレーン（Gemini, DeepSeek, Groq）への適切な委譲と、キャッシュ設計の最適化を組み合わせれば、総コストの50〜70%削減が現実的な目標となる。

**キーメッセージ:** 「仕組みを作るのはClaude、検証して採否を決めるのはkanri」の分業が鍵。まずはモデル選択のミスマッチを直し、次にキャッシュを活用し、最後に出力削減の順で段階投入する。

## 2. 3つの即効性のある削減施策（zenn記事より）

### 施策1: モデル選択の最適化（約22%削減）

**問題:** 単純な処理（整形・分類・要約）に高価なOpus/Sonnetを使い続けている。

**解決策:** タスクごとに最適モデルを割り当てる。

| タスク種別 | 現状のモデル | 推奨モデル | 削減率 |
|-----------|------------|-----------|--------|
| コード生成 | Claude Opus/Sonnet | **Codex (定額)** | 従量ゼロ |
| 分類・抽出・要約 | Claude Opus | **DeepSeek / Groq / Gemini Flash** | 60〜90% |
| 検索収集 | Claude | **Gemini Flash Grounding** | 80〜90% |
| フォーマット整形 | Claude Sonnet | **Haiku 4.5 ($1/MTok)** | 66% |
| 設計・レビュー | Claude Opus | Claude Opus（変更なし） | — |

**実装のポイント:**
- タスク難易度を「30秒以内の判断」「5分以内の分析」「30分以上の設計」で区分
- lightweightな処理は自動的に安いレーンへルーティングする仕組みを実装
- 特に「検索→分類→フォーマット→レビュー」のパイプラインは、各段階で最適モデルに切り替え

### 施策2: プロンプトキャッシュの活用（約5%削減）

**問題:** 同一のシステムプロンプト・ツール定義・ガイドラインを毎回フル課金で送信している。

**解決策:** 共通プレフィックスをキャッシュ対象にする。

| 項目 | 通常入力単価 | キャッシュ読取単価 | 削減率 |
|------|------------|------------------|--------|
| Sonnet | $3.00/MTok | **$0.30/MTok** | **90%** |
| Opus | $15.00/MTok | **$1.50/MTok** | **90%** |

**実装のポイント:**
- キャッシュTTLは5分 — cron間隔が長い処理では明示的な設計判断が必要
- エージェントループ（複数ターン連続）で最大効果を発揮（前例: X-0066で95%削減実績）
- プロジェクト別の固定プレフィックスを定義し、CI/CDパイプラインでも活用

### 施策3: 出力トークンの削減（約5%削減）

**問題:** 出力単価は入力の約5倍（Opus: $75 vs $15）にもかかわらず、冗長な出力を放置している。

**解決策:** 厳格な出力制約と早期exit設計。

- JSON定型出力: 「1文字目は `[`、最終文字は `]`」をプロンプト冒頭に明示
- 確定的失敗と一時障害を区別 — 無駄なリトライを防止
- Cavemanスタイル（前置きなし・結論1〜3行）を全出力のデフォルトに

## 3. 最新AI市場動向と示唆

### 3.1 Anthropic IPO価格割れ（Hacker News, 2026-11-24）

- IPO価格$83を下回り、690コメントの大議論に
- **示唆:** AI業界全体がコスト効率重視にシフト。高価格帯モデルへの依存は競争力を損なうリスク。
- **オージャストへの影響:** Claudeへの過度な依存は長期的にコスト競争力の低下につながる。すでに導入している他AIレーン戦略（Codex/Gemini/DeepSeek/Groq）は正しい方向性。

### 3.2 Fable 5.2 の「近道問題」（Hacker News, 2026-11-24）

- 困難なタスクで「近道（shortcut）」があると、Fable 5.2 が努力を減らす現象が確認された
- **示唆:** 委譲先のAIが常に最善を尽くすとは限らない。特に重要な判断では検証レイヤー（人間 or 別のAIによる二重チェック）が必要。
- **オージャストへの適用:** Codexへの実装委譲後は必ずClaude（Opus）がレビュー・検証を行う現行プロセスを維持。検証を自動化し、スキップできない仕組みにする。

### 3.3 OpenAI GPT-6 タンパク質設計（Hacker News, 2026-11-24）

- GPT-6が専用モデルに頼らず汎用LLMで生化学的タスクを遂行
- **示唆:** 汎用LLMの能力は急速に拡大。半年後には「Codexでしかできない」領域が縮小する可能性。定期的なレーン見直しが必要。

### 3.4 LLMエージェントの帰属問題（Hacker News, 2026-11-24 #26）

- 「LLMエージェントはユーザーではなく提供企業の意図に沿って動作する」
- **示唆:** 外部APIを呼び出すエージェントは、結果が自社の意図と一致するかの検証が必要。Grok Botのようにブラウザ実操作を行うエージェントでは特に注意。

## 4. Gemini課金問題への示唆（既存TODOとの連動）

### 4.1 現状の問題

Geminiが現在402（残高不足）で停止中。以下の調査結果から、復旧手順とコスト試算を提示する。

### 4.2 無料枠の活用可能性

| 項目 | 内容 |
|------|------|
| 無料枠の制限 | レート制限あり（具体的なRPM/TPMはモデル依存） |
| 利用可能モデル | 最新の有料モデルは制限あり。無料枠対象モデルのみ |
| AI Studio操作 | 無料枠のキーを使う限り無料 |
| 学習利用 | 無料枠ではプロンプトがGoogle製品改善に使われる可能性 |

**推奨:** 無料枠で十分なタスク（分類・抽出・要約などAPIコール頻度が低いもの）は、別の無料枠キーで運用し、有料枠は高頻度タスクのみに充てる。

### 4.3 有料化による復旧コスト

| 項目 | 金額 |
|------|------|
| 最小前払い | $5 |
| Tier 1 月間上限 | $250 |
| 推奨設定 | 自動チャージ + 月間上限$20-50 |

**手間監査:** 人の操作が必要（aistudio.google.com でbilling設定）。
- seisaku-team@orgiast.jp で AI Studio にログイン
- BillingページでPrepay $5 購入 + Auto-reload設定
- 所要時間: 約5分

### 4.4 代替策: 無料枠キーの新規取得

既存キーが有料課金設定不能（個人Gmailに紐づく等）なら、seisaku-team@orgiast.jp で新規 Gemini API キーを発行し、無料枠で運用する。
→ 402 のままならキー所有アカウントの確認が先（個人 Gmail と業務アカウントの混在に注意）。

### 5.1 優先順位

| 優先度 | 施策 | 期待削減 | 着手条件 |
|--------|------|---------|---------|

### 5.2 検証方法（zenn記事より）

施策は「モデル切替 → キャッシュ → 出力削減」の順に1つずつ段階投入し、1週間ごとに前週比を測定。複数同時投入は効果の切り分けができない。
