## 1. 問題: 気づかないうちに肥大化するAIコスト

### 1.1 93%は1チャットから

shmidt の実体験: ある月のAI請求額の**93%が単一のチャットセッション**から発生していた。そのチャットは放置されたままで、毎週同じプロンプトを繰り返し高コストモデルに送り続けていた。さらに、プリインストールされていた**デフォルトジョブが269クレジット/回**を消費していたことに何ヶ月も気づかなかった。

これは特殊なケースではない。多くの組織で:
- 「とりあえず作った」自動化が放置され、毎日高コストモデルを呼び続ける
- 全タスクに最上位モデルを使い、簡単な処理に過大な支払いをしている
- クレジット/実行の実測をせず、何がコストを食っているか把握できていない

### 1.2 根本原因

| 原因 | 影響 |
|------|------|
| モデルとタスクのミスマッチ | 簡単な検索や分類にOpus/Fableを使用 → 40〜80倍の過剰支払い |
| 放置された自動化 | 不要になったジョブが無人で稼働し続ける |
| コストの見える化不足 | クレジット/実行の実測なし → 原因箇所を特定できない |
| 上限の欠如 | バグや暴走で予想外の高額請求 |
| 手動再実行 | 同じ処理を何度もLLMに投げる（スクリプト化すれば1回） |

## 2. 9ルール詳細

shmidt のルールは「モデル選択のルール（5つ）」と「自動化のルール（4つ）」に大別される。

### 2.1 モデルルール（5つ）

#### ルール1: 繰り返しステップはスクリプト化してLLMをスキップ

**考え方**: 同じプロンプトを週に3回以上投げているなら、それはLLMでやる処理ではない。

| Before | After | 削減率 |
|--------|-------|--------|
| 毎週「今週の急上昇KWを教えて」とLLMに聞く | cronで自動取得・整形するスクリプトを書く | 100%（LLM呼び出しゼロ） |
| 毎月「先月の出費をカテゴリ別にまとめて」と聞く | 定型レポートを生成するPythonスクリプトを書く | 100% |
| 同じデータに対して毎回「このCSVを要約して」と投げる | 一度スクリプト化して引数で切り替える | 100%（該当チャット分） |

**オージャストでの適用例**:
- 週次SEOレポート（現在LLMで生成 → `weekly-seo-improve.sh` を拡張してLLM不要に）
- 展示会用定型テキストの生成（テンプレートエンジンで代替）
- 在庫確認（現在LLM呼び出し → スプレッドシート関数で完結）

#### ルール2: 簡単な検索はFastモード

**考え方**: 「今月の売上は？」「A社の担当者は誰？」といった既知の情報を探すだけのクエリに高コストモデルは不要。

| モデル | 出力価格/1Mトークン | 適性 |
|--------|-------------------|------|
| Fable 5.2 | $40 | 最高難度・監督判断 |
| Opus 5.5 | $20 | 設計・横断調査 |
| Sonnet 5.5 | $10 | コード生成・通常タスク |
| Haiku 5.5 | **$0.50** | 分類・抽出・軽量検索 |
| DeepSeek-V4.1-Flash | **$0.42** | 安価推論 |
| Gemini 2.0 Flash | **$0.10** | 超軽量検索 |

簡単な検索をHaiku/DeepSeekに回せば、Opus比で**40分の1**のコスト。

**オージャストでの適用例**:
- 在庫確認クエリ → スプレッドシートAPI直接参照（LLM不要）
- 過去見積の検索 → ベクトル検索＋Haiku要約
- 取引先情報の確認 → 軽量モデルで十分

#### ルール3: 週次レポートはBalancedモード

**考え方**: 定型的なレポート生成には中程度の能力で十分。週次のSEOパフォーマンスレポート、コンテンツカレンダーの更新、定例のKPIサマリなどはBalanced（Sonnet/DeepSeek相当）で品質を維持できる。

| レポート種別 | 適切なモデル | Opus比コスト |
|-------------|-------------|-------------|
| 週次SEOレポート | Sonnet / DeepSeek | 1/2〜1/50 |
| ��次コンテンツ実績 | Sonnet | 1/2 |
| 展示会出展後レポート | Opus（判断含む） | 適正 |
| 日次KPIサマリ | Haiku / Gemini Flash | 1/40 |

#### ルール4: 深い推論はSmartモード

**考え方**: 本当に高度な推論が必要なタスクにだけ最上位モデルを使う。具体的には:
- クライアントへの提案戦略の設計
- ブースデザインのコンセプト立案
- コスト構造の分析と改善案
- 法的リスクの評価

日常業務の70〜80%は低〜中難度であり、最上位モデルは**本当に必要な場面だけ**に限定する。

#### ルール5: 公開ミスはトップティアのみ

**考え方**: 顧客向けの最終成果物（見積書・提案書・プレスリリース）の品質チェックには、最上位モデルを使う。ここでのミスは直接的な信用低下につながるため、コスト削減の対象にしない。

| 対象 | 使用モデル | 理由 |
|------|-----------|------|
| 顧客向け提案書の最終チェック | Opus/Fable | ミスが信用低下に直結 |
| プレスリリースの校閲 | Fable | 公開後の修正は高コスト |
| 社内向けメモの下書き | Sonnet/Haiku | 修正は社内で完結 |
| 展示会テキスト案のたたき台 | Haiku/Gemini Flash | 後で人がチェック |

### 2.2 自動化ルール（4つ）

#### ルール6: 1チャットで構築後、スケジュール実行へ移行

**考え方**: 開発・検証は対話的に行い、完成したら定期実行（cron/CI）に移行する。対話セッションを放置すると、毎回同じコンテキストを読み込んで課金され続ける。

**shmidtの実例**: 93%の請求が1チャットから。開発用に作ったチャットを本番運用に使い続けていた。

**オージャストでの適用例**:
- SEOコンテンツ生成パイプライン: 開発はClaude対話 → 完成後はGitHub Actionsのscheduled workflow
- 展示会出展チェックリスト生成: 開発後はcronジョブ
- AIニュース提案（X-0057）: 既にパイプライン化済み ✅

#### ルール7: クレジット/実行でソートし、上位20%を優先修正

**考え方**: 全ジョブをクレジット消費量でソートし、**上位20%のジョブが総コストの80%を占める**（パレートの法則）。この20%を優先的に最適化する。

**実践手順**:
1. 全ジョブのクレジット/実行を計測する
2. クレジット合計で降順ソート
3. 上位20%のジョブを特定
4. 各ジョブに対してルール1〜6を適用
5. 改善後のクレジットを再計測

**shmidtの実例**: 269クレジット/回の隠れデフォルトジョブがこのソートで発見された。

#### ルール8: プリビルトデフォルトジョブを確認し、不要なものをオフ

**考え方**: 多くのAIプラットフォームには初期状態で有効な「おまけジョブ」が含まれている。これらが静かにクレジットを消費し続ける。

**チェックリスト**:
- [ ] プリインストールされたジョブ一覧を確認
- [ ] 使用していないジョブを停止
- [ ] 使用中のジョブもクレジット/実行を確認
- [ ] 週次で変化がないか監視

**オージャストでの適用例**:
- GitHub Actionsのワークフロー一覧を確認し、使っていないものを停止
- GASのトリガー一覧を確認し、不要な定期実行を削除
- Vercel cronジョブの一覧確認

#### ルール9: 全ワークフローにハードキャップを設定

**考え方**: 各ワークフローに月間/実行あたりのハードキャップを設定する。バグや暴走があった場合も、上限で自動停止する。

| キャップ種別 | 設定例 | 効果 |
|-------------|--------|------|
| 月間クレジット上限 | 月500クレジット | 予算超過��防止 |
| 1実行あたりの上限 | 50クレジット/回 | 暴走時の被害を限定 |
| 月間実行回数上限 | 100回/月 | 無制限実行を防止 |
| 日次クレジット上限 | 50クレジット/日 | 日次での異常を早期検知 |

**オージャストでの適用例**:
- 各GitHub Actions workflowに `timeout-minutes` を設定（既に一部設定済み）
- cost-monitor workflow に月間アラート閾値を設定
- AIニュースパイプライン（X-0057）に月間実行回数上限

## 5. 結論

shmidt (@shmidtqq) の9ルールは、LLMコスト削減の「原理原則」をシンプルにまとめた実践的なフレームワークである。特別なツールや大規模な移行を必要とせず、**設定変更と運用ルールの見直しだけで**即座に効果が出せる点が最大の強み。

オージャストでは:
- 既に `cost-monitor` workflow でAPI課金を日次監視している（継続 ✅）
- モデルルーティング（X-0082）やキャッシュ（X-0084）の調査も進行中
- AIニュースパイプライン（X-0057）は既にスケジュール実行に移行済み ✅

次のステップとして:
1. 全GitHub Actions workflowの `timeout-minutes` と月間実行回数のハードキャップ設定
2. 各ジョブのクレジット/実行の計測とダッシュボード化
3. 軽量タスク（分類・抽出・要約）のHaiku/DeepSeek/Gemini Flashへのルーティング
4. 週次SEOレポートのLLM→スクリプト化
