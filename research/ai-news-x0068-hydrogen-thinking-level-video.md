## 2. 思考レベル戦略（4段階の使い分け）

### 2.1 レベル定義

| レベル | 用途 | 品質 | 速度 | トークン消費 |
|-------|------|------|------|------------|
| **xhigh** | 数学的証明・科学分析・複雑なマルチファイルSWE | 最高 | 最遅 | 最大（思考トークン多用） |
| **high**（既定） | マルチステップエージェント・コード生成・複雑なマルチモーダル分析 | 高い | 遅い | 多い |
| **medium** | 一般コーディング・ドキュメントQA・動画理解 | 十分 | 中程度 | 中程度 |
| **low** | 高スループット分類・ルーティング・要約・構造化抽出 | 最低限 | **最速** | **最小** |

### 2.2 オージャスト業務での割当て

| タスク | 推奨思考レベル | 理由 |
|-------|--------------|------|
| 展示会問い合わせの一次分類（見積/在庫/キャンセル） | **low** | 単純な選択肢分類。出力はカテゴリ名のみ。品質十分。 |
| ブース仕様PDFの条件確認（寸法・重量・電源） | **medium** | 数値比較+ルールベース。xhighだと過剰。 |
| 施工メモの要点抽出 | **low** | 構造化抽出。精度はlowでも十分。 |
| 動画のフレーム毎スキャン（什器配置・装飾材） | **medium** | 視覚認識が必要だが、全てのフレームにhighは不要。 |
| コード生成（定型処理・設定ファイル） | **medium** | 複雑度が低い定型コードはmediumで十分。 |
| コード生成（複雑なロジック・リファクタリング） | **high** | 論理的な正確性が必要。 |
| 企画書の構成設計 | **high** | 顧客向け品質。論理構成の正確さが要求される。 |
| 過去事例ベースの類似案件提案 | **medium** | キャッシュヒット率を最大化（同一プレフィックスでmedium固定） |
| 夜間バッチ（全案件の一括分析） | **medium** | 無人実行。速度と品質のバランス。キャッシュ95%適用。 |

### 2.3 コスト比較（レベル別、100万トークンあたり）

**注意**: 思考レベルの変更は**出力トークン消費量**に影響する（出力単価は$7.50固定だが、消費する思考トークン量が変わる）。Googleの価格表では出力に思考トークンが含まれる。

| レベル | 推定出力トークン比 | 実効出力コスト（/M出力トークン換算） |
|-------|-----------------|----------------------------------|
| low | 0.5x（思考抑制） | ~$3.75（見かけの出力トークンあたり） |
| medium | 1.0x（標準） | ~$7.50 |
| high | 2.0x（思考トークン増） | ~$15.00 |
| xhigh | 3.0x+（思考トークン最大） | ~$22.50+ |

**ポイント**: lowでは単純な応答になるため総トークンが減る。high/xhighでは思考トークンが増えるため、出力コストが実質的に増加する。キャッシュ割引（95%）は入力トークンのみに適用され、出力トークンには適用されない。

### 2.4 実務ガイドライン

```
タスク種別ごとに思考レベルを固定し、ルーティングテーブルで管理:

- 分類・抽出 → low（出力トークン最小化）
- 一般的な分析・生成 → medium（標準）
- 顧客向け品質が必要な場合 → high（最終チェックのみ）
- xhighは現時点では不使用（ブース業務に数学的証明は不要）
```

## 3. 動画分析 2段階プロトコル

### 3.1 従来の課題（X-0039の想定）
X-0039では「動画をHydrogenにそのまま流す」単一モデル方式を想定していた。しかし動画分析の実務では、**全フレームスキャン（全体像）** と **クリティカルフレームの詳細指摘** の2段階が必要であり、単一モデルでは出力トークンが膨張する。

### 3.2 2段階プロトコル

```
Step 1: [Hydrogen / medium思考] — 全体像スキャン
  入力: 動画全フレーム（1fpsに間引き、3分動画→180フレーム）
  プロンプト: 「什器配置の主要パターン/装飾材の色調/来場者動線を250トークン以内で列挙」
  出力: 構造化JSON（箇条書きリスト）
  コスト: 入力~50万トークン($0.75) + 出力~250トークン($0.002)

Step 2: [Carbon / high思考] — クリティカルフレーム詳細指摘
  入力: Step1の出力 + 問題箇所のフレーム5〜10枚（Hydrogenが選定）
  プロンプト: 「指定フレームの接合部/照明位置/安全要件の不備を詳細に指摘」
  出力: 詳細レポート（~1,000トークン）
  コスト: 入力~10万トークン($0.10~0.20) + 出力~1,000トークン($0.005〜0.01)

Step 3: [必要時のみ Claude Opus] — 最終品質検証
  顧客提出用レポートのみ、Claude Opusで校正・日本語品質チェック
  コスト: 入力~5,000トークン($0.02) + 出力~500トークン($0.01)
```

### 3.3 コスト比較（動画分析1本あたり）

| 方式 | モデル | 入力コスト | 出力コスト | 合計 |
|------|-------|-----------|-----------|------|
| 従来（Claude一発） | Claude Opus 5.5 | $2.00 | $0.30 | **$2.30** |
| X-0039方式（単一Hydrogen） | Hydrogen high | $0.75 | $0.05 | **$0.80** |
| **X-0068方式（2段階）** | Hydrogen med + Carbon high | $0.85 | $0.02 | **$0.87** |
| 従来（Sonnet一発） | Claude Sonnet 5.5 | $1.50 | $0.15 | **$1.65** |

→ 2段階方式でも単一Hydrogenとほぼ同コストだが、**Carbonによる詳細指摘が加わる**ことで品質が向上。X-0039の「品質リスク（HydrogenはClaudeに劣る）」をCarbonのスポット利用で補完。

### 3.4 動画分析20本/月の比較

| 方式 | 月額 | X-0039対比 |
|------|-----|-----------|
| Claude一発（Opus） | $46.00 | - |
| X-0039方式（Hydrogen単一） | $16.00 | ▲65% |

## 4. 画像素材分析の現実解（Hydrogenの制約）

### 4.1 重要な発見
Web調査の結果、**Gemini 4 Hydrogen は画像生成能力を持たない**。出力はテキストのみ。これはX-0039の前提「画像素材の分析・生成をHydrogenに委譲」を一部修正する。

| 操作 | Hydrogenの対応 | 代替手段 |
|------|---------------|---------|
| 画像の内容分析（什器配置・色調・材質識別） | ✅ 入力対応（マルチモーダル） | - |
| 画像のキャプション生成 | ✅ 入力分析＋テキスト出力で対応可 | - |
| 画像の生成（ブースCG・レイアウト図） | ❌ 非対応 | Imagen / Midjourney / DALL-E |
| 画像の編集（色調補正・部品差し替え） | ❌ 非対応 | Photoshop / Generative Fill |

### 4.2 推奨フロー（画像素材業務）

```
[分析フェーズ] → Gemini 4 Hydrogen: 既存画像の内容分析（キャプション・色調・配置）
[生成フェーズ] → Imagen / Midjourney: 分析結果に基づく画像生成プロンプト作成
[編集フェーズ] → Photoshop / Generative Fill: 最終調整
```

**コストポイント**: Hydrogenによる画像分析は入力画像トークンに通常課金（$1.50/100万トークン）されるが、同一プロンプト+類似画像の連続分析では暗黙的キャッシュが効き、**95%割引が適用される可能性がある**（ただし画像のハッシュ一致が必要かは未確認）。

## 7. 結論

X-0039は「Hydrogen + 95%キャッシュ」の導入意義を価格面で明確にした。X-0068はその**実務運用の細部**を補完する:

1. **思考レベル戦略**: low（分類/抽出）→ medium（一般分析/動画）→ high（顧客品質）の3段階を使い分け、出力トークン費を最小化する。
2. **動画分析2段階**: Hydrogen（全フレームスキャン）→ Carbon（クリティカル詳細）で、単一モデルより高品質かつコストはほぼ同額。
3. **画像生成の制約**: Hydrogenは画像分析のみ。生成は別ツール（Imagen/Midjourney）との併用が必須。
4. **1案件コスト**: 実務想定で **$1.41/案件**（従来Opus 5.5の **$8.62/案件** から **▲83.6%**）。
5. **Carbon利用の期限**: 11/30までが最適。12月以降はCarbon費用が倍増するため、Orchestrator導入判断は早めに。

**次のアクション（実測）**:
1. Gemini APIキーの確認（seisaku-team@のAI Studio TrackPlannerキーを流用）
2. Google AI Studioの無料枠でHydrogenの思考レベル別レイテンシ実測
3. ブース動画（テスト用）をHydrogenで分析し、実効キャッシュヒット率を計測
4. 実測結果をもとにDEC-0006のPROPOSAL→ACTIVE判断
