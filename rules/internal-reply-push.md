# 社内の質問・返事は、見回りの回のうちに返事まで送る（kim 2026-11-27）

期限のある案件で、社内の人から届いた質問・返事・提出物は、それを見つけた見回りの回のうちに AI が返事まで送る。社内宛ては確認不要（インド不在中の社外送信だけ佐藤優奈さんに確認する）。

## 毎回やること
1. **「届いたか」ではなく「相手が何を聞いているか・何を待っているか」を読む。** 写真・ファイルが届いたら中身を開いて条件（手書き署名・日付・押印など）を満たすか確かめ、相手の文面に質問があれば答える。
2. **返事を送る。** 答えられる質問はその回で答える。金さんにしか決められないことは、相手に「確認して○時までに返します」と送ったうえで、金さんにボタンで聞く。「金さんの確認待ち（kim-inbox）に入れた」で終わらせない。
3. **期限まで、こちらから押す。** 「待つ」で見回りを止めない。期限から逆算して、返事がなければ催促・別経路（電話・別の人）に切り替える時刻を決め、その時刻に実行する。夜（22時〜7時）は送らず、翌朝の最初の回で送る。
4. **入口は `node tools/internal-pending-replies.mjs`。** 社内の未返信（質問・依頼、kim-inbox で止まった Discord 判断待ち）を `gb-reports/latest-internal-pending.md` に出す（読むだけ）。見回りはこの一覧を毎回読み、全件に返事を送るか、送れない理由と次の時刻を書く。

## 禁止
- 期限のある案件で「読むだけ・送信しない」監視スクリプトだけを置くこと。読むだけの部品を使うときは、読んだ結果に返事をする担当（見回り）を同時に決めて書く。
- 監視の終わりを「期限＋15分」などで固定し、期限後の催促・別経路を決めないまま止めること。
- 自動返信が「判断待ち」（添付が読めない等）にした社内の質問を、kim-inbox に入れただけで放置すること。添付は別経路（Beeper の media フォルダ、Drive）で開いて確かめ、返事まで送る。
- 返事待ちの一覧に、実はこちらが返事をしていない案件を「先方の返事待ち」と書くこと。

## 再発事例（2026-11-26〜27 労働審判の陳述書署名）
- 11/26 18:19 古川さんが Discord DM で「PDF は自筆の署名ではないがよいか。下に自筆の署名もするか」、18:22「自筆なら今日22時以降」と質問。
- 17:39 に作った監視（watch-loop.ps1 / watch-sign-photos.mjs）は「読むだけ。送信・返信はしない」「21:15 で終了」。18:45 に質問の文面を記録したが、返事をする担当がいなかった。
- 18:22 の自動返信（discord-beeper-autoreply）は、画像2枚の取得に失敗したため「判断待ち」として kim-inbox（ki-20261126092359-e19d）に入れた。この項目は一度も表示されず、未回答のまま。
- 11/27 00:26 の再開セッションは、写真に手書き署名がないことと質問を読んだが、「2026-11-28 12:00 まで待つ」として返事をしなかった。
- 11/27 の見回り・報告は「古川さんの署名写真」を先方の返事待ちとして扱い、返事が出たのは 11/27 19:53（約25時間後）。
