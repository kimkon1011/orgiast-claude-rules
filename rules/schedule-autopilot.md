## 1. 作業中のセッション（全PCの Claude Code）がやること
- 日付・時刻のある予定（送信・配信・納期・提出・金さんの承認待ち・電話・支払）を見つけたら、その返答の中に1件1行で書く:
  `【予定】2026-11-24 09:00｜課題提供企業 第5便の送信｜種別:送信｜担当:008｜金さん判断:この文面で送ってよいか｜推奨:送る｜文面:https://docs.google.com/...`
  - 種別: 送信 / 承認 / 納期 / やること。担当: PC名か人名（金さん本人なら kim）。
  - 金さん判断・推奨・文面は、金さんの判断が要るときだけ。推奨案と文面の全文URLを必ず付け、その場で「可」と答えられる形にする。
- Stop hook（`schedule-autopilot.mjs capture`、非同期）が【予定】行を期限台帳へ自動で書く。台帳に届かないときは `~/.claude/deadline-watch/autopilot-outbox/` に保留し、次の書き込みで流す。
- 手で書くとき: `node tools/schedule-autopilot.mjs add --title "…" --due "2026-11-24 09:00" --type send --assignee 008 --needs-kim "…" --recommend "…" --draft-url "…"`
- 済んだら `node tools/schedule-autopilot.mjs done --id <ID>`。`/session-close` でも未記録の予定を書き出す。
- 前倒しで済ませられる準備（下書き・宛先確認・照合・資料作成）は、着手期限より前に AI 側で終わらせる。金さんに渡すのは判断だけ。

## 2. 000 の定時ジョブがやること（無LLM）
- 期限台帳（https://docs.google.com/spreadsheets/d/1iR9gzpFZxPpNIlPLekkT9ls4YYJyhUmEio4sUU-5okQ/edit）と、読み取り専用の集約元（3億円 実行計画の日次タスク・週次マイルストーン、営業進捗の次回連絡日、案件一覧マスター、問い合わせ一覧）を読む。
- 営業日（土日・祝日・振替休日・国民の休日・年末年始休業）で逆算する:
  - 送信・配信: 期限が休日・連休中なら直前の営業日に前倒しし、**その日の12:00まで**に送る（相手が営業日の午前に読めるように）。
  - 着手期限 = 実行日の N 営業日前（送信・承認は1営業日前が既定。`--prep-days` で変える）。
- 届けるタイミング（同じ内容の連打はしない。段階が変わったときだけ、締切が近いほど強く）:
  1. 毎朝 8:00 の一覧（営業日のみ。休日は急ぎがある時だけ）: 今日の午前中に送るもの／金さんの判断待ち（推奨つき・「1 可」で答えられる）／今日が期限／次の営業日の準備（連休前は連休明けまで前倒し）／遅れと挽回策／3億円の今日のタスクと未完了の過去分・今週の目標／営業・案件・問い合わせの期日。
  2. 前営業日の朝 🟠 → 当日の朝 🔴 → 締切3時間前 🚨（15分ごとの tick で個別に1回）→ 期限直後 ⚠️（挽回策つきで1回）。

## 3. 守ること
- 社外への送信・支払・削除はしない。承認が要るものは「承認依頼」を期限前に出すだけ。承認後の送信は担当PCが従来の送信ゲート（send-context-check 等）を通して行う。
- 3億円計画・営業進捗などの集約元には書き込まない（読み取りのみ）。

## 4. 出欠の確認・返答は積まない（kim 指示 2026-11-25）
- 出欠確認・出欠連絡・参加可否の返答（「出席できますか」「参加可否を教えて」「出欠を回答」など）は、金さんの判断リスト（kim-inbox・朝の一覧・承認待ち）にも、カレンダーの【調整可】予定にも一切積まない。家族の食事会に限らず全般に適用する。
- 金さん本人が出席する当日の会食・式典・打合せそのもの（日時が決まっている予定）は残してよい。除外するのは「出欠を答える」というタスクだけ。
- 既に積まれているものを見つけたら台帳・カレンダーから外し、事後に1行で報告する。

## 社外に送る Drive / Docs リンクの3点確認

送信直前に `node tools/share-before-send-gate.mjs --external-body-file <本文ファイル>` を実行する。本文中の各URLについて、(1) DriveのMIMEがGoogle形式またはPDF（pptx/xlsx/docx等・Office書き出し・`rtpof=true`は不可）、(2) `anyoneWithLink` の `reader`（検索非公開）、(3) cookie・認証ヘッダーなしの取得がHTTP 200でログイン画面へ転送されない、の3点を確認する。どれかNG・確認不能なら非0終了し、送信しない。個人共有の履歴・過去の成功・単なるHTTP 200で代用しない。公開ビューア内の「ログイン」リンクとログイン必須画面は区別する。

くらしのマーケットのローカル送信スクリプトは `tools/curama-share-gate-adapter.mjs` の `assertCuramaLinks(page)` を送信クリックの直前で `await` する。実際の入力欄を検証し、例外時はその送信を止める。ゲートの合格は送信許可を与えるものではなく、宛先・全文確認・既存の送信承認ルールは引き続き適用する。008での配線差分は `docs/curama-share-gate-008.patch` を参照。

- Discordの面談設定などから自動で作る応募者・求人の面談予定は、seisaku-team@orgiast.jp のカレンダーに作り、kim@orgiast.jp は参加者に入れず、kim のカレンダーにも作らない。
