# 構成とデザインの型（design-deck §0 の詳細）

企画書・提案書を作るときは、毎回この順で進める。出典は末尾に書いた4つの X 投稿（2026-11-19 kim 指示で取り込み）。ハイブリッド企画書モデル（Claude が文字・数字を組版し、画像AIは文字なしの写真だけを作る）はそのまま使う。

## A. 作り始める前に「誰に・何を決めてほしいか」を書く（brief.md）

`deck-hybrid/brief.md` に次の6項目を書いてから `pages.json` に入る。案件の情報は case-consult-sources で集めた Gmail・議事録・ヒアリングシートから取り、入力に無いものは作らない。

| 項目 | 書く内容 | 例 |
|---|---|---|
| 相手 | 読む人・決める人と立場（担当者か決裁者か） | 担当: 広報課長／決裁: 部長 |
| 相手の姿勢 | 前向き／比較検討中／反対・懸念あり。懸念は相手の言葉のまま | 「去年より予算を下げたい」 |
| 場面 | メール添付で読む／対面で説明／社内稟議に回る | 社内稟議に転送される |
| 決めてほしいこと | この資料を読み終えたら相手がする1つの行動 | 竹案で正式発注 |
| 手元の根拠 | 使える数字・実績・写真・相手の発言 | 来場者数、過去の名刺獲得数 |
| 用途トーン | 下の表から1つ選ぶ | 営業提案 |

| 用途トーン | 見た目 |
|---|---|
| 営業提案（既定） | 明るく前向き。写真大きめ、主色1色＋グレー、余白多め |
| 決裁者・経営会議向け | 重厚で信頼感。濃い主色、数字と比較表を大きく、装飾を減らす |
| 社内・研修 | すっきり見やすい。図解中心、写真は内容を示すものだけ |
| 採用・イベント告知 | 親しみやすく温かい。人物写真中心、角丸・柔らかい色 |

相手・目的・場面が分からないときだけ、kim に最大3問まで聞く。分かっている項目を聞き直さない。

## B. 説明の型を組み合わせて構成を決める

1つの型だけで1本の資料にしない。役割ごとに2〜5個の型を組み合わせる。

| 役割 | 置く場所 | よく使う型（選ぶ合図） |
|---|---|---|
| 導入 | 1〜2ページ目 | 前提共有（前回打合せの続き：決まったこと・残った論点・今日決めたいこと）／問題意識の掘り起こし（相手が課題に気付いていない） |
| 骨格 | 本論の並び順 | エビデンス強調（懸念・反対がある：相手の発言をそのまま受け止める→覆す根拠→根拠を示す）／意思決定プロモート（決裁者が選ぶ：目的を思い出す→選択肢を同じ物差しで並べる→案ごとの試算→判断基準）／メリット・ファースト（前向きな担当者） |
| 部品 | ページの中 | 基準値（比べる基準を先にグレーで置き、見せたい数字を色で横に）／比較（同じ項目で並べる）／具体例・喩え（抽象の直後に実物） |
| 橋渡し | 章の切れ目 | 要約（ここまでの3点）／振り返り |
| 締め | 最後 | オファー（お願いしたいことを3つ以内）／決裁者サポート（稟議に転記しやすい1枚） |

手順:
1. brief.md から型の組み合わせを3案出し、本命1案と理由、選ばなかった型の理由を1行ずつ書く。決められる判断なので kim に選ばせず本命で進め、最終報告に3案を1行ずつ載せる。
2. ページごとに「このページで相手が分かること」を1文で書いてから見出しを作る。
3. 組み立てメモ（使った型・どのページで・入力のどこから選んだか）は `BUILD-REPORT.md` に書く。お客様向け資料には載せない。

オージャストの展示会ブース提案での定番の組み立て:
- 初回提案: 導入=問題意識の掘り起こし（集客・名刺獲得の課題）→骨格=メリット・ファースト→部品=基準値（前回出展・業界平均と比べる）→締め=オファー（松竹梅から1案）
- 再提案・値下げ相談: 導入=前提共有（前回提案で決まったこと・残った懸念）→骨格=エビデンス強調（懸念を原文で受け止める）＋意思決定プロモート（松竹梅を同じ物差しで比べる）→締め=決裁者サポート

歯止め:
- 入力に無い数字・事例・実績を作らない。不明な値は〈金額〉〈日付〉〈台数〉のように空けて残し、最終報告で一覧にする。
- 相手の懸念・反対は言い換えず原文で載せ、強調色を使わない。答えられない懸念は隠さず「判断基準に残す」と書く。
- 都合の悪い事実（追加費用・制約・前回の不具合）を省かない。
- 同時に起きただけの2つを原因と結果として書かない。
- 推したい案だけを強調するときは、その旨を注記する。

## C. デザイン規則（DESIGN.md）を最初に決めて全ページに貼る

画像生成・組版の前に `deck-hybrid/DESIGN.md` を作り、`visualBrief` と CSS の両方に毎回反映する。規則なしだと20ページを超えたあたりで配色・書体・余白がばらける。

DESIGN.md に書くこと:
- 主色1色（客先ブランド色か用途トーンから）＋グレー階調＋強調用の補色1色まで。色の数をこれ以上増やさない。
- 書体2種まで（見出し・本文）、文字サイズの段階（例: 96/48/28/18px）。
- 余白の段階（例: 8の倍数で 16/32/64/96px）。関連する要素は近く、別のまとまりは広く空ける。
- 写真の扱い（フルブリードかパネルか、角丸の有無、注記の位置）。
- 参考にしたい資料のスクリーンショットがあれば、その分析結果をここに書く。客先のWebサイト・会社案内から色と雰囲気を拾ってよい。

## D. 1ページの作り方（ドパデザ:「気になる→わかる→うれしい」）

1. **比べる**: 違いを見せるときは、変える点を1つに絞り、それ以外（文章・色・書体・倍率）をそろえて A/B で並べる。
2. **問いを回収する**: 問いかけを置いたら、同じページか次のページで答えと理由を示し、指している場所に矢印やラベルを添える。
3. **主役は1つ**: 1ページで強調するのは1つの結論・1つの数字だけ。補足は通常の強さに戻す。色だけに意味を持たせず「結論」などのラベルも付ける。縮小しても主役の言葉が読めるか確かめる。
4. **変化を見せる**: 前後比較（現状ブース→提案ブース、前回→今回）は同じ倍率・同じ位置関係で並べ、変えた所だけにラベルと矢印を付ける。改善前だけ小さく・暗くしない。
5. **一歩で完了**: 相手にお願いすることは小さく具体的に（「竹案でよければ〇日までに返信」）。完了条件が分かる形にする。
6. **喩えは実物とセット**: 比喩やイラストを使ったら、すぐ後に実際の写真・図面・数字を見せる。

## E. 「AIっぽさ」点検（preview の5観点採点に加えて全ページで確認）

次のどれかに当たったら直してから再プレビューする。

- 白背景に箇条書きだけのページ
- 理由なく選んだ青（主色は DESIGN.md から）
- タイトルの下のお決まりの線・意味のない装飾アイコン
- 文字のはみ出し・重なり・途中の改行
- 全部を太字・色付けにしていて主役が分からない
- ページごとに余白・書体・色がばらついている
- 「〜を実現します」「最適なソリューション」のような、どの会社にも言える文
- 型どおりの3列カードが何ページも続く
- 数字に比べる基準（前回・平均・他案）がない
