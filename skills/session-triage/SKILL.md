# セッション・トリアージ（積み残しの発掘）

## 通常はユーザーが打つ必要はない（自動提示）
SessionStart フックが**1日1回、勝手に🔴上位5件を注入**する。
このスキルが明示的に呼ばれた時は、全件・詳細を見たい時なので下の手順で出す。

## まず作り置きを読む（トークン0・待ち時間0）
毎晩の夜間バッチが `~/.claude/session-triage.md` に完成形を書き出している。
まずこれを Read し、`<!-- SESSION-TRIAGE-START -->`〜`<!-- SESSION-TRIAGE-END -->` の中身をそのまま提示する。
**生成時刻が24時間以上前 or ファイルが無い場合のみ**、下の再生成に進む。

## 再生成
```
node ~/orgiast-claude-rules/tools/session-triage.mjs --llm --top 20
```
- `--llm` は Groq（激安・並列）で「完了/未完了の判定＋次の1アクション」を出す。**キーワードだけの判定は誤検出が多いので原則 --llm を付ける**
- LLM 無しの高速版は `--top 20` のみ（0.2秒）
- Markdown 書き出し: `--md "$HOME/.claude/session-triage.md"`（Windows は `$env:USERPROFILE\.claude\session-triage.md`）
- 全分類を見る: `--all-status` / 期間: `--days 30` / 絞り込み: `--status 要対応`

## 自動クローズ済みの扱い
7日以上放置のセッションは夜間バッチ（`tools/session-auto-close.mjs`）が非破壊で自動クローズし、引き継ぎは `~/.claude/session-handoffs.md` に蓄積する。
一覧から消えたセッションも削除されたのではなく、台帳でクローズ済みになっただけ。`--include-closed` でクローズ済みも確認できる。

## 提示のしかた
- 🔴要対応 を上から、1件 = 「タイトル / 何日前 / 次の1アクション / 再開コマンド」の4点だけ。長い引用はしない
- **タイトルは原文のまま出す**（言い換えると VSCode サイドバーの検索に当たらず「探しても出てこない」になる）。検索語をそのまま貼れる形で添える
- 再開は `claude --resume <sessionId>`（cwd が違う場合は cwd も併記する）
- 「どれから手を付けるか」を聞かれたら、経営インパクト（主要プロジェクトの memory）× 放置日数で上位3件を推す

## 注意
- 読み取り専用。セッションファイルは**絶対に削除・移動しない**（過去版が必要 / kim 厳命）
- 実行中の自セッションは自動除外される（`--include-current` で含む）
- サブエージェント・workflows・`_deleted-backup` は対象外
