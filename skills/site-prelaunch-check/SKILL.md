# サイト公開前チェック（25項目）

発端: 2026-11-24 kim 指示（Eswarxcodes 投稿「公開前に Claude に確認させる25項目」を全サイトへ導入）。
Claude Code で作ったサイトは、公開・本番デプロイの前と、大きな改修の後に必ずこの25項目を通す。

## 手順

1. 自動点検を走らせる（外部から見える項目を機械判定）:
   ```
   node tools/site-prelaunch-check.mjs --url <公開URL> --repo <リポジトリのパス> --psi
   ```
   複数サイトは `--list <urls.txt>`（1行「URL<TAB>repoパス」）。判定は OK / NG / 対象外 / 要手動。
2. NG を直す。実装は Codex（`tools/codex-do.mjs --prompt-file`）へ渡し、Claude はレビュー・検証だけ行う。
3. 要手動の項目（12 速度・13 コントラスト・20 CTA・21 操作テスト・23 DBバックアップ・25 認証）は Playwright（/deploy-verify の Layer2）で確かめ、結果を PR 本文に書く。
4. 対象外は理由を必ず書く（例: 「25 認証: ログイン機能なし」「23 DB: DB を使っていない」「5 Cookie同意: 追跡タグなし」）。
5. デプロイ後、ログアウト状態（シークレットウィンドウ相当の未ログイン Playwright）で表示と主要操作を確かめる。Vercel の Deployment Protection（ログイン壁）が公開サイトに掛かっていないことも見る。
6. もう一度 `site-prelaunch-check.mjs` を走らせ、NG が残っていないことを PR 本文の表に貼る。

## 書く内容の決まり

- プライバシーポリシー・利用規約は、運営会社（株式会社オージャスト 等、サイトの実際の運営主体）とサイトの実態（取得する情報・使う外部サービス・問い合わせ先）に合わせる。実際にしていないこと（会員登録・決済・Cookie 利用など）を書かない。雛形の写しで済ませない。
- アクセス解析・エラー監視・スパム対策は無料枠・既存資産だけで入れる（Vercel Web Analytics / Speed Insights の無料枠、Cloudflare Turnstile、honeypot、Sentry 無料枠など）。有料契約が要るなら入れずに kim へ推奨案付きで聞く。
- 既存の公開・フォーム受付を止めない。セキュリティヘッダ（特に CSP）は Report-Only から始めるか、外部スクリプトの許可を確認してから強制にする。
- 社内ツール（社員だけが使う画面）でも 3・4・15・16・17・22・24・25 は対象。SEO 系（6・7・9）や Cookie 同意は「社内限定・noindex」を理由に対象外にしてよい。
