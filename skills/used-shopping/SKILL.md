# 中古品・部品の探し方

## 原則
- **user の手間を Claude の効率（トークン・ツール回数・時間）より優先する**（kim 2026-10-10 厳命）。調べ物は全部 Claude 側で完結。
- 購入・入札（支払い）だけ user 本人。

## 検索
`node ~/orgiast-claude-rules/tools/frima-search.mjs "<語1>|<語2>|<語3>" --min <下限> --exclude ジャンク,... --qty <必要数>`
（tools の場所が違うPCは `~/.claude/nightly-repo/tools/` 等。無ければ `find` で frima-search.mjs を探す）
- WebFetch ではフリプラの中身が取れない（JS描画）。このツールが内部 API を直接叩く。
- **--shops で絞らない**。全サイト横断が既定。user が「ヤフオクで」と言っても PayPayフリマ・Yahoo!ショッピング・メルカリ・ラクマ等も出し、指定サイト分は別枠で示す（2026-10-10 に --shops yahoo で絞り、PayPayフリマの 2,980円を見落として 6,500円を推奨した実害）。
- 言い換え語を最低3つ（正式型番・略称・規格表記・用途語）。1語あたり各サイト約20件しか返らない。
- フリプラ API は売切品も返すので既定で除外済み（`--include-sold` で解除）。ジモティーは status が付かないことがあるので、出品ページで受付中か確認する。

## 候補の出し方
- **必要数 N なら N×2 以上の具体的出品**を表で出す（URL・価格・送料・数量/枚数・状態・返品可否）。
- セット品（2枚組等）は枚数換算し、必要数を満たす組み合わせと合計金額を最安順に2〜3案。
- user が参考 URL を出したら、それより安い同等品が無いか必ず比較して結果を書く。

## 互換性
- 出品ページで確認してから推奨。例: サーバー用メモリは RDIMM / Registered / ECC Reg のみ、UDIMM・SO-DIMM 不可。容量・規格・形状も確認。
- 確認できない項目は「未確認」と書く。

## 出品ページの確認
- WebFetch でヤフオク・PayPayフリマ・メルカリ・ラクマの個別ページは取れる。
- ログインが要るページは Yahoo ログイン済みプロファイル（kim PC のみ）。
