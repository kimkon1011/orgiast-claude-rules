## 4. 検出器の隙間（P3 が取り逃す理由・実測）

既存 `tools/permanent-fix-deferral-scan.mjs` の P3 は
`次に kim がすること: <空でない1行>` かつ その行に FIX 語（`実装|修正|改修|恒久|恒久化|修復|作り直`）
を要求する。このため原典は **2 重に**すり抜ける:

1. `次に kim がすること: なし（4ファイルは未コミットのまま…）` → `HANDOFF_EMPTY`（先頭「なし」）で除外。
2. `次に kim がすること: … git commit を実行する`（`13c7b7ed`）→ 行内に commit はあるが **FIX 語に
   `commit/コミット` が無い**ので除外。

→ 原典・原典の兄弟・`17dc61be` のような **「完了報告に commit 未実施が残る」型は P3 の網の外**。
本監査の新ツールは commit 語 ∧ 未実施標識の近接共起でこの型だけを直接拾う（P3 の代替ではなく補完）。
