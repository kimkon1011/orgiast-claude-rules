## 成功基準と観測
- C1: ゴールの全要求を満たす。要求ごとの対象・確認方法・結果・証跡を state に記録する。
- C2: `{{GATE}}` が終了コード0。テスト収集自体が成功し、未検証の要求を残さない。
- C3: 変更と証拠が対応する小さなコミット。`git commit -F <msgfile> -- <paths>` を使う。
最初は VERIFY から始める。未実行を緑としない。証拠は対象リビジョンに結びつけ、変更で影響する証拠を無効化する。
maker != checker: 客観的な既存テストで検証。危険な変更の独立確認ができなければ未完了と記録する。

## 1メッセージ1イテレーション
1. この契約と `.loop/{{SLUG}}-state.md` を読む。前回の差分・中断・証跡を照合する。
2. 着手前に試行を予約し累積数を増やす。未達要求を一つ選び、予想する観測結果を記録する。
3. DISCOVER → PLAN → EXECUTE → VERIFY。小さな修正か原因を絞る実験を行う。
4. 予測と実測を比較し、続行・方針変更・待機・完了・未完了停止を選び根拠を残す。
5. 全要求の証拠が揃った場合だけ独立した行 `FINAL` を返す。それ以外は `ITERATING`。

## 適応判断
同じ原因で2回進展がなければ仮説または単位を変える。3回新しい証拠がなければ未完了として停止理由と再開条件を書く。
原因を否定した新しい実測も進捗。コマンド反復・文章変更・コミット数だけを進捗にしない。
テストや受け入れ基準を弱めない。自己採点で成功にしない。新たな無関係の仕事へ広げない。

## 復旧可能な状態
`.loop/{{SLUG}}-state.md` にゴール、要求別証跡、累積試行、実行中の試行、失敗仮説、次の1手、停止理由を保存。
中断した試行も消費済み。既存状態を上書き・リセットしない。別途 runner が保持する累積カウンタも上限に従う。

## 停止条件と境界
累積 {{MAX_ITERATIONS}} tick、runner の deadline、枠97%、対話利用検出、検証済み完了のいずれかで停止。
上限・失敗・中断は成功ではない。未完了の証跡と残件を state に残す。
子のデタッチ実行・別ループ開始・スケジュール追加は禁止。人の作業ツリー・認証・課金設定を変更しない。
push・PR作成は外側の runner が担当。自動マージ・本番反映・force-push は禁止。
